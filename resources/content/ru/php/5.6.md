# PHP 5.6: Мост к современному PHP

Простое математическое выражение вида `2 ** 3 ** 2` или строгая проверка переданного пользователем JSON могут полностью изменить логику выполнения вашей программы при переходе на PHP 5.6. Будучи финальным релизом ветки 5.x, PHP 5.6 служит мостом между старым движком PHP и современной экосистемой PHP 7.

До PHP 5.6 написание функций с динамическим числом аргументов требовало использования неуклюжих конструкций вроде `func_get_args()` и их передачи через медленный вызов `call_user_func_array()`. Импорт функций из пространств имен требовал создания лишних оберток, а константы не могли содержать даже базовых математических формул.

> [!IMPORTANT]
> PHP 5.6 представил вариадические сигнатуры, распаковку аргументов и строгие настройки шифрования по умолчанию, чтобы подготовить проекты к переходу на PHP 7.

<a id="variadic"></a>
## Вариадические параметры (`...$params`)

Функции теперь могут принимать произвольное количество аргументов без обращения к `func_get_args()`.

```php
// app/Helpers/Math.php
function sum(int $first, int ...$others): int
{
    $accumulator = $first;
    foreach ($others as $number) {
        $accumulator += $number;
    }
    return $accumulator;
}

echo sum(1, 2, 3, 4); // 10
```

* **Почему это важно**: Сигнатуры методов становятся самодокументируемыми, а среды разработки (IDE) могут корректно проверять типы и автодополнять аргументы.

<a id="unpacking"></a>
## Распаковка аргументов

Массивы и объекты `Traversable` могут быть «распакованы» в список параметров непосредственно при вызове функции.

```php
// app/Services/Logger.php
$args = ["Пользователь %s вошел с IP %s", "admin", "127.0.0.1"];
echo sprintf(...$args);
```

* **Почему это важно**: Заменяет медленные и сложные вызовы `call_user_func_array()` чистым нативным синтаксисом, выполняющимся на уровне компилятора.

<a id="pow-op"></a>
## Оператор возведения в степень (`**`)

В PHP 5.6 добавлен оператор `**` для возведения в степень, предлагающий более лаконичную альтернативу функции `pow()`.

```php
// app/Services/Physics.php
$square = 4 ** 2; // 16
$cube = 2 ** 3;   // 8
```

> [!WARNING]
> Оператор `**` является правоассоциативным. Это означает, что `2 ** 3 ** 2` вычисляется как `2 ** (3 ** 2) = 2 ** 9 = 512`, а не как `(2 ** 3) ** 2 = 8 ** 2 = 64`.

<a id="use-imports"></a>
## `use function` и `use const`

Конструкция `use` расширена и теперь позволяет импортировать конкретные функции и константы из пространств имен, а не только классы.

```php
// app/Services/StringManager.php
namespace App\Services;

use function SomeLib\stringHelper;
use const SomeLib\API_VERSION;

class StringManager
{
    public function getVersion(): string
    {
        return stringHelper(API_VERSION);
    }
}
```

* **Почему это важно**: Это позволяет избежать захламления глобального пространства имен и наглядно декларировать зависимости от внешних библиотек в начале файла.

<a id="const-expr"></a>
## Константные выражения

В объявлениях констант классов, значений свойств по умолчанию и параметров теперь можно использовать скалярные выражения (математические формулы, конкатенацию).

```php
// app/Config/Limits.php
class Limits
{
    public const ONE_MB = 1024 * 1024;
    public const MAX_UPLOAD = self::ONE_MB * 50; // 50MB
    public static $debugMode = (self::MAX_UPLOAD > 10000);
}
```

<a id="hash-equals"></a>
## Безопасное сравнение строк (`hash_equals`)

Сравнивает две строки за одинаковое время, независимо от того, насколько совпадают их символы.

```php
// app/Services/Security.php
$signature = $_GET['signature'];
$expected = hash_hmac('sha256', $data, $key);

if (hash_equals($expected, $signature)) {
    // Подпись верна
}
```

* **Почему это важно**: Предотвращает атаки по времени (timing attacks) при валидации токенов пользователей, паролей или подписей HMAC.

<a id="common-mistakes"></a>
## ⚠️ Частые ошибки

### 1. Приоритет унарных операторов и возведения в степень
Смешивание отрицания `-` или других унарных операторов с `**` без скобок может привести к ошибкам компиляции или неверным математическим расчетам.

```php
// app/Demo/MathErrors.php
// ❌ Ошибка компиляции! Оператор степени имеет более высокий приоритет
$result = -2 ** 2; 

// ✅ Правильный подход
$result = (-2) ** 2; // 4
```

### 2. Использование устаревшей переменной `$HTTP_RAW_POST_DATA`
До PHP 5.6 для необработанных POST-данных использовалась `$HTTP_RAW_POST_DATA`. В PHP 5.6 она объявлена устаревшей.

```php
// app/Http/Webhook.php
// ❌ Устарело в PHP 5.6, вызывает E_DEPRECATED
$data = $HTTP_RAW_POST_DATA;

// ✅ Правильный подход
$data = file_get_contents('php://input');
```

### 3. Обработка ошибок в json_decode()
Метод `json_decode()` стал строже относиться к некорректным литералам (например, `TRUE`, `FALSE`, `NULL` в верхнем регистре), вызывая синтаксические ошибки там, где раньше возвращал `null`.

## Практические рецепты

### Избавляемся от `call_user_func_array`

```php
// app/Demo/UnpackDemo.php
class Invoker
{
    public function execute(callable $callback, array $params)
    {
        // Ожидание: Заменяем медленный call_user_func_array на распаковку
        // Реальность:
        // В PHP 5.5: call_user_func_array($callback, $params);
        // В PHP 5.6:
        return $callback(...$params);
    }
}
```

<a id="backward-incompatible"></a>
## Обратная несовместимость

1. **Строгие проверки SSL/TLS по умолчанию**: Проверка хоста и цепочки сертификатов теперь включена по умолчанию. Запросы к серверам с самоподписанными сертификатами будут отклоняться, если не настроить контекст потока вручную.
2. **Приоритет `**`**: Изменение ассоциативности оператора возведения в степень может повлиять на математические расчеты при переносе кода.
3. **Строгость `json_decode()`**: Использование верхнего регистра в JSON-литералах теперь вызывает ошибки синтаксиса.
4. **Переопределение ключей массивов**: Объявления статических массивов, содержащих дублирующиеся ключи, теперь перезаписывают их строго в порядке следования.

## 🧠 Вопросы для самопроверки

1. **Верно или нет?** Оператор `...` можно указать несколько раз в сигнатуре параметров одной функции.
2. Какой результат вернет выражение `2 ** 3 ** 2` в PHP 5.6?
3. Что пришло на смену устаревшей переменной `$HTTP_RAW_POST_DATA`?
4. **Верно или нет?** Функция `hash_equals()` безопасна против атак по времени, потому что она сравнивает строки за переменное время.

<details>
<summary><b>Показать ответы</b></summary>

1. **Неверно.** Функция может содержать только один вариадический параметр, и он должен располагаться на последнем месте в сигнатуре.
2. `512` (так как оператор правоассоциативен: сначала `3 ** 2 = 9`, затем `2 ** 9 = 512`).
3. Чтение сырого потока ввода из `php://input`.
4. **Неверно.** Она безопасна, поскольку сравнивает строки за **постоянное** время (constant time), то есть время проверки не зависит от совпадения символов.
