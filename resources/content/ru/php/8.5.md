# PHP 8.5: Главные нововведения и интерактивное руководство

PHP 8.5 продолжает двигаться в сторону повышения выразительности языка и консолидации ядра платформы. Ключевые нововведения релиза: долгожданный **Pipe Operator (`|>`)** для красивых цепочек преобразований, атрибут **`#[\NoDiscard]`** для контроля возвращаемых значений и новое системное расширение **URI** для парсинга адресов.

Давайте разберем эти фичи на живых примерах, обсудим подводные камни и проведем тест для самопроверки в конце!

<a id="pipe-operator"></a>
## Оператор пайплайна (`|>`)

Надоели вложенные вызовы вроде `strtolower(trim($input))` или постоянное создание временных переменных? PHP 8.5 добавляет оператор пайпа **`|>`**, который позволяет передавать результат левого выражения в правый вызов по цепочке.

```php
// app/Services/Slugger.php
$slug = $title
    |> trim(...)
    |> strtolower(...)
    |> fn($s) => preg_replace('/\s+/', '-', $s);

echo $slug; // Вывод: hello-world
```

> [!NOTE]
> **А вы знали?**
> Оператор `|>` передает левое значение в качестве **первого аргумента** в правый callable. Если вам нужно передать его вторым или третьим параметром, просто оберните правый вызов в кастомное замыкание или стрелочную функцию.

### ⚠️ Частые ошибки разработчиков

**1. Отсутствие круглых скобок вокруг стрелочных функций**
Если вы используете стрелочную функцию внутри пайпа, ее обязательно нужно обернуть в круглые скобки во избежание неоднозначности парсинга:
```php
// app/Services/Formatter.php
// ❌ Синтаксическая ошибка!
$result = $value |> fn($x) => $x * 2 |> fn($y) => $y + 10;

// ✅ Правильный вариант
$result = ($value |> fn($x) => $x * 2) |> fn($y) => $y + 10;
```

<a id="closures-in-constants"></a>
## Замыкания в константных выражениях

PHP 8.5 позволяет объявлять **замыкания** и **first-class callables** в местах, которые ранее принимали только статические значения: константы классов, значения по умолчанию для свойств и аргументы атрибутов.

```php
// app/Attributes/Route.php
class Route
{
    public function __construct(
        public string $path,
        public Closure $callback = (fn() => 'Default Route')
    ) {}
}
```

Это огромный плюс для роутеров и библиотек валидации, которым нужно описывать легковесную логику прямо в метаданных.

<a id="nodiscard"></a>
## `#[\NoDiscard]` и приведение к `(void)`

При вызове методов валидации или записи результатов разработчики часто забывают обработать возвращаемый булевый флаг или объект ответа. В PHP 8.5 добавлен атрибут `#[\NoDiscard]`, сообщающий о том, что результат вызова игнорировать нельзя.

```php
// app/Services/Transaction.php
class Transaction
{
    #[\NoDiscard]
    public function commit(): bool
    {
        // ...
        return true;
    }
}

$tx = new Transaction();
$tx->commit(); // ❌ Предупреждение: Результат вызова commit() не должен быть отброшен!
```

Если вы хотите явно отбросить результат метода с таким атрибутом, используйте новое приведение к типу `(void)`:

```php
// app/Services/Handler.php
(void) $tx->commit(); // ✅ Ошибка подавлена, мы сознательно проигнорировали результат!
```

<a id="uri-extension"></a>
## Встроенное расширение URI (RFC 3986)

Парсить URL-адреса вручную всегда было рискованно с точки зрения безопасности. PHP 8.5 поставляет встроенное и всегда активное расширение `uri`, полностью соответствующее RFC 3986 и спецификации WHATWG.

```php
// app/Services/UrlParser.php
$uri = Uri\parse('https://user:pass@example.com:8080/path?query=1#hash');

echo $uri->host;     // example.com
echo $uri->port;     // 8080
echo $uri->userInfo; // user:pass
```

<a id="new-functions"></a>
## Новые функции: `array_first()` и `array_last()`

Вместо сброса указателей массива с помощью `reset()` и `end()` теперь можно использовать встроенные и оптимизированные хелперы:

```php
// app/Services/Collection.php
$list = ['яблоко', 'банан', 'вишня'];

$first = array_first($list); // 'яблоко'
$last  = array_last($list);  // 'вишня'
```

Кроме того, флаг `FILTER_THROW_ON_FAILURE` теперь позволяет фильтрам генерировать исключение `ValueError` вместо возврата `false`:

```php
// app/Http/Request.php
$id = filter_input(INPUT_GET, 'id', FILTER_VALIDATE_INT, FILTER_THROW_ON_FAILURE);
```

<a id="backward-incompatible"></a>
## Обратно несовместимые изменения (Чек-лист для перехода)

Перед обновлением продакшн-серверов на PHP 8.5 убедитесь в совместимости вашего кода:

1. **Opcache встроен в бинарный файл**
   Opcache больше не собирается как отдельный модуль. Попытка прописать `zend_extension=opcache.so` в `php.ini` вызовет предупреждение.
2. **Изменение числовых констант PDO**
   Backing-числа некоторых fetch-режимов PDO (например, `PDO::FETCH_GROUP`) изменились в 8.5. Если вы хранили эти числа в БД или конфигах — проверьте их.
3. **Ограничения `class_alias()`**
   Запрещено использовать имена `"array"` и `"callable"` в качестве алиасов классов.

<a id="self-check"></a>
## 🧠 Вопросы для самопроверки

Проверим наши знания по PHP 8.5:
1. **Правда или ложь?** Правая часть оператора пайпа (`|>`) по умолчанию может принимать неограниченное число параметров.
2. Как явно подавить предупреждение при вызове метода, помеченного атрибутом `#[\NoDiscard]`?
3. Какую директиву `zend_extension` нужно указать в `php.ini`, чтобы загрузить Opcache в PHP 8.5?
4. **Правда или ложь?** Хелперы `array_first()` и `array_last()` корректно работают с ассоциативными массивами.

<details>
<summary><b>Показать ответы</b></summary>

1. **Ложь.** Правая часть должна принимать строго один аргумент. Если функция требует больше параметров, оберните ее в замыкание или стрелочную функцию.
2. Перед вызовом нужно добавить приведение к `(void)` (например, `(void) $obj->method();`).
3. Никакую! Opcache уже встроен в ядро. Его достаточно включить через `opcache.enable=1`.
4. **Правда.** Они возвращают первый и последний элемент любого переданного массива, независимо от того, являются ли ключи числовыми или ассоциативными.
</details>
