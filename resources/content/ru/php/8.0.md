<a id="named-arguments"></a>
## Named Arguments (Именованные аргументы)

Передача аргументов в функцию по имени избавляет от необходимости помнить их порядок и позволяет пропускать необязательные параметры. Это делает код самодокументируемым.

```php
// Раньше: приходилось указывать все параметры по порядку
setcookie('test', '', time() + 60 * 60 * 2, '/', '', false, true);

// PHP 8.0: указываем только нужное
setcookie(
    name: 'test',
    expires: time() + 60 * 60 * 2,
    httponly: true
);

```

<a id="match-expression"></a>

## Match Expression

Более строгая и лаконичная альтернатива оператору switch. Возвращает значение и использует строгое сравнение (===), избавляя от неожиданных багов с приведением типов.

<live-terminal></live-terminal>

```PHP

$statusCode = 200;

$statusMessage = match ($statusCode) {
200, 300 => 'Успех или Редирект',
400, 404 => 'Ошибка клиента',
500 => 'Ошибка сервера',
default => 'Неизвестный статус',
};

```

<a id="nullsafe-operator"></a>

## Nullsafe Operator (?->)
Позволяет читать свойства и вызывать методы в цепочке. Если один из элементов null, вся цепочка возвращает null без выброса фатальной ошибки.

```PHP

// PHP 7.4
$country = null;
if ($session !== null) {
    $user = $session->user;
    if ($user !== null) {
        $country = $user->getAddress()->country;
    }
}

// PHP 8.0
$country = $session?->user?->getAddress()?->country;

```

<a id="constructor-promotion"></a>

## Constructor Property Promotion (Продвижение свойств в конструкторе)

Раньше для создания простых DTO (Data Transfer Objects) или Value Objects приходилось писать много однотипного кода: объявлять свойства, передавать их в конструктор и присваивать. PHP 8.0 объединяет все эти три шага в один.

```php
// PHP 7.4: Классический (и многословный) подход
class UserDTO 
{
    public string $name;
    public string $email;
    protected int $age;

    public function __construct(string $name, string $email, int $age) 
    {
        $this->name = $name;
        $this->email = $email;
        $this->age = $age;
    }
}

// PHP 8.0: Элегантно и лаконично
class UserDTO 
{
    public function __construct(
        public string $name,
        public string $email,
        protected int $age,
    ) {}
}

```

<a id="union-types"></a>

## Union Types (Объединенные типы)

До PHP 8.0, если переменная могла принимать несколько типов данных (например, `int` или `float`), мы были вынуждены убирать строгую типизацию и полагаться на PHPDoc аннотации. Теперь PHP поддерживает это нативно на уровне интерпретатора.

```php

// PHP 7.4: Типизация через комментарии
class Calculator 
{
    /** @var int|float */
    private $number;

    /**
     * @param int|float $number
     */
    public function setNumber($number): void 
    {
        $this->number = $number;
    }
}

// PHP 8.0: Нативная поддержка
class Calculator 
{
    private int|float $number;

    public function setNumber(int|float $number): void 
    {
        $this->number = $number;
    }
}

```

<a id="attributes"></a>

## Attributes / Аннотации

Атрибуты (в других языках известные как аннотации или декораторы) позволяют добавлять машиночитаемые метаданные к классам, методам, свойствам и параметрам. Ранее в экосистеме PHP (например, в Symfony или Doctrine) для этого использовались специальные комментарии (DocBlocks), которые приходилось парсить регулярными выражениями.

```php
// PHP 7.4: Метаданные в комментариях (требует сторонних парсеров)
class PostsController
{
    /**
     * @Route("/api/posts/{id}", methods={"GET"})
     * @Cache(expires="tomorrow")
     */
    public function show($id) 
    {
        // ...
    }
}

// PHP 8.0: Нативные атрибуты
class PostsController
{
    #[Route("/api/posts/{id}", methods: ["GET"])]
    #[Cache(expires: "tomorrow")]
    public function show($id) 
    {
        // ...
    }
}

```

## Attributes / Аннотации (Глубокий разбор)

Атрибуты позволяют добавлять структурированные машиночитаемые метаданные прямо в синтаксис языка, отказываясь от медленного парсинга PHPDoc-комментариев.

### 1. Создание кастомного атрибута
Чтобы PHP понял, что класс является атрибутом, его нужно пометить системным атрибутом `#[Attribute]`. Можно строго указать, куда его разрешено применять (например, только к методам или классам).

```php
#[Attribute(Attribute::TARGET_CLASS | Attribute::TARGET_METHOD)]
class Route 
{
    public function __construct(
        public string $path,
        public array $methods = ['GET']
    ) {}
}

```

### Применение атрибута

Теперь мы можем "навесить" этот атрибут на наш контроллер.

```PHP

#[Route('/api/users', methods: ['GET', 'POST'])]
class UserController
{
    public function index() {}
}

```

### Чтение в рантайме (Reflection API)

Главная сила атрибутов раскрывается при их чтении "на лету" ядром фреймворка:

```PHP

$reflection = new ReflectionClass(UserController::class);
$attributes = $reflection->getAttributes(Route::class);

foreach ($attributes as $attribute) {
    // Инстанцируем класс атрибута
    $route = $attribute->newInstance();

    echo "Path: " . $route->path . "\n";
    echo "Methods: " . implode(', ', $route->methods) . "\n";
}
// Вывод:
// Path: /api/users
// Methods: GET, POST

```

<a id="string-functions"></a>

### Новые строковые функции

Вместо использования перегруженной функции strpos() и проверок на !== false, в ядро добавили три интуитивно понятные функции, которые возвращают строгий bool.

```PHP

$string = "DevSense is awesome";

// Раньше: if (strpos($string, "DevSense") === 0)
if (str_starts_with($string, "DevSense")) {
    echo "Начинается с DevSense";
}

// Раньше: if (strpos($string, "awesome") !== false)
if (str_contains($string, "awesome")) {
    echo "Содержит awesome";
}

// Раньше: (substr($string, -strlen("awesome")) === "awesome")
if (str_ends_with($string, "awesome")) {
    echo "Заканчивается на awesome";
}

```

<a id="throw-expression"></a>

### Throw Expression

Оператор throw из конструкции (statement) превратился в выражение (expression). Это позволяет выбрасывать исключения там, где раньше это было синтаксически невозможно — например, в стрелочных функциях или при использовании оператора нулевого слияния ??.

```PHP

// Использование с Null Coalescing оператором
$user = $request->get('user') ?? throw new InvalidArgumentException('User is required');

// Использование в стрелочных функциях
$callable = fn() => throw new Exception('This callback should not be called');

// Использование в тернарном операторе
$value = $condition ? doSomething() : throw new Exception('Condition failed');

```

<a id="jit-performance"></a>

## JIT-компилятор и Производительность

Самое фундаментальное архитектурное изменение под капотом PHP 8.0 — внедрение JIT (Just-In-Time) компилятора.


## Как изменился процесс компиляции и рантайма?

До PHP 8.0 (OPcache): Исходный PHP-код парсился и компилировался в промежуточные инструкции (OpCodes). OPcache сохранял эти инструкции в памяти. В рантайме виртуальная машина Zend (Zend VM) построчно читала OpCodes и выполняла соответствующие им C-функции.

PHP 8.0 (С включенным JIT): JIT анализирует OpCodes и компилирует наиболее часто выполняемые участки кода ("горячие пути" / Tracing JIT) напрямую в машинный код (x86/ARM). В рантайме процессор выполняет эти инструкции напрямую, минуя прослойку Zend VM.


## Влияние на производительность

Web-приложения (I/O Bound): Для типичного Laravel/Symfony приложения прирост скорости минимален (около 1-5%). Узким местом веб-приложений остаются запросы к Базе Данных, сети и файловой системе, а не вычисления CPU.

Математика и фоновые воркеры (CPU Bound): При рендеринге фракталов, обработке видео, парсинге огромных массивов данных или работе с асинхронными серверами (ReactPHP/Swoole) JIT дает феноменальный прирост производительности от 300% до 500%.


<a id="modules-changes"></a>

## Изменения в модулях и ресурсах

PHP 8.0 начал глобальную очистку ядра от старых архитектурных решений. Главное изменение — переход от непрозрачных Ресурсов (Resources) к объектам.

### Миграция Ресурсов на Объекты

В прошлых версиях функции вроде **curl_init()** возвращали тип данных resource. Проблема ресурсов в том, что они не типизируются и не работают с объектно-ориентированными паттернами.


## В PHP 8.0 многие модули переписаны:

Расширение **cURL**: **curl_init()** теперь возвращает объект класса **CurlHandle**.

Расширение **GD**: **imagecreate()** теперь возвращает объект **GdImage**.

Расширение **Sockets**: **socket_create()** возвращает объект **Socket**.

Плюс: Они автоматически очищаются сборщиком мусора, когда на объект больше нет ссылок.


## Изменения в ядре (Core)

**JSON**: Расширение **JSON** теперь встроено в ядро намертво. Его больше нельзя отключить (**опция --disable-json удалена при компиляции PHP**).

**XML-RPC**: Устаревшее расширение перенесено из ядра **PHP** в **PECL**.

Строгость типов: Огромное количество встроенных функций PHP теперь выбрасывают **TypeError**, если им передать параметр неправильного типа (раньше они могли просто выдать Warning и вернуть null).
