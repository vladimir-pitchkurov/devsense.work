# PHP 7.2: Главные нововведения

Что, если обычный подсчет элементов переменной внезапно начнет забивать ваши логи предупреждениями? PHP 7.2 вводит строгий контроль за использованием функции `count()`, обнажая тысячи скрытых багов в проектах, где разработчики вызывали её для несосчитываемых типов, таких как `null` или `boolean`. Данная версия наводит порядок в повседневной разработке благодаря типу `object`, расширению типов параметров, встроенной библиотеке libsodium и строгой гигиене предупреждений.

<a id="object-type"></a>
## Тип `object`

Теперь можно указывать **`object`** в качестве типов аргументов и возвращаемых значений — ему соответствует любой объект. Это нововведение дополняет правила ковариантности и контравариантности типов по мере развития линейки PHP 7.x.

```php
// src/ObjectHandler.php
function acceptsAnyObject(object $x): void 
{
    // Работа с объектом
}
```

> [!NOTE]
> А вы знали? До PHP 7.2 вы не могли объявлять обобщенные типы объектов в аргументах. Разработчикам приходилось рассчитывать на PHPDoc-аннотации или делать ручные проверки через `is_object()`.

<a id="type-widening"></a>
## Расширение типов параметров (type widening)

Классы-наследники теперь могут **опускать типы параметров**, объявленные в родительских методах или интерфейсах (это безопасно с точки зрения контравариантности). Однако вы **не можете** сужать типы или менять их на другие неродственные типы — PHP отклонит такие некорректные переопределения.

```php
// src/Logger.php
interface Logger {
    public function log(string $msg);
}

class MyLogger implements Logger {
    // Тип параметра опущен (расширен), что валидно в PHP 7.2
    public function log($msg) {
        echo $msg;
    }
}
```

> [!NOTE]
> А вы знали? Расширение типов параметров позволяет библиотекам обновлять свои интерфейсы, добавляя строгие типы, без моментального нарушения работы кода пользователей, чьи классы-наследники типы опускают.

<a id="pdo-debug"></a>
## PDO: детальный `debugDumpParams()`

Метод `PDOStatement::debugDumpParams()` теперь отображает **полный SQL-запрос**, отправленный на сервер при использовании **эмулируемых подготавливаемых запросов** (emulated prepares), включая связанные значения. Это сильно упрощает отладку формирования SQL.

```php
// src/DatabaseDebug.php
$stmt = $pdo->prepare("SELECT * FROM users WHERE status = :status");
$stmt->execute(['status' => 'active']);
$stmt->debugDumpParams();
```

<a id="ldap-exop"></a>
## LDAP EXOP (расширенные операции)

Добавлены хелперы **`ldap_exop()`**, **`ldap_exop_passwd()`**, **`ldap_exop_whoami()`**, **`ldap_parse_exop()`**, а также новые константы вроде **`LDAP_EXOP_START_TLS`** — это упрощает работу со стандартными протоколами EXOP без низкоуровневой обвязки.

<a id="sockets-addrinfo"></a>
## Sockets: `socket_addrinfo_*`

Функции **`socket_addrinfo_lookup()`**, **`socket_addrinfo_connect()`**, **`socket_addrinfo_bind()`**, **`socket_addrinfo_explain()`** оборачивают системные вызовы `getaddrinfo()`. Используйте их вместо ручного разбора адресов IPv4/IPv6.

<a id="sodium"></a>
## Sodium (libsodium) в ядре

В PHP 7.2 расширение **Sodium** включено по умолчанию. Оно предоставляет функции AEAD-шифрования, хеширования и генерации ключей. Рассматривайте его как стандарт при написании **нового криптографического кода** взамен удаленного расширения **mcrypt**.

```php
// src/CryptoHelper.php
$nonce = random_bytes(SODIUM_CRYPTO_SECRETBOX_NONCEBYTES);
$key = sodium_crypto_secretbox_keygen();
$ciphertext = sodium_crypto_secretbox('message', $nonce, $key);
```

<a id="extensions-stdlib"></a>
## Стандартная библиотека и расширения

* Функции **`utf8_encode()` / `utf8_decode()`** перенесены в ядро строковых функций (теперь они не требуют обязательного наличия расширения XML).
* Функции **`mail()` / `mb_send_mail()`** теперь поддерживают передачу заголовков в виде **массивов** (в дополнение к строкам).
* Расширение **DBA** получило поддержку драйвера **LMDB**.
* **GD**: функция **`imageantialias()`** адаптирована под системную библиотеку libgd; **`imagegd()`** точнее сохраняет полноцветные (truecolor) изображения.
* Вызов **`session_module_name('user')`** теперь вызывает перехватываемую ошибку (recoverable error) вместо немого сбоя.

<a id="practical-recipes"></a>
## Практические рецепты

### Защищенный вызов `count()`

```php
// src/recipes.php
if (is_array($x) || $x instanceof \Countable) {
    $n = count($x);
}
```

(Функция `is_countable()` появится только в PHP 7.3; на 7.2 используйте это явное условие.)

### Безопасное использование `get_class()`

```php
// src/recipes.php
$cls = is_object($obj) ? get_class($obj) : self::class;
```

<a id="common-mistakes"></a>
## Частые ошибки

Ниже приведены типичные ошибки разработчиков при переходе на PHP 7.2:

### 1. Подсчет несосчитываемых типов
Передача `null`, чисел, строк или стандартных объектов в `count()` теперь вызывает Warning.
```php
// src/BadCount.php
// Плохо: Передача null вызовет Warning: count(): Parameter must be an array or an object that implements Countable
$data = null;
echo count($data); 
```
```php
// src/GoodCount.php
// Хорошо: Проверяйте тип перед подсчетом
$data = null;
echo (is_array($data) || $data instanceof \Countable) ? count($data) : 0;
```

### 2. Передача `null` в функцию `get_class()`
В прошлых версиях вызов `get_class(null)` возвращал имя текущего класса, откуда был вызван метод. Теперь это вызывает E_WARNING.
```php
// src/BadGetClass.php
// Плохо: Вызовет предупреждение, если $obj окажется null
$className = get_class($obj); 
```
```php
// src/GoodGetClass.php
// Хорошо: Проверяйте, является ли переменная объектом
$className = is_object($obj) ? get_class($obj) : 'DefaultClass';
```

<a id="limitations"></a>
## Ограничения

* **Общий тип `object`**: Вы не можете указать структуру объекта; тип просто проверяет, является ли значение экземпляром какого-либо класса. Вы не можете отсечь базовый `stdClass` средствами тайп-хинтинга.
* **Интеграция libsodium**: Предоставляет низкоуровневые криптографические примитивы. Они очень надежны, но требуют от разработчика понимания базовой криптографии (ключи, нонсы), чтобы не допустить уязвимостей.

<a id="backward-incompatible"></a>
## Обратно несовместимые изменения

### Ядро и типы

* Функция **`number_format()`** больше не возвращает значение **`-0`** в пограничных случаях вычислений с плавающей точкой.
* **Приведение массивов к объектам (и наоборот)** с числовыми ключами стало консистентным. Обращение вида **`$obj->{0}`** работает корректно.
* Вызов **`get_class(null)`** теперь **вызывает warning**; не передавайте null или опускайте аргумент.
* Вызов **`count()`** (и его алиаса **`sizeof()`**) для **несосчитываемых** типов генерирует **`E_WARNING`**. Старый код, ожидавший `count(null) === 0`, начнет писать предупреждения.
* Устарел устаревший автозагрузчик **`__autoload`**, используйте стандартный SPL стек.

### Расширения

* **Расширение mcrypt полностью удалено из ядра PHP**. При крайней необходимости его можно поставить через PECL, но правильный путь — **перейти на OpenSSL или Sodium**.

<a id="deprecations"></a>
## Deprecated (исправить заранее)

Главное:

* Магическая функция **`__autoload()`** — замените на **`spl_autoload_register()`**.
* Использование нецитируемых констант (barewords), которые раньше вызывали notice, теперь выдает **warning**.
* Устарели функции **`create_function()`**, **`each()`**, вызовы **`assert()`** со строковыми аргументами, вызов **`parse_str()`** с одним аргументом, **`read_exif_data()`**, функции GD **`png2wbmp` / `jpeg2wbmp`**.

<a id="other-changes"></a>
## Прочие изменения и сборка

* Unix: для компиляции требуется Autoconf версии 2.64 или выше.
* Расширение **mcrypt** вынесено в **PECL**. Используйте **Sodium/OpenSSL** для работы с криптографией.

   * Б) Наследник класса может полностью опустить объявление типа параметра, который был задан в родителе.

   </details>

<a id="closing-thoughts"></a>
## Итог

Переход на PHP 7.2 — это отличный повод **удалить остатки кода под mcrypt**, провести поиск по использованию **`count(`** для переменных, которые могут быть null, и убрать вызовы **`get_class(null)`**. После этого можно переходить к версии 7.3 с ее `JsonException`, `is_countable()` и улучшенным heredoc.
