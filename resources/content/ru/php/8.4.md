# PHP 8.4: Главные нововведения и интерактивное руководство

PHP 8.4 — это крупный релиз «инструментов для взрослых». Он полностью меняет подходы к выражению инвариантов на границе свойств (Property Hooks, асимметричная видимость), добавляет нативные ленивые объекты для фреймворков и ORM (Lazy Objects), а также решает многолетние проблемы совместимости с HTML5 с помощью нового API в пространстве имен `Dom`.

В этом руководстве мы разберем ключевые фичи на живых примерах, обсудим частые ошибки разработчиков и проведем тест для самопроверки в конце!

<a id="property-hooks"></a>
## Property Hooks (логика get/set у свойства)

Годами PHP-разработчикам приходилось писать тонны шаблонного кода (геттеры и сеттеры) только для того, чтобы валидировать или форматировать значения перед их сохранением. В PHP 8.4 представлены **Property Hooks** («хуки свойств») прямо в объявлении свойства.

Существует два вида хуков:
- `set`: срабатывает при записи значения в свойство.
- `get`: срабатывает при чтении значения свойства.

Давайте посмотрим на живой пример:

```php
// app/DTO/Person.php
final class Person
{
    // Хук может производить запись в скрытое свойство через $this->propName
    public string $firstName {
        set => ucfirst(strtolower($value));
    }

    public string $lastName {
        set {
            if (strlen($value) < 2) {
                throw new InvalidArgumentException('Фамилия слишком короткая!');
            }
            $this->lastName = $value;
        }
    }

    // Вычисляемое (виртуальное) свойство без физического хранения значения!
    public string $fullName {
        get => $this->firstName . ' ' . $this->lastName;
    }
}
```

> [!NOTE]
> **А вы знали?**
> Свойства, которые объявляют только хук `get`, автоматически считаются виртуальными. Они не занимают память внутри объекта и не увеличивают его вес.

### ⚠️ Частые ошибки разработчиков

**1. Попытка передать свойство с хуками по ссылке**
Поскольку обращение к свойству с хуками под капотом вызывает функции, передача по ссылке невозможна:
```php
// app/Services/ContactService.php
function cleanString(string &$str) {
    $str = trim($str);
}

$person = new Person();
cleanString($person->firstName); // ❌ Fatal Error: Cannot pass property Person::$firstName by reference
```

**2. Бесконечная рекурсия в хуках `set`**
Если вы попытаетесь присвоить значение свойству внутри его собственного `set`-хука через `$this->propertyName = $value` (без использования сокращенного синтаксиса `=>`), это может вызвать бесконечную рекурсию. К счастью, стрелочный синтаксис `=>` автоматически берет на себя правильное сохранение в backing storage.

<a id="asymmetric-visibility"></a>
## Асимметричная видимость свойств (`public private(set)`)

Теперь вы можете гибко настраивать область видимости для чтения и записи свойств отдельно. Это великолепное решение для создания иммутабельных DTO и корней агрегатов в рамках Domain-Driven Design (DDD).

```php
// app/Models/User.php
final class User
{
    // Свойство доступно для чтения отовсюду, но изменить его можно только внутри класса
    public private(set) string $email;

    public protected(set) int $loginAttempts = 0;

    public function __construct(string $email)
    {
        $this->email = $email;
    }

    public function incrementAttempts(): void
    {
        $this->loginAttempts++;
    }
}
```

> [!NOTE]
> **А вы знали?**
> Асимметричная видимость накладывает правило: область видимости записи (`set`) должна быть **строже**, чем область чтения. Попытка написать `private public(set)` приведет к синтаксической ошибке.

<a id="lazy-objects"></a>
## Lazy Objects (Ленивые объекты через Reflection)

В PHP 8.4 добавлена нативная поддержка **Lazy Objects** (ленивых объектов). Это нововведение создано в первую очередь для авторов ORM (таких как Doctrine или Laravel Eloquent) и DI-контейнеров, чтобы откладывать тяжелые запросы в базу данных до момента реального обращения к объекту.

Раньше библиотекам приходилось генерировать сложные прокси-классы на лету. Теперь рефлексия берет это на себя:

```php
// app/Services/Container.php
$initializer = static function (LargeService $service) {
    $service->loadHeavyConfiguration();
};

$r = new ReflectionClass(LargeService::class);
// Создаем "ленивый призрак" (lazy ghost) объекта LargeService
$lazyService = $r->newLazyGhost($initializer);
```

Код инициализации сработает только тогда, когда мы впервые попытаемся прочитать или записать какое-либо свойство объекта `$lazyService`.

<a id="deprecated-attribute"></a>
## Депрекации в userland с помощью `#[Deprecated]`

Раньше для предупреждения пользователей о том, что метод или класс устарел, приходилось вызывать `trigger_error(..., E_USER_DEPRECATED)`. В PHP 8.4 для этого появился встроенный атрибут:

```php
// app/Helpers/LegacyMath.php
class LegacyMath
{
    #[\Deprecated(message: "Используйте BCMath или стандартное деление", since: "1.4.0")]
    public static function divide(int $a, int $b): float
    {
        return $a / $b;
    }
}
```

Как только сторонний код вызовет этот метод, PHP выбросит депрекацию с вашим текстом.

<a id="dom-modern"></a>
## Стандарты WHATWG в пространстве имен `Dom\*`

Классический класс `DOMDocument` долго страдал от плохой поддержки HTML5. PHP 8.4 представляет современный API в пространстве имен `Dom`.

```php
// app/Services/HtmlParser.php
// Парсим разметку HTML5 без костылей и предупреждений
$dom = Dom\HTMLDocument::createFromString('<main><article>Modern HTML5!</article></main>');
$node = $dom->querySelector('article');

echo $node->textContent; // Вывод: Modern HTML5!
```

Старый API остался для совместимости, но новые проекты стоит писать с использованием `Dom\HTMLDocument` и `Dom\XMLDocument`.

<a id="request-parse-body"></a>
## Поддержка multipart-данных для PUT/PATCH: `request_parse_body()`

Если вы писали REST API с поддержкой загрузки файлов через `PUT` или `PATCH`, то помните боль: суперглобальные массивы `$_FILES` и `$_POST` наполнялись автоматически только при `POST` запросах. Разработчикам приходилось парсить поток `php://input` вручную.

PHP 8.4 решает это с помощью `request_parse_body()`:

```php
// public/index.php
if ($_SERVER['REQUEST_METHOD'] === 'PUT') {
    [$postData, $files] = request_parse_body();
    
    // $postData содержит поля формы
    // $files содержит загруженные файлы в том же формате, что и $_FILES
}
```

<a id="new-functions"></a>
## Удобные хелперы для массивов и UTF-8

PHP 8.4 добавляет несколько крайне полезных функций для повседневной разработки:

### 1. `array_find()`, `array_find_key()`, `array_any()`, `array_all()`

```php
// app/Services/Validator.php
$users = [
    ['name' => 'Алексей', 'role' => 'user'],
    ['name' => 'Дмитрий', 'role' => 'admin'],
];

// Находим первого администратора
$admin = array_find($users, fn($u) => $u['role'] === 'admin');

// Проверяем, есть ли хоть один обычный пользователь
$hasUsers = array_any($users, fn($u) => $u['role'] === 'user');
```

### 2. Безопасная очистка пробелов в UTF-8 (`mb_trim`)
Обычный `trim()` не умеет работать с многобайтовыми пробелами UTF-8. PHP 8.4 добавляет функции `mb_trim()`, `mb_ltrim()` и `mb_rtrim()`.

<a id="backward-incompatible"></a>
## Обратно несовместимые изменения (BC Breaks)

При переходе на PHP 8.4 обратите внимание на следующие моменты:

1. **Устарели неявно обнуляемые параметры**
   ```php
   // ❌ Устарело в PHP 8.4
   function save(string $name = null) {}

   // ✅ Правильный вариант
   function save(?string $name = null) {}
   ```
2. **Изменение поведения `exit()` и `die()`**
   Они стали полноценными функциями. Теперь они проверяют типы параметров. Передача некорректного объекта или массива вместо строки/числа вызовет `TypeError`.
3. **Ресурсы переведены в объекты**
   Подключения в DBA, ODBC и SOAP теперь возвращают объекты, а не ресурсы. Проверки вида `is_resource()` на них начнут возвращать `false`.

## 🧠 Вопросы для самопроверки

Давайте закрепим прочитанное! Ответьте на следующие вопросы:
1. **Правда или ложь?** Можно ли объявить хук `set` для виртуального свойства?
2. Почему вызов `cleanString($person->firstName)` приведет к ошибке Fatal Error, если у `$firstName` настроены хуки?
3. Что произойдет, если объявить свойство с видимостью `private public(set)`?
4. Какую функцию стоит использовать в PHP 8.4, чтобы убедиться, что *все* элементы массива удовлетворяют заданному условию?

<details>
<summary><b>Показать ответы</b></summary>

1. **Ложь.** Виртуальное свойство не имеет физического хранилища (backing storage), поэтому для него нельзя определить хук `set` (если только он не записывает значение в другие реальные свойства класса).
2. Свойства с хуками являются вычисляемыми значениями; у них нет фиксированной ссылки в оперативной памяти, поэтому их невозможно передать по ссылке.
3. PHP выбросит синтаксическую ошибку (Syntax Error). Доступ на запись (`set`) должен быть таким же или более строгим, чем доступ на чтение (`get`).
4. Для этого предназначена функция `array_all()`.
</details>
