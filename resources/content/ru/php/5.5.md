# PHP 5.5: Эффективное управление памятью и безопасность из коробки

Попытка прочитать 5-гигабайтный лог-файл целиком с помощью функции `file()` может исчерпать память вашего сервера за секунды, вызвав ошибку "Allowed memory size exhausted". PHP 5.5 навсегда решил эту проблему, представив генераторы (`yield`), которые позволяют обрабатывать большие потоки данных «на лету» без лишних затрат ресурсов.

До PHP 5.5 разработчикам приходилось загружать целые наборы данных в память в виде огромных массивов или писать многословные объекты-итераторы. Кроме того, надежное хеширование паролей требовало написания собственных оберток над MD5/SHA256 с солями, а очистка ресурсов при возникновении ошибок была запутанной из-за отсутствия блока `finally`.

> [!IMPORTANT]
> PHP 5.5 принес революционные оптимизации работы с памятью благодаря генераторам и стандартизировал работу с криптографией через встроенный интерфейс Password Hashing API.

<a id="generators"></a>
## Генераторы (`yield`)

Генераторы вычисляют значения по мере необходимости, вместо того чтобы строить и возвращать гигантский массив.

```php
// app/Services/LogReader.php
function readLines(string $filePath): Generator
{
    $handle = fopen($filePath, 'r');
    if (!$handle) {
        return;
    }
    try {
        while (($line = fgets($handle)) !== false) {
            yield trim($line);
        }
    } finally {
        fclose($handle);
    }
}
```

* **Почему это важно**: Обход крупных файлов, результатов баз данных или бесконечных последовательностей теперь требует фиксированного минимального объема памяти (всего несколько килобайт), независимо от объема данных.
* **Последствие**: Пакетная обработка данных становится быстрой и стабильной даже под очень высокими нагрузками.

<a id="finally"></a>
## Блок `finally`

PHP 5.5 дополняет конструкцию `try-catch` блоком `finally`. Код внутри него выполняется всегда, независимо от того, возникло ли исключение или был ли вызван `return` внутри блоков `try`/`catch`.

```php
// app/Services/DatabaseClient.php
public function processTransaction()
{
    $this->db->connect();
    try {
        $this->db->execute();
    } catch (\Exception $e) {
        $this->logError($e);
    } finally {
        // Выполняется ВСЕГДА, предотвращая утечки ресурсов
        $this->db->disconnect();
    }
}
```

* **Почему это важно**: Это упрощает закрытие файловых дескрипторов, сетевых соединений или снятие блокировок.

<a id="password-api"></a>
## Встроенное API хеширования паролей

Забудьте о ручной генерации соли и старых алгоритмах MD5/SHA. Новые функции делают безопасность паролей тривиальной.

```php
// app/Services/AuthService.php
// Хеширование пароля с помощью bcrypt (PASSWORD_DEFAULT)
$hash = password_hash($password, PASSWORD_DEFAULT);

// Проверка пароля при входе пользователя
if (password_verify($password, $hash)) {
    // Если требования к стоимости или алгоритм изменились, обновляем хеш
    if (password_needs_rehash($hash, PASSWORD_DEFAULT)) {
        $newHash = password_hash($password, PASSWORD_DEFAULT);
        // Сохраняем $newHash в базу данных
    }
}
```

> [!NOTE]
> Функция `password_hash` автоматически создает криптографически безопасную случайную соль и встраивает ее прямо в возвращаемую строку хеша, поэтому отдельная колонка для соли в базе данных больше не нужна.

<a id="helpers"></a>
## `array_column()` и `::class`

PHP 5.5 добавил два исключительно полезных инструмента для ежедневной разработки:

### 1. `array_column()`
Извлекает значения одного столбца из многомерного массива или массива объектов.

```php
// app/Services/Report.php
$users = [
    ['id' => 1, 'name' => 'Алексей'],
    ['id' => 2, 'name' => 'Игорь']
];
$ids = array_column($users, 'id'); // [1, 2]
```

### 2. `ClassName::class`
Позволяет получить полное имя класса (с учетом пространства имен) в виде строки.

```php
// app/Services/Container.php
use App\Models\User;
echo User::class; // "App\Models\User"
```

<a id="opcache"></a>
## Интеграция Zend OPcache

Расширение Zend OPcache теперь поставляется в ядре PHP. Оно кэширует скомпилированный байт-код в оперативной памяти, избавляя сервер от необходимости парсить и компилировать PHP-файлы при каждом запросе.

* **Почему это важно**: Производительность приложений увеличивается в 2-3 раза (в зависимости от размера фреймворка).
* **Последствие**: При развертывании кода (деплое) необходимо сбрасывать кэш с помощью `opcache_reset()` или перезапускать менеджер процессов PHP-FPM.

<a id="common-mistakes"></a>
## ⚠️ Частые ошибки

### 1. Опасный модификатор `/e` в `preg_replace`
Модификатор `/e` заставляет интерпретатор выполнять подставляемую строку как PHP-код, что регулярно приводило к уязвимостям удаленного выполнения кода (RCE). В PHP 5.5 этот модификатор признан устаревшим.

```php
// app/Helpers/StringHelper.php
// ❌ Устарело и небезопасно!
$output = preg_replace('/(\w+)/e', 'strtoupper("$1")', $text);

// ✅ Правильный подход
$output = preg_replace_callback('/(\w+)/', function($m) {
    return strtoupper($m[1]);
}, $text);
```

### 2. Утечка ресурсов в генераторах при прерывании цикла
Если вы досрочно прерываете обход генератора (через `break`), код после `yield` может не выполниться, что приведет к утечкам ресурсов, если файлы или сокеты не обернуты в блок `finally`.

```php
// app/Services/FileReader.php
// ❌ Опасно: при выходе из цикла fclose() никогда не вызовется
function readData($file) {
    $fh = fopen($file, 'r');
    while($line = fgets($fh)) yield $line;
    fclose($fh);
}

// ✅ Правильный подход
function readDataSafe($file) {
    $fh = fopen($file, 'r');
    try {
        while($line = fgets($fh)) yield $line;
    } finally {
        fclose($fh); // Выполнится гарантированно при уничтожении генератора
    }
}
```

### 3. Использование старого расширения `mysql`
Функции `mysql_connect()` официально объявлены устаревшими в PHP 5.5.

```php
// app/Database/LegacyDb.php
// ❌ Вызывает предупреждение E_DEPRECATED
$conn = mysql_connect('localhost', 'user', 'pass');

// ✅ Правильный подход
$conn = new PDO('mysql:host=localhost;dbname=test', 'user', 'pass');
```

<a id="practical-recipes"></a>
## Практические рецепты

### Ожидание vs Реальность: блок `finally` и возврат значений

Что произойдет, если возврат значения (statement `return`) указан и в `try`, и в `finally`?

```php
// app/Demo/FinallyDemo.php
function testFinally(): string
{
    try {
        return "Возврат из try";
    } finally {
        return "Возврат из finally";
    }
}

// Ожидание: функция вернет "Возврат из try"
// Реальность:
echo testFinally(); // Вывод: Возврат из finally
```

> [!WARNING]
> Если вы возвращаете значение внутри блока `finally`, оно перезапишет любые результаты возврата (return) или выброшенные исключения из блоков `try` и `catch`. Старайтесь не помещать `return` внутрь `finally`.

<a id="backward-incompatible"></a>
## Обратная несовместимость

1. **Устаревание модификатора `/e` в `preg_replace`**: Вызывает предупреждения; используйте только `preg_replace_callback`.
2. **Устаревание `mysql`**: Функции `mysql_*` выдают ошибки уровня `E_DEPRECATED` при запуске.
3. **`empty()` на выражениях**: Ранее `empty()` принимал только переменные. С версии 5.5 выражение `empty(foo())` корректно работает.
4. **Изменения в `pack()` и `unpack()`**: Могут влиять на бинарную обработку данных в зависимости от архитектуры (64-бит).

## 🧠 Вопросы для самопроверки

1. **Верно или нет?** Функция-генератор возвращает объект класса `Generator`, который реализует интерфейс `Iterator`.
2. Если в блоке `try` было выброшено исключение, которое не перехватил ни один блок `catch`, выполнится ли код в `finally`?
3. Что произойдет, если передать массив параметров стоимости (cost) напрямую в `password_verify()`?
4. **Верно или нет?** Конструкция `ClassName::class` возвращает строку на этапе выполнения, даже если класс еще не загружен или не существует.

<details>
<summary><b>Показать ответы</b></summary>

1. **Верно.** Генераторы возвращают встроенный объект `Generator`, что позволяет обходить их стандартным циклом `foreach`.
2. **Да.** Блок `finally` гарантированно выполнится перед тем, как исключение прервет работу скрипта.
3. Ничего, так как `password_verify` принимает только два параметра: хэш и пароль. Она сама считывает стоимость и алгоритм из строки хэша.
4. **Верно.** Конструкция `::class` разрешается на этапе компиляции кода. Она не пытается загрузить класс или проверить его существование, а просто заменяет выражение на строку.
