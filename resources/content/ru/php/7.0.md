# PHP 7.0: Главные нововведения

Что, если бы вы могли удвоить производительность своего веб-приложения за одну ночь, просто обновив интерпретатор языка? Выпуск PHP 7.0 сделал это реальностью. Благодаря новому движку Zend Engine 3, эта версия принесла колоссальный прирост скорости, а также строгие скалярные типы, декларации типов возвращаемых значений и современные операторы вроде null-coalescing. PHP 7.0 стал революционным шагом в истории PHP, заложив фундамент современных безопасных типов и высокопроизводительных веб-приложений.

<a id="scalar-types"></a>
## Объявления скалярных типов

Параметры функций теперь могут иметь скалярные типы: **`int`**, **`float`**, **`string`** и **`bool`**:

```php
// src/Math.php
declare(strict_types=1);

function add(int $a, int $b): int 
{
    return $a + $b;
}
```

> [!NOTE]
> А вы знали? Без строки `declare(strict_types=1);` в начале файла PHP работает в **режиме приведения типов (coercive mode)**. Это значит, что он автоматически и молча приведет строку `"5"` к числу `5` при проверке аргументов.

<a id="return-types"></a>
## Декларация возвращаемых типов

Вы можете строго определить, значение какого типа должна возвращать функция:

```php
// src/Generator.php
function generateId(): string 
{
    return uniqid();
}
```

Если возвращенное значение не соответствует указанному типу, PHP выбросит исключение **`TypeError`**.

<a id="null-coalescing"></a>
## Оператор объединения с null (`??`)

Синтаксический сахар для проверки существования переменной через `isset()`:

```php
// src/Config.php
$username = $_GET['user'] ?? 'anonymous';
```

Оператор можно объединять в цепочки: `$value = $a ?? $b ?? $default;`.

<a id="spaceship-operator"></a>
## Оператор «космический корабль» (`<=>`)

Выполняет трехстороннее сравнение значений, возвращая `-1`, `0` или `1`:

```php
// src/SortHelper.php
usort($list, function($a, $b) {
    return $a <=> $b;
});
```

Удобно использовать в функциях пользовательской сортировки, заменяя громоздкие ветвления `if-else`.

<a id="constant-arrays"></a>
## Массивы в константах через `define()`

Массивы теперь можно объявлять в константах прямо во время выполнения скрипта:

```php
// src/Constants.php
define('ALLOWED_ROLES', ['admin', 'editor', 'guest']);
```

Ранее константы-массивы поддерживались только внутри классов через ключевое слово `const`.

<a id="anonymous-classes"></a>
## Анонимные классы

Создание простых одноразовых объектов на лету:

```php
// src/LoggerProvider.php
$logger = new class {
    public function log(string $msg) {
        echo $msg;
    }
};
```

Часто применяется для создания заглушек (mocks) интерфейсов в юнит-тестах.

<a id="unicode-escape"></a>
## Синтаксис экранирования Unicode-символов

Вывод Unicode-символов напрямую из строк по их шестнадцатеричному коду:

```php
// src/Emoji.php
echo "\u{1F600}"; // Выводит улыбающийся смайлик 😀
```

<a id="group-use"></a>
## Групповые импорты (use)

Лаконичный импорт нескольких классов из одного пространства имен:

```php
// src/Controller.php
use App\Models\{User, Post, Comment};
```

<a id="throwable-exceptions"></a>
## Интерфейс Throwable и системные исключения

Многие фатальные ошибки рантайма теперь выбрасываются как исключения класса **`Error`**. Перехватывать их нужно через общий интерфейс **`Throwable`**:

```php
// src/ErrorHandler.php
try {
    nonExistentFunction();
} catch (Throwable $t) {
    // Перехватывает как ошибки движка Error, так и обычные Exceptions
    echo "Перехвачено: " . $t->getMessage();
}
```

> [!NOTE]
> А вы знали? Класс `Error` не наследуется от `Exception`. Если вы попытаетесь поймать ошибку через `catch (Exception $e)`, фатальные ошибки ядра (например, вызов несуществующей функции) все равно приведут к падению скрипта. Используйте `Throwable` или `Error`.

<a id="csprng-functions"></a>
## Функции CSPRNG

Криптографически безопасная генерация случайных чисел и байт на уровне операционной системы:

```php
// src/TokenGenerator.php
$bytes = random_bytes(32);
$number = random_int(1, 100);
```

Эти функции заменяют небезопасные генераторы вроде `rand()` или `mt_rand()` в контекстах безопасности.

<a id="common-mistakes"></a>
## Частые ошибки

Ниже приведены типичные ошибки разработчиков при переходе на PHP 7.0:

### 1. Забытая декларация строгой типизации
Если не объявить strict_types в каждом файле отдельно, PHP будет работать в режиме приведения типов и приводить неверные аргументы к нужным типам автоматически.
```php
// src/BadStrict.php
// Плохо: Строгий режим выключен, строка "10" тихо приведется к числу int 10
function setAge(int $age) {
    return $age;
}
setAge("10"); // Ошибки нет
```
```php
// src/GoodStrict.php
// Хорошо: Включите строгую типизацию на первой строчке файла
declare(strict_types=1);

function setAgeGood(int $age) {
    return $age;
}
// setAgeGood("10"); // Вызовет исключение TypeError
```

### 2. Попытка перехватить ошибки ядра через класс `Exception`
Разработчики часто ловят `Exception`, ожидая перехватить такие ошибки, как деление на ноль или вызов несуществующего метода, но они проходят мимо этого блока catch.
```php
// src/BadCatch.php
// Плохо: Деление на ноль вызывает DivisionByZeroError (наследник Error), catch не сработает
try {
    $value = 1 / 0;
} catch (Exception $e) {
    echo "Этот код не выполнится!";
}
```
```php
// src/GoodCatch.php
// Хорошо: Перехватывайте Throwable или Error
try {
    $value = 1 / 0;
} catch (Throwable $e) {
    echo "Ошибка перехвачена: " . $e->getMessage();
}
```

<a id="limitations"></a>
## Ограничения

* **Объявления типов параметров**: Не могут принимать `null` по умолчанию. Запись `int $x` выдаст TypeError при передаче null (nullable-типы появятся только в PHP 7.1).
* **Типы возвращаемых значений**: Нельзя указывать возвращаемый тип `void` (он появится в PHP 7.1) или объединение типов (Union-типы появятся в PHP 8.0).

<a id="backward-incompatible"></a>
## Обратно несовместимые изменения

### Ядро языка

* **ASP-теги (`<% %>`) и script-теги (`<script language="php">`)** полностью удалены из парсера PHP.
* Переменная **`$HTTP_RAW_POST_DATA`** удалена; используйте поток `php://input`.
* Использование более одного блока `default` в конструкции `switch` вызывает ParseError.
* Изменен порядок вычисления некоторых динамических выражений и глобальных переменных (например, `$$foo['bar']` разбирается строго слева направо).

## Интерактивный квиз

Проверьте свои знания о PHP 7.0:

1. **Какое утверждение верно касательно строгих типов (strict_types) в PHP 7.0?**
   * А) Строгие типы включаются глобально в конфигурации php.ini.
   * Б) Строгие типы нужно объявлять в начале каждого конкретного файла.
   * В) В PHP 7.0 принудительно включен строгий режим, приведения типов больше нет.
   * Г) Строгие типы применяются только для возвращаемых значений, но не для параметров.

   <details>
   <summary>Показать ответ</summary>
   
   **Правильный ответ: Б**  
   Строгая типизация активируется индивидуально для каждого файла с помощью инструкции `declare(strict_types=1);`.
   </details>

2. **Какой класс НЕ наследуется от Exception, но реализует интерфейс Throwable в PHP 7.0?**
   * А) RuntimeException
   * Б) Error
   * В) BadMethodCallException
   * Г) InvalidArgumentException

   <details>
   <summary>Показать ответ</summary>
   
   **Правильный ответ: Б**  
   Новый класс `Error` и его наследники (такие как `TypeError` или `ParseError`) реализуют интерфейс `Throwable`, но не наследуются от `Exception`.
   </details>

3. **Что возвращает оператор «космический корабль» (`<=>`)?**
   * А) Булево значение (true/false).
   * Б) Число с плавающей точкой (float).
   * В) Целое число (`-1`, `0` или `1`).
   * Г) Строку с результатом сравнения.

   <details>
   <summary>Показать ответ</summary>
   
   **Правильный ответ: В**  
   Оператор сравнивает два значения и возвращает `-1`, если левое меньше, `0`, если они равны, и `1`, если левое больше.
   </details>

<a id="closing-thoughts"></a>
## Итог

PHP 7.0 — это **эпохальная веха** в разработке веб-приложений. Убедитесь, что ваш сервер использует Zend Engine 3, удалите устаревшие ASP-теги из кода, перепишите использование небезопасных случайных чисел на CSPRNG-функции и перехватывайте системные ошибки через интерфейс Throwable.
