# PHP 5.4: Повторное использование кода и очистка безопасности

Представьте, что вы переносите старое приложение PHP на сервер с PHP 5.4 и вдруг обнаруживаете, что все отправляемые формы приходят пустыми, а SQL-запросы вызывают фатальные ошибки. Это было суровой реальностью для разработчиков, когда PHP 5.4 официально избавился от пережитков прошлого вроде «магических кавычек» (magic quotes) и глобальной регистрации переменных (register globals). Но одновременно с этим релиз принес синтаксис, без которого сегодня невозможно представить разработку: трейты и короткие массивы (`[]`).

Безопасность была главной ахиллесовой пятой раннего PHP. Настройки вроде `magic_quotes` пытались автоматически экранировать любые входящие данные (искажая строки), а `register_globals` автоматически превращала GET/POST-параметры в глобальные переменные скрипта. Удаление этих функций потребовало от сообщества перехода к стандартам безопасной разработки.

> [!IMPORTANT]
> PHP 5.4 стал важным санитарным релизом, ликвидировавшим уязвимости архитектуры PHP 4 и предоставившим современные инструменты структурирования кода.

<a id="traits"></a>
## Трейты (горизонтальное наследование)

Трейты позволяют шарить методы между классами без использования классического одиночного наследования.

```php
// app/Traits/Loggable.php
trait Loggable
{
    protected function log(string $msg): void
    {
        echo "[LOG]: " . $msg;
    }
}

// app/Services/UserService.php
class UserService
{
    use Loggable;

    public function create(): void
    {
        $this->log("Пользователь успешно создан.");
    }
}
```

* **Почему это важно**: Одиночное наследование часто заставляет дублировать код или строить неестественные иерархии классов ради общих хелперов.
* **Последствие**: Любые сквозные функции (логирование, кэширование, сериализация) теперь подключаются в одно объявление.

<a id="short-array"></a>
## Короткий синтаксис массивов (`[]`)

PHP 5.4 представляет компактный синтаксис `[]` для создания массивов вместо громоздкой конструкции `array()`.

```php
// app/Config/database.php
// Старый синтаксис:
$config = array("host" => "localhost", "port" => 3306);

// Новый синтаксис:
$config = ["host" => "localhost", "port" => 3306];
```

* **Почему это важно**: Читаемость кода значительно улучшается, приближая PHP к стандартам JSON, JavaScript и других языков программирования.

<a id="callable-hint"></a>
## Тип данных `callable`

Теперь вы можете указывать `callable` в качестве типа параметров функций, чтобы гарантировать передачу корректного колбэка.

```php
// app/Services/EventDispatcher.php
class EventDispatcher
{
    public function registerListener(string $event, callable $callback): void
    {
        // Проверка, что колбэк может быть выполнен
        $callback($event);
    }
}
```

* **Почему это важно**: Исчезает необходимость писать ручные проверки `is_callable()` внутри логики функций.

<a id="closure-this"></a>
## Привязка `$this` в замыканиях

Замыкания, созданные внутри методов объекта, теперь автоматически получают доступ к контексту `$this` этого объекта.

```php
// app/Services/NotificationService.php
class NotificationService
{
    private string $sender = "system@example.com";

    public function getSenderResolver(): Closure
    {
        return function() {
            // Контекст привязан автоматически, доступно приватное свойство
            return $this->sender;
        };
    }
}
```

> [!NOTE]
> Это автоматическое связывание существенно упрощает написание обработчиков событий и моделей в ORM, взаимодействующих со свойствами вызвавшего их объекта.

<a id="built-in-server"></a>
## Встроенный CLI веб-сервер

Запустить HTTP-сервер для тестирования теперь можно напрямую из консоли одной короткой командой.

```bash
# Запуск веб-сервера с корнем в папке public на порту 8000
php -S localhost:8000 -t public/
```

* **Почему это важно**: Больше нет нужды разворачивать тяжелые веб-серверы вроде Apache или nginx для локальной отладки простых скриптов или API.

<a id="common-mistakes"></a>
## ⚠️ Частые ошибки

### 1. Ожидание импорта переменных через register_globals
Если код рассчитывал, что переменная `$userId` материализуется в коде сама по себе из запроса `GET /profile.php?userId=42`, на PHP 5.4+ вы получите ошибку неопределенной переменной.

```php
// app/Http/LegacyController.php
// ❌ Ошибка в PHP 5.4+ (переменные больше не импортируются из глобальных)
echo $userId; 

// ✅ Правильный подход
echo $_GET['userId'] ?? null;
```

### 2. Двойное экранирование данных
Разработчики, использовавшие `stripslashes()` для удаления слешей от `magic_quotes_gpc`, теперь будут портить данные, поскольку автоматическое экранирование отключено на уровне ядра.

```php
// app/Database/Sanitizer.php
// ❌ Удаляет полезные слеши, поскольку magic_quotes больше не работают
$cleaned = stripslashes($_POST['bio']);

// ✅ Правильный подход
$cleaned = $_POST['bio']; // А для SQL используйте подготовленные выражения!
```

### 3. Конфликты методов в Трейтах
Использование нескольких трейтов с одинаковыми именами методов без явного разрешения конфликта вызовет ошибку компиляции.

```php
// app/Demo/TraitConflict.php
trait A { public function run() {} }
trait B { public function run() {} }

// ❌ Фатальная ошибка компиляции
class Runner { use A, B; }

// ✅ Правильный подход
class SafeRunner
{
    use A, B {
        A::run insteadof B;
        B::run as runAlternate;
    }
}
```

<a id="practical-recipes"></a>
## Практические рецепты

### Ожидание vs Реальность: разыменование массива из функции

```php
// app/Demo/DereferenceDemo.php
function getNames(): array
{
    return ["Алексей", "Борис", "Сергей"];
}

// Ожидание: доступ к индексу массива «на лету» сработает
// Реальность:
// В PHP 5.3: Ошибка парсера (Syntax Error)
// В PHP 5.4: Работает без лишних переменных
echo getNames()[1]; // Вывод: Борис
```

<a id="backward-incompatible"></a>
## Обратная несовместимость

1. **Полное удаление `register_globals` и `magic_quotes`**: Все данные форм и запросов приходят в «сыром» виде, их нужно получать из суперглобальных массивов.
2. **Удаление `safe_mode`**: Ограничения прав на основе владельца файла больше не работают, безопасность регулируется правами ОС.
3. **Строгие правила для `break` и `continue`**: Передача неконстантных выражений (например, `$val`) для выхода из циклов запрещена.
4. **Устаревание `mysql`**: Функции `mysql_*` выдают предупреждения, пора переходить на `mysqli` или `PDO`.

4. **Верно или нет?** Переменная `$this` автоматически доступна в замыканиях, объявленных как `static`.

<details>
<summary><b>Показать ответы</b></summary>

1. **Неверно.** Трейты являются лишь шаблонами повторного использования кода и не могут существовать как отдельные объекты. Их могут использовать только классы.
2. `php -S <хост>:<порт>` (например, `php -S localhost:8000`).
3. Возникнет фатальная ошибка на этапе компиляции. Конфликт необходимо разрешить вручную, указав приоритеты ключевыми словами `insteadof` и `as` в блоке `use` трейтов.
4. **Неверно.** Если замыкание объявлено как статическое (например, `static function() {}`), оно теряет связь с контекстом класса, и обращение к `$this` вызовет фатальную ошибку.
