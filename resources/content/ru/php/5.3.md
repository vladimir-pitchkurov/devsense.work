# PHP 5.3: Модернизация и фундамент корпоративной архитектуры

Представьте, что вы обновляете сервер и внезапно получаете «белый экран смерти» только потому, что сторонняя библиотека использовала незакавыченную строку или передачу по ссылке в вызове функции. PHP 5.3 стал тем самым переломным моментом, когда язык перестал быть простым скриптовым движком для домашних страниц и превратился в зрелый ООП-язык корпоративного уровня. Однако этот переход сопровождался жесткими изменениями обратной совместимости, которые в один миг сломали тысячи старых приложений.

До PHP 5.3 разработчики страдали от постоянных конфликтов имен классов в глобальной области, сломанного наследования статических методов и неконтролируемых утечек памяти в долгоживущих скриптах из-за циклических ссылок. Чтобы решить эти проблемы, PHP 5.3 представил пространства имен (namespaces), замыкания (closures), позднее статическое связывание (Late Static Binding) и циклический сборщик мусора. Но одновременно с этим язык избавился от пережитков прошлого вроде передачи по ссылке при вызове и расширения `ereg`.

> [!IMPORTANT]
> PHP 5.3 — это важнейший этап в истории PHP, который заставил разработчиков отказаться от привычек эпохи PHP 4 в пользу изоляции кода и структурированного управления памятью.

<a id="namespaces"></a>
## Пространства имен и автозагрузка

Пространства имен изолируют код и избавляют от необходимости писать бесконечные префиксы классов.

```php
// app/Repositories/UserRepository.php
namespace App\Repositories;

use App\Database\Connection;
use App\Contracts\LoggerInterface;

class UserRepository
{
    private Connection $db;
    private LoggerInterface $log;

    public function __construct(Connection $db, LoggerInterface $log)
    {
        $this->db = $db;
        $this->log = $log;
    }
}
```

* **Почему это важно**: До появления пространств имен конфликты имен классов предотвращали с помощью длинных префиксов в именах файлов и классов (например, `Zend_Db_Table_Row_Abstract`). Пространства имен делают код чистым и читаемым, изолируя короткие имена классов логически.
* **Последствие**: Это нововведение заложило основу для современных PHP-пакетов, стандартов автозагрузки (PSR-0/PSR-4) и создания Composer.

<a id="lsb"></a>
## Позднее статическое связывание (`static::`)

В PHP ключевое слово `self::` всегда указывает на класс, в котором метод был физически описан. Позднее статическое связывание вводит `static::`, которое разрешается в класс, вызвавший метод на этапе выполнения.

```php
// app/Models/ActiveRecord.php
abstract class ActiveRecord
{
    public static function find(int $id): string
    {
        // self::getTable() здесь выдал бы ошибку для подклассов
        return "SELECT * FROM " . static::getTable() . " WHERE id = " . $id;
    }

    abstract protected static function getTable(): string;
}
```

* **Почему это важно**: Без позднего статического связывания написание расширяемых базовых классов со статическими фабричными методами (таких как ActiveRecord ORM) было крайне затруднительным.
* **Последствие**: Разработчики получили возможность создавать элегантные базовые хелперы, корректно взаимодействующие с переопределенными статическими свойствами или методами в наследниках.

<a id="closures"></a>
## Замыкания и конструкция `use`

Анонимные функции теперь можно присваивать переменным, передавать в качестве аргументов и захватывать переменные из родительской области видимости с помощью конструкции `use`.

```php
// app/Services/Calculator.php
$taxRate = 0.20;

$calculateTotal = function (float $price) use ($taxRate): float {
    return $price * (1 + $taxRate);
};

echo $calculateTotal(100); // 120
```

> [!NOTE]
> В PHP 5.3 замыкания по умолчанию копируют захваченные переменные **по значению**. Если вам нужно изменить исходную переменную внутри замыкания, вы должны передать ее **по ссылке** (например, `use (&$counter)`).

<a id="syntax-additions"></a>
## NOWDOC против HEREDOC

NOWDOC относится к HEREDOC так же, как строки в одинарных кавычках относятся к строкам в двойных.

```php
// app/Config/templates.php
// HEREDOC (обрабатывает переменные)
$name = 'Иван';
$heredoc = <<<EOT
Привет, $name!
EOT;

// NOWDOC (не обрабатывает переменные, обратите внимание на одинарные кавычки вокруг EOT)
$nowdoc = <<<'EOT'
Привет, $name!
EOT;
```

* **Почему это важно**: NOWDOC позволяет безопасно вставлять большие блоки необработанного кода, конфигураций или регулярных выражений без необходимости экранировать знак доллара.

<a id="gc"></a>
## Сборщик мусора циклических ссылок

В PHP 5.3 появился сборщик циклических ссылок. Когда объект A ссылается на объект B, а объект B ссылается обратно на объект A, стандартный механизм подсчета ссылок не может их освободить, даже если они больше не используются в программе.

```php
// app/Services/Daemon.php
gc_enable(); // Включение сборщика циклических ссылок

// В долгоживущем процессе:
gc_collect_cycles(); // Принудительный запуск очистки очереди
```

* **Почему это важно**: Это жизненно необходимо для фоновых обработчиков очередей, CLI-команд и демонов, которые иначе быстро исчерпали бы доступную память.

<a id="common-mistakes"></a>
## ⚠️ Частые ошибки

### 1. Передача ссылок при вызове (Call-Time Pass-By-Reference)
Использование знака амперсанда непосредственно при вызове функции приводит к ошибкам.

```php
// app/Services/LegacyFix.php
// ❌ Устарело / Фатальная ошибка в PHP 5.3+
foo(&$value); 

// ✅ Правильный подход
// Ссылка должна быть указана в самой сигнатуре функции:
function foo(&$param) {}
foo($value); 
```

### 2. Использование новых зарезервированных слов
Новые ключевые слова вроде `goto`, `namespace` и `use` нельзя использовать в качестве имен классов или нецитируемых констант.

```php
// app/Classes/Runner.php
// ❌ Фатальная ошибка: нельзя использовать 'goto' как имя класса
class goto {}
```

### 3. Использование устаревшего ereg вместо preg_match
Функции семейства `ereg()` работают медленнее и генерируют предупреждения об устаревшем коде.

```php
// app/Validation/Email.php
// ❌ Устарело в PHP 5.3
if (eregi('^[a-z0-9]+$', $input)) {}

// ✅ Правильный подход
if (preg_match('/^[a-z0-9]+$/i', $input)) {}
```

<a id="practical-recipes"></a>
## Практические рецепты

### Ожидание vs Реальность: `self` vs `static`

```php
// app/Demo/BindingDemo.php
class ParentClass
{
    public static function getClassName(): string
    {
        return self::class; // Или __CLASS__
    }

    public static function getCalledClassName(): string
    {
        return static::class;
    }
}

class ChildClass extends ParentClass {}

// Ожидание: оба метода вернут 'ChildClass'
// Реальность:
echo ChildClass::getClassName();       // Вывод: ParentClass
echo ChildClass::getCalledClassName(); // Вывод: ChildClass
```

<a id="backward-incompatible"></a>
## Обратная несовместимость

1. **Удаление передачи ссылок при вызове**: Синтаксис `foo(&$x)` признан устаревшим и выдает предупреждения в PHP 5.3 (полностью удален в 5.4).
2. **Новые зарезервированные слова**: `goto`, `namespace`, `use`, `const` больше нельзя использовать для имен классов, интерфейсов или констант.
3. **Устаревание ereg**: Использование функций регулярных выражений POSIX `ereg_*` вызывает предупреждения `E_DEPRECATED`.
4. **Строгий порядок параметров**: Изменилось поведение и требования к аргументам в ряде системных функций (например, `clearstatcache()`).

3. В чем разница между `self::` и `static::` при позднем статическом связывании?
4. Что произойдет, если вызвать функцию как `bar(&$var)` в PHP 5.3?

<details>
<summary><b>Показать ответы</b></summary>

1. **Неверно.** В PHP 5.3 замыкания НЕ привязывают `$this` автоматически. Вам нужно передавать объект вручную (например, `$self = $this;` и `use ($self)`) для доступа к методам и свойствам экземпляра. Автоматическая привязка `$this` появилась только в PHP 5.4.
2. Необходимо обернуть идентификатор в одинарные кавычки в открывающем маркере: `<<<'EOT'`.
3. `self::` ссылается на класс, в котором был скомпилирован код (где физически написан метод), тогда как `static::` динамически указывает на класс, который был вызван в рантайме.
4. Будет сгенерировано предупреждение об устаревшем коде (`Deprecated: Call-time pass-by-reference has been deprecated...`). В PHP 5.4+ этот синтаксис приводит к фатальной синтаксической ошибке.
</details>
