# PHP 7.1: Главные нововведения

Что, если бы вы могли перехватывать три разных типа исключений в одном блоке catch, не дублируя шаблонный код? Или объявлять константы класса, которые гарантированно защищены от внешнего доступа? PHP 7.1 вводит эти возможности, выводя безопасность типов и выразительность кода современных приложений на новый уровень. Эта версия расширяет систему типов и синтаксис за счет nullable-типов, функций void, симметричной деструктуризации массивов с поддержкой ключей, управления областью видимости констант и множественного перехвата исключений (multi-catch).

<a id="nullable-types"></a>
## Nullable-типы (?Type)

Знак вопроса перед именем типа указывает, что параметр или возвращаемое значение может принимать тип **`null`**:

```php
// src/UserService.php
function findUser(int $id): ?User 
{
    return $id === 0 ? null : new User($id);
}
```

> [!NOTE]
> А вы знали? В PHP 7.0 строгий тип `User` запрещал возвращать `null` (вызывался TypeError). Добавление nullable-типов решило эту проблему, сохранив строгую проверку типов в рантайме.

<a id="void-functions"></a>
## Возвращаемый тип `void`

Если функция ничего не возвращает, указывается тип **`void`**. Разрешен только пустой оператор **`return;`** либо полное отсутствие return. Попытка вернуть любое значение (даже **`return null;`**) вызовет ошибку компиляции.

```php
// src/Notifier.php
function notify(string $message): void 
{
    echo $message;
    return; // Пустой return валиден, возврат значения вызовет ошибку
}
```

> [!NOTE]
> А вы знали? Тип `void` применим исключительно для возвращаемых значений. Вы не можете типом `void` ограничить входящий параметр функции (код вроде `function test(void $x)` не скомпилируется).

<a id="symmetric-destructuring"></a>
## Симметричная деструктуризация массивов

Теперь можно распаковывать массивы с использованием короткого синтаксиса **`[]`** вместо традиционного **`list()`**:

```php
// src/Config.php
[$host, $port] = ['127.0.0.1', 3306];
```

Этот синтаксис также отлично работает внутри циклов: `foreach ($data as [$id, $name])`.

<a id="constant-visibility"></a>
## Область видимости констант классов

Для констант классов добавлены модификаторы доступа **`public`**, **`protected`** и **`private`**:

```php
// src/PaymentGateway.php
class PaymentGateway {
    private const API_KEY = 'secret-key';
    public const DEFAULT_TIMEOUT = 30;
}
```

> [!NOTE]
> А вы знали? Если модификатор доступа опущен, константа по умолчанию считается публичной (`public`), что гарантирует обратную совместимость со старыми версиями PHP.

<a id="iterable-type"></a>
## Псевдотип `iterable`

Принимает любые типы данных, удовлетворяющие условию `is_array()` или являющиеся экземпляром **`\Traversable`**:

```php
// src/Collection.php
function processItems(iterable $items): void 
{
    foreach ($items as $item) {
        // Поддерживает и массивы, и генераторы/итераторы
    }
}
```

<a id="multi-catch"></a>
## Перехват нескольких типов исключений (multi-catch)

Вы можете объединять обработку разных исключений в один блок catch с помощью оператора **`|`**:

```php
// src/ApiConnector.php
try {
    // Выполнение запроса к API
} catch (ConnectionException | ResponseException $e) {
    // Общая обработка этих двух исключений
}
```

<a id="destructuring-keys"></a>
## Использование ключей при деструктуризации

При распаковке массивов теперь можно явно указывать ключи:

```php
// src/UserProfile.php
['id' => $userId, 'name' => $username] = $user;
```

Это работает как для конструкции `list()`, так и для нового короткого синтаксиса `[]`.

<a id="negative-offsets"></a>
## Поддержка отрицательных смещений в строках

Появилась возможность обращаться к символам строки с конца, используя отрицательные числа:

```php
// src/StrHelper.php
$lastChar = 'abcdef'[-1]; // 'f'
$sub = substr('abcdef', -3, -1); // 'de'
```

Отрицательные смещения поддерживаются также при записи: `$str[-2] = 'z';`.

<a id="extensions-stdlib"></a>
## Расширения и стандартная библиотека

* **cURL HTTP/2**: Добавлена поддержка HTTP/2 push и новых функций мульти-сервера.
* **OpenSSL AEAD**: Добавлена поддержка шифрования в режимах AEAD (GCM и CCM).
* **`session_gc()`**: Позволяет вручную запускать стандартный сборщик мусора сессий.

<a id="common-mistakes"></a>
## Частые ошибки

Ниже приведены типичные ошибки разработчиков при переходе на PHP 7.1:

### 1. Возврат `null` из `void`-функции
Попытка вернуть `null` (явным образом через `return null;`) в функциях, объявленных как `void`, вызовет Fatal Error.
```php
// src/BadVoid.php
// Плохо: Явный возврат null в void-функции запрещен
function doNothing(): void {
    return null; // Fatal Error: A void function must not return a value
}
```
```php
// src/GoodVoid.php
// Хорошо: Используйте пустой return или опустите его вовсе
function doNothingGood(): void {
    return; 
}
```

### 2. Ожидание, что `iterable` принимает только массивы
Если передать в `iterable`-параметр объект `Traversable`, вызовы `is_array()` вернут false. Разработчики иногда забывают об этом и совершают ошибку, пытаясь применить к параметру встроенные функции для массивов.
```php
// src/BadIterable.php
// Плохо: Сбой, если $items окажется генератором (он не реализует Countable)
function dumpItems(iterable $items) {
    echo count($items); 
}
```
```php
// src/GoodIterable.php
// Хорошо: Обходите элементы через foreach (он поддерживает и массивы, и итераторы)
function dumpItemsGood(iterable $items) {
    foreach ($items as $item) {
        echo $item;
    }
}
```

<a id="limitations"></a>
## Ограничения

* **Nullable-типы**: Вы не можете объединять их с Union-типами. Код вида `?int|string` вызовет синтаксическую ошибку (Union-типы появятся только в PHP 8.0).
* **Область видимости констант**: PHP 7.1 контролирует уровень доступа к константам, но не поддерживает указание их типов. Описание вида `public const int TIMEOUT = 10;` скомпилируется с ошибкой (тайп-хинтинг констант появится только в PHP 8.3).

<a id="backward-incompatible"></a>
## Обратно несовместимые изменения

### Ядро и типы

* **Исключения при нехватке аргументов**: передача недостаточного числа аргументов в функции пользователя теперь приводит к выбросу исключения **`ArgumentCountError`** вместо простого предупреждения Warning.
* **Обращение по невалидным индексам строк**: пустой индекс `[]` для строк больше не игнорируется молча.
* **`iterable` теперь является зарезервированным словом**: вы не можете называть этим словом классы, интерфейсы или трейты.

## Интерактивный квиз

Проверьте свои знания о PHP 7.1:

1. **Какое утверждение верно для функции с возвращаемым типом `void`?**
   * А) Она должна явно возвращать `null`.
   * Б) Она вообще не может содержать операторов `return`.
   * В) Она может использовать пустой `return;` или не иметь его вовсе.
   * Г) По умолчанию она возвращает `false`.

   <details>
   <summary>Показать ответ</summary>
   
   **Правильный ответ: В**  
   Функция с типом возврата `void` может использовать пустой оператор `return;` для досрочного выхода из кода, но возвращать любое значение (даже `null`) ей запрещено.
   </details>

2. **Какое исключение выбрасывается в PHP 7.1 при передаче недостаточного количества аргументов в функцию?**
   * А) TypeError
   * Б) ArgumentCountError
   * В) WarningException
   * Г) Error

   <details>
   <summary>Показать ответ</summary>
   
   **Правильный ответ: Б**  
   PHP 7.1 повысил уровень предупреждения о нехватке параметров до перехватываемого исключения `ArgumentCountError`.
   </details>

3. **Как объявить константу класса, доступную только внутри самого класса?**
   * А) `private const MY_CONST = 1;`
   * Б) `const private MY_CONST = 1;`
   * В) `protected const MY_CONST = 1;`
   * Г) `private MY_CONST = 1;`

   <details>
   <summary>Показать ответ</summary>
   
   **Правильный ответ: А**  
   PHP 7.1 вводит стандартные модификаторы видимости для констант: `public const`, `protected const` или `private const`.
   </details>

<a id="closing-thoughts"></a>
## Итог

PHP 7.1 — ключевой релиз для внедрения **строгой дисциплины типов** и чистоты структур данных. Перепишите вызовы `list()` на `[]`, добавьте `?` к необязательным типам параметров и объедините блоки catch для подготовки вашего приложения к переходу на PHP 7.2+.
