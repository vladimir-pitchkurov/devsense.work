# PHP 7.3: Основни нововъведения

Случвало ли ви се е с часове да дебъгвате тихо провалено парсване на JSON в продукционна среда само защото сте забравили да проверите `json_last_error()`? PHP 7.3 решава този вечен проблем на разработчиците, като въвежда изключението `JsonException` чрез флага `JSON_THROW_ON_ERROR`. Този релиз значително подобрява ежедневния комфорт при разработка (DX), предлагайки дългоочакваните отстъпи при heredoc низовете, висящите запетаи при извикване на функции и важни вградени хелпери.

<a id="flexible-heredoc"></a>
## Гъвкав Heredoc и Nowdoc

Затварящият маркер **вече не е задължен** да започва в началото на реда (на колона 0). Сега той може да бъде **отместен надясно (с отстъп)**, като същият този отстъп ще бъде **автоматично премахнат от всеки ред** в тялото на heredoc. Това прави вградения SQL, HTML или текст за помощ в CLI-команди чист и подреден според PSR-12 стандарта.

**Риск при миграция:** ако тялото на низа съдържа същия токен, който се използва за затварящ маркер (дори и с отстъп), PHP може да реши, че низът е приключил по-рано. Използвайте **уникални и дълги маркери** (например `SQL_GET_USER` вместо обикновеното `SQL`).

```php
// src/QueryBuilder.php
$query = <<<SQL
    SELECT id, name
    FROM users
    WHERE active = 1
    SQL;
```

> [!NOTE]
> Знаехте ли, че? Отстъпът на затварящия маркер дефинира колко интервала ще бъдат изрязани от текста. Ако дори един ред в тялото има по-малък отстъп от затварящия маркер, PHP ще хвърли ParseError.

<a id="trailing-commas-calls"></a>
## Висящи запетаи при извикване на функции

При извикване на функции и методи вече е разрешено оставянето на висяща запетая след последния аргумент. Това прави дифовете при коммит чисти и улеснява генерирането на аргументи:

```php
// src/LoggerService.php
$this->logger->info(
    'User saved',
    [
        'id' => $user->id,
        'ip' => $request->ip(),
    ],
);
```

Това важи само за **извикването** на функции. Декларирането на сигнатура с висяща запетая като `function foo($a,)` в PHP 7.3 все още е невалидно (висящите запетаи при декларация на параметри се появяват едва в PHP 8.0).

> [!NOTE]
> Знаехте ли, че? Висящите запетаи при дефиниране на функции в PHP 7.3 ще доведат до синтактична грешка ParseError. Те са разрешени единствено при извикването им.

<a id="list-references"></a>
## Деструктуриране по референция в `list()` и `[]`

При разпаковане на масиви вече е възможно свързването на променливи **по референция**:

```php
// src/Destructure.php
[&$head, $middle, &$tail] = $parts;
// И аналогично с list():
list(&$a, $b) = $pair;
```

Използвайте това само когато наистина трябва да променяте части от споделен масив; в противен случай работете по стойност, за да запазите потока от данни предвидим.

<a id="instanceof-literals"></a>
## `instanceof` с литерали

Лявата част на израза `instanceof` може да бъде **литерал**, като в този случай резултатът винаги е **`false`**. Това е въведено за консистентност на парсера и улеснение на статичния анализ, а не за употреба в реалната бизнес логика.

```php
// src/Validation.php
$result = (123 instanceof User); // false
```

<a id="compile-error"></a>
## `CompileError`

Класът `CompileError` е въведен като базово изключение за грешки при компилация; `ParseError` вече се **наследява** от него. Това е най-забележимо, когато функцията **`token_get_all($code, TOKEN_PARSE)`** срещне проблеми с разбора — грешки, които преди водеха до фатален срив, вече могат да бъдат уловени от инструментите за анализ.

```php
// src/ErrorHandling.php
try {
    eval('invalid code');
} catch (CompileError $e) {
    echo "Грешка при компилация: " . $e->getMessage();
}
```

<a id="core-helpers"></a>
## Нови хелпери в ядрото

* **`array_key_first($array)`** / **`array_key_last($array)`** — спестяват триковете с `reset()`/`end()` за вземане на първия или последния ключ на масив.
* **`is_countable($value)`** — връща `true` за масиви и обекти, имплементиращи `Countable` (замества дългата проверка `is_array($x) || $x instanceof \Countable`).
* **`hrtime($as_number = false)`** — монотонно системно време с висока точност (в наносекунди). Идеално за измерване на интервали за изпълнение, тъй като не се влияе от корекции на системния часовник (за разлика от `microtime`).
* **`net_get_interfaces()`** — връща списък с мрежовите интерфейси на сървъра (зависи от платформата).

```php
// src/Helpers.php
$firstKey = array_key_first($myArray);
if (is_countable($data)) {
    $count = count($data);
}
```

> [!NOTE]
> Знаехте ли, че? Функция `hrtime()` използва монотонния часовник на операционната система, който е защитен от автоматични синхронизации на времето (например по NTP). Това е единственият надежден начин за измерване на фини интервали на изпълнение.

<a id="json-exceptions"></a>
## JSON: `JSON_THROW_ON_ERROR` и `JsonException`

Подавайте флага **`JSON_THROW_ON_ERROR`** към функциите **`json_encode()`** и **`json_decode()`**, за да улавяте изключението **`JsonException`** вместо досадните проверки на `json_last_error()`.

```php
// src/JsonParser.php
try {
    $data = json_decode($json, true, 512, JSON_THROW_ON_ERROR);
} catch (JsonException $e) {
    // Обработка на грешката
}
```

<a id="argon2id"></a>
## Хеширане на пароли: Argon2id

Ако PHP е компилиран с достатъчно нова библиотека **libargon2**, функцията **`password_hash()`** приема алгоритъма **`PASSWORD_ARGON2ID`**, който съчетава предимствата на Argon2i и Argon2d.

```php
// src/Security.php
$hash = password_hash('secret', PASSWORD_ARGON2ID);
```

<a id="extensions-stdlib"></a>
## Разширения и стандартна библиотека

* **PCRE**: ядрото е обновено до **PCRE2** — възможни са дребни промени в поведението на регулярните изрази (по-строги диапазони в символни класове); **`preg_quote()`** вече екранира символа **`#`**.
* **Multibyte (mbstring)**: поддръжка на **Unicode 11**, работа с низове **>2 GB**, по-бързи регистрови операции; именованите групи в **`mb_ereg_*`** са приведени към ергономията на PCRE.
* **LDAP**: поддръжка на LDAP **controls** в функциите за търсене и модификация, както и в **`ldap_parse_result()`**.
* **MySQLi / PDO MySQL**: подготвените заявки вече коректно връщат **дробната част от секундите** за колони от тип `DATETIME(6)` / `TIMESTAMP(6)`.
* **FPM**: нови настройки за логване (`log_limit`, `log_buffering`, `decorate_workers_output`); функцията **`getallheaders()`** е налична под FPM.
* **Сесии и бисквитки**: нови параметри за **`session_set_cookie_params()`** и бисквитка-опция **`samesite`** в `setcookie()`.
* **Стримове**: адресите IPv6, връщани от **`stream_socket_get_name()`**, вече са обградени в квадратни скоби (например `[::1]:1337`).
* **SPL autoload**: ако един автозаредител **хвърли изключение**, следващите в стека **се пропускат** (преди се извикваха верижно).
* **IMAP**: авторизацията по протоколите **rsh/ssh е изключена по подразбиране** от съображения за сигурност (`imap.enable_insecure_rsh`).

<a id="common-mistakes"></a>
## Чести грешки

Ето типични грешки на разработчиците при работа с PHP 7.3:

### 1. Неправилен отстъп в затварящия маркер на Heredoc
Ако макар и един ред от тялото на низа е отместен по-наляво от затварящия маркер, или след маркера има празни пространства, PHP ще хвърли ParseError.
```php
// src/BadHeredoc.php
// Лошо: ред в тялото е по-наляво от затварящия маркер TEXT, хвърля ParseError
$text = <<<TEXT
Line 1
    Line 2
      TEXT;
```
```php
// src/GoodHeredoc.php
// Добре: отстъпът на затварящия маркер съвпада с минималния отстъп на тялото
$text = <<<TEXT
    Line 1
    Line 2
    TEXT;
```

### 2. Използване на `continue` вътре в `switch`
В PHP изразът `continue` вътре в switch се държи като `break`. Разработчиците често грешат, очаквайки той да продължи външния цикъл. В PHP 7.3 това генерира предупреждение.
```php
// src/BadContinueSwitch.php
// Лошо: генерира предупреждение, че "continue" в switch работи като "break"
foreach ($items as $item) {
    switch ($item) {
        case 'skip':
            continue;
    }
}
```
```php
// src/GoodContinueSwitch.php
// Добре: използвайте "continue 2" за преминаване към следваща итерация на външния foreach
foreach ($items as $item) {
    switch ($item) {
        case 'skip':
            continue 2;
    }
}
```

<a id="limitations"></a>
## Ограничения

* **Висящи запетаи**: Поддържат се единствено при извиквания на функции и методи. Дефинирането на параметри с висяща запетая като `function test($a, $b,) {}` ще генерира грешка ParseError.
* **Гъвкав Heredoc**: Затварящият ред трябва да съдържа само маркера и точка и запетая (или нов ред). Всякакви символи след маркера ще счупят парсера.

<a id="backward-incompatible"></a>
## Обратно несъвместими промени (миграционни бележки)

### Ядро

* **Гъвкав heredoc/nowdoc**: низове, които **съдържат затварящия маркер** вътре в себе си, могат да променят значението си или да доведат до **ParseError**.
* **`continue` вътре в `switch`**: вече генерира **warning**. **Проверете конструкциите `switch` с `continue`.**
* **`ArrayAccess` с числови низови ключове**: за ключове като **`"123"`** PHP **вече не ги преобразува** автоматично към цели числа при `ArrayAccess` — извиква се **`offsetGet("123")`** вместо **`offsetGet(123)`**.
* **Статични свойства и референции**: статични свойства, наследени от родителски клас, вече не могат да се разделят с референция.
* **Референции от достъп до масиви/свойства**: референциите, връщани от верижен достъп до свойства/масиви, се разплитат веднага.
* **Разопаковане на `...$traversable`**: **нецелочислените ключове** на `Traversable` обекти вече **не се разопаковат** при извиквания.
* **Предупреждения стават изключения (`EH_THROW`)**: тези изключения вече не се записват в **`error_get_last()`**.
* **Съобщения за `TypeError`**: грешните типове се показват като **`int` / `bool`** вместо **`integer` / `boolean`**.
* **`compact()`**: предаването на недефинирана променлива като име води до **notice**.
* **`getimagesize()`**: MIME типът за BMP вече е **`image/bmp`** (вместо `image/x-ms-bmp`).
* **Бисквитки (от PHP 7.3.23)**: имената на входящите бисквитки **не** се декодират от URL формат.

### BCMath

* Предупрежденията се подават през стандартния обработчик на грешки на PHP.
* **`bcmul()` / `bcpow()`** спазват по-строго зададения мащаб (scale).

### IMAP

* Тунелирането през **rsh/ssh** е забранено. За разрешаване ползвайте **`imap.enable_insecure_rsh`**.

### Регулярни изрази Multibyte (`mb_ereg_*`)

* Именованите групи променят структурата на резултатния масив.

### MySQLi и PDO MySQL

* Дробните части от секундите вече са видими в резултатите при таймстампове.

### Reflection

* Експортът на типове в низ показва имената **`int` / `bool`**.

### SimpleXML

* Математическите операции над текстови възли на SimpleXML избират автоматично int или float вместо принудително преобразуване към int.

### Платформа

* Прекратена поддръжка на операционната система BeOS.
* **`stream_socket_get_name()`** форматира адресите IPv6 с квадратни скоби.

<a id="deprecations"></a>
## Deprecated (поправете рано)

Акценти:

* **Регистронезависими константи**: подаване на `true` като трети аргумент в `define()`.
* **Функция с име `assert()` вътре в namespace** — избягвайте; ядрото обработва `assert()` по специален начин.
* **Не-низови игли** в семейството функции `strpos` — преобразувайте явно или използвайте `chr()`.
* Функциите **`fgetss()`**, **`gzgetss()`**, **`SplFileObject::fgetss()`** и филтърът **`string.strip_tags`**.
* Флаговете **`FILTER_FLAG_SCHEME_REQUIRED` / `FILTER_FLAG_HOST_REQUIRED`** при валидация на URL (вече се подразбират).
* Функция **`image2wbmp()`** (GD).
* Константа **`Normalizer::NONE`** при ICU ≥ 56.
* Устарели алиаси **`mbereg_*()`** — заменете с **`mb_ereg_*()`**.

<a id="other-changes"></a>
## Други промени и експлоатация (build, INI, perf)

* **Syslog INI**: настройки **`syslog.facility`**, **`syslog.filter`**, **`syslog.ident`** при `error_log=syslog`.
* **Сборщик на отпадъци (GC)**: оптимизация при почистване на циклични връзки.
* **`var_export()`**: при експорт на обекти от тип **`stdClass`** се генерира код от вида **`(object) array(...)`** вместо остарелия `__setState`.
* **FTP**: по подразбиране се използва двоичен режим на пренос на файлове (binary).
* **FILTER_VALIDATE_FLOAT**: добавена е опция **`thousand`** за кастомни разделители за хиляди.
* **PDO SQLite**: добавена е възможност за отваряне на база данни в режим „само за четене“ (`PDO::SQLITE_OPEN_READONLY`).
* **cURL**: изисква се библиотека **libcurl версия 7.15.5 или по-нова**.
* **OPcache**: премахната е остарялата директива `opcache.inherited_hack`.

   **Правилен отговор: В**  
   PHP 7.3 генерира Warning, тъй като разработчиците често се бъркат в логиката и очакват продължаване на външния цикъл, докато в PHP `continue` вътре в switch е еквивалентно на `break`.
   </details>

3. **Коя функция е въведена в PHP 7.3 за проверка дали променлива може да бъде подадена на `count()`?**
   * А) `is_iterable()`
   * Б) `is_countable()`
   * В) `can_count()`
   * Г) `is_array_or_countable()`

   <details>
   <summary>Кликнете, за да видите отговора</summary>
   
   **Правилен отговор: Б**  
   Функцията `is_countable()` връща `true`, ако на нея е подаден масив или обект, който имплементира интерфейса `Countable`.
   </details>

## Обобщение

Преходът към PHP 7.3 изисква **внимателен преглед на дифовете**: намерете в кода конструкции с **`continue` + `switch`**, използването на **`compact(`**, имплементации на **`ArrayAccess`**, маркери на **heredoc** и разопаковане на **`...$generator`**. Тествайте регулярните изрази и датите, след което можете да продължите напред — версия **7.4** ще донесе далеч по-значителни промени.
