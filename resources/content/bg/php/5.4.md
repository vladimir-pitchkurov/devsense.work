# PHP 5.4: Повторно използване на код и изчистване на сигурността

Представете си, че прехвърляте старо PHP приложение на сървър с PHP 5.4 и изведнъж откривате, че всички изпратени форми пристигат напълно празни, а SQL заявките ви изхвърлят фатални грешки. Това беше реалността за разработчиците, когато PHP 5.4 официално премахна поддръжката за сериозни пропуски в сигурността като „магически кавички“ (magic quotes) и автоматична глобална регистрация на променливи (register globals). Но в същото време PHP 5.4 донесе синтаксис, без който днес не можем: трейтове и кратки масиви (`[]`).

Сигурността беше огромна слабост в ранния PHP. Инструменти като `magic_quotes` се опитваха автоматично да ескейпват входящите данни (което водеше до деформация на текстовете), а `register_globals` автоматично превръщаше HTTP параметрите в глобални променливи на скрипта. Премахването им принуди общността да премине към по-сигурни практики.

> [!IMPORTANT]
> PHP 5.4 беше окончателното почистване на архитектурните проблеми от ерата на PHP 4, но и важна стъпка напред за модерния синтаксис на езика.

<a id="traits"></a>
## Трейтове (хоризонтално наследяване)

Трейтовете ви позволяват да споделяте имплементации на методи в различни класове, без да разчитате на множествено наследяване.

```php
// app/Traits/Loggable.php
trait Loggable
{
    protected function log(string $msg): void
    {
        echo "[LOG]: " . $msg;
    }
}

// app/Services/UserService.php
class UserService
{
    use Loggable;

    public function create(): void
    {
        $this->log("Потребителят е създаден успешно.");
    }
}
```

* **Защо това е важно**: Единичното наследяване често принуждава разработчиците да пишат повтарящ се код или да създават изкуствени йерархии от базови класове само за да споделят проста функционалност.
* **Последица**: Споделеното поведение (като логиране, времеви клейма или сериализация) вече може лесно да се внедри във всеки клас.

<a id="short-array"></a>
## Кратък синтаксис на масиви (`[]`)

PHP 5.4 въвежда краткия синтаксис `[]` за деклариране на масиви, който заменя дългата ключова дума `array()`.

```php
// app/Config/database.php
// Стар синтаксис:
$config = array("host" => "localhost", "port" => 3306);

// Нов синтаксис:
$config = ["host" => "localhost", "port" => 3306];
```

* **Защо това е важно**: Значително подобрява четимостта на кода, като доближава PHP до стандартите на JSON, JavaScript и други модерни скриптови езици.

<a id="callable-hint"></a>
## Тип данни `callable`

Вече можете да използвате `callable` като тип за параметри на функции, което гарантира, че предадената стойност е валиден колбек.

```php
// app/Services/EventDispatcher.php
class EventDispatcher
{
    public function registerListener(string $event, callable $callback): void
    {
        // Проверява дали колбекът може да бъде изпълнен
        $callback($event);
    }
}
```

* **Защо това е важно**: Елиминира необходимостта от ръчни проверки с `is_callable()` вътре в логиката на функцията.

<a id="closure-this"></a>
## `$this` в анонимни функции

Анонимните функции, дефинирани вътре в метод на обект, вече автоматично привързват контекста `$this` на текущия обект.

```php
// app/Services/NotificationService.php
class NotificationService
{
    private string $sender = "system@example.com";

    public function getSenderResolver(): Closure
    {
        return function() {
            // Контекстът е обвързан автоматично, достъпно е частно свойство
            return $this->sender;
        };
    }
}
```

> [!NOTE]
> Това автоматично обвързване прави много по-лесно писането на колбеци за събития и модели, които си взаимодействат с инстанцията на обекта.

<a id="built-in-server"></a>
## Вграден CLI уеб сървър

Можете бързо да стартирате лек HTTP сървър директно от командния ред за целите на разработката.

```bash
# Стартиране на сървър, насочен към папка public на порт 8000
php -S localhost:8000 -t public/
```

* **Защо това е важно**: Вече не е необходимо да конфигурирате тежки инструменти като Apache, nginx или виртуални хостове само за да прегледате прост скрипт или да тествате локално API.

<a id="common-mistakes"></a>
## ⚠️ Чести грешки

### 1. Очакване на автоматичен импорт на променливи през register_globals
Ако кодът ви е разчитал, че променливата `$userId` ще се появи автоматично при заявка `GET /profile.php?userId=42`, под PHP 5.4+ ще получите грешка за недефинирана променлива.

```php
// app/Http/LegacyController.php
// ❌ Счупено в PHP 5.4+ (променливите не се импортират автоматично)
echo $userId; 

// ✅ Правилен подход
echo $_GET['userId'] ?? null;
```

### 2. Двойно ескейпване на входящи данни
Разработчиците, използвали `stripslashes()` за премахване на наклонените черти от `magic_quotes_gpc`, сега неволно ще развалят своите данни, тъй като автоматичното ескейпване е изключено на ниво ядро.

```php
// app/Database/Sanitizer.php
// ❌ Премахва полезни наклонени черти, тъй като magic_quotes вече не работят
$cleaned = stripslashes($_POST['bio']);

// ✅ Правилен подход
$cleaned = $_POST['bio']; // За SQL заявки използвайте prepared statements!
```

### 3. Конфликти при използване на Трейтове
Използването на няколко трейта с еднакви имена на методи без изрично решаване на конфликта ще доведе до грешка при компилация.

```php
// app/Demo/TraitConflict.php
trait A { public function run() {} }
trait B { public function run() {} }

// ❌ Фатална грешка при компилация
class Runner { use A, B; }

// ✅ Правилен подход
class SafeRunner
{
    use A, B {
        A::run insteadof B;
        B::run as runAlternate;
    }
}
```

## Практически рецепти

### Очакване срещу Реалност: Разименоване на масиви от функции

```php
// app/Demo/DereferenceDemo.php
function getNames(): array
{
    return ["Алекс", "Боб", "Чарли"];
}

// Очакване: достъпът до индекса на масива в движение ще проработи
// Реалност:
// В PHP 5.3: Грешка в парсера (Syntax Error)
// В PHP 5.4: Работи без допълнителни променливи
echo getNames()[1]; // Резултат: Боб
```

<a id="backward-incompatible"></a>
## Обратна несъвместимост

1. **Премахване на `register_globals` и `magic_quotes_gpc`**: Всички данни пристигат в суров вид и трябва да се извличат от суперглобалните масиви.
2. **Премахване на `safe_mode`**: Ограниченията за собственост върху файловете са премахнати; сигурността се управлява от правата на операционната система.
3. **Строги правила за `break` и `continue`**: Вече не се поддържа предаването на променливи (например `break $val`) за излизане от цикли.
4. **Остаряване на разширението `mysql`**: Функциите `mysql_*` излъчват предупреждения; преминете към `mysqli` или `PDO`.

4. **Вярно или грешно?** `$this` е автоматично достъпен в статични анонимни функции (static closures).

<details>
<summary><b>Покажи отговорите</b></summary>

1. **Грешно.** Трейтовете са просто шаблони за повторно използване на код и не могат да съществуват самостоятелно. Те се използват само от класове.
2. `php -S <хост>:<порт>` (например `php -S localhost:8000`).
3. PHP ще изхвърли фатална грешка за конфликт при компилация. Трябва да разрешите сблъсъка ръчно, като използвате ключовите думи `insteadof` и `as` в декларацията на класа.
4. **Грешно.** Ако анонимната функция е декларирана като статична (например `static function() {}`), тя губи връзка с контекста на класа и опитът за достъп до `$this` ще доведе до фатална грешка.
