# PHP 7.1: Основни нововъведения

Какво би станало, ако можехте да уловите три различни типа изключения в един блок catch, без да повтаряте шаблонен код? Или да дефинирате константи на клас, които са строго защитени от външен достъп? PHP 7.1 въвежда тези възможности, внасяйки по-голяма сигурност на типовете и изразителност в съвременните PHP архитектури. Тази версия подобрява типовата система и синтаксиса чрез nullable типове, void функции, симетрично деструктуриране на масиви с ключове, видимост на константите на класовете и мулти-catch изключения.

<a id="nullable-types"></a>
## Nullable типове (?Type)

Въпросителният знак пред името на типа указва, че параметърът или връщаната стойност може да бъде и **`null`**:

```php
// src/UserService.php
function findUser(int $id): ?User 
{
    return $id === 0 ? null : new User($id);
}
```

> [!NOTE]
> Знаехте ли, че? В PHP 7.0 строгият тип `User` забраняваше връщането на `null` (хвърляше се TypeError). Nullable типовете решават този проблем, запазвайки строгата проверка в рантайм.

<a id="void-functions"></a>
## Тип на връщане `void`

Ако функцията не връща нищо, се декларира тип **`void`**. Разрешена е само празна инструкция **`return;`** или пълно отсъствие на return. Опитът да се върне каквато и да е стойност (дори **`return null;`**) ще предизвика грешка при компилация.

```php
// src/Notifier.php
function notify(string $message): void 
{
    echo $message;
    return; // Празна инструкция return е валидна, връщането на стойност води до грешка
}
```

> [!NOTE]
> Знаехте ли, че? Типът `void` е приложим единствено за връщани стойности. Не можете да го използвате за типизиране на входящ аргумент (код от вида `function test(void $x)` няма да се компилира).

<a id="symmetric-destructuring"></a>
## Симетрично деструктуриране на масиви

Вече можете да разпакетирате масиви с краткия синтаксис **`[]`** вместо традиционния **`list()`**:

```php
// src/Config.php
[$host, $port] = ['127.0.0.1', 3306];
```

Този синтаксис работи отлично и вътре в цикли: `foreach ($data as [$id, $name])`.

<a id="constant-visibility"></a>
## Видимост на константите на класовете

За константите на класовете са добавени модификатори за достъп **`public`**, **`protected`** и **`private`**:

```php
// src/PaymentGateway.php
class PaymentGateway {
    private const API_KEY = 'secret-key';
    public const DEFAULT_TIMEOUT = 30;
}
```

> [!NOTE]
> Знаехте ли, че? Ако модификаторът за достъп бъде изпуснат, константата се счита за публична (`public`), което гарантира обратна съвместимост с по-старите версии на PHP.

<a id="iterable-type"></a>
## Псевдотип `iterable`

Приема всякакви данни, които удовлетворяват условието `is_array()` или са инстанция на **`\Traversable`**:

```php
// src/Collection.php
function processItems(iterable $items): void 
{
    foreach ($items as $item) {
        // Поддържа както масиви, така и генератори/итератори
    }
}
```

<a id="multi-catch"></a>
## Улавяне на няколко типа изключения (multi-catch)

Можете да обединявате обработката на различни изключения в един catch блок с помощта на оператора **`|`**:

```php
// src/ApiConnector.php
try {
    // Изпълнение на заявка към API
} catch (ConnectionException | ResponseException $e) {
    // Обща обработка на двете изключения
}
```

<a id="destructuring-keys"></a>
## Използване на ключове при деструктуриране

При разпакетиране на масиви вече може изрично да се указват ключове:

```php
// src/UserProfile.php
['id' => $userId, 'name' => $username] = $user;
```

Това работи както за конструкцията `list()`, так и за новия кратък синтаксис `[]`.

<a id="negative-offsets"></a>
## Поддръжка на отрицателни индекси при низове

Появи се възможност за обръщение към символи на низ отзад напред с използване на отрицателни числа:

```php
// src/StrHelper.php
$lastChar = 'abcdef'[-1]; // 'f'
$sub = substr('abcdef', -3, -1); // 'de'
```

Отрицателните индекси се поддържат и при запис: `$str[-2] = 'z';`.

<a id="extensions-stdlib"></a>
## Разширения и стандартна библиотека

* **cURL HTTP/2**: Добавена е поддръжка за HTTP/2 push и нови функции за мулти-сървър.
* **OpenSSL AEAD**: Добавена е поддръжка за шифроване в режими AEAD (GCM и CCM).
* **`session_gc()`**: Позволява ръчно стартиране на стандартния почистващ механизъм за сесии.

<a id="common-mistakes"></a>
## Чести грешки

Ето типични грешки на разработчиците при прехода към PHP 7.1:

### 1. Връщане на `null` от `void` функция
Опитът да се върне `null` (явно чрез `return null;`) във функции, дефинирани като `void`, ще предизвика Fatal Error.
```php
// src/BadVoid.php
// Лошо: Явното връщане на null във void функция е забранено
function doNothing(): void {
    return null; // Fatal Error: A void function must not return a value
}
```
```php
// src/GoodVoid.php
// Добре: Използвайте празен return или го изпуснете напълно
function doNothingGood(): void {
    return; 
}
```

### 2. Очакване, че `iterable` приема само масиви
Ако предадете на `iterable` параметър обект от тип `Traversable`, функцията `is_array()` ще върне false. Разработчиците понякога забравят това и правят грешка, като се опитват да приложат вградени функции за масиви.
```php
// src/BadIterable.php
// Лошо: Грешка, ако $items се окаже генератор (той не имплементира Countable)
function dumpItems(iterable $items) {
    echo count($items); 
}
```
```php
// src/GoodIterable.php
// Добре: Обхождайте елементите с foreach (той поддържа и масиви, и итератори)
function dumpItemsGood(iterable $items) {
    foreach ($items as $item) {
        echo $item;
    }
}
```

<a id="limitations"></a>
## Ограничения

* **Nullable типове**: Не можете да ги комбинирате с Union типове. Код от вида `?int|string` ще предизвика синтактична грешка (Union типовете се появяват едва в PHP 8.0).
* **Видимост на константите**: PHP 7.1 контролира достъпа до константите, но не поддържа указване на техния тип. Код от вида `public const int TIMEOUT = 10;` ще даде грешка (тайп-хинтинг на константи се появява едва в PHP 8.3).

<a id="backward-incompatible"></a>
## Обратно несъвместими промени

### Ядро и типове

* **Изключения при недостатъчно аргументи**: подаването на по-малко аргументи към потребителска функция вече хвърля изключение **`ArgumentCountError`** вместо просто предупреждение Warning.
* **Невалидни индекси на низове**: празен индекс `[]` при низове вече не се игнорира тихо.
* **`iterable` вече е запазена дума**: не можете да именувате по този начин класове, интерфейси или трейтове.

## Интерактивен куиз

Проверете знанията си за PHP 7.1:

1. **Кое твърдение е вярно за функция с тип на връщане `void`?**
   * А) Тя трябва явно да връща `null`.
   * Б) Тя изобщо не може да съдържа оператори `return`.
   * В) Тя може да използва празен `return;` или да няма такъв изобщо.
   * Г) По подразбиране връща `false`.

   <details>
   <summary>Кликнете, за да видите отговора</summary>
   
   **Правилен отговор: В**  
   Функцията с тип на връщане `void` може да използва празен оператор `return;` за досрочно излизане, но връщането на каквато и да е стойност (дори `null`) е забранено.
   </details>

2. **Какво изключение се хвърля в PHP 7.1 при предаване на недостатъчно аргументи към функция?**
   * А) TypeError
   * Б) ArgumentCountError
   * В) WarningException
   * Г) Error

   <details>
   <summary>Кликнете, за да видите отговора</summary>
   
   **Правилен отговор: Б**  
   PHP 7.1 повиши нивото на предупреждението при липсващи аргументи до изключение `ArgumentCountError`.
   </details>

3. **Как се декларира константа на клас, достъпна само вътре в самия клас?**
   * А) `private const MY_CONST = 1;`
   * Б) `const private MY_CONST = 1;`
   * В) `protected const MY_CONST = 1;`
   * Г) `private MY_CONST = 1;`

   <details>
   <summary>Кликнете, за да видите отговора</summary>
   
   **Правилен отговор: А**  
   PHP 7.1 въвежда стандартни модификатори за достъп до константите: `public const`, `protected const` или `private const`.
   </details>

<a id="closing-thoughts"></a>
## Обобщение

PHP 7.1 е ключова стъпка към **строга дисциплина на типовете** и по-чисти структури от данни. Пренапишете извикванията на `list()` с `[]`, добавете `?` към опционалните аргументи и обединете catch блоковете си, за да подготвите проекта за преход към PHP 7.2+.
