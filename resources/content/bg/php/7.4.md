# PHP 7.4: Основни нововъведения

Представете си, че сте обновили версията на PHP и производствената ви среда се срива само защото свойство на клас не е било инициализирано. PHP 7.4 въвежда дългоочакваната строга типизация на свойствата на класовете, но с тази възможност идва и строго изискване: всяко типизирано свойство трябва да бъде инициализирано преди първото четене. Тази версия служи като мост към модерния PHP 8, въвеждайки типизирани свойства и стрелкови функции, които изискват дисциплина от разработчика.

<a id="typed-properties"></a>
## Типизирани свойства

Свойствата на клас могат да имат типове. **Неинициализирано** typed property **не трябва** да се чете преди присвояване — хвърля се грешката **`Typed property ... must not be accessed before initialization`**.

```php
// src/User.php
final class User
{
    public int $id;
    public string $name;
    public ?string $nickname = null;
}
```

От практиката:

* Ако „няма стойност“ е валидно — ползвайте **`?Type`** или стойност по подразбиране.
* Тип **`callable`** за свойства **не се поддържа** (зависи от контекста).
* Обектните типизирани свойства имат ограничения при декларация — вижте документацията.

> [!NOTE]
> Знаехте ли, че? В PHP 7.4 типизираните свойства са реализирани на ниво ядро със защита за „мързелива инициализация“. Свойството съществува в неинициализирано състояние (uninitialized), което е различно от `null`. Извикването на `isset($user->id)` ще върне `false`, ако не е зададено, дори ако типът не е nullable.

<a id="arrow-functions"></a>
## Arrow functions

`fn` улавя променливи от обкръжението **по стойност** и връща един израз — удобно за кратки callback-и.

```php
// src/MathHelper.php
$factor = 10;
$nums = array_map(fn($n) => $n * $factor, [1, 2, 3]);
```

**`fn` е запазена дума** — не може да се използва за име на функция или клас (методи и константи са разрешени).

> [!NOTE]
> Знаехте ли, че? За разлика от стрелковите функции в JavaScript, в PHP променливите се улавят само по стойност. Промяната на стойността на променлива вътре в стрелковата функция няма да повлияе на външната променлива.

<a id="variance"></a>
## Ковариантност и контравариантност

Типовете на връщане могат да се **стесняват** (ковариантност), а типовете на параметрите — да се **разширяват** (контравариантност) при наследяване, с ограничения. Пълната вариантност работи най-добре с **autoload**; в рамките на един файл са позволени само **нециклични** препратки към класове.

```php
// src/Repository.php
interface Repository {
    public function get(int $id): object;
}

class UserRepository implements Repository {
    public function get(int $id): User { // Ковариантен тип на връщане
        return new User();
    }
}
```

<a id="null-coalesce-assign"></a>
## Присвояване с null coalescing (`??=`)

Присвоява се стойност само ако лявата страна е **незададена** или е **`null`**:

```php
// src/Config.php
$config['debug'] ??= false;
```

<a id="array-spread"></a>
## Spread оператор в масиви

Разпаковане на итерируеми стойности в литерал на масив:

```php
// src/ArrayMerge.php
$base = [1, 2];
$all = [0, ...$base, 3]; // [0, 1, 2, 3]
```

Комбинира се отлично с `array_merge(...$arrays)`: **`array_merge()`** без аргументи вече връща **`[]`**.

<a id="numeric-separator"></a>
## Разделител в числови литерали

Подчертаванията подобряват четимостта и **не променят** стойността:

```php
// src/Constants.php
$million = 1_000_000;
$hex = 0xFF_FF_FF;
```

<a id="weak-references"></a>
## Слаби референции (WeakReference)

`WeakReference` държи референция, която **не предотвратява** унищожаването на обекта от сборщика на отпадъци — полезно за кешове без изтичане на памет.

```php
// src/Cache.php
$obj = new stdClass();
$weakRef = WeakReference::create($obj);
```

<a id="tostring-exceptions"></a>
## Изключения от `__toString()`

Хвърлянето на изключения от `__toString()` е разрешено (преди беше fatal). Някои от предишните recoverable fatals са станали **`Error`** — проверете преобразуванията към низ.

```php
// src/Stringy.php
class Stringy {
    public function __toString(): string {
        throw new Exception("Failed to cast to string");
    }
}
```

<a id="custom-serialize"></a>
## Сериализация: `__serialize` / `__unserialize`

Нов механизъм, който постепенно измества `Serializable`:

```php
// src/Point.php
final class Point
{
    private int $x;
    private int $y;

    public function __serialize(): array
    {
        return ['x' => $this->x, 'y' => $this->y];
    }

    public function __unserialize(array $data): void
    {
        $this->x = $data['x'];
        $this->y = $data['y'];
    }
}
```

SPL типове като `ArrayObject` могат да генерират **нови** сериализирани данни, четими на 7.4+, но не и на по-стари версии на PHP.

<a id="extensions-stdlib"></a>
## Разширения и стандартна библиотека

* **FFI**: извикване на C библиотеки (мощно; изисква модел за сигурност).
* **OPcache preloading**: зареждане на набор от файлове при стартиране — `opcache.preload`, често `opcache.preload_user`.
* **`mb_str_split()`**: като `str_split()`, но по **кодпойнти**.
* **`proc_open()`**: команда като **масив** (без shell), дескриптори `redirect` / `null`.
* **`strip_tags()`**: разрешени тагове като **масив** от имена.
* **PDO**: потребител/парола в DSN за повече драйвери; **`??`** в SQL екранира литерален `?` (напр. при PostgreSQL JSON оператори).
* **PCRE**: `preg_replace_callback*` приема `flags` — **`PREG_OFFSET_CAPTURE`**, **`PREG_UNMATCHED_AS_NULL`** и др.
* **Password**: Argon2 през **sodium** без libargon.

<a id="common-mistakes"></a>
## Чести грешки

Ето някои типични грешки на разработчиците при прехода към PHP 7.4:

### 1. Четене на неинициализирано типизирано свойство
```php
// src/BadPropertyAccess.php
// Лошо: четене на типизирано свойство преди неговата инициализация
class BadUser {
    public int $id;
}
$user = new BadUser();
echo $user->id; // Fatal Error: Typed property BadUser::$id must not be accessed before initialization
```
```php
// src/GoodPropertyAccess.php
// Добре: задайте стойност по подразбиране или инициализирайте в конструктора
class GoodUser {
    public int $id = 0;
}
```

### 2. Опит за модифициране на външни променливи в стрелкови функции
```php
// src/BadArrowScope.php
// Лошо: очакване, че външната променлива ще се промени по референция
$count = 0;
$increment = fn() => $count++;
$increment();
echo $count; // Резултат: 0 (Външната променлива не се е променила!)
```
```php
// src/GoodArrowScope.php
// Добре: използвайте традиционна анонимна функция с `use (&$count)`
$count = 0;
$increment = function() use (&$count) {
    $count++;
};
$increment();
echo $count; // Резултат: 1
```

<a id="limitations"></a>
## Ограничения

* **Стрелкови функции**: Могат да съдържат само един израз. Не можете да използвате многоредова логика или изрична инструкция `return`.
* **OPcache Preloading**: Заредените файлове се кешират в паметта завинаги. Всяка промяна в кода изисква пълно рестартиране на PHP-FPM процеса или уеб сървъра.
* **FFI**: Осигурява максимална производителност, но заобикаля защитните слоеве на PHP. Грешки в кода могат да доведат до Segmentation Fault (срив на процеса).

<a id="backward-incompatible"></a>
## Обратно несъвместими промени (миграционни бележки)

### Ядро

* **Достъп като масив към не-масиви**: за `null`, `bool`, `int`, `float`, `resource` във вид `$x['k']` — **notice**.
* **`get_declared_classes()`**: вече **не** връща анонимни класове, докато не бъдат инстанцирани.
* **`fn`**: запазено за имена на функции/класове.
* **`<?php` в края на файл** без нов ред: вече се тълкува като **отварящ PHP таг** (преди зависеше от `short_open_tag`).
* **Stream wrappers**: при `include`/`require` на stream може да се извика `streamWrapper::stream_set_option(STREAM_OPTION_READ_BUFFER)` — имплементирайте метода или върнете `false`, за да няма предупреждение.
* **Сериализация**: форматът **`o`** е премахнат.
* **Константи за password алгоритми**: `PASSWORD_*` са **низове** (`'2y'`, `'argon2id'`, …), а не цели числа — код, който ги сравнява с `1`/`2`/`3`, се чупи.
* **`htmlentities()`**: **notice**, когато кодирането се свежда до поведение като `htmlspecialchars`.
* **`fread`/`fwrite`**: при неуспех връщат **`false`** (не `''`/`0`); възможен е **notice**.
* **BCMath**: предупреждение при лошо формирани числови низове.
* **CURL**: сериализацията на **`CURLFile`** хвърля по-рано; нестандартен аргумент на `curl_version()` — предупреждение/игнориране.
* **Date**: `var_dump` на `DateTime*` не оставя „излишни“ свойства; сравнението на **`DateInterval`** предупреждава и винаги дава **`false`**.
* **Intl**: по подразбиране `idn_to_ascii` / `idn_to_utf8` използват **`INTL_IDNA_VARIANT_UTS46`**.
* **MySQLi**: премахнат embedded server; премахнато е `$mysqli->stat` — ползвайте **`mysqli::stat()`**.
* **OpenSSL**: `openssl_random_pseudo_bytes` хвърля като **`random_bytes`** при грешка; `$crypto_strong` е **`true`**, ако няма изключение.
* **PCRE**: с **`PREG_UNMATCHED_AS_NULL`** крайните несъвпаднали групи са **`null`** (стабилен размер на `$matches`).
* **PDO**: сериализация на **`PDO`/`PDOStatement`** хвърля **`Exception`** (не `PDOException`).
* **Reflection**: сериализация на reflection обекти **хвърля**; променени са някои константи на модификатори.
* **SPL / `ArrayObject`**: променено поведение на **`get_object_vars`** без `STD_PROP_LIST`; `SplPriorityQueue::setExtractFlags(0)` хвърля веднага.
* **Tokenizer**: неочакваните байтове се превръщат в **`T_BAD_CHARACTER`**.
* **Бисквитки (от 7.4.11)**: имената на входящите бисквитки **не** се URL-декодират.

<a id="deprecations"></a>
## Deprecated (поправете рано)

Акценти:

* **Вложени тернарни оператори** без изрични скоби (освен еднозначната форма с влагане в средния операнд).
* **Фигурни скоби** за офсет `$str{0}` / `$arr{0}` → използвайте **`[]`**.
* **`(real)`** и **`is_real()`** → **`(float)`** / **`is_float()`**.
* **`array_key_exists()` върху обекти** → **`isset()`** / **`property_exists()`**.
* **`implode($parts, $glue)`** — обърнат ред → **`implode($glue, $parts)`**.
* **`ReflectionType::__toString()`** и **`Reflection*::export()`** → API като **`ReflectionNamedType::getName()`** и string cast на reflection обекти.
* **`allow_url_include`**, **`FILTER_SANITIZE_MAGIC_QUOTES`**, остарели LDAP paged функции, `money_format()`, `hebrevc()` и др. — пълен списък: [migration74 deprecated](https://www.php.net/manual/en/migration74.deprecated.php).

<a id="other-changes"></a>
## Други промени и експлоатация

* **`zend.exception_ignore_args`**: нов INI (по подразбиране може да скрие **аргументи** в stack traces — проверете error reporting).
* **`opcache.preload_user`**: потребител за preload, когато не е root.
* **Миграция към pkg-config**: много `./configure` флагове вече не приемат `=DIR`; ползвайте **`PKG_CONFIG_PATH`** или `FOO_CFLAGS`/`FOO_LIBS`.
* **Премахнати бандли**: **SQLite3**, **Zip**, **onig** (mbregex) — нужни са системни библиотеки; **hash** винаги е включен.
* **CSV**: празен низ за **`$escape`** изключва PHP escape механизма; `str_getcsv()` е съгласуван.
* **GD**: `imagecropauto()` е синхронизиран със system libgd; променен default режим; **`imagescale()`** с `-1` запазва пропорциите.
* **PEAR**: не се инсталира по подразбиране (`--with-pear` е опционално и deprecated).
* **Производителност**: opcode за **`array_key_exists()`** при статично разрешаване; UTF-8 **`preg_match`** валидира низа веднъж при повторни извиквания.

## Интерактивен куиз

Проверете знанията си за PHP 7.4:

1. **Какво се случва при четене на неинициализирано типизирано свойство в PHP 7.4?**
   * А) Връща `null`
   * Б) Извежда Notice и връща `null`
   * В) Хвърля изключение Error
   * Г) Връща `false`

   <details>
   <summary>Кликнете, за да видите отговора</summary>
   
   **Правилен отговор: В**  
   PHP 7.4 изрично забранява четенето на типизирани свойства преди тяхното инициализиране. Опитът за това хвърля `Error` с известие `Typed property ... must not be accessed before initialization`.
   </details>

2. **Може ли да се промени променлива от външния обхват вътре в стрелкова функция?**
   * А) Да, променливите се улавят по референция
   * Б) Не, променливите се улавят автоматично по стойност
   * В) Да, но само ако използвате ключовата дума `use`
   * Г) Да, но само за обекти

   <details>
   <summary>Кликнете, за да видите отговора</summary>
   
   **Правилен отговор: Б**  
   Стрелковите функции в PHP автоматично улавят променливите от външния обхват по стойност. Всякакви промени на тези променливи вътре в функцията остават локални.
   </details>

3. **Декларирането на кой тип за свойства на класове е ЗАБРАНЕНО в PHP 7.4?**
   * А) `object`
   * Б) `callable`
   * В) `iterable`
   * Г) `?string`

   <details>
   <summary>Кликнете, за да видите отговора</summary>
   
   **Правилен отговор: Б**  
   Типът `callable` не е разрешен за типизиране на свойства на клас, тъй като неговата валидност зависи от контекста на извикване.
   </details>

<a id="closing-thoughts"></a>
## Обобщение

PHP 7.4 е **мост** към 8.x: въведете типизирани свойства и `__serialize`/`__unserialize` отрано; търсете **`fn`**, **`$var{idx}`**, целочислени password алгоритми и чуплив `ArrayObject` код; тествайте streams, OpenSSL random и сериализация на PDO/Reflection.
