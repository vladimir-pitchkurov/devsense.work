# PHP 5.5: Ефективност на паметта и вградена сигурност

Опитът да прочетете 5GB лог файл наведнъж с функцията `file()` може да изчерпи паметта на сървъра ви за секунди, хвърляйки грешката "Allowed memory size exhausted". PHP 5.5 реши този проблем веднъж завинаги, като въведе генераторите (`yield`), позволяващи обработка на големи потоци от данни в движение с минимален разход на ресурси.

Преди PHP 5.5 разработчиците трябваше да зареждат цели масиви с данни в паметта или да пишат сложни и дълги обекти-итератори. Освен това сигурното хеширане на пароли изискваше собствени алгоритми с генериране на соли върху MD5/SHA256, а изчистването на ресурси при възникване на грешки беше неудобно поради липсата на блок `finally`.

> [!IMPORTANT]
> PHP 5.5 въведе ключови оптимизации за управление на паметта чрез генератори и стандартизира криптографията с вграденото Password Hashing API.

<a id="generators"></a>
## Генератори (`yield`)

Генераторите изчисляват стойностите в движение, вместо да изграждат и връщат гигантски масив.

```php
// app/Services/LogReader.php
function readLines(string $filePath): Generator
{
    $handle = fopen($filePath, 'r');
    if (!$handle) {
        return;
    }
    try {
        while (($line = fgets($handle)) !== false) {
            yield trim($line);
        }
    } finally {
        fclose($handle);
    }
}
```

* **Защо това е важно**: Обхождането на големи файлове, бази данни или безкрайни поредици вече изисква минимален и постоянен обем памет (само няколко килобайта), независимо от общия размер на данните.
* **Последица**: Пакетната обработка на данни става много по-бърза и стабилна при тежки натоварвания.

<a id="finally"></a>
## Блокът `finally`

PHP 5.5 допълва структурата `try-catch` с блока `finally`. Кодът вътре в него се изпълнява винаги, независимо дали е възникнало изключение или е извикан `return` в блоковете `try` или `catch`.

```php
// app/Services/DatabaseClient.php
public function processTransaction()
{
    $this->db->connect();
    try {
        $this->db->execute();
    } catch (\Exception $e) {
        $this->logError($e);
    } finally {
        // Изпълнява се ВИНАГИ, предотвратявайки изтичане на ресурси
        $this->db->disconnect();
    }
}
```

* **Защо това е важно**: Опростява операции по почистване като затваряне на отворени файлове, връзки към бази данни или освобождаване на заключвания.

<a id="password-api"></a>
## Вградено API за хеширане на пароли

Забравете за ръчното генериране на соли и остарелите алгоритми. Новите функции правят сигурността на паролите тривиална задача.

```php
// app/Services/AuthService.php
// Хеширане на парола с bcrypt (PASSWORD_DEFAULT)
$hash = password_hash($password, PASSWORD_DEFAULT);

// Проверка на паролата при влизане
if (password_verify($password, $hash)) {
    // Ако изискванията за сложност се променят, обновяваме хеша
    if (password_needs_rehash($hash, PASSWORD_DEFAULT)) {
        $newHash = password_hash($password, PASSWORD_DEFAULT);
        // Записваме $newHash в базата данни
    }
}
```

> [!NOTE]
> `password_hash` автоматично генерира криптографски сигурна сол и я вгражда в самия върнат низ на хеша, така че вече не ви е необходима отделна колона в базата данни за соли.

<a id="helpers"></a>
## `array_column()` и `::class`

PHP 5.5 добави два изключително полезни инструмента за ежедневната разработка:

### 1. `array_column()`
Извлича стойностите от единична колона в многомерен масив или масив от обекти.

```php
// app/Services/Report.php
$users = [
    ['id' => 1, 'name' => 'Алекс'],
    ['id' => 2, 'name' => 'Игор']
];
$ids = array_column($users, 'id'); // [1, 2]
```

### 2. `ClassName::class`
Позволява да получите пълното име на класа (заедно с пространството от имена) като низ.

```php
// app/Services/Container.php
use App\Models\User;
echo User::class; // "App\Models\User"
```

<a id="opcache"></a>
## Интеграция на Zend OPcache

Разширението Zend OPcache вече е част от ядрото на PHP. То кешира компилирания байт-код в оперативната памет, премахвайки нуждата от четене и компилиране на PHP файловете при всяка заявка.

* **Защо това е важно**: Производителността на приложенията се увеличава между 2 и 3 пъти (в зависимост от размера на фреймуорка).
* **Последица**: При разполагане на код (деплой) трябва да изчиствате кеша с `opcache_reset()` или да рестартирате PHP-FPM процесите.

<a id="common-mistakes"></a>
## ⚠️ Чести грешки

### 1. Използване на опасния модификатор `/e` в `preg_replace`
Модификаторът `/e` кара интерпретатора да изпълнява заместващия низ като PHP код, което често водеше до уязвимости за отдалечено изпълнение на код (RCE). В PHP 5.5 той е остарял.

```php
// app/Helpers/StringHelper.php
// ❌ Остаряло и изключително опасно!
$output = preg_replace('/(\w+)/e', 'strtoupper("$1")', $text);

// ✅ Правилен подход
$output = preg_replace_callback('/(\w+)/', function($m) {
    return strtoupper($m[1]);
}, $text);
```

### 2. Изтичане на ресурси в генераторите при преждевременно прекъсване на цикъл
Ако излезете от генератор по-рано (чрез `break`), кодът след `yield` може да не се изпълни, което ще доведе до изтичане на ресурси, освен ако файловете не са обградени в блок `finally` вътре в генератора.

```php
// app/Services/FileReader.php
// ❌ Опасно: при изход от цикъла fclose() никога няма да се изпълни
function readData($file) {
    $fh = fopen($file, 'r');
    while($line = fgets($fh)) yield $line;
    fclose($fh);
}

// ✅ Правилен подход
function readDataSafe($file) {
    $fh = fopen($file, 'r');
    try {
        while($line = fgets($fh)) yield $line;
    } finally {
        fclose($fh); // Гарантирано изпълнение при унищожаване на генератора
    }
}
```

### 3. Използване на старото разширение `mysql`
Функциите `mysql_connect()` са официално обявени за остарели в PHP 5.5.

```php
// app/Database/LegacyDb.php
// ❌ Генерира предупреждение E_DEPRECATED
$conn = mysql_connect('localhost', 'user', 'pass');

// ✅ Правилен подход
$conn = new PDO('mysql:host=localhost;dbname=test', 'user', 'pass');
```

<a id="practical-recipes"></a>
## Практически рецепти

### Очакване срещу Реалност: блокът `finally` и връщането на стойности

Какво се случва, когато `return` израз е указан и в `try`, и в `finally`?

```php
// app/Demo/FinallyDemo.php
function testFinally(): string
{
    try {
        return "Връщане от try";
    } finally {
        return "Връщане от finally";
    }
}

// Очакване: функцията ще върне "Връщане от try"
// Реалност:
echo testFinally(); // Резултат: Връщане от finally
```

> [!WARNING]
> Ако върнете стойност в блока `finally`, тя ще презапише всички резултати от `try` или `catch` блоковете. Избягвайте поставянето на `return` изрази в `finally`.

<a id="backward-incompatible"></a>
## Обратна несъвместимост

1. **Остаряване на модификатора `/e` в `preg_replace`**: Генерира предупреждения; преминете към `preg_replace_callback`.
2. **Остаряване на `mysql`**: Функциите `mysql_*` излъчват предупреждения от ниво `E_DEPRECATED` при използване.
3. **`empty()` с изрази**: Преди `empty()` приемаше само променливи. От 5.5 нататък изразът `empty(foo())` работи коректно.
4. **Промени в `pack()` и `unpack()`**: Могат да повлияят на бинарната обработка на данни в зависимост от 64-битовата архитектура.

## 🧠 Въпроси за самопроверка

1. **Вярно или грешно?** Генераторната функция връща обект от клас `Generator`, който имплементира интерфейса `Iterator`.
2. Ако в `try` блока бъде хвърлено изключение, което не е уловено от нито един `catch` блок, ще се изпълни ли кодът във `finally`?
3. Какво ще се случи, ако предадете масив с параметри за цена (cost) директно в `password_verify()`?
4. **Вярно или грешно?** Конструкцията `ClassName::class` връща низ в рантайм, дори ако класът все още не е зареден или не съществува.

<details>
<summary><b>Покажи отговорите</b></summary>

1. **Вярно.** Генераторите връщат вградения обект `Generator`, което позволява обхождането им със стандартен `foreach` цикъл.
2. **Да.** Блокът `finally` се изпълнява гарантирано, преди изключението да спре работата на скрипта.
3. Нищо, тъй като `password_verify` приема само два параметъра: парола и хэш. Тя сама прочита параметрите за цена и алгоритъм от самия хэш низ.
4. **Вярно.** Конструкцията `::class` се разрешава по време на компилация на кода. Тя не се опитва да зареди класа или да провери неговото съществуване, а просто заменя израза с низ.
