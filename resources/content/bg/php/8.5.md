# PHP 8.5: Основни нововъведения и интерактивно ръководство

PHP 8.5 продължава тенденцията за подобряване на изразителността на езика и консолидиране на ядрото на платформата. Основните акценти на релийза са дългоочакваният **Pipe Operator (`|>`)**, атрибутът **`#[\NoDiscard]`** за контрол на връщаните стойности и вграденото разширение **URI**, съобразено със стандартите на WHATWG.

<a id="pipe-operator"></a>
## Pipe оператор (`|>`)

Омръзна ли ви да влагате функции една в друга като `strtolower(trim($input))` или да създавате излишни временни променливи? PHP 8.5 въвежда оператора **`|>`**, който ви позволява да предавате резултата на лявото изражение към десния извикваем обект по веригата.

```php
// app/Services/Slugger.php
$slug = $title
    |> trim(...)
    |> strtolower(...)
    |> fn($s) => preg_replace('/\s+/', '-', $s);

echo $slug; // Изход: hello-world
```

> [!NOTE]
> **Знаехте ли, че?**
> Операторът `|>` предава лявата стойност като **първи аргумент** на десния callable. Ако трябва да я подадете като втори или трети параметър, просто я обградете в анонимна или стрелкова функция.

### ⚠️ Чести грешки при разработка

**1. Липса на скоби около стрелковите функции**
Ако използвате стрелкова функция в рамките на конвейера, тя задължително трябва да бъде затворена в скоби, за да се избегне синтактично двусмислие:
```php
// app/Services/Formatter.php
// ❌ Синтактична грешка!
$result = $value |> fn($x) => $x * 2 |> fn($y) => $y + 10;

// ✅ Правилен вариант
$result = ($value |> fn($x) => $x * 2) |> fn($y) => $y + 10;
```

## Затваряния (closures) в константни изрази

PHP 8.5 позволява дефиниране на **затваряния** и **first-class callables** на места, които преди приемаха само статични стойности: константи на класове, стойности по подразбиране на свойства и аргументи на атрибути.

```php
// app/Attributes/Route.php
class Route
{
    public function __construct(
        public string $path,
        public Closure $callback = (fn() => 'Default Route')
    ) {}
}
```

Това е сериозен плюс за маршрутизиращи системи и библиотеки за валидация, на които се налага да описват кратка логика директно в метаданните.

<a id="nodiscard"></a>
## `#[\NoDiscard]` и преобразуването към `(void)`

Често разработчиците забравят да проверят върнатия резултат от валидация или операция по запис. В PHP 8.5 е добавен атрибутът `#[\NoDiscard]`, който сигнализира, че стойността не трябва да бъде пренебрегвана.

```php
// app/Services/Transaction.php
class Transaction
{
    #[\NoDiscard]
    public function commit(): bool
    {
        // ...
        return true;
    }
}

$tx = new Transaction();
$tx->commit(); // ❌ Предупреждение: Резултатът от commit() не трябва да бъде пренебрегван!
```

Ако съзнателно желаете да игнорирате стойността, използвайте новото преобразуване към тип `(void)`:

```php
// app/Services/Handler.php
(void) $tx->commit(); // ✅ Предупреждението е потиснато, умишлено игнорираме резултата!
```

<a id="uri-extension"></a>
## Вградено разширение URI (RFC 3986)

Ръчното парсване на URL адреси винаги е било рисковано за сигурността. PHP 8.5 включва вградено и винаги активно разширение `uri`, напълно съвместимо с RFC 3986 и спецификацията на WHATWG.

```php
// app/Services/UrlParser.php
$uri = Uri\parse('https://user:pass@example.com:8080/path?query=1#hash');

echo $uri->host;     // example.com
echo $uri->port;     // 8080
echo $uri->userInfo; // user:pass
```

<a id="new-functions"></a>
## Нови функции: `array_first()` и `array_last()`

Вместо да нулирате указателите на масива чрез `reset()` и `end()`, вече можете да използвате вградени хелпъри:

```php
// app/Services/Collection.php
$list = ['ябълка', 'банан', 'череша'];

$first = array_first($list); // 'ябълка'
$last  = array_last($list);  // 'череша'
```

Освен това флагът `FILTER_THROW_ON_FAILURE` позволява на филтрите да хвърлят изключение `ValueError` вместо да връщат `false`:

```php
// app/Http/Request.php
$id = filter_input(INPUT_GET, 'id', FILTER_VALIDATE_INT, FILTER_THROW_ON_FAILURE);
```

<a id="backward-incompatible"></a>
## Обратно несъвместими промени (BC Breaks)

Преди да обновите производствените сървъри към PHP 8.5, проверете следните точки:

1. **Opcache е вграден в бинарния файл**
   Opcache вече не се компилира като отделен модул. Опитът да добавите `zend_extension=opcache.so` в `php.ini` ще доведе до предупреждение.
2. **Промяна в числовите константи на PDO**
   Стойностите на някои PDO fetch режими (например `PDO::FETCH_GROUP`) се променят в 8.5. Ако сте ги съхранявали директно като числа в конфигурации или БД, ги проверете.
3. **Ограничения в `class_alias()`**
   Забранено е използването на имената `"array"` и `"callable"` като алиаси на класове.

## 🧠 Въпроси за самопроверка

Нека проверим знанията ни за PHP 8.5:
1. **Истина или лъжа?** Десният операнд на pipe оператора (`|>`) може да приема неограничен брой параметри по подразбиране.
2. Как се потиска предупреждението при извикване на метод, маркиран с атрибута `#[\NoDiscard]`?
3. Каква директива `zend_extension` трябва да напишете в `php.ini`, за да заредите Opcache в PHP 8.5?
4. **Истина или лъжа?** Хелпърите `array_first()` и `array_last()` работят коректно с асоциативни масиви.

<details>
<summary><b>Покажи отговорите</b></summary>

1. **Лъжа.** Десният операнд трябва да приема точно един аргумент. Ако функцията изисква повече параметри, я обградете в анонимна или стрелкова функция.
2. Преди извикването се добавя `(void)` cast (напр. `(void) $obj->method();`).
3. Никаква! Opcache вече е вграден в ядрото. Достатъчно е да бъде активиран чрез `opcache.enable=1`.
4. **Истина.** Те връщат първия и последния елемент на всеки подаден масив, независимо дали ключовете са числови или асоциативни.
