# PHP 7.2: Основни нововъведения

Какво би станало, ако обикновеното преброяване на елементи в променлива внезапно започне да запълва логовете ви с предупреждения? PHP 7.2 въвежда строг контрол върху използването на функцията `count()`, разкривайки хиляди скрити грешки в проекти, където разработчиците са я викали за неброими типове като `null` или `boolean`. Тази версия въвежда ред в ежедневната разработка благодарение на типа `object`, разширяването на параметрите, вградената библиотека libsodium и строгата хигиена на предупрежденията.

<a id="object-type"></a>
## Тип `object`

Вече можете да декларирате **`object`** за параметри и тип на връщане — всеки обект ще отговаря на това условие. Това нововъведение допълва правилата за вариантност при развитието на PHP 7.x.

```php
// src/ObjectHandler.php
function acceptsAnyObject(object $x): void 
{
    // Работа с обекта
}
```

> [!NOTE]
> Знаехте ли, че? Преди PHP 7.2 не можехте да декларирате общи типове обекти в аргументи. Разработчиците трябваше да разчитат на PHPDoc анотации или на ръчни проверки с `is_object()`.

<a id="type-widening"></a>
## Разширяване на типове параметри (type widening)

Класовете-наследници вече могат да **изпускат типовете на параметрите**, декларирани в родителските методи или интерфейси (това е безопасно от гледна точка на контравариантността). Въпреки това, **не можете** да стеснявате типове или да ги сменяте с други несвързани типове — PHP ще отхвърли такива некоректни пренаписвания.

```php
// src/Logger.php
interface Logger {
    public function log(string $msg);
}

class MyLogger implements Logger {
    // Типът на параметъра е изпуснат (разширен), което е валидно в PHP 7.2
    public function log($msg) {
        echo $msg;
    }
}
```

> [!NOTE]
> Знаехте ли, че? Разширяването на типовете на параметрите позволява на библиотеките да обновяват своите интерфейси, добавяйки строги типове, без веднага да чупят кода на потребителите, чиито класове-наследници изпускат типовете.

<a id="pdo-debug"></a>
## PDO: по-богат `debugDumpParams()`

Методът `PDOStatement::debugDumpParams()` вече показва **пълната SQL заявка**, изпратена към сървъра при използване на **емулирани подготвени заявки** (emulated prepares), включително обвързаните стойности. Това силно улеснява дебъгването на SQL.

```php
// src/DatabaseDebug.php
$stmt = $pdo->prepare("SELECT * FROM users WHERE status = :status");
$stmt->execute(['status' => 'active']);
$stmt->debugDumpParams();
```

<a id="ldap-exop"></a>
## LDAP EXOP (разширени операции)

Добавени са хелпери **`ldap_exop()`**, **`ldap_exop_passwd()`**, **`ldap_exop_whoami()`**, **`ldap_parse_exop()`**, както и нови константи като **`LDAP_EXOP_START_TLS`** — това улеснява работата със стандартните EXOP протоколи.

<a id="sockets-addrinfo"></a>
## Sockets: `socket_addrinfo_*`

Функциите **`socket_addrinfo_lookup()`**, **`socket_addrinfo_connect()`**, **`socket_addrinfo_bind()`**, **`socket_addrinfo_explain()`** обвиват системните извиквания `getaddrinfo()`. Използвайте ги вместо ръчен разбор на IPv4/IPv6 адреси.

<a id="sodium"></a>
## Sodium (libsodium) в ядрото

В PHP 7.2 разширението **Sodium** е включено по подразбиране. То предоставя функции за AEAD шифроване, хеширане и генериране на ключове. Разглеждайте го като стандарт при писане на **нов криптографски код** вместо премахнатото разширение **mcrypt**.

```php
// src/CryptoHelper.php
$nonce = random_bytes(SODIUM_CRYPTO_SECRETBOX_NONCEBYTES);
$key = sodium_crypto_secretbox_keygen();
$ciphertext = sodium_crypto_secretbox('message', $nonce, $key);
```

<a id="extensions-stdlib"></a>
## Стандартна библиотека и разширения

* Функциите **`utf8_encode()` / `utf8_decode()`** са преместени в ядрото на строковите функции (вече не изискват задължително присъствие на XML разширението).
* Функциите **`mail()` / `mb_send_mail()`** вече поддържат предаване на хедъри като **масиви** (в допълнение към низове).
* Разширението **DBA** получи поддръжка за драйвера **LMDB**.
* **GD**: функцията **`imageantialias()`** е адаптирана под системната библиотека libgd; **`imagegd()`** записва truecolor изображения по-точно.
* Извикването **`session_module_name('user')`** вече хвърля възстановима грешка (recoverable error) вместо тих срив.

<a id="practical-recipes"></a>
## Практични рецепти

### Защитен извик на `count()`

```php
// src/recipes.php
if (is_array($x) || $x instanceof \Countable) {
    $n = count($x);
}
```

(Функцията `is_countable()` се появява едва в PHP 7.3; за 7.2 използвайте това изрично условие.)

### Безопасно използване на `get_class()`

```php
// src/recipes.php
$cls = is_object($obj) ? get_class($obj) : self::class;
```

<a id="common-mistakes"></a>
## Чести грешки

Ето типични грешки на разработчиците при работа с PHP 7.2:

### 1. Броене на неброими типове
Подаването на `null`, числа, низове или обикновени обекти в `count()` вече предизвиква Warning.
```php
// src/BadCount.php
// Лошо: Подаването на null ще доведе до Warning: count(): Parameter must be an array or an object that implements Countable
$data = null;
echo count($data); 
```
```php
// src/GoodCount.php
// Добре: Проверявайте типа преди броене
$data = null;
echo (is_array($data) || $data instanceof \Countable) ? count($data) : 0;
```

### 2. Подаване на `null` във функцията `get_class()`
В предишните версии извикването на `get_class(null)` връщаше името на текущия клас, откъдето е извикан методът. Сега това предизвиква E_WARNING.
```php
// src/BadGetClass.php
// Лошо: Ще доведе до предупреждение, ако $obj се окаже null
$className = get_class($obj); 
```
```php
// src/GoodGetClass.php
// Добре: Проверявайте дали променливата е обект
$className = is_object($obj) ? get_class($obj) : 'DefaultClass';
```

<a id="limitations"></a>
## Ограничения

* **Общ тип `object`**: Не можете да укажете структурата на обекта; типът просто проверява дали стойността е инстанция на някакъв клас. Не можете да отсеете базовия `stdClass` чрез тайп-хинтинг.
* **Интеграция на libsodium**: Предоставя нисконивови криптографски примитиви. Те са много надеждни, но изискват от разработчика разбиране на криптографията (ключове, нонсове), за да не се допуснат уязвимости.

<a id="backward-incompatible"></a>
## Обратно несъвместими промени

### Ядро и типове

* Функция **`number_format()`** вече не връща стойност **`-0`** при гранични изчисления с плаваща запетая.
* **Кастването на масиви към обекти (и обратно)** с числови ключове стана консистентно. Обръщения от вида **`$obj->{0}`** работят коректно.
* Извикването **`get_class(null)`** вече **хвърля warning**; не подавайте null или изпускайте аргумента.
* Извикването на **`count()`** (и неговия алиас **`sizeof()`**) за **неброими** типове генерира **`E_WARNING`**. Старият код, който очаква `count(null) === 0`, ще започне да пише предупреждения.
* Остаря старият автозаредител **`__autoload`**, използвайте стандартния SPL стек.

### Разширения

* **Разширението mcrypt е напълно премахнато от ядрото на PHP**. При крайна нужда може да се инсталира през PECL, но правилният път е **преминаване към OpenSSL или Sodium**.

<a id="deprecations"></a>
## Deprecated (поправете рано)

Основно:

* Магическата функция **`__autoload()`** — заменете с **`spl_autoload_register()`**.
* Използването на нецитирани константи (barewords), които преди предизвикваха notice, сега хвърля **warning**.
* Остаряха функциите **`create_function()`**, **`each()`**, извикванията на **`assert()`** с низови аргументи, извикването на **`parse_str()`** с един аргумент, **`read_exif_data()`**, GD функциите **`png2wbmp` / `jpeg2wbmp`**.

<a id="other-changes"></a>
## Други промени и компилиране

* Unix: за компилиране се изисква Autoconf версия 2.64 или по-нова.
* Разширението **mcrypt** е изнесено в **PECL**. Използвайте **Sodium/OpenSSL** за криптографска работа.

<a id="closing-thoughts"></a>
## Обобщение

Преходът към PHP 7.2 е отлична възможност **да премахнете остатъците от mcrypt**, да направите търсене за използване на **`count(`** върху променливи, които могат да бъдат null, и да премахнете извикванията на **`get_class(null)`**. След това можете да продължите към версия 7.3 с нейните `JsonException`, `is_countable()` и подобрения heredoc.
