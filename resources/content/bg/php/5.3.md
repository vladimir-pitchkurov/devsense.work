# PHP 5.3: Модернизация и основа на корпоративната архитектура

Представете си, че обновявате сървъра си и внезапно се сблъсквате с „бял екран на смъртта“, само защото външна библиотека е използвала недекларирана дума или предаване по референция при извикване на функция. PHP 5.3 беше преломният момент, в който езикът спря да бъде просто скриптово ядро за домашни страници и се превърна в зрял ООП език от корпоративен клас. Този преход обаче дойде с тежки промени в обратната съвместимост, които за една нощ счупиха хиляди наследени приложения.

Преди PHP 5.3 разработчиците се бореха с чести конфликти на имена на класове в глобалната област, неработещо наследяване на статични методи и неконтролируемо изтичане на памет в дълго работещи скриптове поради циклични референции. За решаването на тези проблеми PHP 5.3 въведе пространства от имена (namespaces), анонимни функции (closures), късно статично свързване (Late Static Binding) и цикличен събирач на боклук. Но същевременно езикът се изчисти от остатъци като предаването по референция при извикване и разширението `ereg`.

> [!IMPORTANT]
> PHP 5.3 е фундаментален етап в историята на PHP, който принуди разработчиците да изоставят навиците от ерата на PHP 4 в полза на изолацията на кода и структурираното управление на паметта.

<a id="namespaces"></a>
## Пространства от имена и автозареждане

Пространствата от имена изолират кода и спестяват писането на безкрайни префикси на класове.

```php
// app/Repositories/UserRepository.php
namespace App\Repositories;

use App\Database\Connection;
use App\Contracts\LoggerInterface;

class UserRepository
{
    private Connection $db;
    private LoggerInterface $log;

    public function __construct(Connection $db, LoggerInterface $log)
    {
        $this->db = $db;
        $this->log = $log;
    }
}
```

* **Защо това е важно**: Преди пространствата от имена конфликтите се избягваха чрез дълги префикси в имената на файловете и класовете (например `Zend_Db_Table_Row_Abstract`). Пространствата от имена правят кода чист и четим, като логически изолират кратки имена на класове.
* **Последица**: Това нововъведение положи основите за съвременните PHP пакети, стандартите за автозареждане (PSR-0/PSR-4) и създаването на Composer.

<a id="lsb"></a>
## Късно статично свързване (`static::`)

В PHP ключовата дума `self::` винаги сочи към класа, в който методът е физически дефиниран. Късното статично свързване въвежда `static::`, което се разрешава динамично към класа, извикал метода в рантайм.

```php
// app/Models/ActiveRecord.php
abstract class ActiveRecord
{
    public static function find(int $id): string
    {
        // self::getTable() тук би дало грешка при подкласове
        return "SELECT * FROM " . static::getTable() . " WHERE id = " . $id;
    }

    abstract protected static function getTable(): string;
}
```

* **Защо това е важно**: Без късно статично свързване създаването на базови класове със статични фабрични методи (като ActiveRecord ORM) беше изключително трудно.
* **Последица**: Разработчиците вече могат да пишат елегантни базови хелпъри, които си взаимодействат коректно с предефинираните статични свойства или методи в наследниците.

<a id="closures"></a>
## Анонимни функции и конструкцията `use`

Анонимните функции вече могат да се присвояват на променливи, да се предават като аргументи и да улавят променливи от родителския обхват с помощта на конструкцията `use`.

```php
// app/Services/Calculator.php
$taxRate = 0.20;

$calculateTotal = function (float $price) use ($taxRate): float {
    return $price * (1 + $taxRate);
};

echo $calculateTotal(100); // 120
```

> [!NOTE]
> В PHP 5.3 анонимните функции по подразбиране копират уловените променливи **по стойност**. Ако искате да промените оригиналната променлива вътре във функцията, трябва да я предадете **по референция** (например `use (&$counter)`).

<a id="syntax-additions"></a>
## NOWDOC срещу HEREDOC

NOWDOC се отнася към HEREDOC така, както низовете в единични кавички се отнасят към низовете в двойни кавички.

```php
// app/Config/templates.php
// HEREDOC (парсва променливи)
$name = 'Иван';
$heredoc = <<<EOT
Здравей, $name!
EOT;

// NOWDOC (не парсва променливи, обърнете внимание на единичните кавички около EOT)
$nowdoc = <<<'EOT'
Здравей, $name!
EOT;
```

* **Защо това е важно**: NOWDOC позволява безопасно вграждане на големи блокове от необработен код, конфигурации или регулярни изрази без нужда от ескейпване на знака за долар.

<a id="gc"></a>
## Събиране на боклук при циклични референции

PHP 5.3 въведе инструмент за почистване на циклични референции. Когато обект А сочи към обект Б, а обект Б сочи обратно към обект А, стандартният механизъм за броене на референции не може да ги освободи, дори ако те вече не са достъпни в програмата.

```php
// app/Services/Daemon.php
gc_enable(); // Активиране на събирането на циклични референции

// В дълго работещ процес:
gc_collect_cycles(); // Принудително стартиране на изчистването
```

* **Защо това е важно**: Изключително важно за фонови процеси, CLI команди и демони, които в противен случай бързо биха изразходили паметта.

<a id="common-mistakes"></a>
## ⚠️ Чести грешки

### 1. Предаване на референции при извикване (Call-Time Pass-By-Reference)
Използването на амперсанд директно при извикването на функция води до грешки.

```php
// app/Services/LegacyFix.php
// ❌ Остаряло / Фатална грешка в PHP 5.3+
foo(&$value); 

// ✅ Правилен подход
// Референцията трябва да е дефинирана в самата сигнатура на функцията:
function foo(&$param) {}
foo($value); 
```

### 2. Използване на нови запазени думи
Нови ключови думи като `goto`, `namespace` и `use` не могат да се използват като имена на класове или недекларирани константи.

```php
// app/Classes/Runner.php
// ❌ Фатална грешка: не може да се използва 'goto' като име на клас
class goto {}
```

### 3. Използване на остарялото ereg вместо preg_match
Функциите от семейството `ereg()` работят по-бавно и генерират предупреждения за остарял код.

```php
// app/Validation/Email.php
// ❌ Остаряло в PHP 5.3
if (eregi('^[a-z0-9]+$', $input)) {}

// ✅ Правилен подход
if (preg_match('/^[a-z0-9]+$/i', $input)) {}
```

<a id="practical-recipes"></a>
## Практически рецепти

### Очакване срещу Реалност: `self` срещу `static`

```php
// app/Demo/BindingDemo.php
class ParentClass
{
    public static function getClassName(): string
    {
        return self::class; // Или __CLASS__
    }

    public static function getCalledClassName(): string
    {
        return static::class;
    }
}

class ChildClass extends ParentClass {}

// Очакване: и двата метода ще върнат 'ChildClass'
// Реалност:
echo ChildClass::getClassName();       // Резултат: ParentClass
echo ChildClass::getCalledClassName(); // Резултат: ChildClass
```

<a id="backward-incompatible"></a>
## Обратна несъвместимость

1. **Премахване на предаването по референция при извикване**: Синтаксисът `foo(&$x)` е остарял и генерира предупреждения в PHP 5.3 (напълно премахнат в 5.4).
2. **Нови запазени думи**: `goto`, `namespace`, `use`, `const` вече не могат да се използват за имена на класове, интерфейси или константи.
3. **Остаряване на ereg**: Използването на POSIX регулярни изрази `ereg_*` води до предупреждения `E_DEPRECATED`.
4. **Строг ред на параметрите**: Променено поведение при аргументи в някои системни функции (например `clearstatcache()`).

<details>
<summary><b>Покажи отговорите</b></summary>

1. **Грешно.** В PHP 5.3 анонимните функции НЕ привързват автоматично контекста `$this`. Трябва да го предавате ръчно (например `$self = $this;` и `use ($self)`) за достъп до методите и свойствата на обекта. Автоматичното привързване беше въведено в PHP 5.4.
2. Трябва да обградите идентификатора в единични кавычки в отварящия маркер: `<<<'EOT'`.
3. `self::` се отнася до класа, в който кодът е бил компилиран (където методът е написан физически), докато `static::` динамично сочи към класа, извикан по време на изпълнение (runtime).
4. Ще бъде генерирано предупреждение за остарял код (`Deprecated: Call-time pass-by-reference has been deprecated...`). В PHP 5.4+ този синтаксис води до фатална синтактична грешка.
</details>
