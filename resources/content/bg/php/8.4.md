# PHP 8.4: Основни нововъведения и интерактивно ръководство

PHP 8.4 е релийз с „инструменти за напреднали“. Той напълно променя начина, по който изразяваме инварианти на границата на свойствата (Property Hooks, асиметрична видимост), внедрява нативна поддръжка за лениви обекти (Lazy Objects) и модернизира управлението на HTML5 чрез новия API под пространство от имена `Dom`.

В това ръководство ще разгледаме ключовите промени с ясни примери, ще обсъдим честите грешки при разработка и ще проверим наученото с тест в края!

<a id="property-hooks"></a>
## Property Hooks (логика get/set върху свойства)

Години наред PHP разработчиците трябваше да пишат досаден код (getters и setters) само за да валидират или форматират стойностите преди запис. В PHP 8.4 се въвеждат **Property Hooks** директно в декларацията на свойствата.

Има два типа хукове:
- `set`: задейства се при опит за запис в свойството.
- `get`: задейства се при четене на стойността на свойството.

Нека разгледаме следния пример:

```php
// app/DTO/Person.php
final class Person
{
    // Хукът може да запише в скритото свойство чрез $this->propName
    public string $firstName {
        set => ucfirst(strtolower($value));
    }

    public string $lastName {
        set {
            if (strlen($value) < 2) {
                throw new InvalidArgumentException('Фамилията е твърде къса!');
            }
            $this->lastName = $value;
        }
    }

    // Виртуално свойство без физическо запазване на стойността!
    public string $fullName {
        get => $this->firstName . ' ' . $this->lastName;
    }
}
```

> [!NOTE]
> **Знаехте ли, че?**
> Свойства, които дефинират само хук `get`, се считат за виртуални. Те не заемат памет в обекта и не изискват физическо поле за съхранение.

### ⚠️ Чести грешки при разработка

**1. Опит за предаване на свойство с хукове по референция**
Тъй като достъпът до свойство с хукове под капака извиква функции, предаването по референция е невъзможно:
```php
// app/Services/ContactService.php
function cleanString(string &$str) {
    $str = trim($str);
}

$person = new Person();
cleanString($person->firstName); // ❌ Fatal Error: Cannot pass property Person::$firstName by reference
```

**2. Безкрайна рекурсия в хука `set`**
Ако се опитате да зададете стойност в собствения му `set` хук чрез директно присвояване `$this->propertyName = $value` (без съкратения синтаксис `=>`), това може да причини безкрайна рекурсия. Съкратеният синтаксис `=>` автоматично записва стойността в скрития backing storage без рекурсивни повиквания.

<a id="asymmetric-visibility"></a>
## Асиметрична видимост на свойствата (`public private(set)`)

Вече можете да настройвате различни нива на видимост за четене и запис на свойствата. Това е перфектно решение за създаване на имутабелни DTO и Aggregate Roots в контекста на Domain-Driven Design (DDD).

```php
// app/Models/User.php
final class User
{
    // Свойството е публично за четене, но може да се променя само вътре в класа
    public private(set) string $email;

    public protected(set) int $loginAttempts = 0;

    public function __construct(string $email)
    {
        $this->email = $email;
    }

    public function incrementAttempts(): void
    {
        $this->loginAttempts++;
    }
}
```

> [!NOTE]
> **Знаехте ли, че?**
> Асиметричната видимост изисква видимостта за запис (`set`) да бъде **по-строга** от видимостта за четене (`get`). Опит за дефиниране на `private public(set)` ще доведе до синтактична грешка.

<a id="lazy-objects"></a>
## Lazy Objects (Лениви обекти чрез Reflection)

В PHP 8.4 е добавена нативна поддръжка за **Lazy Objects** (лениви обекти). Това решение е създадено специално за автори на ORM (като Doctrine или Laravel Eloquent) и DI контейнери, за да отложи зареждането на обекти от базата данни до момента на реално обръщение към тях.

Преди библиотеките трябваше да генерират сложни прокси класове в движение. Сега рефлексията поема тази задача:

```php
// app/Services/Container.php
$initializer = static function (LargeService $service) {
    $service->loadHeavyConfiguration();
};

$r = new ReflectionClass(LargeService::class);
// Създаваме ленив обект (lazy ghost) от клас LargeService
$lazyService = $r->newLazyGhost($initializer);
```

Кодът за инициализация ще се задейства само тогава, когато се опитаме да прочетем или запишем свойство на обекта `$lazyService`.

<a id="deprecated-attribute"></a>
## Депрекации в userland чрез `#[Deprecated]`

Преди, за да предупредите потребителите, че метод или клас е остарял, трябваше ръчно да извиквате `trigger_error(..., E_USER_DEPRECATED)`. В PHP 8.4 се появява вграден атрибут за това:

```php
// app/Helpers/LegacyMath.php
class LegacyMath
{
    #[\Deprecated(message: "Използвайте BCMath или стандартно деление", since: "1.4.0")]
    public static function divide(int $a, int $b): float
    {
        return $a / $b;
    }
}
```

Когато друг код извика този метод, PHP автоматично ще генерира депрекация с посоченото съобщение.

<a id="dom-modern"></a>
## Стандарти на WHATWG в пространство от имена `Dom\*`

Класическият клас `DOMDocument` страдаше от лоша поддръжка на HTML5. PHP 8.4 представя съвременен API под пространство от имена `Dom`.

```php
// app/Services/HtmlParser.php
// Парсваме HTML5 без предупреждения и костили
$dom = Dom\HTMLDocument::createFromString('<main><article>Modern HTML5!</article></main>');
$node = $dom->querySelector('article');

echo $node->textContent; // Изход: Modern HTML5!
```

Старият API остава за съвместимост, но новите проекти трябва да се пишат с `Dom\HTMLDocument` и `Dom\XMLDocument`.

<a id="request-parse-body"></a>
## Поддръжка на multipart данни за PUT/PATCH: `request_parse_body()`

Ако сте писали REST API с качване на файлове чрез `PUT` или `PATCH` заявки, сигурно си спомняте болката: масивите `$_FILES` и `$_POST` се попълваха автоматично само при `POST` заявки. Разработчиците трябваше да парсват потока `php://input` ръчно.

PHP 8.4 решава това с `request_parse_body()`:

```php
// public/index.php
if ($_SERVER['REQUEST_METHOD'] === 'PUT') {
    [$postData, $files] = request_parse_body();
    
    // $postData съдържа данните от формата
    // $files съдържа качените файлове в същия формат като $_FILES
}
```

<a id="new-functions"></a>
## Полезни хелпъри за масиви и UTF-8

PHP 8.4 добавя няколко много полезни функции за ежедневна разработка:

### 1. `array_find()`, `array_find_key()`, `array_any()`, `array_all()`

```php
// app/Services/Validator.php
$users = [
    ['name' => 'Алексей', 'role' => 'user'],
    ['name' => 'Димитър', 'role' => 'admin'],
];

// Намираме първия администратор
$admin = array_find($users, fn($u) => $u['role'] === 'admin');

// Проверяваме дали има поне един обикновен потребител
$hasUsers = array_any($users, fn($u) => $u['role'] === 'user');
```

### 2. Безопасно изрязване на интервали в UTF-8 (`mb_trim`)
Обикновеният `trim()` не поддържа многобайтови интервали в UTF-8. PHP 8.4 добавя функциите `mb_trim()`, `mb_ltrim()` и `mb_rtrim()`.

<a id="backward-incompatible"></a>
## Обратно несъвместими промени (BC Breaks)

При преход към PHP 8.4 обърнете внимание на следните промени:

1. **Неявно обнуляеми параметри са deprecated**
   ```php
   // ❌ Остаряло в PHP 8.4
   function save(string $name = null) {}

   // ✅ Правилен вариант
   function save(?string $name = null) {}
   ```
2. **Промяна в поведението на `exit()` и `die()`**
   Те вече се третират като функции и проверяват типовете на аргументите си. Подаването на невалиден обект или масив ще доведе до `TypeError`.
3. **Ресурси преминават в обекти**
   Връзките в DBA, ODBC и SOAP вече връщат обекти, а не ресурси. Проверките с `is_resource()` на тези връзки ще започнат да връщат `false`.

## 🧠 Въпроси за самопроверка

Нека затвърдим наученото! Отговорете на следните въпроси:
1. **Истина или лъжа?** Може ли да дефинирате `set` хук за виртуално свойство?
2. Защо извикването на `cleanString($person->firstName)` ще доведе до Fatal Error, ако свойството има хукове?
3. Какво ще стане, ако декларирате видимост `private public(set)` на свойство?
4. Коя функция трябва да се използва в PHP 8.4, за да се провери дали *поне един* елемент от масив отговаря на дадено условие?

<details>
<summary><b>Покажи отговорите</b></summary>

1. **Лъжа.** Виртуалните свойства нямат физически backing storage, така че за тях не може да се дефинира `set` хук (освен ако той не записва стойността в други реални свойства на класа).
2. Защото свойствата с хукове се оценяват като изчислими стойности; те нямат постоянна референция в паметта и затова не могат да се предават по референция.
3. PHP ще генерира синтактична грешка (Syntax Error). Достъпът за запис (`set`) трябва да бъде същият или по-строг от този за четене (`get`).
4. За целта се използва функцията `array_any()`.
</details>
