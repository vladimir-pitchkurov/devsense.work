PHP 8.2 насочва езика към по-ясни модели, строга типизация и структурна сигурност. С въвеждането на readonly класовете и DNF (Disjunctive Normal Form) типовете, разработчиците получават пълен контрол над имютабилността на обектите и сложните типови дефиниции. Защитата на чувствителни данни вече е вградена директно на ниво синтаксис: атрибутът `#[SensitiveParameter]` гарантира, че пароли и токени няма да изтекат случайно в лог файловете при генериране на stack trace. В същото време версия 8.2 въвежда сериозни промени, сред които най-забележителна е deprecation на динамичните свойства. Ето вашия пътеводител за преход към PHP 8.2.

<a id="sensitive-parameter"></a>
## #[SensitiveParameter] и трасиращи изходи

`#[\SensitiveParameter]` маркира параметри за редактиране в stack traces — по-малко случайни токени и пароли в логове.

> [!NOTE]
> **А знаехте ли?**
> Атрибутът `#[SensitiveParameter]` работи нативно със стандартния механизъм на PHP за извеждане на изключения. Когато PHP генерира stack trace, той автоматично заменя стойността на този параметър с обект `SensitiveParameterValue`, скривайки напълно оригиналния низ от логовете!

```php
// app/Services/DatabaseService.php
function connect(#[\SensitiveParameter] string $password): void
{
    throw new RuntimeException('fail');
}
```

Атрибутът не замества политика за логове: в production не показвайте сурови изключения на клиента и дръжте чувствителните полета извън слепите копия на грешки.

### Практичен рецепт: маркирайте тайни на границата

Слагайте `#[\SensitiveParameter]` върху параметри, които могат да попаднат в exceptions (client wrappers, auth helper-и). Stack trace остава полезен, но секретите не изтичат в логовете.

```php
// app/Clients/ApiClient.php
final class ApiClient
{
    public function __construct(
        private readonly string $baseUrl,
        #[\SensitiveParameter] private readonly string $token,
    ) {}
}
```

<a id="readonly-classes"></a>
## Readonly класове

`readonly class` прави всички instance properties readonly и ги инициализира през конструктора.

> [!NOTE]
> **А знаехте ли?**
> Readonly класовете автоматично предотвратяват използването на динамични свойства! Дори не е необходимо да използвате атрибута `#[AllowDynamicProperties]`, тъй като всеки опит за добавяне на динамично свойство към readonly клас незабавно ще хвърли Fatal Error.

```php
// app/DTO/Point.php
readonly class Point
{
    public function __construct(
        public int $x,
        public int $y,
    ) {}
}
```

Подходящо за **immutable** value обекти и DTO, където целият обект трябва да „замръзне“ след конструктора.

<a id="standalone-types-dnf"></a>
## Самостоятелни типове (`null`, `false`, `true`) и DNF

`null`, `false` и `true` могат да се ползват като **самостоятелни** типове в декларации (не само като част от union в по-стари форми).

**DNF** (нормализирана дизюнктивна форма) комбинира **union** и **intersection** — например `(A&B)|null` за прецизни API без загуба на nullability.

```php
// app/Services/ExportService.php
function accepts((Countable&Traversable)|null $c): void {}
```

<a id="random-extension"></a>
## Random разширение

Разширението **Random** обединява и разширява API за произволни числа: по-ясни „двигатели“, по-малко хаотично смесване само със стари функции. За нов код с възпроизводими seed или криптографски токени вижте `Random\Engine` и `Random\Randomizer` в ръководството.

### Практичен рецепт: `Randomizer` за токени и sampling

```php
// app/Services/TokenGenerator.php
$engine = new Random\Engine\Mt19937(random_int());
$randomizer = new Random\Randomizer($engine);
$token = $randomizer->getBytesFromString('0123456789abcdef', 32);
```

В тестове използвайте **seeded** engine за възпроизводимост; за секрети изберете криптографски подходящ `Random\Engine` според документацията.

## Разширения: cURL, PCRE

<a id="backward-incompatible"></a>
## Обратно несъвместими промени (миграция)

### Дата и час

- Tentative `static` при factory методите на DateTime / DateTimeImmutable.
- По-строги относителни формати за `number`.

### Стандартна библиотека

- Основните string функции за case — **ASCII**, не locale; за локал — **mbstring**.
- `str_split('')` → празен масив.
- `glob` / `GlobIterator` при `open_basedir` — различно `[]`/`false` и предупреждения.
- `FilesystemIterator` — `SKIP_DOTS` вече не е принудително подразбиране през стари флагове по подразбиране.
- **`ksort` / `krsort`**: при `SORT_REGULAR` се прилагат правилата на PHP 8 за **числови низове** последователно с другите сравнения.
- `var_export` — пълно квалифицирани имена на класове (водещата обратна наклонена черта не се пропуска).

### ODBC / PDO_ODBC

Екраниране на user/pass при допълване на connection string.

**Бележка:** при липса на timezone настройки `date_default_timezone_get()` може да върне **UTC** — валидирайте допусканията след ъпгрейд.

### SPL

Някои методи на **`SplFileObject`** спазват по-строго сигнатури; за част от тях са стегнати типовете на връщане (**`hasChildren`**, **`getChildren`** и др.) — прегледайте наследници.

<a id="deprecations"></a>
## Deprecated

### Динамични свойства

Създаването на **динамични свойства** върху произволни класове е deprecated, освен ако класът няма **`#[\AllowDynamicProperties]`** (или не наследява типове като `stdClass`, където това е позволено). Предпочитайте декларирани свойства, **`WeakMap`** за външни метаданни или явни **`__get`/`__set`**.

### Частични callables

Форми, приемани от **`call_user_func()`**, но не и от **`$callable()`** — напр. `"self::method"`, `"parent::method"`, определени масивни форми — са deprecated. Нормализирайте до `Foo::bar` или `[Class::class, 'method']`.

### Интерполация на низове

Стилът `"${var}"` / `"${expr}"` е deprecated; ползвайте `"{$var}"` или конкатенация.

### Друго

- **`utf8_encode` / `utf8_decode`**: deprecated (предпочитайте **`mb_convert_encoding`** или **`iconv`**).

<a id="extensions-notes"></a>
## Разширения и runtime

- **OpenSSL**: AEAD **chacha20-poly1305**, където сборката го поддържа.
- **OCI8**: настройка на prefetch за LOB чрез INI и **`oci_set_prefetch_lob()`** на поддържани Oracle версии.
- **DBA (LMDB)**: флагове за поведение с поддиректории при създаване на DB файлове.

## Чести грешки

Ето няколко често срещани капана при използването на новите възможности на PHP 8.2:

### 1. Създаване на динамични свойства
В PHP 8.2 присвояването на стойност на недекларирано свойство на клас предизвиква предупреждение за остарял синтаксис (deprecation warning), а в PHP 9.0 това ще води до фатална грешка.

```php
// app/Services/UserService.php
// ЛОШО: Задейства предупреждение за остарял синтаксис в PHP 8.2
class UserService {
    public string $name;
}

$service = new UserService();
$service->email = 'user@example.com'; // Deprecation Warning: Creation of dynamic property is deprecated
```

### 2. Използване на остарял синтаксис за интерполация на низове
Старият синтаксис `${var}` е deprecated в PHP 8.2.

```php
// app/Services/NotificationService.php
// ЛОШО: Задейства предупреждение за остарял синтаксис
$name = 'Alice';
echo "Hello ${name}"; // Deprecation Warning

// ДОБРЕ: Използвайте стандартния синтаксис с фигурни скоби
echo "Hello {$name}";
```

### 3. Опит за наследяване на readonly клас от обикновен клас
Клас със спецификатор `readonly` може да наследява единствено друг `readonly` клас.

```php
// app/DTO/Point3D.php
class Point2D {}

// ЛОШО: Fatal Error: Readonly class Point3D cannot extend non-readonly class Point2D
readonly class Point3D extends Point2D {}
```

## Квиз за самопроверка

Проверете знанията си за възможностите на PHP 8.2. Изберете отговор и проверете под спойлера.

### Въпрос 1: Какво се случва, когато дефинирате клас като `readonly` в PHP 8.2?
- A) Всички негови свойства автоматично се маркират като `readonly`, но не е необходимо да бъдат типизирани.
- B) Не можете да добавяте динамични свойства към класа и всички свойства трябва да бъдат типизирани.
- C) Разрешено е да наследява всеки обикновен клас, но обикновените класове не могат да го наследяват.

<details>
<summary>Покажи отговора</summary>

**Правилен отговор: B**
Декларирането на клас като `readonly` означава, че всички негови свойства са имплицитно readonly и трябва да бъдат типизирани. Освен това readonly класовете не могат да имат динамични свойства и могат да наследяват само други readonly класове.
</details>

### Въпрос 2: Кой синтаксис за интерполация задейства предупреждение за остарял синтаксис в PHP 8.2?
- A) `"Hello {$name}"`
- B) `"Hello ${name}"`
- C) `"Hello " . $name`

<details>
<summary>Покажи отговора</summary>

**Правилен отговор: B**
Стилът `${var}` за интерполация на низове е остарял (deprecated) в PHP 8.2 и задейства предупреждение. Вместо това трябва да използвате `{$var}`.
</details>
