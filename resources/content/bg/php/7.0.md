# PHP 7.0: Основни нововъведения

Какво би станало, ако можехте да удвоите производителността на вашето уеб приложение за една нощ, просто като обновите интерпретатора на езика? Версия PHP 7.0 направи това реалност. Благодарение на новия енджин Zend Engine 3, тази версия донесе колосално увеличение на скоростта, както и строги скаларни типове, декларации за връщаните стойности на функциите и съвременни оператори като null-coalescing. PHP 7.0 бе революционна стъпка в историята на PHP, полагайки основите на съвременните сигурни и високопроизводителни уеб приложения.

<a id="scalar-types"></a>
## Скаларни типове

Параметрите на функциите вече могат да имат скаларни типове: **`int`**, **`float`**, **`string`** и **`bool`**:

```php
// src/Math.php
declare(strict_types=1);

function add(int $a, int $b): int 
{
    return $a + $b;
}
```

> [!NOTE]
> Знаехте ли, че? Без декларацията `declare(strict_types=1);` в началото на файла PHP работи в **режим на автоматично приведение на типове (coercive mode)**. Това означава, че той автоматично и безшумно ще превърне низ `"5"` в число `5` при проверка на аргументите.

<a id="return-types"></a>
## Декларации на типове на връщане

Можете строго да дефинирате какъв тип стойност трябва да връща функцията:

```php
// src/Generator.php
function generateId(): string 
{
    return uniqid();
}
```

Ако върнатата стойност не съответства на посочения тип, PHP ще хвърли изключение **`TypeError`**.

<a id="null-coalescing"></a>
## Оператор за обединяване с null (`??`)

Синтактична замяна на проверката за съществуване чрез `isset()`:

```php
// src/Config.php
$username = $_GET['user'] ?? 'anonymous';
```

Операторът може да бъде свързван във вериги: `$value = $a ?? $b ?? $default;`.

<a id="spaceship-operator"></a>
## Оператор „космически кораб“ (`<=>`)

Извършва тристранно сравнение на стойности, като връща `-1`, `0` или `1`:

```php
// src/SortHelper.php
usort($list, function($a, $b) {
    return $a <=> $b;
});
```

Удобен е за използване във функции за потребителско сортиране, спестявайки разклонения с `if-else`.

<a id="constant-arrays"></a>
## Масиви в константи чрез `define()`

Масивите вече могат да бъдат дефинирани в константи директно по време на изпълнение на скрипта:

```php
// src/Constants.php
define('ALLOWED_ROLES', ['admin', 'editor', 'guest']);
```

Преди това масивите като константи се поддържаха само в класове чрез ключовата дума `const`.

<a id="anonymous-classes"></a>
## Анонимни класове

Създаване на прости еднократни обекти в движение:

```php
// src/LoggerProvider.php
$logger = new class {
    public function log(string $msg) {
        echo $msg;
    }
};
```

Често се използват за създаване на заглушки (mocks) на интерфейси при юнит тестове.

<a id="unicode-escape"></a>
## Екраниране на Unicode символи

Извеждане на Unicode символи директно в низове по техния шестнадесетичен код:

```php
// src/Emoji.php
echo "\u{1F600}"; // Извежда усмихващо се емоджи 😀
```

<a id="group-use"></a>
## Групово импортиране (use)

Кратък импорт на няколко класа от едно и също пространство от имена:

```php
// src/Controller.php
use App\Models\{User, Post, Comment};
```

<a id="throwable-exceptions"></a>
## Интерфейс Throwable и системни изключения

Много фатални грешки в рантайм вече се хвърлят като изключения от клас **`Error`**. Прехващането им става през общия интерфейс **`Throwable`**:

```php
// src/ErrorHandler.php
try {
    nonExistentFunction();
} catch (Throwable $t) {
    // Прехваща както грешки на енджина Error, така и стандартни Exceptions
    echo "Прехванато: " . $t->getMessage();
}
```

> [!NOTE]
> Знаехте ли, че? Класът `Error` не наследява `Exception`. Ако се опитате да хванете грешка с `catch (Exception $e)`, фаталните грешки на ядрото (например извикване на несъществуваща функция) все пак ще доведат до срив на скрипта. Използвайте `Throwable` или `Error`.

<a id="csprng-functions"></a>
## Функции CSPRNG

Криптографски сигурно генериране на случайни числа и байтове на ниво операционна система:

```php
// src/TokenGenerator.php
$bytes = random_bytes(32);
$number = random_int(1, 100);
```

Тези функции заменят несигурните генератори като `rand()` или `mt_rand()` в контексти, свързани със сигурността.

<a id="common-mistakes"></a>
## Чести грешки

Ето типични грешки на разработчиците при работа с PHP 7.0:

### 1. Забравена декларация за строга типизация
Ако не декларирате strict_types във всеки файл поотделно, PHP ще работи в режим на автоматично приведение на типовете и ще променя неверните аргументи без предупреждение.
```php
// src/BadStrict.php
// Лошо: Строгият режим е изключен, низът "10" се превръща в int 10 без грешка
function setAge(int $age) {
    return $age;
}
setAge("10"); // Няма грешка
```
```php
// src/GoodStrict.php
// Добре: Включете строгата типизация на първия ред на файла
declare(strict_types=1);

function setAgeGood(int $age) {
    return $age;
}
// setAgeGood("10"); // Ще хвърли TypeError
```

### 2. Опит за прихващане на грешки на ядрото през клас `Exception`
Разработчиците често улавят `Exception`, очаквайки да прехванат грешки като деление на нула или извикване на несъществуващ метод, но те пропускат този блок catch.
```php
// src/BadCatch.php
// Лошо: Деление на нула хвърля DivisionByZeroError (наследник на Error), catch няма да сработи
try {
    $value = 1 / 0;
} catch (Exception $e) {
    echo "Този код няма да се изпълни!";
}
```
```php
// src/GoodCatch.php
// Добре: Прехващайте Throwable или Error
try {
    $value = 1 / 0;
} catch (Throwable $e) {
    echo "Грешката е уловена: " . $e->getMessage();
}
```

<a id="limitations"></a>
## Ограничения

* **Обявяване на скаларни типове**: Не могат да приемат `null` по подразбиране. Декларация `int $x` ще хвърли TypeError при подаване на null (nullable типовете се появяват едва в PHP 7.1).
* **Типове на връщане на функциите**: Не може да се указва тип `void` (той се появява в PHP 7.1) или обединение на типове (Union типове се появяват в PHP 8.0).

<a id="backward-incompatible"></a>
## Обратно несъвместими промени

### Ядро на езика

* **ASP тагове (`<% %>`) и script тагове (`<script language="php">`)** са напълно премахнати от парсера на PHP.
* Променливата **`$HTTP_RAW_POST_DATA`** е премахната; използвайте потока `php://input`.
* Използването на повече от един `default` блок в `switch` конструкция води до ParseError.
* Променен е редът на оценяване на някои динамични изрази и глобални променливи (например `$$foo['bar']` се оценява строго отляво надясно).

## Интерактивен куиз

Проверете знанията си за PHP 7.0:

1. **Кое твърдение е вярно относно строгата типизация (strict_types) в PHP 7.0?**
   * А) Строгата типизация се активира глобално в конфигурационния файл php.ini.
   * Б) Строгата типизация трябва да се декларира в началото на всеки конкретен файл.
   * В) В PHP 7.0 е принудително включен строг режим, автоматично приведение на типовете няма.
   * Г) Строгата типизация се прилага само за връщаните стойности, но не и за параметрите.

   <details>
   <summary>Кликнете, за да видите отговора</summary>
   
   **Правилен отговор: Б**  
   Строгата типизация се активира индивидуално за всеки файл с помощта на инструкцията `declare(strict_types=1);`.
   </details>

2. **Кой клас НЕ наследява Exception, но имплементира Throwable в PHP 7.0?**
   * А) RuntimeException
   * Б) Error
   * В) BadMethodCallException
   * Г) InvalidArgumentException

   <details>
   <summary>Кликнете, за да видите отговора</summary>
   
   **Правилен отговор: Б**  
   Новият клас `Error` и неговите наследници (като `TypeError` или `ParseError`) имплементират `Throwable`, но не наследяват `Exception`.
   </details>

3. **Какво връща операторът „космически кораб“ (`<=>`)?**
   * А) Булева стойност (true/false).
   * Б) Число с плаваща запетая (float).
   * В) Цяло число (`-1`, `0` или `1`).
   * Г) Низ с резултата от сравнението.

   <details>
   <summary>Кликнете, за да видите отговора</summary>
   
   **Правилен отговор: В**  
   Операторът сравнява две стойности и връща `-1`, ако лявата е по-малка, `0`, ако са равни, и `1`, ако лявата е по-голяма.
   </details>

<a id="closing-thoughts"></a>
## Обобщение

PHP 7.0 е **революционен етап** в развитието на уеб приложенията. Уверете се, че вашият сървър използва Zend Engine 3, премахнете остарелите ASP тагове от кода, заменете несигурните случайни числа с CSPRNG функции и прихващайте системните грешки през интерфейса Throwable.
