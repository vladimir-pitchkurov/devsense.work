# PHP 5.5: Ефективне керування пам'яттю та безпека з коробки

Спроба прочитати 5-гігабайтний лог-файл повністю за допомогою функції `file()` може вичерпати пам'ять вашого сервера за секунди, викликавши помилку \"Allowed memory size exhausted\". PHP 5.5 назавжди вирішив цю проблему, представивши генератори (`yield`), які дозволяють обробляти великі потоки даних «на льоту» без зайвих витрат ресурсів.

До PHP 5.5 розробникам доводилося завантажувати цілі набори даних у пам'ять у вигляді величезних масивів або писати багатослівні об'єкти-ітератори. Крім того, надійне хешування паролів вимагало написання власних обгорток над MD5/SHA256 із солями, а очищення ресурсів при виникненні помилок було заплутаним через відсутність блоку `finally`.

> [!IMPORTANT]
> PHP 5.5 приніс революційні оптимізації роботи з пам'яттю завдяки генераторам та стандартизував роботу з криптографією через вбудований інтерфейс Password Hashing API.

<a id="generators"></a>
## Генератори (`yield`)

Генератори обчислюють значення в міру потреби, замість того щоб будувати та повертати гігантський масив.

```php
// app/Services/LogReader.php
function readLines(string $filePath): Generator
{
    $handle = fopen($filePath, 'r');
    if (!$handle) {
        return;
    }
    try {
        while (($line = fgets($handle)) !== false) {
            yield trim($line);
        }
    } finally {
        fclose($handle);
    }
}
```

* **Чому це важливо**: Обхід великих файлів, результатів баз даних чи нескінченних послідовностей тепер вимагає фіксованого мінімального обсягу пам'яті (всього кілька кілобайт), незалежно від обсягу даних.
* **Наслідок**: Пакетна обробка даних стає швидкою та стабільною навіть під дуже високими навантаженнями.

<a id="finally"></a>
## Блок `finally`

PHP 5.5 доповнює конструкцію `try-catch` блоком `finally`. Код всередині нього виконується завжди, незалежно від того, чи виникло виключення, чи було викликано `return` всередині блоків `try`/`catch`.

```php
// app/Services/DatabaseClient.php
public function processTransaction()
{
    $this->db->connect();
    try {
        $this->db->execute();
    } catch (\Exception $e) {
        $this->logError($e);
    } finally {
        // Виконується ЗАВЖДИ, запобігаючи витоку ресурсів
        $this->db->disconnect();
    }
}
```

* **Чому це важливо**: Це спрощує закриття файлових дескрипторів, мережевих з'єднань або зняття блокувань.

<a id="password-api"></a>
## Вбудоване API хешування паролей

Забудьте про ручну генерацію солей та старі алгоритми MD5/SHA. Нові функції роблять безпеку паролей тривіальною.

```php
// app/Services/AuthService.php
// Хешування пароля за допомогою bcrypt (PASSWORD_DEFAULT)
$hash = password_hash($password, PASSWORD_DEFAULT);

// Перевірка пароля при вході користувача
if (password_verify($password, $hash)) {
    // Якщо вимоги до вартості або алгоритм змінилися, оновлюємо хеш
    if (password_needs_rehash($hash, PASSWORD_DEFAULT)) {
        $newHash = password_hash($password, PASSWORD_DEFAULT);
        // Зберігаємо $newHash у базу даних
    }
}
```

> [!NOTE]
> Функція `password_hash` автоматично створює криптографічно безпечну випадкову сіль та вбудовує її прямо у рядок хешу, тому окрема колонка для солі в базі даних більше не потрібна.

<a id="helpers"></a>
## `array_column()` та `::class`

PHP 5.5 додав два виключно корисні інструменти для щоденної розробки:

### 1. `array_column()`
Витягує значення одного стовпця з багатовимірного масиву або масиву об'єктів.

```php
// app/Services/Report.php
$users = [
    ['id' => 1, 'name' => 'Олексій'],
    ['id' => 2, 'name' => 'Ігор']
];
$ids = array_column($users, 'id'); // [1, 2]
```

### 2. `ClassName::class`
Дозволяє отримати повне ім'я класу (з урахуванням простору назв) у вигляді рядка.

```php
// app/Services/Container.php
use App\Models\User;
echo User::class; // "App\Models\User"
```

<a id="opcache"></a>
## Інтеграція Zend OPcache

Розширення Zend OPcache тепер постачається у ядрі PHP. Воно кешує скомпільований байт-код в оперативній пам'яті, позбавляючи сервер потреби парсити та компілювати PHP-файли при кожному запиті.

* **Чому це важливо**: Продуктивність додатків збільшується в 2-3 рази (залежно від розміру фреймворку).
* **Наслідок**: При розгортанні коду (деплої) необхідно скидати кеш за допомогою `opcache_reset()` або перезапускати менеджер процесів PHP-FPM.

<a id="common-mistakes"></a>
## ⚠️ Часті помилки

### 1. Небезпечний модифікатор `/e` у `preg_replace`
Модифікатор `/e` змушує інтерпретатор виконувати рядок заміни як PHP-код, що регулярно призводило до вразливостей віддаленого виконання коду (RCE). У PHP 5.5 цей модифікатор визнано застарілим.

```php
// app/Helpers/StringHelper.php
// ❌ Застаріло та небезпечно!
$output = preg_replace('/(\w+)/e', 'strtoupper("$1")', $text);

// ✅ Правильний підхід
$output = preg_replace_callback('/(\w+)/', function($m) {
    return strtoupper($m[1]);
}, $text);
```

### 2. Витік ресурсів у генераторах при перериванні циклу
Якщо ви достроково перериваєте обхід генератора (через `break`), код після `yield` може не виконатися, що призведе до витоку ресурсів, якщо файли або сокети не обгорнуті в блок `finally`.

```php
// app/Services/FileReader.php
// ❌ Небезпечно: при виході з циклу fclose() ніколи не викличеться
function readData($file) {
    $fh = fopen($file, 'r');
    while($line = fgets($fh)) yield $line;
    fclose($fh);
}

// ✅ Correct Approach
function readDataSafe($file) {
    $fh = fopen($file, 'r');
    try {
        while($line = fgets($fh)) yield $line;
    } finally {
        fclose($fh); // Виконається гарантовано при знищенні генератора
    }
}
```

### 3. Використання старого розширення `mysql`
Функції `mysql_connect()` офіційно оголошено застарілими в PHP 5.5.

```php
// app/Database/LegacyDb.php
// ❌ Викликає попередження E_DEPRECATED
$conn = mysql_connect('localhost', 'user', 'pass');

// ✅ Правильний підхід
$conn = new PDO('mysql:host=localhost;dbname=test', 'user', 'pass');
```

<a id="practical-recipes"></a>
## Практичні рецепти

### Очікування vs Реальність: блок `finally` та повернення значень

Що станеться, если повернення значення (statement `return`) вказано і в `try`, і в `finally`?

```php
// app/Demo/FinallyDemo.php
function testFinally(): string
{
    try {
        return "Повернення з try";
    } finally {
        return "Повернення з finally";
    }
}

// Очікування: функція поверне "Повернення з try"
// Реальність:
echo testFinally(); // Вивід: Повернення з finally
```

> [!WARNING]
> Якщо ви повертаєте значення всередині блоку `finally`, воно перезапише будь-які результати повернення (return) або викинуті виключення з блоків `try` та `catch`. Намагайтеся не поміщати `return` всередину `finally`.

<a id="backward-incompatible"></a>
## Зворотна несумісність

1. **Застарівання модифікатора `/e` у `preg_replace`**: Викликає попередження; використовуйте тільки `preg_replace_callback`.
2. **Застарівання `mysql`**: Функції `mysql_*` видають помилки рівня `E_DEPRECATED` при запуску.
3. **`empty()` на виразах**: Раніше `empty()` приймав тільки змінні. З версії 5.5 вираз `empty(foo())` коректно працює.
4. **Зміни в `pack()` та `unpack()`**: Можуть впливати на бінарну обробку даних залежно від архітектури (64-біт).

## 🧠 Питання для самоперевірки

1. **Правильно чи ні?** Функція-генератор повертає об'єкт класу `Generator`, який реалізує інтерфейс `Iterator`.
2. Якщо в блоці `try` було викинуто виключення, яке не перехопив жоден блок `catch`, чи виконається код у `finally`?
3. Що станеться, якщо передати масив параметрів вартості (cost) безпосередньо в `password_verify()`?
4. **Правильно чи ні?** Конструкція `ClassName::class` повертає рядок на етапі виконання, навіть якщо клас ще не завантажений або не існує.

<details>
<summary><b>Показати відповіді</b></summary>

1. **Правильно.** Генератори повертають вбудований об'єкт `Generator`, що дозволяє обходити їх стандартним циклом `foreach`.
2. **Так.** Блок `finally` гарантовано виконається перед тим, як виключення перерве роботу скрипта.
3. Нічого, оскільки `password_verify` приймає лише два параметри: хеш та пароль. Вона сама зчитує вартість та алгоритм із рядка хешу.
4. **Правильно.** Конструкція `::class` дозволяється на етапі компіляції коду. Вона не намагається завантажити клас або перевірити його існування, а просто замінює вираз на рядок.
</details>
