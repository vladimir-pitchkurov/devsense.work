# PHP 5.5: Головні нововведення

**PHP 5.5** впроваджує **генератори** (`yield`), блок **`finally`**, API **`password_hash` / `password_verify` / `password_needs_rehash`**, допоміжні **`array_column()`** та **`ClassName::class`**. У багатьох збірках з’являється **OPcache** — змінюється швидкодія та те, як підхоплюються оновлення файлів після деплою.

Хаб: [migration55](https://www.php.net/manual/en/migration55.php).

<a id="generators"></a>
## Генератори

```php
function lines($path)
{
    $fh = fopen($path, 'rb');
    try {
        while (($line = fgets($fh)) !== false) {
            yield rtrim($line, "\r\n");
        }
    } finally {
        fclose($fh);
    }
}
```

<a id="finally"></a>
## `finally`

Виконується завжди після try/catch, навіть якщо був `return` або виняток.

<a id="password-api"></a>
## Паролі

```php
$hash = password_hash($plain, PASSWORD_DEFAULT);
if (password_verify($plain, $hash) && password_needs_rehash($hash, PASSWORD_DEFAULT)) {
    $hash = password_hash($plain, PASSWORD_DEFAULT);
}
```

<a id="helpers"></a>
## Допоміжні функції

**`array_column()`** витягує стовпець з масиву рядків; **`::class`** дає рядок з ім’ям класу.

<a id="opcache"></a>
## OPcache

Після релізу може знадобитися скидання кешу опкодів або перезапуск воркерів.

<a id="practical-recipes"></a>
## Рецепти

### Ітератор замість масиву

На дуже великих файлах уникайте **`file()`**, який тягне все в пам’ять. Краще **генератор** з **`yield`**, що читає рядок за рядком і тримає споживання RAM передбачуваним.

### Міграція паролів

Під час логіну викликайте **`password_verify`** проти старих хешів (bcrypt, md5 у спадщині тощо). Якщо пароль вірний і **`password_needs_rehash`** повертає true, одразу перезапишіть хеш через **`password_hash(..., PASSWORD_DEFAULT)`**, щоб поступово підтягнути всі облікові записи до сучасних параметрів.

<a id="backward-incompatible"></a>
## Зворотна несумісність

Ключові зміни (повний перелік: [migration55 incompatible](https://www.php.net/manual/en/migration55.incompatible.php)):

- **`foreach`** з **внутрішніми вказівниками масиву** та **ітерацією за посиланням** — змінилися крайові випадки; регресійно перевірте код, який змінює масив під час обходу.
- **`list()`** всередині **`foreach`** — семантика вкладених списків стала суворішою; перевірте шаблони, що розпаковують вкладені масиви.
- **`GD`**, **`intl`**, **`openssl`** та інші розширення — сигнатури й режими помилок; якщо ви обгортаєте їх у власні шари, перегляньте нотатки до конкретних функцій.
- **`::class`** у контексті ключового слова **`class`** — переконайтеся, що в дуже старому коді не використовували `class` як ім’я без лапок там, де PHP 5.5 це трактує інакше.

<a id="deprecations"></a>
## Deprecated

- Розширення **`mysql`** — подальший шлях лише через **mysqli** або **PDO**.
- Модифікатор **`/e`** у **`preg_replace()``** — **небезпечний**; замініть на **`preg_replace_callback()`**.

Деталі: [migration55 deprecated](https://www.php.net/manual/en/migration55.deprecated.php).

<a id="other-changes"></a>
## Інше

- Розширено **`empty()`** для виразів — змінилася поведінка; прогоніть тести форм і перевірте шаблони на кшталт `empty($x->y)`.
- **Вартість хешування паролів** з часом оновлюється в PHP — плануйте періодичний **rehash під час успішного логіну**.

---

## Підсумок

PHP 5.5 — реліз **«пам’ять під контролем + нормальні паролі»** перед синтаксичним цукром у 5.6: опануйте **генератори** й **`password_*`**, завершіть відмову від **`mysql`**, після чого **варіадика та `**` у 5.6** виглядатимуть природним кроком.
