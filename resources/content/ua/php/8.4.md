# PHP 8.4: Головні нововведення та інтерактивний гайд

PHP 8.4 — це масштабний реліз «інструментів для дорослих». Він повністю змінює підходи до вираження інваріантів на межі властивостей (Property Hooks, асиметрична видимість), додає нативну підтримку лінивих об'єктів для фреймворків та ORM (Lazy Objects) та вирішує старі проблеми сумісності з HTML5 завдяки новому API у просторі імен `Dom`.

У цьому гайді ми розберемо ключові фічі на живих прикладах, обговоримо часті помилки розробників та проведемо тест для самоперевірки наприкінці!

<a id="property-hooks"></a>
## Property Hooks (логіка get/set у властивості)

Роками PHP-розробникам доводилося писати купу шаблонного коду (геттери та сеттери) лише для того, щоб валідувати чи форматувати значення перед їх збереженням. У PHP 8.4 представлено **Property Hooks** («хуки властивостей») прямо в оголошенні властивості.

Існує два типи хуків:
- `set`: спрацьовує при записі значення у властивість.
- `get`: спрацьовує при читанні значення властивості.

Давайте подивимося на живий приклад:

```php
// app/DTO/Person.php
final class Person
{
    // Хук може записувати у приховану властивість через $this->propName
    public string $firstName {
        set => ucfirst(strtolower($value));
    }

    public string $lastName {
        set {
            if (strlen($value) < 2) {
                throw new InvalidArgumentException('Прізвище надто коротке!');
            }
            $this->lastName = $value;
        }
    }

    // Обчислювальна (віртуальна) властивість без фізичного збереження значення!
    public string $fullName {
        get => $this->firstName . ' ' . $this->lastName;
    }
}
```

> [!NOTE]
> **А ви знали?**
> Властивості, які оголошують тільки хук `get`, автоматично вважаються віртуальними. Вони не займають пам'ять всередині об'єкта.

### ⚠️ Часті помилки розробників

**1. Спроба передати властивість із хуками по посиланню**
Оскільки звернення до властивості з хуками під капотом викликає функції, передача по посиланню неможлива:
```php
// app/Services/ContactService.php
function cleanString(string &$str) {
    $str = trim($str);
}

$person = new Person();
cleanString($person->firstName); // ❌ Fatal Error: Cannot pass property Person::$firstName by reference
```

**2. Нескінченна рекурсія в хуках `set`**
Якщо ви спробуєте призначити значення властивості всередині її власного `set`-хука через `$this->propertyName = $value` (без використання скороченого синтаксису `=>`), це може викликати нескінченну рекурсію. На щастя, стрілочний синтаксис `=>` автоматично бере на себе правильне збереження в backing storage.

<a id="asymmetric-visibility"></a>
## Асиметрична видимість властивостей (`public private(set)`)

Тепер ви можете гнучко налаштовувати область видимості для читання та запису властивостей окремо. Це чудове рішення для створення імутабельних DTO та коренів агрегатів у рамках Domain-Driven Design (DDD).

```php
// app/Models/User.php
final class User
{
    // Властивість доступна для читання звідси, але змінити її можна лише всередині класу
    public private(set) string $email;

    public protected(set) int $loginAttempts = 0;

    public function __construct(string $email)
    {
        $this->email = $email;
    }

    public function incrementAttempts(): void
    {
        $this->loginAttempts++;
    }
}
```

> [!NOTE]
> **А ви знали?**
> Асиметрична видимість вимагає, щоб видимість запису (`set`) була **суворішою**, ніж область читання. Спроба написати `private public(set)` призведе до синтаксичної помилки.

<a id="lazy-objects"></a>
## Lazy Objects (Ліниві об'єкти через Reflection)

У PHP 8.4 додано нативну підтримку **Lazy Objects** (лінивих об'єктів). Це нововведення створено насамперед для авторів ORM (таких як Doctrine або Laravel Eloquent) та DI-контейнерів, щоб відкладати важкі запити до бази даних до моменту реального звернення до об'єкта.

Раніше бібліотекам доводилося генерувати складні проксі-класи на льоту. Тепер рефлексія бере це на себе:

```php
// app/Services/Container.php
$initializer = static function (LargeService $service) {
    $service->loadHeavyConfiguration();
};

$r = new ReflectionClass(LargeService::class);
// Створюємо "ліниву копію" (lazy ghost) об'єкта LargeService
$lazyService = $r->newLazyGhost($initializer);
```

Код ініціалізації спрацює тільки тоді, коли ми вперше спробуємо прочитати або записати будь-яку властивість об'єкта `$lazyService`.

<a id="deprecated-attribute"></a>
## Депрекації у userland за допомогою `#[Deprecated]`

Раніше для попередження користувачів про те, що метод або клас застарів, доводилося викликати `trigger_error(..., E_USER_DEPRECATED)`. У PHP 8.4 для цього з'явився вбудований атрибут:

```php
// app/Helpers/LegacyMath.php
class LegacyMath
{
    #[\Deprecated(message: "Використовуйте BCMath або стандартне ділення", since: "1.4.0")]
    public static function divide(int $a, int $b): float
    {
        return $a / $b;
    }
}
```

Як тільки сторонній код викличе цей метод, PHP автоматично викине депрекацію з вашим повідомленням.

<a id="dom-modern"></a>
## Стандарти WHATWG у просторі імен `Dom\*`

Класичний клас `DOMDocument` довго страждав від поганої сумісності з HTML5. PHP 8.4 представляє сучасний API в просторі імен `Dom`.

```php
// app/Services/HtmlParser.php
// Парсимо розмітку HTML5 без костилів та попереджень
$dom = Dom\HTMLDocument::createFromString('<main><article>Modern HTML5!</article></main>');
$node = $dom->querySelector('article');

echo $node->textContent; // Вивід: Modern HTML5!
```

Старий API залишився для сумісності, але нові проекти варто писати з використанням `Dom\HTMLDocument` та `Dom\XMLDocument`.

<a id="request-parse-body"></a>
## Підтримка multipart-даних для PUT/PATCH: `request_parse_body()`

Якщо ви писали REST API з підтримкою завантаження файлів через `PUT` або `PATCH`, то пам'ятаєте біль: суперглобальні масиви `$_FILES` та `$_POST` наповнювалися автоматично тільки при `POST` запитах. Розробникам доводилося парсити потік `php://input` вручну.

PHP 8.4 вирішує це за допомогою `request_parse_body()`:

```php
// public/index.php
if ($_SERVER['REQUEST_METHOD'] === 'PUT') {
    [$postData, $files] = request_parse_body();
    
    // $postData містить поля форми
    // $files містить завантажені файли у тому ж форматі, що й $_FILES
}
```

<a id="new-functions"></a>
## Зручні хелпери для масивів та юнікоду

PHP 8.4 додає кілька вкрай корисних функцій для повсякденної розробки:

### 1. `array_find()`, `array_find_key()`, `array_any()`, `array_all()`

```php
// app/Services/Validator.php
$users = [
    ['name' => 'Олексій', 'role' => 'user'],
    ['name' => 'Дмитро', 'role' => 'admin'],
];

// Знаходимо першого адміністратора
$admin = array_find($users, fn($u) => $u['role'] === 'admin');

// Перевіряємо, чи є хоч один звичайний користувач
$hasUsers = array_any($users, fn($u) => $u['role'] === 'user');
```

### 2. Безпечне очищення пробілів у UTF-8 (`mb_trim`)
Звичайний `trim()` не вміє працювати з багатобайтними пробілами UTF-8. PHP 8.4 додає функції `mb_trim()`, `mb_ltrim()` та `mb_rtrim()`.

<a id="backward-incompatible"></a>
## Зворотно несумісні зміни (BC Breaks)

При переході на PHP 8.4 зверніть увагу на такі моменти:

1. **Застаріли неявно обнуляємі параметри**
   ```php
   // ❌ Застаріло в PHP 8.4
   function save(string $name = null) {}

   // ✅ Правильний варіант
   function save(?string $name = null) {}
   ```
2. **Зміна поведінки `exit()` та `die()`**
   Вони стали повноцінними функціями. Тепер вони перевіряють типи параметрів. Передача некоректного об'єкта або масиву замість рядка/числа викличе `TypeError`.
3. **Ресурси переведені в об'єкти**
   Підключення в DBA, ODBC та SOAP тепер повертають об'єкти, а не ресурси. Перевірки виду `is_resource()` на них почнуть повертати `false`.

<a id="self-check"></a>
## 🧠 Питання для самоперевірки

Давайте закріпимо прочитане! Дайте відповіді на такі питання:
1. **Правда чи брехня?** Чи можна оголосити хук `set` для віртуальної властивості?
2. Чому виклик `cleanString($person->firstName)` призведе до помилки Fatal Error, якщо у `$firstName` налаштовані хуки?
3. Що станеться, якщо оголосити властивість із видимістю `private public(set)`?
4. Яку функцію варто використовувати в PHP 8.4, щоб переконатися, що *хоча б один* елемент масиву задовольняє задану умову?

<details>
<summary><b>Показати відповіді</b></summary>

1. **Брехня.** Віртуальна властивість не має фізичного сховища (backing storage), тому для неї не можна визначити хук `set` (якщо тільки він не записує значення в інші реальні властивості класу).
2. Властивості з хуками є обчислювальними значеннями; у них немає фіксованого посилання в оперативній пам'яті, тому їх неможливо передати по посиланню.
3. PHP викине синтаксичну помилку (Syntax Error). Доступ на запис (`set`) має бути таким самим або суворішим, ніж доступ на читання (`get`).
4. Для цього призначена функція `array_any()`.
</details>
