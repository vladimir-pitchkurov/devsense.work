# PHP 8.2: Головні нововведення

PHP 8.2 впевнено розвиває екосистему в бік строгої типізації та безпеки структури даних. З введенням readonly-класів та типів у формі DNF (Disjunctive Normal Form), розробники отримали повний контроль над імутабельністю об'єктів та складними деклараціями типів. Захист даних тепер вбудований прямо на рівні синтаксису: атрибут `#[SensitiveParameter]` гарантує, що облікові дані та паролі не опиняться випадково у файлах логів при генерації stack trace. При цьому версія 8.2 вносить критично важливі зміни — такі як застарівання динамічних властивостей, що вимагають уваги при перенесенні старого коду. Нижче описані ключові аспекти міграції.

<a id="sensitive-parameter"></a>
## #[SensitiveParameter] та трасування

Атрибут `#[\SensitiveParameter]` позначає параметри, які потрібно приховувати в stack trace та налагоджувальному виведенні — менше ризику витоку паролів та токенів у логи.

> [!NOTE]
> **А ви знали?**
> Атрибут `#[SensitiveParameter]` нативно підтримується стандартним механізмом виведення винятків у PHP. Коли PHP генерує stack trace, він автоматично замінює значення цього параметра об'єктом `SensitiveParameterValue`, повністю приховуючи вихідний рядок з логів!

```php
// app/Services/DatabaseService.php
function connect(#[\SensitiveParameter] string $password): void
{
    throw new RuntimeException('fail');
}
```

Поєднуйте з політикою логування та не виводьте сирі винятки користувачам у production.

### Практичний рецепт: позначайте секрети на кордоні

Ставте `#[\SensitiveParameter]` на параметри, які можуть опинитися у винятках (обгортки клієнтів, auth‑хелпери). Stack trace залишається корисним, але секрети не «просочуються» в логи.

```php
// app/Clients/ApiClient.php
final class ApiClient
{
    public function __construct(
        private readonly string $baseUrl,
        #[\SensitiveParameter] private readonly string $token,
    ) {}
}
```

<a id="readonly-classes"></a>
## Readonly-класи

Клас можна оголосити `readonly`: всі його властивості екземпляра стають readonly і задаються при конструюванні.

> [!NOTE]
> **А ви знали?**
> Readonly-класи автоматично захищають вас від створення динамічних властивостей! Вам навіть не потрібно використовувати атрибут `#[AllowDynamicProperties]`, оскільки будь-яка спроба додати динамічну властивість до readonly-класу відразу ж викличе Fatal Error.

```php
// app/DTO/Point.php
readonly class Point
{
    public function __construct(
        public int $x,
        public int $y,
    ) {}
}
```

Зручно для імутабельних value object та DTO, де об'єкт повністю не повинен змінюватися після створення.

<a id="standalone-types-dnf"></a>
## Окремі типи (`null`, `false`, `true`) та DNF

У PHP 8.2 **`null`**, **`false`**, **`true`** допустимі як самостійні типи в оголошеннях.

**DNF** дозволяє комбінувати union та intersection в нормалізованій формі, наприклад `(A&B)|null`.

```php
// app/Services/ExportService.php
function accepts((Countable&Traversable)|null $c): void {}
```

<a id="traits-constants"></a>
## Константи в трейтах та enum в константних виразах

- У **трейтах** можна оголошувати константи — зручно для спільних значень без зайвого базового класу.
- У **константних виразах** дозволено звертатися до властивостей enum там, де це передбачено синтаксисом — багатша конфігурація на етапі компіляції.

<a id="error-log-mode"></a>
## INI: `error_log_mode`

Директива **`error_log_mode`** задає права файлу error log при створенні PHP — корисно для жорстко налаштованих серверів.

<a id="random-extension"></a>
## Розширення Random

Розширення **Random** систематизує генератори випадкових чисел і дає більш передбачуваний API для тестів та криптографічно осмислених сценаріїв.

### Практичний рецепт: `Randomizer` для токенів та вибірки

```php
// app/Services/TokenGenerator.php
$engine = new Random\Engine\Mt19937(random_int());
$randomizer = new Random\Randomizer($engine);
$token = $randomizer->getBytesFromString('0123456789abcdef', 32);
```

У тестах задавайте **seeded** engine для відтворюваності; для секретів вибирайте криптографічно відповідний `Random\Engine` за документацією.

<a id="extension-updates"></a>
## Помітні зміни розширень (cURL, PCRE)

- **cURL**: `CURLINFO_EFFECTIVE_METHOD`, функція `curl_upkeep()`, нові константи при підтримуваній libcurl.
- **PCRE**: модифікатор **`n` (NO_AUTO_CAPTURE)** — звичайні `()` не захоплюють, тільки іменовані групи.

<a id="backward-incompatible"></a>
## Зворотно несумісні зміни (нотатки для міграції)

### Дата та час

- У `DateTime::createFromImmutable()` / `DateTimeImmutable::createFromMutable()` — tentative return type **`static`**.
- В відносних форматах більше не допускається кілька знаків у `number` (наприклад `+-2`).

### Стандартна бібліотека (важливо)

- **`strtolower`/`strtoupper`/stri\*/`str_ireplace`/lcfirst/ucfirst/ucwords`**: **не locale-sensitive** — тільки ASCII, як `"C"`. Локалізований регістр — через **mbstring**.
- **`str_split('')`** тепер повертає `[]` (раніше був масив з однією порожньою строкою).
- **`glob()` / `GlobIterator`**: при `open_basedir` змінилася поведінка `[]` vs `false` та попередження — перевірте обхід каталогів.
- **`FilesystemIterator`**: `SKIP_DOTS` більше не включений за замовчуванням через прапорці — задайте явно за потреби.
- **`ksort`/`krsort`** з `SORT_REGULAR` — узгоджені правила числових рядків PHP 8.
- **`var_export()`**: імена класів експортуються з провідним зворотним слешем (повністю кваліфіковані).

### ODBC / PDO_ODBC

Екранування username/password при дописуванні до connection string — перевірте інтеграції.

### SPL

У частини методів `SplFileObject` посилені сигнатури; у `hasChildren`/`getChildren` — уточнені tentative return types.

**Зауваження:** у деяких оточеннях `date_default_timezone_get()` при відсутності явної зони може повертати **UTC** — перевірте припущення про таймзону.

<a id="deprecations"></a>
## Deprecated (виправити до появи помилок)

### Динамічні властивості

Створення динамічних властивостей у класів без оголошення — **deprecated**, якщо клас не позначений **`#[\AllowDynamicProperties]`** (або не `stdClass` тощо). Краще оголосити властивості, використовувати `WeakMap` або магічні методи.

### «Відносні» callables

Застаріли форми на кшталт `"self::method"`, частина масивних callables — приведіть до стабільних `Class::method` / `[Class::class, 'method']`.

### Інтерполяція рядків

Стиль `"${var}"` — deprecated; використовуйте `"{$var}"` або конкатенацію.

### Інше

- **`utf8_encode` / `utf8_decode`** — deprecated.

<a id="extensions-notes"></a>
## Розширення та runtime

- **OpenSSL**: AEAD для chacha20-poly1305 за наявності підтримки.
- **OCI8**: налаштування prefetch LOB для Oracle 12.2+.
- **DBA (LMDB)**: прапорці підкаталогу при створенні БД.

## Частые ошибки

Ось кілька поширених пасток при використанні можливостей PHP 8.2:

### 1. Створення динамічних властивостей
У PHP 8.2 спроба присвоїти значення необ'явленій властивості класу викликає попередження (deprecation warning), а в PHP 9.0 це призведе до фатальної помилки.

```php
// app/Services/UserService.php
// ПОГАНО: Викличе попередження устарівання у PHP 8.2
class UserService {
    public string $name;
}

$service = new UserService();
$service->email = 'user@example.com'; // Deprecation Warning: Creation of dynamic property is deprecated
```

### 2. Використання застарілого синтаксису інтерполяції рядків
Старий синтаксис `${var}` оголошений застарілим у PHP 8.2.

```php
// app/Services/NotificationService.php
// ПОГАНО: Викличе попередження устарівання
$name = 'Alice';
echo "Hello ${name}"; // Deprecation Warning

// ДОБРЕ: Використовуйте стандартний синтаксис фігурних дужок
echo "Hello {$name}";
```

### 3. Спроба успадкувати readonly-клас від звичайного класу
Клас зі специфікатором `readonly` може успадковуватися тільки від іншого `readonly`-класу.

```php
// app/DTO/Point3D.php
class Point2D {}

// ПОГАНО: Fatal Error: Readonly class Point3D cannot extend non-readonly class Point2D
readonly class Point3D extends Point2D {}
```

## Квіз для самоперевірки

Перевірте свої знання можливостей PHP 8.2. Виберіть відповідь та звіртеся під спойлером.

### Запитання 1: Що відбувається при оголошенні класу як `readonly` в PHP 8.2?
- A) Усі його властивості автоматично стають `readonly`, але вказувати їхній тип не обов'язково.
- B) Заборонено додавати динамічні властивості, і всі властивості обов'язково мають бути типізованими.
- C) Дозволено успадковуватися від будь-якого звичайного класу, але звичайні класи не можуть успадковуватися від нього.

<details>
<summary>Показати відповідь</summary>

**Правильна відповідь: B**
Оголошення класу як `readonly` означає, що всі його властивості неявно стають властивостями тільки для читання і мають бути типізованими. Крім того, у readonly-класах заборонено використання динамічних властивостей, і успадковуватися вони можуть тільки від інших readonly-класів.
</details>

### Запитання 2: Який синтаксис інтерполяції викликає попередження устарівання в PHP 8.2?
- A) `"Hello {$name}"`
- B) `"Hello ${name}"`
- C) `"Hello " . $name`

<details>
<summary>Показати відповідь</summary>

**Правильна відповідь: B**
Синтаксис інтерполяції виду `${var}` оголошений застарілим у PHP 8.2 і викликає попередження. Замість нього слід використовувати синтаксис `{$var}`.
</details>
