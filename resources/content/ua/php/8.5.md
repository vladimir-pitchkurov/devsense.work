# PHP 8.5: Головні нововведення та інтерактивний гайд

PHP 8.5 продовжує розвивати виразність синтаксису мови та зміцнювати ядро платформи. Ключові оновлення релізу: довгоочікуваний **Pipe Operator (`|>`)**, атрибут **`#[\NoDiscard]`** для контролю повернених значень та інтеграція вбудованого розширення **URI** для відповідності стандартам WHATWG.

Давайте розберемо ці фічі на живих прикладах, обговоримо підводні камені та проведемо тест для самоперевірки наприкінці!

<a id="pipe-operator"></a>
## Оператор конвеєра (`|>`)

Набридли вкладені виклики на кшталт `strtolower(trim($input))` або постійне створення тимчасових змінних? PHP 8.5 додає оператор пайпу **`|>`**, який дозволяє передавати результат лівого виразу в правий виклик по ланцюжку.

```php
// app/Services/Slugger.php
$slug = $title
    |> trim(...)
    |> strtolower(...)
    |> fn($s) => preg_replace('/\s+/', '-', $s);

echo $slug; // Вивід: hello-world
```

> [!NOTE]
> **А ви знали?**
> Оператор `|>` передає ліве значення як **перший аргумент** у правий callable. Якщо вам потрібно передати його другим або третім параметром, оберніть правий виклик у кастомне замикання або стрілочну функцію.

### ⚠️ Часті помилки розробників

**1. Відсутність круглих дужок навколо стрілочних функцій**
Якщо ви використовуєте стрілочну функцію всередині пайпу, її обов'язково потрібно обернути в круглі дужки, щоб уникнути неоднозначності парсингу:
```php
// app/Services/Formatter.php
// ❌ Синтаксична помилка!
$result = $value |> fn($x) => $x * 2 |> fn($y) => $y + 10;

// ✅ Правильний варіант
$result = ($value |> fn($x) => $x * 2) |> fn($y) => $y + 10;
```

<a id="closures-in-constants"></a>
## Замикання в константних виразах

PHP 8.5 дозволяє оголошувати **замикання** та **first-class callables** у місцях, які раніше приймали тільки статичні значення: константи класів, значення за замовчуванням для властивостей та аргументи атрибутів.

```php
// app/Attributes/Route.php
class Route
{
    public function __construct(
        public string $path,
        public Closure $callback = (fn() => 'Default Route')
    ) {}
}
```

Це великий плюс для роутерів та бібліотек валідації, яким потрібно описувати легковажну логіку безпосередньо в метаданих.

<a id="nodiscard"></a>
## `#[\NoDiscard]` та приведення до `(void)`

При виклику методів валідації або запису результатів розробники часто забувають обробити повернений булевий прапорець чи об'єкт відповіді. У PHP 8.5 додано атрибут `#[\NoDiscard]`, який повідомляє про те, що результат виклику ігнорувати не можна.

```php
// app/Services/Transaction.php
class Transaction
{
    #[\NoDiscard]
    public function commit(): bool
    {
        // ...
        return true;
    }
}

$tx = new Transaction();
$tx->commit(); // ❌ Попередження: Результат commit() не повинен бути відкинутий!
```

Якщо ви хочете явно відкинути результат методу з таким атрибутом, використовуйте нове приведення до типу `(void)`:

```php
// app/Services/Handler.php
(void) $tx->commit(); // ✅ Помилку приглушено, ми свідомо проігнорували результат!
```

<a id="uri-extension"></a>
## Вбудоване розширення URI (RFC 3986)

Парсити URL-адреси вручную завжди було ризиковано з точки зору безпеки. PHP 8.5 поставляє вбудоване розширення `uri`, яке повністю відповідає RFC 3986 та специфікації WHATWG.

```php
// app/Services/UrlParser.php
$uri = Uri\parse('https://user:pass@example.com:8080/path?query=1#hash');

echo $uri->host;     // example.com
echo $uri->port;     // 8080
echo $uri->userInfo; // user:pass
```

<a id="new-functions"></a>
## Нові функції: `array_first()` та `array_last()`

Замість скидання вказівників масиву за допомогою `reset()` та `end()` тепер можна використовувати вбудовані та оптимізовані хелпери:

```php
// app/Services/Collection.php
$list = ['яблуко', 'банан', 'вишня'];

$first = array_first($list); // 'яблуко'
$last  = array_last($list);  // 'вишня'
```

Крім того, прапорець `FILTER_THROW_ON_FAILURE` тепер дозволяє фільтрам генерувати виняток `ValueError` замість повернення `false`:

```php
// app/Http/Request.php
$id = filter_input(INPUT_GET, 'id', FILTER_VALIDATE_INT, FILTER_THROW_ON_FAILURE);
```

<a id="backward-incompatible"></a>
## Зворотно несумісні зміни (BC Breaks)

Перед оновленням продакшн-серверів на PHP 8.5 переконайтеся в сумісності вашого коду:

1. **Opcache вбудовано в бінарний файл**
   Opcache більше не збирається як окремий модуль. Спроба прописати `zend_extension=opcache.so` в `php.ini` викличе попередження.
2. **Зміна числових констант PDO**
   Backing-числа деяких fetch-режимів PDO (наприклад, `PDO::FETCH_GROUP`) змінилися в 8.5. Якщо ви зберігали ці числа в БД чи конфігах — перевірте їх.
3. **Обмеження `class_alias()`**
   Заборонено використовувати імена `"array"` та `"callable"` як аліаси класів.

<a id="self-check"></a>
## 🧠 Питання для самоперевірки

Перевіримо наші знання по PHP 8.5:
1. **Правда чи брехня?** Права частина оператора пайпу (`|>`) за замовчуванням може приймати необмежену кількість параметрів.
2. Як явно придушити попередження при виклику методу, позначеного атрибутом `#[\NoDiscard]`?
3. Яку директиву `zend_extension` потрібно вказати в `php.ini`, щоб завантажити Opcache в PHP 8.5?
4. **Правда чи брехня?** Хелпери `array_first()` та `array_last()` коректно працюють з асоціативними масивами.

<details>
<summary><b>Показати відповіді</b></summary>

1. **Брехня.** Права частина повинна приймати строго один аргумент. Якщо функція вимагає більше параметрів, оберніть її в замикання або стрілочну функцію.
2. Перед викликом потрібно додати приведення до `(void)` (наприклад, `(void) $obj->method();`).
3. Ніяку! Opcache вже вбудований у ядро. Його достатньо увімкнути через `opcache.enable=1`.
4. **Правда.** Вони повертають перший і останній елемент будь-якого переданого масиву, незалежно від того, є ключі числовими чи асоціативними.
</details>
