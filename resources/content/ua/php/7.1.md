# PHP 7.1: Головні нововведення

Що, якби ви могли перехоплювати три різних типи винятків в одному блоці catch, не дублюючи шаблонний код? Або оголошувати константи класу, які гарантовано захищені від зовнішнього доступу? PHP 7.1 вводить ці можливості, виводячи безпеку типів та виразність коду сучасних додатків на новий рівень. Ця версія розширює систему типів та синтаксис за рахунок nullable-типів, функцій void, симетричної деструктуризації масивів з підтримкою ключів, управління областю видимості констант та множинного перехоплення винятків (multi-catch).

<a id="nullable-types"></a>
## Nullable-типи (?Type)

Знак питання перед ім'ям типу вказує, що параметр або повертане значення може приймати тип **`null`**:

```php
// src/UserService.php
function findUser(int $id): ?User 
{
    return $id === 0 ? null : new User($id);
}
```

> [!NOTE]
> Чи знали ви? У PHP 7.0 суворий тип `User` забороняв повертати `null` (викликався TypeError). Додавання nullable-типів вирішило цю проблему, зберігши сувору перевірку типів у рантаймі.

<a id="void-functions"></a>
## Повертаний тип `void`

Якщо функція нічого не повертає, вказується тип **`void`**. Дозволений тільки порожній оператор **`return;`** або повна відсутність return. Спроба повернути будь-яке значення (навіть **`return null;`**) викличе помилку компіляції.

```php
// src/Notifier.php
function notify(string $message): void 
{
    echo $message;
    return; // Порожній return валідний, повернення значення викличе помилку
}
```

> [!NOTE]
> Чи знали ви? Тип `void` застосовний виключно для значень повернення. Ви не можете типом `void` обмежити вхідний параметр функції (код на кшталт `function test(void $x)` не скомпілюється).

<a id="symmetric-destructuring"></a>
## Симетрична деструктуризація масивів

Тепер можна розпаковувати масиви з використанням короткого синтаксису **`[]`** замість традиційного **`list()`**:

```php
// src/Config.php
[$host, $port] = ['127.0.0.1', 3306];
```

Цей синтаксис також відмінно працює всередині циклів: `foreach ($data as [$id, $name])`.

<a id="constant-visibility"></a>
## Область видимості констант класів

Для констант класів додано модифікатори доступу **`public`**, **`protected`** та **`private`**:

```php
// src/PaymentGateway.php
class PaymentGateway {
    private const API_KEY = 'secret-key';
    public const DEFAULT_TIMEOUT = 30;
}
```

> [!NOTE]
> Чи знали ви? Якщо модифікатор доступу опущений, константа за замовчуванням вважається публічною (`public`), що гарантує зворотну сумісність зі старими версіями PHP.

<a id="iterable-type"></a>
## Псевдотип `iterable`

Приймає будь-які типи даних, що задовольняють умові `is_array()` або є екземпляром **`\Traversable`**:

```php
// src/Collection.php
function processItems(iterable $items): void 
{
    foreach ($items as $item) {
        // Підтримує і масиви, і генератори/ітератори
    }
}
```

<a id="multi-catch"></a>
## Перехоплення кількох типів винятків (multi-catch)

Ви можете об'єднувати обробку різних винятків в один блок catch за допомогою оператора **`|`**:

```php
// src/ApiConnector.php
try {
    // Виконання запиту до API
} catch (ConnectionException | ResponseException $e) {
    // Спільна обробка цих двох винятків
}
```

<a id="destructuring-keys"></a>
## Використання ключів при деструктуризації

При розпакуванні масивів тепер можна явно вказувати ключі:

```php
// src/UserProfile.php
['id' => $userId, 'name' => $username] = $user;
```

Це працює як для конструкції `list()`, так і для нового короткого синтаксису `[]`.

<a id="negative-offsets"></a>
## Підтримка негативних зміщень у рядках

З'явилася можливість звертатися до символів рядка з кінця, використовуючи негативні числа:

```php
// src/StrHelper.php
$lastChar = 'abcdef'[-1]; // 'f'
$sub = substr('abcdef', -3, -1); // 'de'
```

Негативні зміщення підтримуються також при записі: `$str[-2] = 'z';`.

<a id="extensions-stdlib"></a>
## Розширення та стандартна бібліотека

* **cURL HTTP/2**: Додано підтримку HTTP/2 push та нових функцій мульти-сервера.
* **OpenSSL AEAD**: Додано підтримку шифрування в режимах AEAD (GCM та CCM).
* **`session_gc()`**: Дозволяє вручну запускати стандартний збирач сміття сесій.

<a id="common-mistakes"></a>
## Часті помилки

Нижче наведено типові помилки розробників при переході на PHP 7.1:

### 1. Повернення `null` з `void`-функції
Спроба повернути `null` (явним чином через `return null;`) у функціях, оголошених як `void`, викличе Fatal Error.
```php
// src/BadVoid.php
// Погано: Явне повернення null у void-функції заборонено
function doNothing(): void {
    return null; // Fatal Error: A void function must not return a value
}
```
```php
// src/GoodVoid.php
// Добре: Використовуйте порожній return або опустіть його зовсім
function doNothingGood(): void {
    return; 
}
```

### 2. Очікування, що `iterable` приймає тільки масиви
Якщо передати в `iterable`-параметр об'єкт `Traversable`, виклики `is_array()` повернуть false. Розробники іноді забувають про це і роблять помилку, намагаючись застосувати до параметра вбудовані функції для масивів.
```php
// src/BadIterable.php
// Погано: Збій, якщо $items виявиться генератором (він не реалізує Countable)
function dumpItems(iterable $items) {
    echo count($items); 
}
```
```php
// src/GoodIterable.php
// Добре: Обходьте елементи через foreach (він підтримує і масиви, і ітератори)
function dumpItemsGood(iterable $items) {
    foreach ($items as $item) {
        echo $item;
    }
}
```

<a id="limitations"></a>
## Обмеження

* **Nullable-типи**: Ви не можете об'єднувати їх з Union-типами. Код виду `?int|string` викличе синтаксичну помилку (Union-типи з'являться тільки в PHP 8.0).
* **Область видимості констант**: PHP 7.1 контролює рівень доступу до констант, але не підтримує вказування їх типів. Опис виду `public const int TIMEOUT = 10;` скомпілюється з помилкою (тайп-хінтинг констант з'явиться тільки в PHP 8.3).

<a id="backward-incompatible"></a>
## Зворотно несумісні зміни

### Ядро та типи

* **Винятки при нестачі аргументів**: передача недостатньої кількості аргументів у функції користувача тепер призводить до викидання винятку **`ArgumentCountError`** замість простого попередження Warning.
* **Звернення за невалідними індексами рядків**: порожній індекс `[]` для рядків більше не ігнорується мовчки.
* **`iterable` тепер є зарезервованим словом**: ви не можете називати цим словом класи, інтерфейси або трейти.

## Інтерактивний квіз

Перевірте свої знання про PHP 7.1:

1. **Яке твердження є правильним для функції з повертаним типом `void`?**
   * А) Вона повинна явно повертати `null`.
   * Б) Вона взагалі не може містити операторів `return`.
   * В) Вона може використовувати порожній `return;` або не мати його зовсім.
   * Г) За замовчуванням вона повертає `false`.

   <details>
   <summary>Показати відповідь</summary>
   
   **Правильна відповідь: В**  
   Функція з типом повернення `void` може використовувати порожній оператор `return;` для дострокового виходу з коду, але повертати будь-яке значення (навіть `null`) їй заборонено.
   </details>

2. **Який виняток викидається в PHP 7.1 при передачі недостатньої кількості аргументів у функцію?**
   * А) TypeError
   * Б) ArgumentCountError
   * В) WarningException
   * Г) Error

   <details>
   <summary>Показати відповідь</summary>
   
   **Правильна відповідь: Б**  
   PHP 7.1 підвищив рівень попередження про брак параметрів до винятку `ArgumentCountError`.
   </details>

3. **Як оголосити константу класу, доступну тільки всередині самого класу?**
   * А) `private const MY_CONST = 1;`
   * Б) `const private MY_CONST = 1;`
   * В) `protected const MY_CONST = 1;`
   * Г) `private MY_CONST = 1;`

   <details>
   <summary>Показати відповідь</summary>
   
   **Правильна відповідь: А**  
   PHP 7.1 вводить стандартні модифікатори видимості для констант: `public const`, `protected const` або `private const`.
   </details>

<a id="closing-thoughts"></a>
## Підсумок

PHP 7.1 — ключовий реліз для впровадження **суворої дисципліни типів** та чистоти структур даних. Перепишіть виклики `list()` на `[]`, додайте `?` до необов'язкових типів параметрів та об'єднайте блоки catch для підготовки вашого додатка до переходу на PHP 7.2+.
