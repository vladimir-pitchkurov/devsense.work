# PHP 5.6: Міст до сучасного PHP

Простий математичний вираз вигляду `2 ** 3 ** 2` або сувора перевірка переданого користувачем JSON можуть повністю змінити логіку виконання вашої програми при переході на PHP 5.6. Як фінальний реліз гілки 5.x, PHP 5.6 служить мостом між старим рушієм PHP та сучасною екосистемою PHP 7.

До PHP 5.6 написання функцій з динамічною кількістю аргументів вимагало використання незграбних конструкцій на кшталт `func_get_args()` та їх передачі через повільний виклик `call_user_func_array()`. Імпорт функцій з просторів назв вимагав створення зайвих обгорток, а константи не могли містити навіть базових математичних формул.

> [!IMPORTANT]
> PHP 5.6 представив варіадичні сигнатури, розпаковку аргументів та суворі налаштування шифрування за замовчуванням, щоб підготувати проекти до переходу на PHP 7.

<a id="variadic"></a>
## Варіадичні параметри (`...$params`)

Функції тепер можуть приймати довільну кількість аргументів без звернення до `func_get_args()`.

```php
// app/Helpers/Math.php
function sum(int $first, int ...$others): int
{
    $accumulator = $first;
    foreach ($others as $number) {
        $accumulator += $number;
    }
    return $accumulator;
}

echo sum(1, 2, 3, 4); // 10
```

* **Чому це важливо**: Сигнатури методів стають самодокументованими, а середовища розробки (IDE) можуть коректно перевіряти типи та автодоповнювати аргументи.

<a id="unpacking"></a>
## Розпаковка аргументів

Масиви та об'єкти `Traversable` можуть бути «розпаковані» у список параметрів безпосередньо при виклику функції.

```php
// app/Services/Logger.php
$args = ["Користувач %s увійшов з IP %s", "admin", "127.0.0.1"];
echo sprintf(...$args);
```

* **Чому це важливо**: Замінює повільні та складні виклики `call_user_func_array()` чистим нативним синтаксисом, що виконується на рівні компілятора.

<a id="pow-op"></a>
## Оператор піднесення до ступеня (`**`)

У PHP 5.6 додано оператор `**` для піднесення до ступеня, що пропонує лаконічнішу альтернативу функції `pow()`.

```php
// app/Services/Physics.php
$square = 4 ** 2; // 16
$cube = 2 ** 3;   // 8
```

> [!WARNING]
> Оператор `**` є правоасоціативним. Це означає, що `2 ** 3 ** 2` обчислюється як `2 ** (3 ** 2) = 2 ** 9 = 512`, а не як `(2 ** 3) ** 2 = 8 ** 2 = 64`.

<a id="use-imports"></a>
## `use function` та `use const`

Конструкція `use` розширена і тепер дозволяє імпортувати конкретні функції та константи з просторів назв, а не тільки класи.

```php
// app/Services/StringManager.php
namespace App\Services;

use function SomeLib\stringHelper;
use const SomeLib\API_VERSION;

class StringManager
{
    public function getVersion(): string
    {
        return stringHelper(API_VERSION);
    }
}
```

* **Чому це важливо**: Це дозволяє уникнути захаращення глобального простору назв та наочно декларувати залежності від зовнішніх бібліотек на початку файлу.

<a id="const-expr"></a>
## Константні вирази

В оголошеннях констант класів, значень властивостей за замовчуванням та параметрів тепер можна використовувати скалярні вирази (математичні формули, конкатенацію).

```php
// app/Config/Limits.php
class Limits
{
    public const ONE_MB = 1024 * 1024;
    public const MAX_UPLOAD = self::ONE_MB * 50; // 50MB
    public static $debugMode = (self::MAX_UPLOAD > 10000);
}
```

<a id="hash-equals"></a>
## Безпечне порівняння рядків (`hash_equals`)

Порівнює два рядки за однаковий час, незалежно від того, наскільки збігаються їхні символи.

```php
// app/Services/Security.php
$signature = $_GET['signature'];
$expected = hash_hmac('sha256', $data, $key);

if (hash_equals($expected, $signature)) {
    // Підпис вірний
}
```

* **Чому це важливо**: Запобігає атакам за часом (timing attacks) при валідації токенів користувачів, паролів або підписів HMAC.

<a id="common-mistakes"></a>
## ⚠️ Часті помилки

### 1. Пріоритет унарних операторів та піднесення до ступеня
Змішування заперечення `-` або інших унарних операторів з `**` без дужок може призвести до помилок компіляції або невірних математичних розрахунків.

```php
// app/Demo/MathErrors.php
// ❌ Помилка компіляції! Оператор ступеня має вищий пріоритет
$result = -2 ** 2; 

// ✅ Правильний підхід
$result = (-2) ** 2; // 4
```

### 2. Використання застарілої змінної `$HTTP_RAW_POST_DATA`
До PHP 5.6 для необроблених POST-даних використовувалася `$HTTP_RAW_POST_DATA`. У PHP 5.6 вона оголошена застарілою.

```php
// app/Http/Webhook.php
// ❌ Застаріло в PHP 5.6, викликає E_DEPRECATED
$data = $HTTP_RAW_POST_DATA;

// ✅ Правильний підхід
$data = file_get_contents('php://input');
```

### 3. Обробка помилок у json_decode()
Метод `json_decode()` став суворіше ставитися до некоректних літералів (наприклад, `TRUE`, `FALSE`, `NULL` у верхньому регістрі), викликаючи синтаксичні помилки там, де раніше повертав `null`.

## Практичні рецепти

### Позбуваємося `call_user_func_array`

```php
// app/Demo/UnpackDemo.php
class Invoker
{
    public function execute(callable $callback, array $params)
    {
        // Очікування: Замінюємо повільний call_user_func_array на розпаковку
        // Реальність:
        // У PHP 5.5: call_user_func_array($callback, $params);
        // У PHP 5.6:
        return $callback(...$params);
    }
}
```

<a id="backward-incompatible"></a>
## Зворотна несумісність

1. **Суворі перевірки SSL/TLS за замовчуванням**: Перевірка хоста та ланцюжка сертифікатів тепер увімкнена за замовчуванням. Запити до серверів із самопідписаними сертифікатами відхилятимуться, якщо не налаштувати контекст потоку вручну.
2. **Пріоритет `**`**: Зміна асоціативності оператора піднесення до ступеня може вплинути на математичні розрахунки при перенесенні коду.
3. **Суворість `json_decode()`**: Використання верхнього регістру в JSON-літералах тепер викликає помилки синтаксису.
4. **Перевизначення ключів масивів**: Оголошення статичних масивів, що містять ключі, які дублюються, тепер перезаписують їх строго в порядку слідування.

## 🧠 Питання для самоперевірки

1. **Правильно чи ні?** Оператор `...` можна вказати кілька разів у сигнатурі параметрів однієї функції.
2. Який результат поверне вираз `2 ** 3 ** 2` у PHP 5.6?
3. Що прийшло на зміну застарілій змінній `$HTTP_RAW_POST_DATA`?
4. **Правильно чи ні?** Функція `hash_equals()` безпечна проти атак за часом, тому що вона порівнює рядки за змінний час.

<details>
<summary><b>Показати відповіді</b></summary>

1. **Неправильно.** Функція може містити лише один варіадичний параметр, і він має розташовуватися на останньому місці в сигнатурі.
2. `512` (оскільки оператор правоасоціативний: спочатку `3 ** 2 = 9`, потім `2 ** 9 = 512`).
3. Читання сирого потоку введення з `php://input`.
4. **Неправильно.** Вона безпечна, оскільки порівнює рядки за **постійний** час (constant time), тобто час перевірки не залежить від збігу символів.
</details>
