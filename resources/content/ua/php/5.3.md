# PHP 5.3: Модернізація та фундамент корпоративної архітектури

Уявіть, що ви оновлюєте сервер і раптово отримуєте «білий екран смерті» лише через те, що стороння бібліотека використала незакавичковане слово або передачу по посиланню у виклику функції. PHP 5.3 став тим самим переломним моментом, коли мова перестала бути простим скриптовим рушієм для домашніх сторінок і перетворилася на зрілу ООП-мову корпоративного рівня. Проте цей перехід супроводжувався жорсткими змінами зворотної сумісності, які в одну мить зламали тисячі старих додатків.

До PHP 5.3 розробники потерпали від постійних конфліктів імен класів у глобальній області, зламаного успадкування статичних методів та неконтрольованих витоків пам'яті в довготривалих скриптах через циклічні посилання. Щоб вирішити ці проблеми, PHP 5.3 представив простори назв (namespaces), замикання (closures), пізнє статичне зв'язування (Late Static Binding) та циклічний збирач сміття. Але водночас мова позбулася пережитків минулого, таких як передача посиланню при виклику та розширення `ereg`.

> [!IMPORTANT]
> PHP 5.3 — це найважливіший етап в історії PHP, який змусив розробників відмовитися від звичок епохи PHP 4 на користь ізоляції коду та структурованого управління пам'яттю.

<a id="namespaces"></a>
## Простори назв та автозавантаження

Простори назв ізолюють код і позбавляють потреби писати нескінченні префікси класів.

```php
// app/Repositories/UserRepository.php
namespace App\Repositories;

use App\Database\Connection;
use App\Contracts\LoggerInterface;

class UserRepository
{
    private Connection $db;
    private LoggerInterface $log;

    public function __construct(Connection $db, LoggerInterface $log)
    {
        $this->db = $db;
        $this->log = $log;
    }
}
```

* **Чому це важливо**: До появи просторів назв конфліктам імен класів запобігали за допомогою довгих префіксів в іменах файлів та класів (наприклад, `Zend_Db_Table_Row_Abstract`). Простори назв роблять код чистим і читабельним, логічно ізолюючи короткі імена класів.
* **Наслідок**: Це нововведення заклало основу для сучасних PHP-пакетів, стандартів автозавантаження (PSR-0/PSR-4) та створення Composer.

<a id="lsb"></a>
## Пізнє статичне зв'язування (`static::`)

У PHP ключове слово `self::` завжди вказує на клас, в якому метод був фізично описаний. Пізнє статичне зв'язування вводить `static::`, яке дозволяється в клас, що безпосередньо викликав метод на етапі виконання.

```php
// app/Models/ActiveRecord.php
abstract class ActiveRecord
{
    public static function find(int $id): string
    {
        // self::getTable() тут видав би помилку для підкласів
        return "SELECT * FROM " . static::getTable() . " WHERE id = " . $id;
    }

    abstract protected static function getTable(): string;
}
```

* **Чому це важливо**: Без пізнього статичного зв'язування написання розширюваних базових класів зі статичними фабричними методами (таких як ActiveRecord ORM) було вкрай складним завданням.
* **Наслідок**: Розробники отримали можливість створювати елегантні базові хелпери, які коректно взаємодіють з перевизначеними статичними властивостями чи методами в нащадках.

<a id="closures"></a>
## Замикання та конструкція `use`

Анонімні функції тепер можна присвоювати змінним, передавати як аргументи та захоплювати змінні з батьківської області видимості за допомогою конструкції `use`.

```php
// app/Services/Calculator.php
$taxRate = 0.20;

$calculateTotal = function (float $price) use ($taxRate): float {
    return $price * (1 + $taxRate);
};

echo $calculateTotal(100); // 120
```

> [!NOTE]
> У PHP 5.3 замикання за замовчуванням копіюють захоплені змінні **за значенням**. Якщо вам потрібно змінити вихідну змінну всередині замикання, ви маєте передати її **за посиланням** (наприклад, `use (&$counter)`).

<a id="syntax-additions"></a>
## NOWDOC проти HEREDOC

NOWDOC відноситься до HEREDOC так само, як рядочки в одинарних лапках відносяться до рядочків у подвійних лапках.

```php
// app/Config/templates.php
// HEREDOC (обробляє змінні)
$name = 'Іван';
$heredoc = <<<EOT
Привіт, $name!
EOT;

// NOWDOC (не обробляє змінні, зверніть увагу на одинарні лапки навколо EOT)
$nowdoc = <<<'EOT'
Привіт, $name!
EOT;
```

* **Чому це важливо**: NOWDOC дозволяє безпечно вставляти великі блоки необробленого коду, конфігурацій або регулярних виразів без потреби екранувати знак долара.

<a id="gc"></a>
## Збирач сміття циклічних посилань

У PHP 5.3 з'явився збирач циклічних посилань. Коли об'єкт A посилається на об'єкт B, а об'єкт B посилається назад на об'єкт A, стандартний механізм підрахунку посилань не може їх звільнити, навіть якщо вони більше не використовуються в програмі.

```php
// app/Services/Daemon.php
gc_enable(); // Увімкнення збирача циклічних посилань

// У довготривалому процесі:
gc_collect_cycles(); // Примусовий запуск очищення черги
```

* **Чому це важливо**: Це життєво необхідно для фонових обробників черг, CLI-команд та демонів, які інакше швидко вичерпали б усю доступну пам'ять.

<a id="common-mistakes"></a>
## ⚠️ Часті помилки

### 1. Передача посилань при виклику (Call-Time Pass-By-Reference)
Використання знака амперсанда безпосередньо під час виклику функції призводить до помилок.

```php
// app/Services/LegacyFix.php
// ❌ Застаріло / Фатальна помилка в PHP 5.3+
foo(&$value); 

// ✅ Правильний підхід
// Посилання має бути вказане в самій сигнатурі функції:
function foo(&$param) {}
foo($value); 
```

### 2. Використання нових зарезервованих слів
Нові ключові слова на кшталт `goto`, `namespace` та `use` не можна використовувати як імена класів або нецитовані константи.

```php
// app/Classes/Runner.php
// ❌ Фатальна помилка: не можна використовувати 'goto' як ім'я класу
class goto {}
```

### 3. Використання застарілого ereg замість preg_match
Функції сімейства `ereg()` працюють повільніше та генерують попередження про застарілий код.

```php
// app/Validation/Email.php
// ❌ Застаріло в PHP 5.3
if (eregi('^[a-z0-9]+$', $input)) {}

// ✅ Правильний підхід
if (preg_match('/^[a-z0-9]+$/i', $input)) {}
```

<a id="practical-recipes"></a>
## Практичні рецепти

### Очікування vs Реальність: `self` vs `static`

```php
// app/Demo/BindingDemo.php
class ParentClass
{
    public static function getClassName(): string
    {
        return self::class; // Або __CLASS__
    }

    public static function getCalledClassName(): string
    {
        return static::class;
    }
}

class ChildClass extends ParentClass {}

// Очікування: обидва методи повернуть 'ChildClass'
// Реальність:
echo ChildClass::getClassName();       // Вивід: ParentClass
echo ChildClass::getCalledClassName(); // Вивід: ChildClass
```

<a id="backward-incompatible"></a>
## Зворотна несумісність

1. **Вилучення передачі посилань при виклику**: Синтаксис `foo(&$x)` визнано застарілим і видає попередження в PHP 5.3 (повністю вилучено в 5.4).
2. **Нові зарезервовані слова**: `goto`, `namespace`, `use`, `const` більше не можна використовувати для імен класів, інтерфейсів чи констант.
3. **Застарівання ereg**: Використання функцій регулярних виразів POSIX `ereg_*` викликає попередження `E_DEPRECATED`.
4. **Строгий порядок параметрів**: Змінилася поведінка та вимоги до аргументів у ряді системних функцій (наприклад, `clearstatcache()`).

## 🧠 Питання для самоперевірки

1. **Правильно чи ні?** Замикання в PHP 5.3 автоматично прив'язують контекст `$this` при оголошенні всередині методу об'єкта.
2. Як оголосити строковий блок NOWDOC?
3. У чому різниця між `self::` та `static::` при пізньому статичному зв'язуванні?
4. Що станеться, якщо викликати функцію як `bar(&$var)` у PHP 5.3?

<details>
<summary><b>Показати відповіді</b></summary>

1. **Неправильно.** У PHP 5.3 замикання НЕ прив'язують `$this` автоматично. Вам потрібно передавати об'єкт вручну (наприклад, `$self = $this;` і `use ($self)`) для доступу до методів та властивостей екземпляра. Автоматична прив'язка `$this` з'явилася тільки в PHP 5.4.
2. Необхідно обгорнути ідентифікатор в одинарні лапки у відкриваючому маркері: `<<<'EOT'`.
3. `self::` посилається на клас, в якому був скомпільований код (де фізично написаний метод), тоді як `static::` динамічно вказує на клас, який був викликаний під час виконання (runtime).
4. Буде згенеровано попередження про застарілий код (`Deprecated: Call-time pass-by-reference has been deprecated...`). У PHP 5.4+ цей синтаксис призводить до фатальної синтаксичної помилки.
</details>
