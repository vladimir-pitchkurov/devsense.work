# PHP 7.4: Головні нововведення

Уявіть, що ви оновили версію PHP, і ваш продакшн упав лише через те, що властивість класу не була ініціалізована. PHP 7.4 приносить довгоочікувану строгу типізацію властивостей класів, але разом із цією силою з'являється сувора вимога: будь-яка типізована властивість має бути ініціалізована до першого читання. Ця версія служить головним мостом до сучасного PHP 8, впроваджуючи типізовані властивості та стрілочні функції, які вимагають дисципліни від розробника.

<a id="typed-properties"></a>
## Типізовані властивості

У властивостей класу можна оголошувати типи. **Неініціалізовану** typed property **не можна читати** до присвоєння — буде викинуто помилку **`Typed property ... must not be accessed before initialization`**.

```php
// src/User.php
final class User
{
    public int $id;
    public string $name;
    public ?string $nickname = null;
}
```

З практики:

* Якщо «немає значення» допустимо — використовуйте **`?Type`** або значення за замовчуванням.
* Тип **`callable`** для властивостей **заборонений** (контекстно-залежна поведінка).
* Об’єктні typed properties мають обмеження на оголошенні — див. мануал.

> [!NOTE]
> Чи знали ви? У PHP 7.4 типізовані властивості реалізовані на рівні рушія із захистом «лінивої ініціалізації». Властивість перебуває в стані «uninitialized» (неініціалізовано), що відрізняється від `null`. Перевірка `isset($user->id)` поверне `false`, якщо властивість не була задана, навіть якщо тип не допускає `null`.

<a id="arrow-functions"></a>
## Arrow functions

`fn` захоплює змінні з оточення **за значенням** і повертає один вираз — зручно для коротких колбеків.

```php
// src/MathHelper.php
$factor = 10;
$nums = array_map(fn($n) => $n * $factor, [1, 2, 3]);
```

**`fn` — зарезервоване слово**: не можна назвати функцію чи клас `fn` (методи/константи — дозволено).

> [!NOTE]
> Чи знали ви? На відміну від стрілочних функцій у JavaScript, у PHP змінні захоплюються виключно за значенням. Зміна змінної всередині стрілочної функції не вплине на її значення у зовнішній області видимості.

<a id="variance"></a>
## Коваріантність і контраваріантність

Типи повернення можна **звужувати** (коваріантність), типи параметрів — **розширювати** (контраваріантність) при успадкуванні, з обмеженнями. Повна варіантність краще працює з **autoload**; в одному файлі дозволені лише **нециклічні** посилання на класи.

```php
// src/Repository.php
interface Repository {
    public function get(int $id): object;
}

class UserRepository implements Repository {
    public function get(int $id): User { // Коваріантний тип повернення
        return new User();
    }
}
```

<a id="null-coalesce-assign"></a>
## Присвоєння з null coalescing (`??=`)

Присвоєння виконується, якщо зліва **unset** або **`null`**:

```php
// src/Config.php
$config['debug'] ??= false;
```

<a id="array-spread"></a>
## Оператор spread у масивах

Розпакування ітерованих значень у літералі масиву:

```php
// src/ArrayMerge.php
$base = [1, 2];
$all = [0, ...$base, 3]; // [0, 1, 2, 3]
```

Добре поєднується з `array_merge(...$arrays)`; **`array_merge()`** без аргументов повертає **`[]`**.

<a id="numeric-separator"></a>
## Роздільник у числових літералах

Підкреслення покращують читання і **не змінюють** значення:

```php
// src/Constants.php
$million = 1_000_000;
$hex = 0xFF_FF_FF;
```

<a id="weak-references"></a>
## Слабкі посилання (WeakReference)

`WeakReference` тримає посилання, яке **не заважає** збирати об’єкт сміттєзбирачем — корисно для кешів без витоків пам'яті.

```php
// src/Cache.php
$obj = new stdClass();
$weakRef = WeakReference::create($obj);
```

<a id="tostring-exceptions"></a>
## Винятки з `__toString()`

Кидати винятки з `__toString()` дозволено (раніше — fatal). Частина старих recoverable fatals стала **`Error`** — перевірте приведення до рядка.

```php
// src/Stringy.php
class Stringy {
    public function __toString(): string {
        throw new Exception("Failed to cast to string");
    }
}
```

<a id="custom-serialize"></a>
## Серіалізація: `__serialize` / `__unserialize`

Новий механізм, що поступово витісняє `Serializable`:

```php
// src/Point.php
final class Point
{
    private int $x;
    private int $y;

    public function __serialize(): array
    {
        return ['x' => $this->x, 'y' => $this->y];
    }

    public function __unserialize(array $data): void
    {
        $this->x = $data['x'];
        $this->y = $data['y'];
    }
}
```

Типи SPL на кшталт `ArrayObject` можуть записувати **нові** серіалізовані представлення, читані на 7.4+, але не на старіших PHP.

<a id="extensions-stdlib"></a>
## Розширення і стандартна бібліотека

* **FFI**: виклик нативних C-бібліотек з PHP (потужно; потрібна модель загроз та обмеження доступу).
* **OPcache preloading**: `opcache.preload`, часто `opcache.preload_user`.
* **`mb_str_split()`**: як `str_split()`, но по **кодпойнтах**.
* **`proc_open()`**: команда **масивом** (без shell), дескриптори `redirect` / `null`.
* **`strip_tags()`**: дозволені теги **масивом** імен.
* **PDO**: логін/пароль у DSN для більшої кількості драйверів; **`??`** у SQL екранує літеральний `?` (наприклад, для JSON-операторів у PostgreSQL).
* **PCRE**: `preg_replace_callback*` приймає прапорці — **`PREG_OFFSET_CAPTURE`**, **`PREG_UNMATCHED_AS_NULL`** тощо.
* **Password**: Argon2 через **sodium** без libargon.

<a id="common-mistakes"></a>
## Часті помилки

Нижче наведено типові помилки розробників під час переходу на PHP 7.4:

### 1. Читання неініціалізованої типізованої властивості
```php
// src/BadPropertyAccess.php
// Погано: звернення до типізованої властивості до її ініціалізації
class BadUser {
    public int $id;
}
$user = new BadUser();
echo $user->id; // Fatal Error: Typed property BadUser::$id must not be accessed before initialization
```
```php
// src/GoodPropertyAccess.php
// Добре: вкажіть значення за замовчуванням або ініціалізуйте в конструкторі
class GoodUser {
    public int $id = 0;
}
```

### 2. Спроба змінити зовнішні змінні всередині стрілочних функцій
```php
// src/BadArrowScope.php
// Погано: очікування, що зовнішня змінна зміниться за посиланням
$count = 0;
$increment = fn() => $count++;
$increment();
echo $count; // Вивід: 0 (Зовнішня змінна не змінилася!)
```
```php
// src/GoodArrowScope.php
// Добре: використовуйте традиційну анонімну функцію з `use (&$count)`
$count = 0;
$increment = function() use (&$count) {
    $count++;
};
$increment();
echo $count; // Вивід: 1
```

<a id="limitations"></a>
## Обмеження

* **Стрілочні функції**: можуть містити лише один вираз. Ви не можете використовувати багаторядкову логіку або явний оператор `return`.
* **OPcache Preloading**: передзавантажені файли кешуються в пам'яті назавжди. Будь-які зміни в коді вимагають повного перезапуску процесу PHP-FPM або веб-сервера.
* **FFI**: дає максимальну продуктивність, але відключає захисні шари PHP. Помилки у коді можуть призвести до Segmentation Fault (падіння процесу PHP).

<a id="backward-incompatible"></a>
## Зворотно несумісні зміни (міграційні нотатки)

### Ядро

* **Доступ як до масиву до не-масивів**: `$null["key"]` та подібне для `null`, `bool`, `int`, `float`, `resource` — **notice**.
* **`get_declared_classes()`**: більше **не** повертає анонімні класи, доки їх не інстанційовано.
* **`fn`**: зарезервоване ключове слово для імен функцій/класів.
* **`<?php` в кінці файлу** без нового рядка: тепер трактується як **відкриваючий PHP-тег** (раніше залежало від `short_open_tag`).
* **Stream wrappers**: під час `include`/`require` по stream може викликатися `streamWrapper::stream_set_option(STREAM_OPTION_READ_BUFFER)` — реалізуйте метод або повертайте `false`, щоб не було warning.
* **Серіалізація**: формат **`o`** прибрано (актуально лише для вручну складених рядків).
* **Константи алгоритмів паролів**: `PASSWORD_*` — це **рядки** (`'2y'`, `'argon2id'`, …), не цілі — код з порівнянням з `1`/`2`/`3` ламається.
* **`htmlentities()`**: **notice**, коли кодування зводиться до поведінки як у `htmlspecialchars`.
* **`fread`/`fwrite`**: при невдачі повертають **`false`** (не `''`/`0`); можливий **notice**.
* **BCMath**: попередження для некоректних числових рядків (раніше часто трактувалися як нуль).
* **CURL**: серіалізація **`CURLFile`** кидає раніше; нестандартний аргумент `curl_version()` — попередження/ігнорування.
* **Date**: `var_dump` для `DateInterval`/`DateTime*` без «зайвих» властивостей; порівняння **`DateInterval`** попереджає і завжди дає **`false`**.
* **Intl**: за замовчуванням `idn_to_ascii` / `idn_to_utf8` використовують **`INTL_IDNA_VARIANT_UTS46`**.
* **MySQLi**: прибрано embedded server; прибрано недокументоване `$mysqli->stat` — користуйтеся **`mysqli::stat()`**.
* **OpenSSL**: `openssl_random_pseudo_bytes` кидає як **`random_bytes`** при помилці; `$crypto_strong` — **`true`**, якщо винятку немає.
* **PCRE**: з **`PREG_UNMATCHED_AS_NULL`** хвостові неспівпадіння груп — **`null`** (стабільний розмір `$matches`).
* **PDO**: серіалізація **`PDO`/`PDOStatement`** кидає **`Exception`** (не `PDOException`).
* **Reflection**: серіалізація reflection-об’єктів **кидає**; змінено **числові значення** деяких констант модифікаторів.
* **SPL / `ArrayObject`**: змінена поведінка **`get_object_vars`** без `STD_PROP_LIST`; `SplPriorityQueue::setExtractFlags(0)` кидає одразу.
* **Tokenizer**: несподівані байти стають **`T_BAD_CHARACTER`** замість «пробілів» у потоці.
* **Cookie (з 7.4.11)**: імена вхідних cookie **не** URL-декодуються.

<a id="deprecations"></a>
## Deprecated (виправити завчасно)

Акценти:

* **Вкладені тернарні оператори** без явних дужок (окрім однозначної форми з вкладенням у середній операнд).
* **Фігурні дужки** для offset `$str{0}` / `$arr{0}` → використовуйте **`[]`**.
* **`(real)`** і **`is_real()`** → **`(float)`** / **`is_float()`**.
* **`array_key_exists()` для об’єктів** → **`isset()`** / **`property_exists()`**.
* **`implode($parts, $glue)`** — зворотний порядок → **`implode($glue, $parts)`**.
* **`ReflectionType::__toString()`** і **`Reflection*::export()`** → API на кшталт **`ReflectionNamedType::getName()`** і string cast reflection-об’єктів.
* **`allow_url_include`**, **`FILTER_SANITIZE_MAGIC_QUOTES`**, застарілі LDAP paged-функції, `money_format()`, `hebrevc()` тощо — повний список: [migration74 deprecated](https://www.php.net/manual/en/migration74.deprecated.php).

<a id="other-changes"></a>
## Інші зміни та експлуатація (збірка, INI, продуктивність)

* **`zend.exception_ignore_args`**: новий INI (за замовчуванням може приховувати **аргументи** у stack traces — перевірте error reporting).
* **`opcache.preload_user`**: користувач для preload, коли не root.
* **Міграція на pkg-config**: багато `./configure`-прапорів більше не приймають `=DIR`; використовуйте **`PKG_CONFIG_PATH`** або `FOO_CFLAGS`/`FOO_LIBS`.
* **Прибрані бандли**: **SQLite3**, **Zip**, **onig** (mbregex) — потрібні системні бібліотеки; **hash** завжди вбудований.
* **CSV**: порожній рядок для **`$escape`** вимикає PHP escape-механізм; `str_getcsv()` узгоджено.
* **GD**: `imagecropauto()` узгоджено з системною libgd; змінено режим за замовчуванням; **`imagescale()`** з `-1` зберігає пропорції.
* **PEAR**: не встановлюється за замовчуванням (`--with-pear` опційно і deprecated).
* **Продуктивність**: opcode для **`array_key_exists()`** при статичному розв’язанні; UTF-8 **`preg_match`** валідує рядок один раз при повторних викликах.

<a id="interactive-quiz"></a>
## Інтерактивний квіз

Перевірте свої знання про PHP 7.4:

1. **Що станеться, якщо спробувати прочитати неініціалізовану типізовану властивість класу?**
   * А) Повернеться `null`
   * Б) Викличеться Notice, і повернеться `null`
   * В) Буде викинуто виняток Error
   * Г) Повернеться `false`

   <details>
   <summary>Показати відповідь</summary>
   
   **Правильна відповідь: В**  
   PHP 7.4 суворо забороняє читання властивостей до їх ініціалізації. Спроба звернутися до такої властивості викидає виняток `Error` з повідомленням `Typed property ... must not be accessed before initialization`.
   </details>

2. **Чи можна змінити значення зовнішньої змінної всередині стрілочної функції (arrow function)?**
   * А) Так, змінні передаються за посиланням
   * Б) Ні, змінні захоплюються тільки за значенням
   * В) Так, але тільки при явному використанні слова `use`
   * Г) Так, але тільки для об'єктів

   <details>
   <summary>Показати відповідь</summary>
   
   **Правильна відповідь: Б**  
   Стрілочні функції в PHP автоматично захоплюють змінні з зовнішньої області видимості за значенням. Будь-які зміни цієї змінної всередині функції залишаються локальними.
   </details>

3. **Оголошення якого типу для властивостей класу ЗАБОРОНЕНО в PHP 7.4?**
   * A) `object`
   * Б) `callable`
   * B) `iterable`
   * Г) `?string`

   <details>
   <summary>Показати відповідь</summary>
   
   **Правильна відповідь: Б**  
   Тип `callable` не може бути використаний для типізації властивостей класу, оскільки його валідність залежить від контексту виклику.
   </details>

<a id="closing-thoughts"></a>
## Підсумок

PHP 7.4 — це **міст** до 8.x: впровадьте typed properties і `__serialize`/`__unserialize` заздалегідь; шукайте цілі **`PASSWORD_*`**, ім’я **`fn`**, синтаксис **`$var{idx}`** і крихкий код з **`ArrayObject`**; тестуйте streams, OpenSSL random і серіалізацію PDO/Reflection.
