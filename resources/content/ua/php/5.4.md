# PHP 5.4: Повторне використання коду та очищення безпеки

Уявіть, що ви переносите старий додаток PHP на сервер з PHP 5.4 і раптом виявляєте, що всі відправлені форми приходять порожніми, а SQL-запити викликають фатальні помилки. Це було суворою реальністю для розробників, коли PHP 5.4 офіційно позбувся пережитків минулого на кшталт «магічних лапок» (magic quotes) та глобальної реєстрації змінних (register globals). Але водночас цей реліз приніс синтаксис, без якого сьогодні неможливо уявити розробку: трейти та короткі масиви (`[]`).

Безпека була головною ахіллесовою п'ятою раннього PHP. Налаштування на кшталт `magic_quotes` намагалися автоматично екранувати будь-які вхідні дані (спотворюючи рядки), а `register_globals` автоматично перетворювала GET/POST-параметри на глобальні змінні скрипта. Вилучення цих функцій вимагало від спільноти переходу до стандартів безпечної розробки.

> [!IMPORTANT]
> PHP 5.4 став важливим санітарним релізом, що ліквідував вразливості архітектури PHP 4 та надав сучасні інструменти структурування коду.

<a id="traits"></a>
## Трейти (горизонтальне успадкування)

Трейти дозволяють ділити методи між класами без використання класичного поодинокого успадкування.

```php
// app/Traits/Loggable.php
trait Loggable
{
    protected function log(string $msg): void
    {
        echo "[LOG]: " . $msg;
    }
}

// app/Services/UserService.php
class UserService
{
    use Loggable;

    public function create(): void
    {
        $this->log("Користувача успішно створено.");
    }
}
```

* **Чому це важливо**: Поодиноке успадкування часто змушує дублювати код або будувати неприродні ієрархії класів заради спільних хелперів.
* **Наслідок**: Будь-які наскрізні функції (логування, кешування, серіалізація) тепер підключаються в одне оголошення.

<a id="short-array"></a>
## Короткий синтаксис масивів (`[]`)

PHP 5.4 представляє компактний синтаксис `[]` для створення масивів замість громіздкої конструкції `array()`.

```php
// app/Config/database.php
// Старий синтаксис:
$config = array("host" => "localhost", "port" => 3306);

// Новий синтаксис:
$config = ["host" => "localhost", "port" => 3306];
```

* **Чому це важливо**: Читабельність коду значно покращується, наближаючи PHP до стандартів JSON, JavaScript та інших мов програмування.

<a id="callable-hint"></a>
## Тип даних `callable`

Тепер ви можете вказувати `callable` як тип параметрів функцій, щоб гарантувати передачу коректного колбеку.

```php
// app/Services/EventDispatcher.php
class EventDispatcher
{
    public function registerListener(string $event, callable $callback): void
    {
        // Перевірка, що колбек може бути виконаний
        $callback($event);
    }
}
```

* **Чому це важливо**: Зникає потреба писати ручні перевірки `is_callable()` всередині логіки функцій.

<a id="closure-this"></a>
## Прив'язка `$this` у замиканнях

Замикання, створені всередині методів об'єкта, тепер автоматично отримують доступ до контексту `$this` цього об'єкта.

```php
// app/Services/NotificationService.php
class NotificationService
{
    private string $sender = "system@example.com";

    public function getSenderResolver(): Closure
    {
        return function() {
            // Контекст прив'язаний автоматично, доступна приватна властивість
            return $this->sender;
        };
    }
}
```

> [!NOTE]
> Це автоматичне зв'язування істотно спрощує написання обробників подій та моделей в ORM, які взаємодіють із властивостями об'єкта, що їх викликав.

<a id="built-in-server"></a>
## Вбудований CLI веб-сервер

Запустити HTTP-сервер для тестування тепер можна безпосередньо з консолі однією короткою командою.

```bash
# Запуск веб-сервера з коренем у папці public на порту 8000
php -S localhost:8000 -t public/
```

* **Чому це важливо**: Більше немає потреби розгортати важкі веб-сервери на кшталт Apache або nginx для локальної відладки простих скриптів або API.

<a id="common-mistakes"></a>
## ⚠️ Часті помилки

### 1. Очікування імпорту змінних через register_globals
Якщо код розраховував, що змінна `$userId` матеріалізується в коді сама по собі із запиту `GET /profile.php?userId=42`, на PHP 5.4+ ви отримаєте помилку невизначеної змінної.

```php
// app/Http/LegacyController.php
// ❌ Помилка в PHP 5.4+ (змінні більше не імпортуються з глобальних)
echo $userId; 

// ✅ Правильний підхід
echo $_GET['userId'] ?? null;
```

### 2. Подвійне екранування даних
Розробники, які використовували `stripslashes()` для видалення слешів від `magic_quotes_gpc`, тепер псуватимуть дані, оскільки автоматичне екранування вимкнено на рівні ядра.

```php
// app/Database/Sanitizer.php
// ❌ Видаляє корисні слеші, оскільки magic_quotes більше не працюють
$cleaned = stripslashes($_POST['bio']);

// ✅ Правильний підхід
$cleaned = $_POST['bio']; // А для SQL використовуйте підготовлені запити!
```

### 3. Конфлікти методів у Трейти
Використання кількох трейтів з однаковими іменами методів без явного вирішення конфлікту викличе помилку компіляції.

```php
// app/Demo/TraitConflict.php
trait A { public function run() {} }
trait B { public function run() {} }

// ❌ Фатальна помилка компіляції
class Runner { use A, B; }

// ✅ Правильний підхід
class SafeRunner
{
    use A, B {
        A::run insteadof B;
        B::run as runAlternate;
    }
}
```

## Практичні рецепти

### Очікування vs Реальність: розіменування масиву з функції

```php
// app/Demo/DereferenceDemo.php
function getNames(): array
{
    return ["Олексій", "Борис", "Сергій"];
}

// Очікування: доступ до індексу масиву «на льоту» спрацює
// Реальність:
// В PHP 5.3: Помилка парсера (Syntax Error)
// В PHP 5.4: Працює без зайвих змінних
echo getNames()[1]; // Вивід: Борис
```

<a id="backward-incompatible"></a>
## Зворотна несумісність

1. **Повне вилучення `register_globals` та `magic_quotes`**: Усі дані форм та запитів приходять у «сирому» вигляді, їх потрібно отримувати із суперглобальних масивів.
2. **Вилучення `safe_mode`**: Обмеження прав на основі власника файлу більше не працюють, безпека регулюється правами ОС.
3. **Суворі правила для `break` та `continue`**: Передача неконстантних виразів (наприклад, `$val`) для виходу з циклів заборонена.
4. **Застарівання `mysql`**: Функції `mysql_*` видають попередження, час переходити на `mysqli` або `PDO`.

## 🧠 Питання для самоперевірки

1. **Правильно чи ні?** Трейти в PHP 5.4 можна інстанціювати (створювати екземпляри) напряму.
2. Яка CLI-команда запускає вбудований веб-сервер?
3. Що станеться, якщо підключити два трейти з однаковими іменами методів без явного вирішення конфлікту?
4. **Правильно чи ні?** Змінна `$this` автоматично доступна в замиканнях, оголошених як `static`.

<details>
<summary><b>Показати відповіді</b></summary>

1. **Неправильно.** Трейти є лише шаблонами повторного використання коду і не можуть існувати як окремі об'єкти. Їх можуть використовувати лише класи.
2. `php -S <хост>:<порт>` (наприклад, `php -S localhost:8000`).
3. Виникне фатальна помилка на етапі компіляції. Конфлікт необхідно вирішити вручную, вказавши пріоритети ключовими словами `insteadof` та `as` у блоці `use` трейтів.
4. **Неправильно.** Якщо замикання оголошено як статичне (наприклад, `static function() {}`), воно втрачає зв'язок із контекстом класу, і звернення до `$this` викличе фатальну помилку.
</details>
