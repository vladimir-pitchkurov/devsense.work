# PHP 7.0: Головні нововведення

Що, якби ви могли подвоїти продуктивність свого веб-додатка за одну ніч, просто оновивши інтерпретатор мови? Випуск PHP 7.0 зробив це реальністю. Завдяки новому движку Zend Engine 3, ця версія принесла колосальний приріст швидкості, а також строгі скалярні типи, декларації типів повертаних значень та сучасні оператори на кшталт null-coalescing. PHP 7.0 став революційним кроком в історії PHP, заклавши фундамент сучасних безпечних типів та високопродуктивних веб-додатків.

<a id="scalar-types"></a>
## Оголошення скалярних типів

Параметри функцій тепер можуть мати скалярні типи: **`int`**, **`float`**, **`string`** та **`bool`**:

```php
// src/Math.php
declare(strict_types=1);

function add(int $a, int $b): int 
{
    return $a + $b;
}
```

> [!NOTE]
> Чи знали ви? Без рядка `declare(strict_types=1);` на початку файлу PHP працює в **режимі приведення типів (coercive mode)**. Це означає, що він автоматично та мовчки приведе рядок `"5"` до числа `5` при перевірці аргументів.

<a id="return-types"></a>
## Декларація повертаних типів

Ви можете строго визначити, значення якого типу має повертати функція:

```php
// src/Generator.php
function generateId(): string 
{
    return uniqid();
}
```

Якщо повернуте значення не відповідає вказаному типу, PHP викине виняток **`TypeError`**.

<a id="null-coalescing"></a>
## Оператор об'єднання з null (`??`)

Синтаксичний цукор для перевірки існування змінної через `isset()`:

```php
// src/Config.php
$username = $_GET['user'] ?? 'anonymous';
```

Оператор можна об'єднувати в ланцюжки: `$value = $a ?? $b ?? $default;`.

<a id="spaceship-operator"></a>
## Оператор «космічний корабель» (`<=>`)

Виконує тристороннє порівняння значень, повертаючи `-1`, `0` або `1`:

```php
// src/SortHelper.php
usort($list, function($a, $b) {
    return $a <=> $b;
});
```

Зручно використовувати у функціях користувацького сортування, замінюючи громіздкі розгалуження `if-else`.

<a id="constant-arrays"></a>
## Масиви в константах через `define()`

Масиви тепер можна оголошувати в константах прямо під час виконання скрипта:

```php
// src/Constants.php
define('ALLOWED_ROLES', ['admin', 'editor', 'guest']);
```

Раніше константи-масиви підтримувалися тільки всередині класів через ключове слово `const`.

<a id="anonymous-classes"></a>
## Анонімні класи

Створення простих одноразових об'єктів на льоту:

```php
// src/LoggerProvider.php
$logger = new class {
    public function log(string $msg) {
        echo $msg;
    }
};
```

Часто застосовується для створення заглушок (mocks) інтерфейсів у юніт-тестах.

<a id="unicode-escape"></a>
## Синтаксис екранування Unicode-символів

Виведення Unicode-символів безпосередньо з рядків за їх шістнадцятковим кодом:

```php
// src/Emoji.php
echo "\u{1F600}"; // Виводить усміхнений смайлик 😀
```

<a id="group-use"></a>
## Групові імпорти (use)

Лаконічний імпорт кількох класів з одного простору імен:

```php
// src/Controller.php
use App\Models\{User, Post, Comment};
```

<a id="throwable-exceptions"></a>
## Інтерфейс Throwable та системні винятки

Багато фатальних помилок рантайму тепер викидаються як винятки класу **`Error`**. Перехоплювати їх потрібно через загальний інтерфейс **`Throwable`**:

```php
// src/ErrorHandler.php
try {
    nonExistentFunction();
} catch (Throwable $t) {
    // Перехоплює як помилки движка Error, так і звичайні Exceptions
    echo "Перехоплено: " . $t->getMessage();
}
```

> [!NOTE]
> Чи знали ви? Клас `Error` не успадковується від `Exception`. Якщо ви спробуєте зловити помилку через `catch (Exception $e)`, фатальні помилки ядра (наприклад, виклик неіснуючої функції) все одно призведуть до падіння скрипта. Використовуйте `Throwable` або `Error`.

<a id="csprng-functions"></a>
## Функції CSPRNG

Криптографічно безпечна генерація випадкових чисел та байт на рівні операційної системи:

```php
// src/TokenGenerator.php
$bytes = random_bytes(32);
$number = random_int(1, 100);
```

Ці функції замінюють небезпечні генератори на кшталт `rand()` або `mt_rand()` у контекстах безпеки.

<a id="common-mistakes"></a>
## Часті помилки

Нижче наведено типові помилки розробників при переході на PHP 7.0:

### 1. Забута декларація строгої типізації
Якщо не оголосити strict_types у кожному файлі окремо, PHP працюватиме в режимі приведення типів і приводитиме невірні аргументи до потрібних типів автоматично.
```php
// src/BadStrict.php
// Погано: Строгий режим вимкнено, рядок "10" тихо приведеться до числа int 10
function setAge(int $age) {
    return $age;
}
setAge("10"); // Помилки немає
```
```php
// src/GoodStrict.php
// Добре: Увімкніть строгу типізацію на першому рядку файлу
declare(strict_types=1);

function setAgeGood(int $age) {
    return $age;
}
// setAgeGood("10"); // Викличе виняток TypeError
```

### 2. Спроба перехопити помилки ядра через клас `Exception`
Розробники часто ловлять `Exception`, очікуючи перехопити такі помилки, як ділення на нуль або виклик неіснуючого методу, але вони проходять повз цей блок catch.
```php
// src/BadCatch.php
// Погано: Ділення на нуль викликає DivisionByZeroError (нащадок Error), catch не спрацює
try {
    $value = 1 / 0;
} catch (Exception $e) {
    echo "Цей код не виконається!";
}
```
```php
// src/GoodCatch.php
// Добре: Перехоплюйте Throwable або Error
try {
    $value = 1 / 0;
} catch (Throwable $e) {
    echo "Помилку перехоплено: " . $e->getMessage();
}
```

<a id="limitations"></a>
## Обмеження

* **Оголошення типів параметрів**: Не можуть приймати `null` за замовчуванням. Запис `int $x` видасть TypeError при передачі null (nullable-типи з'являться тільки в PHP 7.1).
* **Типи повертаних значень**: Не можна вказувати повертаний тип `void` (він з'явиться в PHP 7.1) або об'єднання типів (Union-типи з'являться в PHP 8.0).

<a id="backward-incompatible"></a>
## Зворотно несумісні зміни

### Ядро мови

* **ASP-теги (`<% %>`) та script-теги (`<script language="php">`)** повністю видалено з парсера PHP.
* Змінна **`$HTTP_RAW_POST_DATA`** видалена; використовуйте потік `php://input`.
* Використання більше ніж одного блоку `default` у конструкції `switch` викликає ParseError.
* Змінено порядок обчислення деяких динамічних виразів та глобальних змінних (наприклад, `$$foo['bar']` розбирається строго зліва направо).

## Інтерактивний квіз

Перевірте свої знання про PHP 7.0:

1. **Яке твердження є правильним щодо строгих типів (strict_types) у PHP 7.0?**
   * А) Строгі типи вмикаються глобально в конфігурації php.ini.
   * Б) Строгі типи потрібно оголошувати на початку кожного конкретного файлу.
   * В) У PHP 7.0 примусово увімкнено строгий режим, приведення типів більше немає.
   * Г) Строгі типи застосовуються тільки для повертаних значень, але не для параметрів.

   <details>
   <summary>Показати відповідь</summary>
   
   **Правильна відповідь: Б**  
   Строга типізація активується індивідуально для кожного файлу за допомогою інструкції `declare(strict_types=1);`.
   </details>

2. **Який клас НЕ успадковується від Exception, але реалізує інтерфейс Throwable у PHP 7.0?**
   * А) RuntimeException
   * Б) Error
   * В) BadMethodCallException
   * Г) InvalidArgumentException

   <details>
   <summary>Показати відповідь</summary>
   
   **Правильна відповідь: Б**  
   Новий клас `Error` та його нащадки (такі як `TypeError` або `ParseError`) реалізують інтерфейс `Throwable`, але не успадковуються від `Exception`.
   </details>

3. **Що повертає оператор «космічний корабель» (`<=>`)?**
   * А) Булеве значення (true/false).
   * Б) Число з плаваючою точкою (float).
   * В) Ціле число (`-1`, `0` або `1`).
   * Г) Рядок з результатом порівняння.

   <details>
   <summary>Показати відповідь</summary>
   
   **Правильна відповідь: В**  
   Оператор порівнює два значення і повертає `-1`, якщо ліве менше, `0`, якщо вони рівні, і `1`, если ліве більше.
   </details>

<a id="closing-thoughts"></a>
## Підсумок

PHP 7.0 — це **епохальна віха** в розробці веб-додатків. Переконайтеся, що ваш сервер використовує Zend Engine 3, видаліть застарілі ASP-теги з коду, перепишіть використання небезпечних випадкових чисел на CSPRNG-функції та перехоплюйте системні помилки через інтерфейс Throwable.
