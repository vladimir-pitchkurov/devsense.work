Якщо PHP 8.0 «перезапустив платформу», то версія 8.1 наповнює синтаксис глибоким практичним змістом. Завдяки додаванню нативних перерахувань (Enums), readonly-властивостей та перетинів типів безпосередньо в ядро, розробники отримали можливість писати строго типізований код без тонн шаблонного коду. Тим не менш, рантайм став ще більш вимогливим: заборонено прямий перезапис масиву `$GLOBALS`, розширення MySQLi тепер за замовчуванням викидає винятки замість тихих попереджень, а десятки застарілих мовних патернів оголошено deprecated. Нижче наведено детальний аналіз нововведень, практичних прийомів та нюансів міграції.

<a id="enums"></a>
## Enums

Enums — це типобезпечний спосіб представляти “закритий” набор значень.

- **Backed enums** зберігають скалярне значення (`string|int`), зручне для збереження/передачі через API.
- **Pure enums** — тільки ідентичність, добре підходять для доменних станів та вичерпної обробки.

> [!NOTE]
> **А ви знали?**
> Enums у PHP під капотом реалізовані як класи! Це означає, що вони можуть реалізовувати інтерфейси, містити методи (зокрема статичні) та підключати трейти (з обмеженням: трейти не повинні містити властивостей), прямо як звичайні PHP-класи.

```php
// app/Enums/Status.php
enum Status: string
{
    case Draft = 'draft';
    case Published = 'published';
    case Archived = 'archived';
}

// app/Services/PostService.php
function canEdit(Status $status): bool
{
    return $status !== Status::Archived;
}

$status = Status::from('draft');  // Status::Draft
$value  = $status->value;         // 'draft'
```

**Практичні рекомендації**

- Використовуйте enums замість “строкових прапорців” (`'draft'|'published'`) у сигнатурах та DTO.
- Для БД та публічних API зазвичай зручніше backed enums; для внутрішніх workflow — pure enums.
- Комбінуйте з `match` для вичерпної обробки:

```php
// app/Services/PostService.php
function label(Status $status): string
{
    return match ($status) {
        Status::Draft => 'Draft',
        Status::Published => 'Published',
        Status::Archived => 'Archived',
    };
}
```

<a id="readonly-properties"></a>
## Readonly properties

Readonly properties можна присвоїти **лише один раз** — зазвичай у конструкторі. Це великий крок для імутабельних DTO, value objects та безпечніших доменних моделей.

> [!NOTE]
> **А ви знали?**
> Властивості зі специфікатором readonly не можуть мати значень за замовчуванням! Якщо ви спробуєте оголосити `public readonly string $status = 'draft';`, PHP видасть фатальну помилку на етапі компіляції.

```php
// app/DTO/UserProfile.php
final class UserProfile
{
    public function __construct(
        public readonly int $id,
        public readonly string $email,
    ) {}
}
```

**Що змінюється архітектурно**

- Підштовхує до об’єктів “сконструювали повністю — далі не мутуємо”.
- Для DTO-подібних сутностей зменшує потребу у private + getter’ах.
- Чудово поєднується з constructor property promotion.

<a id="first-class-callable"></a>
## First-class callable syntax

PHP 8.1 додає зручний синтаксис для створення closures з callables:

```php
// app/Helpers/StringHelper.php
function normalize(string $s): string
{
    return strtolower(trim($s));
}

// app/Services/DataService.php
$fn = normalize(...);                 // Closure
$out = array_map($fn, [' A ', 'B ']); // ['a', 'b']
```

Це еквівалент `Closure::fromCallable('normalize')`, але коротший і краще читається в пайплайнах.

<a id="fibers"></a>
## Fibers

Fibers — низькорівневий примітив для **кооперативної конкуррентності**. Він сам по собі не робить код async, але дозволяє бібліотекам та фреймворкам будувати async-рантайми, планувальники та “structured concurrency”.

```php
// app/Services/FiberService.php
$fiber = new Fiber(function (): void {
    $value = Fiber::suspend('paused');
    echo "resumed with: {$value}\n";
});

echo $fiber->start() . "\n"; // paused
$fiber->resume('payload');   // resumed with: payload
```

**Коли це важливо**

- Якщо ви використовуєте async-фреймворк/event loop (ReactPHP, Amp): Fibers можуть суттєво спростити інтеграції.
- У класичних request/response застосунках Fibers найчастіше залишаються “інфраструктурою для бібліотек”.

<a id="intersection-types"></a>
## Intersection types

Intersection types виражають “має задовольняти всім цим інтерфейсам/класам одночасно”.

```php
// app/Services/ExporterService.php
function export(iterable&Countable $items): array
{
    if (count($items) === 0) {
        return [];
    }

    return iterator_to_array($items, preserve_keys: true);
}
```

Важливо: intersection types не можна комбінувати з union types у PHP 8.1 (DNF-типи з'являться пізніше у 8.2).

<a id="never-type"></a>
## never return type

Return type `never` означає, що функція **ніколи не повертає** керування: вона завжди кидає виняток або викликає exit.

```php
// app/Helpers/ErrorHelper.php
function fail(string $message): never
{
    throw new RuntimeException($message);
}
```

Це покращує статичний аналіз і робить control flow явним.

<a id="new-in-initializers"></a>
## new in initializers

PHP 8.1 дозволяє `new` вирази у більшій кількості місць: defaults параметрів, static variables, ініціалізація констант та аргументи атрибутів.

```php
// app/Services/Clock.php
final class Clock
{
    public function now(): DateTimeImmutable
    {
        return new DateTimeImmutable('now');
    }
}

// app/Services/HandlerService.php
function handler(Clock $clock = new Clock()): DateTimeImmutable
{
    return $clock->now();
}
```

Це прибирає багато “factory boilerplate” у простих випадках. (У DI-контейнері акуратно з часом життя сервісів.)

<a id="syntax-tweaks"></a>
## Синтаксичні та мовні покращення (0o, unpack, named args після unpack)

### Octal integer literal prefix: `0o` / `0O`

```php
// app/Config/FileConfig.php
$mask = 0o755;
```

### Array unpacking with string keys

```php
// app/Services/ArrayService.php
$a = [1, 'a' => 'b'];
$b = [...$a, 'c' => 'd']; // [1, 'a' => 'b', 'c' => 'd']
```

### Named argument after argument unpacking

```php
// app/Services/ArgumentService.php
foo(...$args, named: $arg);
```

### full_path for file uploads

У `$_FILES` тепер з’являється ключ `full_path` (насамперед для завантажень `webkitdirectory`).

### Практичні рецепти

#### Backed enum з ненадійного введення (`tryFrom`)

```php
// app/Http/Controllers/StatusController.php
$status = Status::tryFrom($row['status']) ?? Status::Draft;
```

#### Пайплайни з first-class callable

```php
// app/Services/PipelineService.php
$normalize = static fn(string $s): string => strtolower(trim($s));
$mapper = $normalize(...);
$lines = array_map($mapper, $raw);
```

<a id="backward-incompatible"></a>
## Зворотно несумісні зміни (нотатки для міграції)

Цей розділ навмисно практичний: він фокусується на речах, які найчастіше реально ламають апгрейд.

### PHP core / language

- **Обмеження на запис у $GLOBALS**: запис у “весь” `$GLOBALS` більше не підтримується (наприклад, `array_pop($GLOBALS)` — помилка). Доступ до елементів `$GLOBALS['x']` як і раніше працює.
- **static variables в успадкованих методах**: успадковані (не перевизначені) методи тепер розділяють static variables з батьківським методом.
- **Optional перед required параметрами**: optional параметри, оголошені до required, вважаються required; у PHP 8.1 це може призводити до `ArgumentCountError` при виклику (навіть із named arguments).
- **Return type compatibility з internal classes**: перевизначення внутрішніх методів без сумісного return type викликає deprecation; для крос-версії використовуйте `#[ReturnTypeWillChange]`.
- **Нові ключові слова**:
  - `readonly` тепер keyword (але все ще можна використовувати як ім'я функції).
  - `never` тепер reserved word (неожна використовувати для імен class/interface/trait та заборонено в namespaces).

### Resource → object migration (продовжується)

Кілька розширень перевели ресурси в об’єкти (перевірки `is_resource()` потрібно замінити на перевірки на `false` або на object types):

- **FileInfo**: `finfo` objects замість `fileinfo` resources.
- **FTP**: `FTP\Connection` objects.
- **IMAP**: `IMAP\Connection` objects.
- **LDAP**: `LDAP\Connection`, `LDAP\Result`, `LDAP\ResultEntry` objects.
- **PgSQL**: `PgSql\Connection`, `PgSql\Result`, `PgSql\Lob` objects.
- **PSpell**: `PSpell\Dictionary` та `PSpell\Config` objects.

### PDO / MySQLi behavior changes

- **MySQLi**: default error reporting mode змінився з “silent” на “exceptions”. Щоб повернути стару поведінку: `mysqli_report(MYSQLI_REPORT_OFF);`
- **PDO**: змінилася поведінка `PDO::ATTR_STRINGIFY_FETCHES` для bool; драйвери SQLite/MySQL стали стабільніше повертати ints/floats як нативні PHP-типи.

### Зміни у стандартній бібліотеці

- `version_compare()` більше не приймає недокументовані скорочення операторів.
- HTML escaping функції тепер за замовчуванням використовують `ENT_QUOTES | ENT_SUBSTITUTE` (лапки екрануються; некоректний UTF-8 замінюється).

<a id="deprecations"></a>
## Deprecated (що краще виправити заздалегідь)

Deprecations у 8.1 — це “майбутні помилки”. Виправивши їх зараз, ви сильно спростите переходи на PHP 8.2+.

### Core deprecations

- Передача `null` у non-nullable параметри вбудованих функцій — deprecated.
- Неявні “втрачені” float → int конверсії — deprecated (ключі масивів, int type declarations в coercive mode, int-оператори).
- Виклик static елемента на trait — deprecated.
- Autovivification з `false` — deprecated (`$x = false; $x[] = 1;`).

### Важливі deprecations розширень

- **Date**: `strftime()` / `gmstrftime()` та `strptime()` deprecated (віддавайте перевагу `date()` / `date_parse_from_format()` / `IntlDateFormatter`).
- **Filter**: `FILTER_SANITIZE_STRING` та `FILTER_SANITIZE_STRIPPED` deprecated.
- **Hash**: `mhash*()` deprecated (використовуйте `hash_*()`).
- **PDO**: `PDO::FETCH_SERIALIZE` deprecated.

<a id="extensions-changes"></a>
## Extensions: важливі зміни

Тут зібрані “корисно знати” зміни, які не завжди ламають код безпосередньо, але впливають на поведінку та експлуатацію.

- **Reflection**: `ReflectionProperty::setAccessible()` / `ReflectionMethod::setAccessible()` більше не мають ефекту (все вважається доступним через Reflection).
- **Phar**: SHA256 використовується за замовчуванням для підписів; підтримано OpenSSL_SHA256/OpenSSL_SHA512.
- **OpenSSL**: підтримано OpenSSL 3.0; доступність шифрів та валідація параметрів стали суворішими.
- **CLI**: `php -a` без readline тепер призводить до помилки.
- **PHPDBG**: видалено remote функціонал.

<a id="common-mistakes"></a>
## Часті помилки

Ось кілька поширених пасток при використанні нових можливостей PHP 8.1:

### 1. Зміна Readonly властивостей всередині класу або в спадкоємцях
Властивість зі специфікатором `readonly` не може бути перезаписана навіть зсередини класу або в його спадкоємцях після того, як вона була один раз ініціалізована.

```php
// app/DTO/UserProfile.php
// ПОГАНО: Модифікація readonly-властивості після ініціалізації викличе Error
class UserProfile {
    public function __construct(public readonly string $email) {}

    public function updateEmail(string $newEmail): void {
        $this->email = $newEmail; // Fatal Error: Cannot modify readonly property
    }
}
```

### 2. Автозаповнення масиву з хибного значення (Autovivification from False)
У PHP 8.1 автоматичне створення масиву з булевої змінної зі значенням `false` оголошено застарілим (deprecated).

```php
// app/Services/ArrayService.php
// ПОГАНО: Викличе попередження про застарілість у PHP 8.1 (і фатальну помилку в PHP 8.2)
$data = false;
$data[] = 'value';

// ДОБРЕ: Спочатку ініціалізуйте змінну порожнім масивом
$data = [];
$data[] = 'value';
```

### 3. Переприсвоєння масиву $GLOBALS
Ви можете змінювати змінні всередині `$GLOBALS`, але ви не можете переприсвоювати або повністю знищувати змінну `$GLOBALS`.

```php
// app/Services/LegacyService.php
// ПОГАНО: Викличе Fatal Error у PHP 8.1
$GLOBALS = []; 

// ПОГАНО: Переприсвоєння посилання також заборонено
$GLOBALS = &$someOtherArray;
```

<a id="self-test-quiz"></a>
## Квіз для самоперевірки

Перевірте свої знання можливостей PHP 8.1. Виберіть відповідь та звіртеся під спойлером.

### Запитання 1: Що з переліченого є правильним для властивостей Readonly в PHP 8.1?
- A) Їх можна перепризначити, якщо нове значення має той самий тип.
- B) Їх можна оголошувати лише у типізованих властивостях (без типів не можна).
- C) Їм можна задати значення за замовчуванням при оголошенні класу.

<details>
<summary>Показати відповідь</summary>

**Правильна відповідь: B**
У PHP 8.1 специфікатор `readonly` може бути застосований лише до типізованих властивостей. Оголошення властивості тільки для читання без зазначення типу викличе помилку синтаксису. Також вони не можуть мати значень за замовчуванням і не можуть бути перепризначені після ініціалізації.
</details>

### Запитання 2: Що станеться, якщо спробувати автоматично створити масив зі змінної зі значенням `false` (наприклад, `$x = false; $x[] = 1;`) у PHP 8.1?
- A) Код відпрацює без помилок, перетворивши змінну на масив.
- B) Викличеться попередження про застарілість (deprecation warning).
- C) Виникне миттєва фатальна помилка (Fatal Error).

<details>
<summary>Показати відповідь</summary>

**Правильна відповідь: B**
У PHP 8.1 автоматичне створення масиву з `false` (autovivification) є застарілою поведінкою та викликає попередження. У PHP 8.2 це попередження перетворюється на Fatal Error.
</details>
