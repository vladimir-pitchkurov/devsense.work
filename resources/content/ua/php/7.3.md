# PHP 7.3: Головні нововведення

Чи траплялося вам годинами відлагоджувати упалий на продакшені імпорт даних лише тому, що ви забули перевірити `json_last_error()` після парсингу JSON? PHP 7.3 вирішує цей одвічний біль розробників, впроваджуючи `JsonException` за допомогою прапорця `JSON_THROW_ON_ERROR`. Цей реліз значно підвищує зручність розробки (DX), пропонуючи довгоочікувані відступи в heredoc-рядках, висячі коми в аргументах виклику функцій та низку корисних вбудованих хелперів.

<a id="flexible-heredoc"></a>
## Гнучкий Heredoc і Nowdoc

Закриваючий маркер **більше не зобов’язаний** перебувати на самому початку рядка (на нульовій колонці). Тепер його можна **зсунути вправо (зробити відступ)**, і цей самий відступ буде **автоматично віднятий від кожного рядка** всередині тіла heredoc. Це робить вбудований SQL, HTML або текст допомоги в CLI-командах чистим і акуратним у коді за PSR-12.

**Ризик міграції:** якщо тіло рядка містить той самий токен, який використовується як закриваючий маркер (нехай навіть з відступом), PHP може вирішити, що рядок завершився завчасно. Використовуйте **унікальні довгі маркери** (наприклад, `SQL_GET_USER` замість звичайного `SQL`).

```php
// src/QueryBuilder.php
$query = <<<SQL
    SELECT id, name
    FROM users
    WHERE active = 1
    SQL;
```

> [!NOTE]
> Чи знали ви? Відступ закриваючого маркера задає еталон для видалення пробілів з тексту. Якщо хоча б один рядок у тілі heredoc матиме менший відступ, ніж закриваючий маркер, PHP видасть помилку ParseError.

<a id="trailing-commas-calls"></a>
## Висячі коми у викликах функцій

У викликах функцій та методів тепер дозволено залишати висячу кому в кінці списку аргументів. Це робить diff у комітах чистішим та зручнішим при генерації списків аргументів:

```php
// src/LoggerService.php
$this->logger->info(
    'User saved',
    [
        'id' => $user->id,
        'ip' => $request->ip(),
    ],
);
```

Це стосується лише **виклику** функцій. Оголошення сигнатури виду `function foo($a,)` у PHP 7.3, як і раніше, заборонено (висячі коми в параметрах оголошень з'являться тільки в PHP 8.0).

> [!NOTE]
> Чи знали ви? Висячі коми при оголошенні функцій у PHP 7.3 викликають синтаксичну помилку ParseError. Вони дозволені виключно при безпосередньому запуску (виклику) функцій.

<a id="list-references"></a>
## Деструктуризація за посиланням у `list()` и `[]`

При розпакуванні масивів тепер можна біндити змінні **за посиланням**:

```php
// src/Destructure.php
[&$head, $middle, &$tail] = $parts;
// І аналогічно з list():
list(&$a, $b) = $pair;
```

Використовуйте це тільки за наявності явної потреби змінювати частини спільного масиву; в інших випадках краще працювати за значенням.

<a id="instanceof-literals"></a>
## `instanceof` з літералами

Ліва частина виразу `instanceof` може бути **літералом**, у цьому випадку вираз завжди повертає **`false`**. Це додано для консистентності парсера та зручності статичного аналізу, а не для застосування в логіці рантайму.

```php
// src/Validation.php
$result = (123 instanceof User); // false
```

<a id="compile-error"></a>
## `CompileError`

Клас `CompileError` додано як базовий виняток для помилок компіляції; `ParseError` тепер **успадковується** від нього. Найчастіше це помітно, коли **`token_get_all($code, TOKEN_PARSE)`** спотикається на розборі коду — помилки, які раніше призводили до фатального збою, тепер можуть перехоплюватися інструментами аналізу коду.

```php
// src/ErrorHandling.php
try {
    eval('invalid code');
} catch (CompileError $e) {
    echo "Помилка компіляції: " . $e->getMessage();
}
```

<a id="core-helpers"></a>
## Нові хелпери ядра

* **`array_key_first($array)`** / **`array_key_last($array)`** — позбавляють від костилів з `reset()`/`end()` для отримання ключів.
* **`is_countable($value)`** — повертає `true` для масивів та об'єктів, що реалізують `Countable` (заміна конструкції `is_array($x) || $x instanceof \Countable`).
* **`hrtime($as_number = false)`** — монотонний системний час високої точності (в наносекундах). Ідеально для вимірювання інтервалів виконання коду, оскільки воно не піддається стрибкам годинника (на відміну від `microtime`).
* **`net_get_interfaces()`** — видає список мережевих інтерфейсів сервера (залежить від платформи).

```php
// src/Helpers.php
$firstKey = array_key_first($myArray);
if (is_countable($data)) {
    $count = count($data);
}
```

> [!NOTE]
> Чи знали ви? Функція `hrtime()` використовує монотонний годинник операційної системи, який захищений від коригувань часу (наприклад, по протоколу NTP). Це єдиний надійний спосіб вимірювати мікро-інтервали виконання коду.

<a id="json-exceptions"></a>
## JSON: `JSON_THROW_ON_ERROR` і `JsonException`

Передавайте флаг **`JSON_THROW_ON_ERROR`** у функції **`json_encode()`** та **`json_decode()`**, щоб ловити виняток **`JsonException`** замість стомлюючих ручних перевірок `json_last_error()`.

```php
// src/JsonParser.php
try {
    $data = json_decode($json, true, 512, JSON_THROW_ON_ERROR);
} catch (JsonException $e) {
    // Обробка помилки
}
```

<a id="argon2id"></a>
## Хешування паролей: Argon2id

Якщо PHP зібрано з актуальною бібліотекою **libargon2**, функція **`password_hash()`** приймає алгоритм **`PASSWORD_ARGON2ID`**, який є гібридною (i+d) версією Argon2.

```php
// src/Security.php
$hash = password_hash('secret', PASSWORD_ARGON2ID);
```

<a id="extensions-stdlib"></a>
## Розширення і стандартна бібліотека

* **PCRE**: рушій оновлено до **PCRE2** — можливі невеликі зміни в поведінці регулярних виразів (більш суворі діапазони в символьних класах); **`preg_quote()`** тепер екранує символ **`#`**.
* **Multibyte (mbstring)**: підтримка **Unicode 11**, робота з рядками **>2 ГБ**, прискорені регістрові операції; іменовані кишені (captures) в **`mb_ereg_*`** приведені до ергономіки PCRE.
* **LDAP**: підтримка LDAP **controls** у функціях пошуку та модифікації, а також у **`ldap_parse_result()`**.
* **MySQLi / PDO MySQL**: підготовлені вирази тепер коректно віддають **дробову частину секунд** для полів типів `DATETIME(6)` / `TIMESTAMP(6)`.
* **FPM**: нові налаштування логування (`log_limit`, `log_buffering`, `decorate_workers_output`); функція **`getallheaders()`** тепер доступна всередині FPM.
* **Сесії та кукі**: нові параметри для **`session_set_cookie_params()`** та кукі-опція **`samesite`** в `setcookie()`.
* **Стріми**: адреси IPv6, що повертаються з **`stream_socket_get_name()`**, тепер обгорнуті в квадратні дужки (наприклад, `[::1]:1337`).
* **SPL autoload**: якщо один автозавантажувач **викидає виняток**, наступні завантажувачі в стеку **ігноруються** (раніше вони викликалися ланцюжком).
* **IMAP**: авторизація за протоколами **rsh/ssh вимкнена за замовчуванням** з міркувань безпеки (`imap.enable_insecure_rsh`).

## Практичні рецепти

### Перевірка перед `count()`

```php
// src/recipes.php
if (is_countable($rows)) {
    $n = count($rows);
}
```

### Надійне отримання першого і останнього ключа

```php
// src/recipes.php
$firstKey = array_key_first($map);
$lastKey = array_key_last($map);
```

### Строгий парсинг JSON

```php
// src/recipes.php
try {
    $payload = json_decode($raw, true, 512, JSON_THROW_ON_ERROR);
} catch (JsonException $e) {
    // Логування або прокидання
}
```

### Високоточне вимірювання часу

```php
// src/recipes.php
$t0 = hrtime(true);
// ... виконання коду ...
$elapsedNs = hrtime(true) - $t0;
```

<a id="common-mistakes"></a>
## Часті помилки

Нижче описано типові помилки розробників при переході на PHP 7.3:

### 1. Неправильний відступ у Heredoc закриваючому маркері
Якщо хоча б один рядок тіла зсунутий лівіше, ніж закриваючий маркер, або після маркера залишилися пробіли — PHP видасть помилку парсингу.
```php
// src/BadHeredoc.php
// Погано: рядки всередині тіла зсунуті лівіше маркера TEXT, викличе ParseError
$text = <<<TEXT
Line 1
    Line 2
      TEXT;
```
```php
// src/GoodHeredoc.php
// Добре: відступ закриваючого маркера відповідає мінімальному відступу рядків тіла
$text = <<<TEXT
    Line 1
    Line 2
    TEXT;
```

### 2. Використання `continue` в конструкції `switch`
В PHP оператор `continue` всередині switch поводиться так само, як `break`. Розробники часто помиляються, очікуючи, що він перейде до наступного кроку зовнішнього циклу. У PHP 7.3 це викликає попередження.
```php
// src/BadContinueSwitch.php
// Погано: викличе попередження "continue" в switch прирівнюється до "break"
foreach ($items as $item) {
    switch ($item) {
        case 'skip':
            continue;
    }
}
```
```php
// src/GoodContinueSwitch.php
// Добре: використовуйте "continue 2" для переходу на наступну ітерацію зовнішнього циклу foreach
foreach ($items as $item) {
    switch ($item) {
        case 'skip':
            continue 2;
    }
}
```

<a id="limitations"></a>
## Обмеження

* **Висячі коми**: Підтримуються виключно у викликах (аргументах функцій/методів). Написання виду `function test($a, $b,) {}` викине синтаксичну помилку ParseError.
* **Гнучкий Heredoc**: Закриваючий рядок повинен містити тільки маркер і крапку з комою (або переклад рядка). Будь-які пробільні символи після маркера зламають парсер.

<a id="backward-incompatible"></a>
## Зворотно несумісні зміни (міграційні нотатки)

### Ядро

* **Гнучкий heredoc/nowdoc**: рядки, в яких **міститься закриваючий маркер** (навіть з відступом), можуть змінити поведінку або викликати **ParseError**.
* **`continue` всередині `switch`**: тепер викликає **warning**. **Перевірте всі конструкції `switch` з `continue`.**
* **`ArrayAccess` з числовими рядковими ключами**: для ключів на кшталт **`"123"`** PHP **більше не приводить** їх до цілого числа при зверненні до об'єктів з `ArrayAccess` — викликається **`offsetGet("123")`** замість **`offsetGet(123)`**.
* **Статичні властивості та посилання**: статичні властивості класів, успадковані від батька, більше не можна розділяти за допомогою посилань.
* **Посилання із звернень до масивів/властивостей**: посилання, що повертаються з ланцюжків читань масивів або властивостей, розгортаються негайно.
* **Розпакування `...$traversable`**: **нецілі ключі** у `Traversable` об'єктів більше **не розпасовуються** при виклику функцій.
* **Warnings підвищено до винятків (`EH_THROW`)**: такі винятки більше не пишуться в **`error_get_last()`**.
* **Текст `TypeError`**: замість **`integer` / `boolean`** тепер виводиться **`int` / `bool`**.
* **`compact()`**: звернення до неіснуючої змінної всередині `compact()` викличе **notice**.
* **`getimagesize()`**: MIME-тип для BMP тепер віддається як **`image/bmp`** (замість застарілого `image/x-ms-bmp`).
* **Cookies (з PHP 7.3.23)**: імена вхідних cookie-файлів **не** декодуються з URL-формату (безпека).

### BCMath

* Попередження тепер йдуть через стандартний обробник помилок PHP.
* **`bcmul()` / `bcpow()`** більш строго дотримуються вказаного масштабу (scale).

### IMAP

* Тунелювання **rsh/ssh** вимкнено. Якщо потрібно увімкнути — використовуйте **`imap.enable_insecure_rsh`**.

### Регулярні вирази Multibyte (`mb_ereg_*`)

* Іменовані кишені (captures) змінюють структуру результуючого масиву.

### MySQLi та PDO MySQL

* Дробова частина секунд тепер видна в результатах запитів для тайм stamp'ів.

### Reflection

* Експорт типів у рядок використовує назви **`int` / `bool`**.

### SimpleXML

* Математичні операції над текстовими вузлами SimpleXML тепер автоматично приводять значення до int або float замість примусового int.

### Платформа

* Припинено підтримку операційної системи BeOS.
* **`stream_socket_get_name()`** форматує адреси IPv6 з використанням квадратних дужок.

<a id="deprecations"></a>
## Deprecated (виправити завчасно)

Головне:

* **Регістронезалежні константи**: передача `true` третім аргументом у функцію `define()`.
* **Функція з ім'ям `assert()` всередині простору імен** — уникайте; рушій обробляє `assert()` на системному рівні.
* **Не-рядкові голки** у функціях пошуку підрядка (`strpos` та ін.) — приводьте аргумент до рядка явно або використовуйте `chr()`.
* Функції **`fgetss()`**, **`gzgetss()`**, **`SplFileObject::fgetss()`** та стрім-фільтр **`string.strip_tags`**.
* Прапорці **`FILTER_FLAG_SCHEME_REQUIRED` / `FILTER_FLAG_HOST_REQUIRED`** при валідації URL (тепер вони включені за замовчуванням).
* Функція **`image2wbmp()`** (GD).
* Константа **`Normalizer::NONE`** при ICU ≥ 56.
* Застарілі аліаси **`mbereg_*()`** — перепишіть на **`mb_ereg_*()`**.

<a id="other-changes"></a>
## Інші зміни та експлуатація (збірка, INI, продуктивність)

* **Логування Syslog**: налаштування **`syslog.facility`**, **`syslog.filter`**, **`syslog.ident`** при перенаправленні `error_log=syslog`.
* **Збирач сміття (GC)**: оптимізовано чистку циклічних посилань.
* **`var_export()`**: при експорті об'єктів класу **`stdClass`** генерується код виду **`(object) array(...)`** замість застарілого `__setState`.
* **FTP**: за замовчуванням використовується двійковий режим передачі файлів (binary).
* **FILTER_VALIDATE_FLOAT**: додано опцію **`thousand`** для кастомних роздільників тисяч.
* **PDO SQLite**: додано можливість відкривати базу даних у режимі «тільки для читання» (`PDO::SQLITE_OPEN_READONLY`).
* **cURL**: тепер потрібна бібліотека **libcurl версії 7.15.5 або вище**.
* **OPcache**: видалено застарілу директиву `opcache.inherited_hack`.

1. **Яке твердження про висячі коми в PHP 7.3 є правильним?**
   * А) Вони дозволені при виклику функцій, але заборонені при їх оголошенні.
   * Б) Вони дозволені при оголошенні функцій, але заборонені при їх виклику.
   * В) Вони дозволені і при оголошенні, і при виклику.
   * Г) Вони по-прежнему викликають синтаксичну помилку всюди.

   <details>
   <summary>Показати відповідь</summary>
   
   **Правильна відповідь: А**  
   PHP 7.3 дозволяє ставити кому після останнього аргументу при виклику функції. Однак у списку параметрів при оголошенні функції висяча кома призведе до помилки ParseError.
   </details>

2. **Як поведеться PHP 7.3 при виявленні `continue` всередині блоку `switch`?**
   * А) Мовчки перейде до наступної ітерації зовнішнього циклу.
   * Б) Викличе фатальну помилку компіляції.
   * В) Видасть попередження (Warning) про те, що `continue` в `switch` працює як `break`.
   * Г) Видасть попередження Deprecated.

   <details>
   <summary>Показати відповідь</summary>
   
   **Правильна відповідь: В**  
   PHP 7.3 видає Warning, оскільки розробники часто плутають логіку і очікують продовження зовнішнього циклу, тоді як в PHP `continue` всередині switch еквівалентний `break`.
   </details>

3. **Яка функція була додана в PHP 7.3 для перевірки можливості підрахунку елементів змінної перед запуском `count()`?**
   * А) `is_iterable()`
   * Б) `is_countable()`
   * В) `can_count()`
   * Г) `is_array_or_countable()`

   <details>
   <summary>Показати відповідь</summary>
   
   **Правильна відповідь: Б**  
   Функція `is_countable()` повертає `true`, якщо їй передано масив або об'єкт, що реалізує інтерфейс `Countable`.
   </details>

<a id="closing-thoughts"></a>
## Підсумок

Перехід на PHP 7.3 вимагає **уважного аналізу диффу**: знайдіть у коді конструкції **`continue` + `switch`**, використання **`compact(`**, реалізації **`ArrayAccess`**, маркери **heredoc** та розпакування параметрів **`...$generator`**. Запустіть тести для регулярних виразів та дат, після чого можна рухатися далі — версія **7.4** принесе куди більш масштабні зміни.
