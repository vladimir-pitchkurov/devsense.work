# PHP 7.2: Головні нововведення

Що, як звичайний підрахунок елементів змінної раптово почне забивати ваші логи попередженнями? PHP 7.2 вводить суворий контроль за використанням функції `count()`, викриваючи тисячі прихованих багів у проектах, де розробники викликали її для нелічених типів, таких як `null` або `boolean`. Ця версія наводить лад у повсякденній розробці завдяки типу `object`, розширенню типів параметрів, вбудованій бібліотеці libsodium та суворій гігієні попереджень.

<a id="object-type"></a>
## Тип `object`

Тепер можна вказувати **`object`** як типи аргументів та значень повернення — йому відповідає будь-який об'єкт. Це нововведення доповнює правила коваріантності та контраваріантності типів по мірі розвитку лінійки PHP 7.x.

```php
// src/ObjectHandler.php
function acceptsAnyObject(object $x): void 
{
    // Робота з об'єктом
}
```

> [!NOTE]
> Чи знали ви? До PHP 7.2 ви не могли оголошувати загальні типи об'єктів в аргументах. Розробникам доводилося розраховувати на PHPDoc-анотації або робити ручні перевірки через `is_object()`.

<a id="type-widening"></a>
## Розширення типів параметрів (type widening)

Класи-нащадки тепер можуть **опускати типи параметрів**, оголошені в батьківських методах або інтерфейсах (це безпечно з точки зору контраваріантності). Проте ви **не можете** звужувати типи або змінювати їх на інші неспоріднені типи — PHP відхилить такі некоректні перевизначення.

```php
// src/Logger.php
interface Logger {
    public function log(string $msg);
}

class MyLogger implements Logger {
    // Тип параметра опущено (розширено), що є валідним у PHP 7.2
    public function log($msg) {
        echo $msg;
    }
}
```

> [!NOTE]
> Чи знали ви? Розширення типів параметрів дозволяє бібліотекам оновлювати свої інтерфейси, додаючи строгі типи, без моментального порушення роботи коду користувачів, чиї класи-нащадки опускають типи.

<a id="pdo-debug"></a>
## PDO: детальний `debugDumpParams()`

Метод `PDOStatement::debugDumpParams()` тепер відображає **повний SQL-запит**, відправлений на сервер при використанні **емульованих підготовлюваних запитів** (emulated prepares), включаючи зв'язані значення. Це значно спрощує відлагодження формування SQL.

```php
// src/DatabaseDebug.php
$stmt = $pdo->prepare("SELECT * FROM users WHERE status = :status");
$stmt->execute(['status' => 'active']);
$stmt->debugDumpParams();
```

<a id="ldap-exop"></a>
## LDAP EXOP (розширені операції)

Додано хелпери **`ldap_exop()`**, **`ldap_exop_passwd()`**, **`ldap_exop_whoami()`**, **`ldap_parse_exop()`**, а також нові константи на кшталт **`LDAP_EXOP_START_TLS`** — це спрощує роботу зі стандартними протоколами EXOP без низькорівневої обв'язки.

<a id="sockets-addrinfo"></a>
## Sockets: `socket_addrinfo_*`

Функції **`socket_addrinfo_lookup()`**, **`socket_addrinfo_connect()`**, **`socket_addrinfo_bind()`**, **`socket_addrinfo_explain()`** обгортають системні виклики `getaddrinfo()`. Використовуйте їх замість ручного розбору адрес IPv4/IPv6.

<a id="sodium"></a>
## Sodium (libsodium) в ядрі

У PHP 7.2 розширення **Sodium** включено за замовчуванням. Воно надає функції AEAD-шифрування, хешування та генерації ключів. Розглядайте його як стандарт при написанні **нового криптографічного коду** замість видаленого розширення **mcrypt**.

```php
// src/CryptoHelper.php
$nonce = random_bytes(SODIUM_CRYPTO_SECRETBOX_NONCEBYTES);
$key = sodium_crypto_secretbox_keygen();
$ciphertext = sodium_crypto_secretbox('message', $nonce, $key);
```

<a id="extensions-stdlib"></a>
## Стандартна бібліотека та розширення

* Функції **`utf8_encode()` / `utf8_decode()`** перенесено в ядро строкових функцій (тепер вони не вимагають обов'язкової наявності розширення XML).
* Функції **`mail()` / `mb_send_mail()`** тепер підтримують передачу заголовків у вигляді **масивів** (на додачу до рядків).
* Розширення **DBA** отримало підтримку драйвера **LMDB**.
* **GD**: функція **`imageantialias()`** адаптована під системну бібліотеку libgd; **`imagegd()`** точніше зберігає повноколірні (truecolor) зображення.
* Виклик **`session_module_name('user')`** тепер викликає помилку (recoverable error) замість німого збою.

<a id="practical-recipes"></a>
## Практичні рецепти

### Захищений виклик `count()`

```php
// src/recipes.php
if (is_array($x) || $x instanceof \Countable) {
    $n = count($x);
}
```

(Функція `is_countable()` з'явиться тільки в PHP 7.3; на 7.2 використовуйте цю явну умову.)

### Безпечне використання `get_class()`

```php
// src/recipes.php
$cls = is_object($obj) ? get_class($obj) : self::class;
```

<a id="common-mistakes"></a>
## Часті помилки

Нижче наведено типові помилки розробників при переході на PHP 7.2:

### 1. Підрахунок нелічених типів
Передача `null`, чисел, рядків або стандартних об'єктів у `count()` тепер викликає Warning.
```php
// src/BadCount.php
// Погано: Передача null викличе Warning: count(): Parameter must be an array or an object that implements Countable
$data = null;
echo count($data); 
```
```php
// src/GoodCount.php
// Добре: Перевіряйте тип перед підрахунком
$data = null;
echo (is_array($data) || $data instanceof \Countable) ? count($data) : 0;
```

### 2. Передача `null` у функцію `get_class()`
У минулих версіях виклик `get_class(null)` повертав ім'я поточного класу, звідки був викликаний метод. Тепер це викликає E_WARNING.
```php
// src/BadGetClass.php
// Погано: Викличе попередження, якщо $obj виявиться null
$className = get_class($obj); 
```
```php
// src/GoodGetClass.php
// Добре: Перевіряйте, чи є змінна об'єктом
$className = is_object($obj) ? get_class($obj) : 'DefaultClass';
```

<a id="limitations"></a>
## Обмеження

* **Загальний тип `object`**: Ви не можете вказати структуру об'єкта; тип просто перевіряє, чи є значення екземпляром якогось класу. Ви не можете відсікти базовий `stdClass` засобами тайп-хінтінгу.
* **Інтеграція libsodium**: Надає низькорівневі криптографічні примітиви. Вони дуже надійні, але вимагають від розробника розуміння базової криптографії (ключі, нонси), щоб не допустити вразливостей.

<a id="backward-incompatible"></a>
## Зворотно несумісні зміни

### Ядро та типи

* Функція **`number_format()`** більше не повертає значення **`-0`** у пограничних випадках обчислень з плаваючою точкою.
* **Приведення масивів до об'єктів (і навпаки)** з числовими ключами стало консистентним. Звернення виду **`$obj->{0}`** працює коректно.
* Виклик **`get_class(null)`** тепер **викликає warning**; не передавайте null або опускайте аргумент.
* Виклик **`count()`** (та його аліасу **`sizeof()`**) для **нелічених** типів генерує **`E_WARNING`**. Старий код, що очікував `count(null) === 0`, почне писати попередження.
* Застарів старий автозавантажувач **`__autoload`**, використовуйте стандартний SPL стек.

### Розширення

* **Розширення mcrypt повністю видалено з ядра PHP**. При крайній необхідності його можна встановити через PECL, але правильний шлях — **перейти на OpenSSL або Sodium**.

<a id="deprecations"></a>
## Deprecated (виправити завчасно)

Головне:

* Магічна функція **`__autoload()`** — замінить на **`spl_autoload_register()`**.
* Використання нецитованих констант (barewords), які раніше викликали notice, тепер видає **warning**.
* Устаріли функції **`create_function()`**, **`each()`**, виклики **`assert()`** зі строковими аргументами, виклик **`parse_str()`** з одним аргументом, **`read_exif_data()`**, функції GD **`png2wbmp` / `jpeg2wbmp`**.

<a id="other-changes"></a>
## Інші зміни та збірка

* Unix: для компіляції потрібен Autoconf версії 2.64 або вище.
* Розширення **mcrypt** винесено в **PECL**. Використовуйте **Sodium/OpenSSL** для роботи з криптографією.

<a id="closing-thoughts"></a>
## Підсумок

Перехід на PHP 7.2 — це чудовий привід **видалити залишки коду під mcrypt**, провести пошук за використанням **`count(`** для змінних, які можуть бути null, та прибрати виклики **`get_class(null)`**. Після цього можна переходити до версії 7.3 з її `JsonException`, `is_countable()` та покращеним heredoc.
