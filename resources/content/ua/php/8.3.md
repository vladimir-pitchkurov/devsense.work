# PHP 8.3: Головні нововведення

Випуск про «полірування» для команд на PHP 8.2.x: сильніші інваріанти (`#[Override]`, типізовані константи), зручніші JSON та рядки (`json_validate`, `str_increment`/`str_decrement`), плюс довгий хвіст дрібних змін runtime, які проявляються під навантаженням або в рідкісних гілках коду.

PHP 8.3 фокусується на посиленні суворості інтерфейсних контрактів та оптимізації споживання ресурсів. З введенням типізованих констант класів та атрибута `#[\Override]` процес рефакторингу стає набагато безпечнішим, запобігаючи невідповідностям у сигнатурах методів на етапі компіляції. Для додатків, що обробляють великі обсяги зовнішніх даних, нова функція `json_validate()` пропонує легковагий спосіб валідації JSON без зайвих витрат пам'яті на парсинг. У той же час, рантайм стандартної бібліотеки став суворішим (особливо це помітно у функції `range()` та мережевих сокетах), а звичні інкременти нечислових рядків тепер офіційно оголошено deprecated. Нижче наведено інструкцію для безперешкодного переходу.

<a id="override-attribute"></a>
## `#[\Override]` — ловимо відсутні override на етапі компіляції

Позначайте методи, які повинні перевизначати батька або інтерфейс. Якщо ім'я помилкове або метод прибрали з батька, **PHP падає рано**, замість того щоб тихо додати новий метод.

> [!NOTE]
> **А ви знали?**
> Атрибут `#[Override]` повністю ігнорується рушієм PHP під час виконання (runtime)! Він призначений виключно для перевірки на етапі компіляції, допомагаючи вчасно виявити помилки рефакторингу та розбіжності в сигнатурах до того, как код буде запущено.

```php
// app/Services/Loggers/FileLogger.php
interface Logger
{
    public function log(string $message): void;
}

final class FileLogger implements Logger
{
    #[\Override]
    public function log(string $message): void
    {
        // ...
    }
}
```

Особливо корисно в великих кодових базах при рефакторингах інтерфейсів.

<a id="typed-constants"></a>
## Типізовані константи класу

Константи в **класах, інтерфейсах, трейтах та enum** можуть оголошувати типи — константи наближаються до решти системи типів.

```php
// app/Config/AppConfig.php
interface Config
{
    public const string APP_NAME = 'MyApp';
}
```

Менше помилок «не той тип константи», які раніше спливали тільки в місцях використання.

<a id="readonly-tweaks"></a>
## Readonly: анонимні класи та клонування

- **Анонімні класи** можуть бути оголошені `readonly`.
- **Readonly-властивості** можна **переініціалізувати при `clone`** (всередині методу `__clone()`) — клони immutable-об'єктів стають менш болісними, ніж суто на патернах 8.2.

<a id="language-qol"></a>
## Покращення мови (quality-of-life)

- **Динамічний доступ до константи класу**: `SomeClass::{$name}` для імен констант під час виконання.
- **Ініціалізатори static-змінних** можуть використовувати довільні вирази (не тільки константи).
- **`final` у методів трейту** при імпорті методу з трейту.
- **Замикання з magic methods** можуть приймати **іменовані аргументи** при виклику.
- **`php.ini`**: синтаксис fallback/default для чистішої конфігурації.

<a id="new-functions"></a>
## Нові функції (`json_validate`, `str_*`, DOM, Random та ін.)

### `json_validate()`

Перевірка JSON **без декодування** у значення PHP — зручно для API, черг та швидкої перевірки до дорогого `json_decode()`.

> [!NOTE]
> **А ви знали?**
> Функція `json_validate()` споживає суттєво менше пам'яті, ніж `json_decode()`, оскільки вона не створює жодних масивів або об'єктів PHP в оперативній пам'яті! Вона лише сканує синтаксис рядка, що робить її ідеальним вибором для валідації великих payloads.

```php
// app/Http/Middleware/JsonValidateMiddleware.php
if (!json_validate($payload)) {
    throw new InvalidArgumentException('Invalid JSON');
}
$data = json_decode($payload, true, flags: JSON_THROW_ON_ERROR);
```

### `str_increment()` / `str_decrement()`

Краща заміна застарілим `++`/`--` для рядків (див. deprecations). Використовуйте для алфавітно-цифрових лічильників, де раніше спиралися на оператори інкременту.

```php
// app/Services/CounterService.php
$next = str_increment('a9'); // крок без рядкового ++
$prev = str_decrement($next);
```

### DOM, Intl, Random, POSIX та ін.

У PHP 8.3 додано багато методів **DOM** (наприклад `insertAdjacentElement`, `getRootNode`, `replaceChildren`), helper’ів **Intl** для календарів, методів **Random** у `Randomizer` (`getFloat`, `nextFloat`, …) та функцій **POSIX** (`sysconf`/`pathconf`/`eaccess`) — корисно для системних скриптів та tooling’у.

<a id="backward-incompatible"></a>
## Зворотно несумісні зміни (нотатки для міграції)

### Стек / таймери / fibers

- **Глибока рекурсія** біля межі стека може викинути `Error` при перевищенні `zend.max_allowed_stack_size` (мінус резерв); у fibers враховується `fiber.stack_size`.
- **Zend Max Execution Timers** за замовчуванням **включені** для ZTS-збірок на Linux — стежте за довгоживучими CLI-воркерами.

### Процеси

- **`proc_get_status()`** на POSIX повертає коректні значення при **повторних** викликах; результат може **кешуватися** (дивіться ключ `"cached"`). **`proc_close()`** після `proc_get_status()` тепер дає коректний код виходу (не `-1`).

### Масиви та трейти

- **Видимість констант класу**: при успадкуванні з **інтерфейсів** тепер перевіряється variance — код із м'якшою видимістю може вимагати правок.
- **Порожній масив + негативний перший індекс**: наступний неявний ключ — `n+1` (не `0`).
- **Трейти зі static-властивостями**: успадковані static у батька **переоголошуються** для кожного класу, що використовує трейт (окреме сховище) — може торкнутися тонкого static-стану.

### Стандартна бібліотека (високий ризик)

- **`range()`**: суворіша валідація (`TypeError`/`ValueError` для поганих входів), більше попереджень на дивних межах, інша поведінка для символьних діапазонів, коли межі виглядають як числа — **перевірте** код, де діапазони будуються з користувацького введення.
- **`number_format()`**: негативний `$decimals` тепер округлює **до** десяткової крапки (раніше ігнорувалося).
- **`file()`**: невірні комбінації прапорців відхиляються (наприклад `FILE_APPEND` раніше мовчки приймався).

### Date / DOM / FFI / Opcache

- **Date**: виразніші ієрархії **`DateError`/`DateException`** замість загальних попереджень/винятків — оновіть `catch`.
- **DOM**: поведінка ближче до специфікації для вузлів без батька; правки **`createAttributeNS()`**; нові члени можуть **конфліктувати** з користувацькими підкласами — перевірте сумісність сигнатур.
- **FFI**: `void` C-функції повертають **`null`**, а не фіктивний об'єкт `FFI\CData:void`.
- **Opcache**: `opcache.consistency_checks` **видалений** (був несумісний з tracing JIT / кешем успадкування).

### WeakMap

- **Самопосилальні ключі** в `WeakMap` можуть збиратися в циклах, де досяжність є тільки через ітерацію — перегляньте екзотичні кеші.

<a id="deprecations"></a>
## Deprecated (інкремент/декремент рядків, `get_class()`, assert INI)

### Рядкові `++` / `--`

Інкремент/декремент для **порожніх або нечислових** рядків позначений deprecated; **нечисловий інкремент** — «м'який» deprecated. Для нового коду кращі **`str_increment()`** / **`str_decrement()`**.

### `get_class()` / `get_parent_class()` без аргументів

Виклик **без аргументів** deprecated — передавайте об'єкт або ім'я класу явно.

### Assert

- **`assert_options()`** та пов'язані **константи** — deprecated.
- **INI-налаштування `assert.*`** — deprecated; міграція описана в розділі migration 8.3 про обробку INI.

### Інше

- **Reflection**: `ReflectionProperty::setValue($value)` (один аргумент) для static-властивостей deprecated — для static передавайте `null` як об'єкт.
- **SQLite3**: кращі винятки; `enableExceptions(false)` дає deprecation.
- **Random**: варіант `MT_RAND_PHP` deprecated.

<a id="other-changes"></a>
## Інші зміни та експлуатація (gc_status, streams, highlights)

- **`gc_status()`** віддає більше полів за часом (collector/destructor/free) — корисно при налаштуванні пам'яті.
- **Streams**: `fread()` на сокетах може повернути раніше при наявності даних у буфері; memory streams поводяться ближче до файлів при seek за кінець.
- **`open_basedir`**: runtime `ini_set` відхиляє шляхи з `..` навіть з префіксом `./`.
- **highlight_string/file**: змінилася структура HTML — оновіть снапшоти тестів, якщо підсвічування порівнюєте порозрядно.

## Часті помилки

Ось кілька поширених пасток при переході на PHP 8.3:

### 1. Використання оператора інкременту (++) на нечислових рядках
Використання операторів `++` або `--` на нечислових рядках у PHP 8.3 викликає попередження про застарілість (deprecation warning).

```php
// app/Services/Counter.php
// ПОГАНО: Викличе попередження устарівання у PHP 8.3
$code = 'a9';
$code++; 

// ДОБРЕ: Використовуйте нову функцію str_increment
$code = str_increment('a9'); // 'b0'
```

### 2. Відсутність сумісності типів констант у спадкоємцях
Якщо батьківський клас оголошує типізовану константу, дочірні класи при її перевизначенні повинні в точності зберігати її тип.

```php
// app/Config/DatabaseConfig.php
class ParentConfig {
    public const string DRIVER = 'mysql';
}

// ПОГАНО: Fatal Error: ChildConfig::DRIVER type (int) is not compatible with ParentConfig::DRIVER type (string)
class ChildConfig extends ParentConfig {
    public const int DRIVER = 123; 
}
```

### 3. Виклик `get_class()` без аргументів
Виклик `get_class()` без параметрів для отримання імені поточного класу застарів у PHP 8.3.

```php
// app/Services/LogService.php
// ПОГАНО: Викличе попередження устарівання у PHP 8.3
class LogService {
    public function log(): void {
        echo "Logging from " . get_class(); 
    }
}

// ДОБРЕ: Використовуйте self::class або передавайте $this явно
class LogService {
    public function log(): void {
        echo "Logging from " . self::class; 
        // АБО: echo "Logging from " . get_class($this);
    }
}
```

## Квиз для самоперевірки

Перевірте свої знання можливостей PHP 8.3. Виберіть відповідь та звіртеся під спойлером.

### Запитання 1: Що станеться, якщо в PHP 8.3 оголосити константу класу певного типу та присвоїти їй значення іншого типу (наприклад, `public const int NAME = 'MyApp';`)?
- A) Буде видано попередження, але код успішно виконається.
- B) PHP автоматично перетворить рядок на ціле число `0`.
- C) Виникне фатальна помилка (Fatal Error) на етапі компіляції.

<details>
<summary>Показати відповідь</summary>

**Правильна відповідь: C**
У PHP 8.3 типізовані константи строго перевіряються на етапі компіляції. Спроба присвоїти константі несумісне з її типом значення призводить до Fatal Error.
</details>

### Запитання 2: У яких випадках краще використовувати `json_validate()` замість `json_decode()`?
- A) `json_validate()` працює швидше та споживає значно менше пам'яті, оскільки не будує PHP-структур у пам'яті, а лише перевіряє синтаксис.
- B) `json_validate()` підтримує розширені формати JSON, які `json_decode()` обробити не може.
- C) `json_decode()` в майбутньому буде оголошена застарілою.

<details>
<summary>Показати відповідь</summary>

**Правильна відповідь: A**
`json_validate()` тільки сканує валідність синтаксису JSON-рядка без виділення пам'яті під розпаковані масиви або об'єкти, що робить її високопродуктивним рішенням для чистої перевірки валідності даних.
</details>
