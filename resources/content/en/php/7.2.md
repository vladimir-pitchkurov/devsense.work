# PHP 7.2: Major Features

What if checking the length of a variable suddenly flooded your error logs with warnings? PHP 7.2 introduces strict count warning hygiene, exposing thousands of latent bugs where developers called `count()` on non-countable types like null or boolean. It tightens everyday engineering with the generic `object` type hint, parameter type widening, first-class libsodium integration, and strict count warning hygiene.

<a id="object-type"></a>
## `object` type

You can declare **`object`** for parameters and return types—any instance satisfies it. This pairs with return-type covariance / parameter contravariance rules as PHP evolved across 7.x.

```php
// src/ObjectHandler.php
function acceptsAnyObject(object $x): void 
{
    // Do something with the object
}
```

> [!NOTE]
> Did you know? Prior to PHP 7.2, you could not type-hint generic objects. Developers had to rely on PHPDoc annotations or manually assert `is_object()`.

<a id="type-widening"></a>
## Parameter type widening

Implementations may **omit parameter type hints** that appear on the parent/interface method (still contravariance-safe). You **cannot** narrow or change to an unrelated type on abstract/interface chains—PHP will reject incompatible overrides.

```php
// src/Logger.php
interface Logger {
    public function log(string $msg);
}

class MyLogger implements Logger {
    // Parameter type is omitted (widened), which is valid in PHP 7.2
    public function log($msg) {
        echo $msg;
    }
}
```

> [!NOTE]
> Did you know? Parameter type widening allows libraries to update their interfaces without breaking third-party implementations immediately, since subclasses can omit the type hint.

<a id="pdo-debug"></a>
## PDO: richer `debugDumpParams()`

`PDOStatement::debugDumpParams()` can show the **full SQL** sent to the server for **emulated prepares**, including bound values—useful when debugging query construction (only when emulation is on).

```php
// src/DatabaseDebug.php
$stmt = $pdo->prepare("SELECT * FROM users WHERE status = :status");
$stmt->execute(['status' => 'active']);
$stmt->debugDumpParams();
```

<a id="ldap-exop"></a>
## LDAP extended operations (EXOP)

New helpers such as **`ldap_exop()`**, **`ldap_exop_passwd()`**, **`ldap_exop_whoami()`**, **`ldap_parse_exop()`**, plus constants like **`LDAP_EXOP_START_TLS`**—covering common EXOP flows without raw LDAP glue code.

<a id="sockets-addrinfo"></a>
## Sockets: `socket_addrinfo_*`

**`socket_addrinfo_lookup()`**, **`socket_addrinfo_connect()`**, **`socket_addrinfo_bind()`**, **`socket_addrinfo_explain()`** wrap **`getaddrinfo()`**-style resolution and connection setup—prefer this over manual `AF_INET` parsing when you need modern address families.

<a id="sodium"></a>
## Sodium (libsodium) in core

The **Sodium** extension ships with PHP 7.2+, exposing libsodium’s AEAD, hashing, and KDF primitives. Treat it as the default path for **new crypto** instead of **mcrypt** (removed from core—see below).

```php
// src/CryptoHelper.php
$nonce = random_bytes(SODIUM_CRYPTO_SECRETBOX_NONCEBYTES);
$key = sodium_crypto_secretbox_keygen();
$ciphertext = sodium_crypto_secretbox('message', $nonce, $key);
```

<a id="extensions-stdlib"></a>
## Notable extensions & stdlib

* **`utf8_encode()` / `utf8_decode()`** moved to **core string functions** (no longer tied to needing the XML extension).
* **`mail()` / `mb_send_mail()`** accept **header arrays** as well as strings.
* **DBA** gains **LMDB** backend support.
* **GD**: **`imageantialias()`** with system libgd; **`imagegd()`** stores truecolor more faithfully.
* **`session_module_name('user')`** now raises **recoverable error** instead of failing silently.

<a id="practical-recipes"></a>
## Practical recipes

### Guard `count()`

```php
// src/recipes.php
if (is_array($x) || $x instanceof \Countable) {
    $n = count($x);
}
```

(`is_countable()` arrives in PHP 7.3—on 7.2 use the explicit check.)

### Safe `get_class()`

```php
// src/recipes.php
$cls = is_object($obj) ? get_class($obj) : self::class;
```

<a id="common-mistakes"></a>
## Common Mistakes

Here are typical pitfalls in PHP 7.2:

### 1. Counting Non-Countable Variables
Calling `count()` on `null`, booleans, integers, or standard objects now triggers a Warning.
```php
// src/BadCount.php
// Bad: Null is not countable, triggers Warning: count(): Parameter must be an array or an object that implements Countable
$data = null;
echo count($data); 
```
```php
// src/GoodCount.php
// Good: Verify the variable is countable before counting
$data = null;
echo (is_array($data) || $data instanceof \Countable) ? count($data) : 0;
```

### 2. Passing `null` to `get_class()`
In previous versions, `get_class(null)` returned the name of the class from where it was called. In PHP 7.2, it issues an E_WARNING.
```php
// src/BadGetClass.php
// Bad: Triggers E_WARNING if $obj is null
$className = get_class($obj); 
```
```php
// src/GoodGetClass.php
// Good: Guard the call or check if the variable is an object
$className = is_object($obj) ? get_class($obj) : 'DefaultClass';
```

<a id="limitations"></a>
## Limitations

* **Generic `object` Type**: You cannot specify *which* object structure you expect; it simply validates that the value is an object instance. You cannot use it to allow classes while rejecting `stdClass` dynamically.
* **libsodium Integration**: Exposes low-level cryptographic functions. While extremely secure, it requires understanding cryptographic concepts (like nonces and keys) to avoid vulnerability pitfalls.

<a id="backward-incompatible"></a>
## Backward incompatible changes

### Core & types

* **`number_format()`** no longer returns **`-0`** for odd floating edge cases.
* **Casting arrays/objects with numeric keys**: accessing **`$obj->{0}`** / **`$obj->{'0'}`** and mirrored **`(array)`** access is **consistent** for integer-ish keys.
* **`get_class(null)`** now **warns**; omit the argument or pass an object.
* **`count()`** (and **`sizeof()`**) on **non-countable** types emits **`E_WARNING`**—code that relied on `count(null) === 0` breaks.
* **`spl_autoload_register()`** parity: deprecations around legacy **`__autoload`**.

### Extensions

* **MCrypt extension removed from core**—install from **PECL** if you truly must, but **migrate to OpenSSL/Sodium**.

<a id="deprecations"></a>
## Deprecations (fix early)

High-signal items:

* **`__autoload()`**—use **`spl_autoload_register()`**.
* Unquoted barewords that used to be **notice** are now **warning** (future: `Error`).
* Legacy **`create_function()`**, **`each()`**, string **`assert()`**, single-argument **`parse_str()`**, **`read_exif_data()`** alias, **`gmp_random()`**, **`png2wbmp` / `jpeg2wbmp`**.

<a id="other-changes"></a>
## Other changes & build

* **Autoconf ≥ 2.64** on Unix; **`--with-pdo-oci`** no longer needs Instant Client version in the flag; removed unused **`--enable-gd-native-ttf`**.
* **MCrypt → PECL**; adopt **Sodium/OpenSSL** for crypto work.

<a id="closing-thoughts"></a>
## Closing thoughts

PHP 7.2 is a good moment to **delete mcrypt code paths**, grep for **`count(`** on possibly-null values, and fix **`get_class(null)`**. Then continue toward 7.3+ for `JsonException`, `is_countable()`, and heredoc quality-of-life.
