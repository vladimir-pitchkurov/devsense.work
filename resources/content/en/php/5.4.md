# PHP 5.4: Code Reuse & Security Cleanup

Imagine deploying an old PHP application to a new PHP 5.4 environment, only to find out that all form submissions are completely blank or SQL queries throw fatal syntax errors. That was the reality for developers when PHP 5.4 officially dropped support for security vulnerabilities like magic quotes and register globals. But at the same time, PHP 5.4 brought syntax options that we take for granted today: traits and short arrays (`[]`).

Security was a massive issue in early PHP. Tools like `magic_quotes` attempted to auto-escape SQL input (causing terrible data distortion), while `register_globals` automatically turned HTTP query params into global variables (introducing serious security vulnerabilities). Removing these while keeping code clean was a major challenge.

> [!IMPORTANT]
> PHP 5.4 was the ultimate \"clean-up\" release, eliminating legacy security issues while providing powerful code reuse patterns via traits and the modern short array syntax.

<a id="traits"></a>
## Traits (Horizontal Reuse)

Traits allow you to share method implementations across class hierarchies without multiple inheritance.

```php
// app/Traits/Loggable.php
trait Loggable
{
    protected function log(string $msg): void
    {
        echo "[LOG]: " . $msg;
    }
}

// app/Services/UserService.php
class UserService
{
    use Loggable;

    public function create(): void
    {
        $this->log("User created successfully.");
    }
}
```

* **Why it matters**: Single inheritance often forces developers to write boilerplate or create unnatural base-class hierarchies just to share simple functionality.
* **Consequence**: Shared behaviors (like logging, timestamps, or serialization) can be cleanly injected into any class.

## Short Array Syntax (`[]`)

PHP 5.4 introduces the concise `[]` syntax for declaring arrays, replacing the verbose `array()` keyword.

```php
// app/Config/database.php
// Old syntax:
$config = array("host" => "localhost", "port" => 3306);

// New short syntax:
$config = ["host" => "localhost", "port" => 3306];
```

* **Why it matters**: Vastly improves code readability, bringing PHP inline with JSON, JavaScript, and other modern scripting languages.

<a id="callable-hint"></a>
## Callable Type Hint

You can now use `callable` as a type hint in function parameters, ensuring that the passed value is a valid callback.

```php
// app/Services/EventDispatcher.php
class EventDispatcher
{
    public function registerListener(string $event, callable $callback): void
    {
        // Validates that $callback can be executed
        $callback($event);
    }
}
```

* **Why it matters**: Eliminates the need for manual `is_callable()` checks inside functions, shifting callback validation to the engine level.

<a id="closure-this"></a>
## `$this` in Closures

Closures declared inside an object method now automatically bind the `$this` context of the current object.

```php
// app/Services/NotificationService.php
class NotificationService
{
    private string $sender = "system@example.com";

    public function getSenderResolver(): Closure
    {
        return function() {
            // Automatically binds and accesses private member
            return $this->sender;
        };
    }
}
```

> [!NOTE]
> This automatic binding makes it much cleaner to write event callbacks and model callbacks that interact with the calling object instance.

<a id="built-in-server"></a>
## Built-in CLI Web Server

You can spin up a quick HTTP server directly from the command line for development purposes.

```bash
# Run server targeting public folder on port 8000
php -S localhost:8000 -t public/
```

* **Why it matters**: You no longer need to configure heavy tools like Apache, nginx, or virtual hosts just to preview a simple script or test an API locally.

<a id="common-mistakes"></a>
## ⚠️ Common Mistakes

### 1. Expecting `register_globals` to import variables automatically
If your legacy code relied on variables like `$userId` automatically appearing because of `GET /profile.php?userId=42`, it will now throw undefined variable warnings.

```php
// app/Http/LegacyController.php
// ❌ Broken in PHP 5.4+ (variables are not imported automatically)
echo $userId; 

// ✅ Correct Approach
echo $_GET['userId'] ?? null;
```

### 2. Double-Escaping Database Input
Developers who used `stripslashes()` to counter `magic_quotes_gpc` will now accidentally corrupt their data since magic quotes no longer run.

```php
// app/Database/Sanitizer.php
// ❌ Dangerous (removes valid slashes now that magic_quotes is gone)
$cleaned = stripslashes($_POST['bio']);

// ✅ Correct Approach
$cleaned = $_POST['bio']; // Use prepared statements instead!
```

### 3. Conflict resolution in Traits
Using multiple traits with the same method names without explicit conflict resolution leads to compile-time errors.

```php
// app/Demo/TraitConflict.php
trait A { public function run() {} }
trait B { public function run() {} }

// ❌ Fatal Error: trait methods conflict
class Runner { use A, B; }

// ✅ Correct Approach
class SafeRunner
{
    use A, B {
        A::run insteadof B;
        B::run as runAlternate;
    }
}
```

## Practical Recipes

### Expectation vs Reality: Function Array Dereferencing

```php
// app/Demo/DereferenceDemo.php
function getNames(): array
{
    return ["Alice", "Bob", "Charlie"];
}

// Expectation: Accessing index immediately works
// Reality:
// In PHP 5.3: Parses as a Syntax Error
// In PHP 5.4: Works perfectly
echo getNames()[1]; // Output: Bob
```

<a id="backward-incompatible"></a>
## Backward Incompatible Changes

1. **`register_globals` and `magic_quotes_gpc` removed**: You must retrieve variables from superglobals and stop relying on magic escaping.
2. **`safe_mode` removed**: Server limits based on file ownership are gone. Use native filesystem permissions.
3. **`break` and `continue` strictness**: Passing variable numbers to loop exit keywords (e.g., `break $val`) is no longer supported.
4. **`mysql` extension deprecated**: `mysql_*` functions throw warnings; prepare to use `mysqli` or `PDO` before PHP 7.

## 🧠 Self-Check Questions

1. **True or False?** In PHP 5.4, traits can instantiate objects directly.
2. What is the CLI command to start the built-in web server?
3. What happens if two traits imported into a class share a method with the same signature?
4. **True or False?** `$this` is automatically available in static closures.

<details>
<summary><b>Reveal Answers</b></summary>

1. **False.** Traits are only templates for classes and cannot be instantiated on their own. They can only be used by classes.
2. `php -S <host>:<port>` (e.g. `php -S localhost:8000`).
3. PHP will throw a fatal compile-time conflict error. You must resolve the collision manually using the `insteadof` and `as` adaptation syntax inside the class declaration.
4. **False.** If a closure is declared as static (e.g. `static function() {}`), it cannot access `$this` and will throw a fatal error if you try to reference it.
</details>
