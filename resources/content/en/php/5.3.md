# PHP 5.3: Modernization & Enterprise Foundation

Imagine updating your server and suddenly encountering a white screen of death because a vendor library used an unquoted word or a reference in a function call. PHP 5.3 was the inflection point where the language ceased being a simple scripting engine and transformed into a mature, enterprise-grade OOP language. However, this transition came with severe backward-incompatible changes that broke thousands of legacy apps overnight.

Before PHP 5.3, developers struggled with global class name collisions, broken static method inheritance, and uncontrollable memory leaks in long-running scripts due to reference cycles. To solve this, PHP 5.3 introduced namespaces, closures, late static binding, and a cycle-detecting garbage collector. But it also stripped away legacy features like call-time pass-by-reference and the `ereg` extension.

> [!IMPORTANT]
> PHP 5.3 is the foundational milestone of modern object-oriented PHP, forcing developers to abandon PHP 4 habits in favor of namespace isolation and structured memory management.

## Namespaces & Autoloading

Namespaces isolate code and replace endless class prefixing. 

```php
// app/Repositories/UserRepository.php
namespace App\Repositories;

use App\Database\Connection;
use App\Contracts\LoggerInterface;

class UserRepository
{
    private Connection $db;
    private LoggerInterface $log;

    public function __construct(Connection $db, LoggerInterface $log)
    {
        $this->db = $db;
        $this->log = $log;
    }
}
```

* **Why it matters**: Before namespaces, class name clashes were avoided by naming files and classes with long prefix strings (e.g. `Zend_Db_Table_Row_Abstract`). Namespaces make code clean and readable, allowing shorter class names that are logically isolated.
* **Consequence**: This feature laid the groundwork for modern PHP packages, standard autoloading (PSR-0/PSR-4), and the creation of Composer.

<a id="lsb"></a>
## Late Static Binding (`static::`)

In PHP, `self::` always resolves to the class in which the method was defined. Late Static Binding introduces `static::`, which resolves to the class that was actually called at runtime.

```php
// app/Models/ActiveRecord.php
abstract class ActiveRecord
{
    public static function find(int $id): string
    {
        // self::getTable() would fail here for subclasses
        return "SELECT * FROM " . static::getTable() . " WHERE id = " . $id;
    }

    abstract protected static function getTable(): string;
}
```

* **Why it matters**: Without LSB, writing extensible base classes with static factory methods (like Active Record ORMs) was highly problematic.
* **Consequence**: Developers can write elegant parent-class helpers that properly interact with overridden static properties or methods in subclass contexts.

<a id="closures"></a>
## Closures and the `use` Clause

Anonymous functions can now be assigned to variables, passed as arguments, and capture variables from the parent scope using the `use` keyword.

```php
// app/Services/Calculator.php
$taxRate = 0.20;

$calculateTotal = function (float $price) use ($taxRate): float {
    return $price * (1 + $taxRate);
};

echo $calculateTotal(100); // 120
```

> [!NOTE]
> In PHP 5.3, closures copy captured variables **by value** by default. If you need to modify the original variable inside the closure, you must pass it **by reference** (e.g. `use (&$counter)`).

<a id="syntax-additions"></a>
## NOWDOC vs HEREDOC

NOWDOC is to HEREDOC what single-quoted strings are to double-quoted strings.

```php
// app/Config/templates.php
// HEREDOC (parses variables)
$name = 'John';
$heredoc = <<<EOT
Hello $name!
EOT;

// NOWDOC (does not parse variables, notice single quotes around EOT)
$nowdoc = <<<'EOT'
Hello $name!
EOT;
```

* **Why it matters**: NOWDOC makes it safe to embed raw blocks of configuration, shell scripts, or regular expressions without escaping dollar signs.

<a id="gc"></a>
## Reference Cycle Garbage Collection

PHP 5.3 introduced a circular reference collector. When object A points to object B, and object B points back to object A, standard reference-counting fails to clean them up even when they are no longer reachable.

```php
// app/Services/Daemon.php
gc_enable(); // Enable the circular reference collector

// In a long-running process:
gc_collect_cycles(); // Forces collection of cleanup queues
```

* **Why it matters**: Essential for background queue workers, CLI commands, and long-running daemons that would otherwise run out of memory.

<a id="common-mistakes"></a>
## ⚠️ Common Mistakes

### 1. Call-Time Pass-By-Reference
Passing variables with an ampersand in function calls causes fatal errors.

```php
// app/Services/LegacyFix.php
// ❌ Deprecated / Fatal Error in PHP 5.3+
foo(&$value); 

// ✅ Correct Approach
// The reference must be defined in the signature:
function foo(&$param) {}
foo($value); 
```

### 2. Using Reserved Keywords as Identifiers
New keywords like `goto`, `namespace`, and `use` cannot be used as class names or unquoted constants.

```php
// app/Classes/Runner.php
// ❌ Fatal Error: Cannot use 'goto' as class name
class goto {}
```

### 3. Mixing POSIX and PCRE Regular Expressions
Using `ereg()` functions instead of `preg_match()`. POSIX functions are deprecated in PHP 5.3 and removed in PHP 7.0.

```php
// app/Validation/Email.php
// ❌ Deprecated in PHP 5.3
if (eregi('^[a-z0-9]+$', $input)) {}

// ✅ Correct Approach
if (preg_match('/^[a-z0-9]+$/i', $input)) {}
```

## Practical Recipes

### Expectation vs Reality: `self` vs `static`

```php
// app/Demo/BindingDemo.php
class ParentClass
{
    public static function getClassName(): string
    {
        return self::class; // Or __CLASS__
    }

    public static function getCalledClassName(): string
    {
        return static::class;
    }
}

class ChildClass extends ParentClass {}

// Expectation: Both return 'ChildClass'
// Reality:
echo ChildClass::getClassName();       // Output: ParentClass
echo ChildClass::getCalledClassName(); // Output: ChildClass
```

<a id="backward-incompatible"></a>
## Backward Incompatible Changes

1. **Call-time pass-by-reference removal**: The `foo(&$x)` syntax is deprecated and throws warnings in PHP 5.3 (removed completely in 5.4).
2. **New reserved words**: `goto`, `namespace`, `use`, `const` cannot be used for class, interface, or constant names.
3. **`ereg` family deprecation**: Using `ereg_*` regex helper functions throws `E_DEPRECATED` warnings.
4. **Parameter order strictness**: Functions like `clearstatcache()` and various math utilities tightened parameters.

## 🧠 Self-Check Questions

1. **True or False?** In PHP 5.3, closures automatically bind the `$this` context when defined inside an object method.
2. How do you declare a NOWDOC string block?
3. What is the difference between `self::` and `static::` under Late Static Binding?
4. What happens if you try to call a function using `bar(&$var)` in PHP 5.3?

<details>
<summary><b>Reveal Answers</b></summary>

1. **False.** In PHP 5.3, closures do NOT bind `$this`. You must pass the object manually (e.g. `$self = $this;` and `use ($self)`) to access instance variables. Automatic binding of `$this` inside closures was introduced in PHP 5.4.
2. Put single quotes around the identifier in the opening marker: `<<<'EOT'`.
3. `self::` refers to the class in which the code was compiled (the defining class), whereas `static::` dynamically refers to the class actually called at runtime.
4. It will emit a deprecation warning (`Deprecated: Call-time pass-by-reference has been deprecated...`). In PHP 5.4+, this syntax throws a fatal syntax error.
</details>
