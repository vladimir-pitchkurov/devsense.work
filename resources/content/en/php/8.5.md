PHP 8.5 is a major release focusing on syntax expressiveness and core platform consolidation. It brings the highly requested **Pipe Operator (`|>`)**, the **`#[\NoDiscard]`** attribute to enforce function return value handling, and native WHATAWG-aligned **URL/URI parsing**.

<a id="pipe-operator"></a>
## The Pipe Operator (`|>`)

Tired of nesting functions like `strtolower(trim($input))` or polluting your scope with temporary variables? PHP 8.5 introduces the **Pipe Operator (`|>`)** which lets you write sequential transformations from left to right.

```php
// app/Services/Slugger.php
$slug = $title
    |> trim(...)
    |> strtolower(...)
    |> fn($s) => preg_replace('/\s+/', '-', $s);

echo $slug; // Output: hello-world
```

> [!NOTE]
> **Did you know?**
> The pipe operator passes the value on the left as the **first parameter** to the callable on the right. If you need to pass it as a second or third parameter, wrap the call in a custom closure or arrow function.

### ⚠️ Common Mistakes

**1. Forgetting to parenthesize arrow functions**
If you chain custom arrow functions directly in a pipe, you must wrap them in parentheses to prevent parse ambiguity:
```php
// app/Services/Formatter.php
// ❌ Syntax Error!
$result = $value |> fn($x) => $x * 2 |> fn($y) => $y + 10;

// ✅ Correct Approach
$result = ($value |> fn($x) => $x * 2) |> fn($y) => $y + 10;
```

## Closures & First-Class Callables in Constant Expressions

PHP 8.5 allows you to define **closures** and **first-class callables** in places that only accepted static values before, such as class constants, property defaults, and attribute parameters.

```php
// app/Attributes/Route.php
class Route
{
    public function __construct(
        public string $path,
        public Closure $callback = (fn() => 'Default Route')
    ) {}
}
```

This is a massive win for routing engines and validation libraries that need to bundle light logic in metadata.

<a id="nodiscard"></a>
## `#[\NoDiscard]` and the `(void)` Cast

When write operations or validation calls return status results, developers often forget to check them. PHP 8.5 adds the `#[\NoDiscard]` attribute to warn when a return value is ignored.

```php
// app/Services/Transaction.php
class Transaction
{
    #[\NoDiscard]
    public function commit(): bool
    {
        // ...
        return true;
    }
}

$tx = new Transaction();
$tx->commit(); // ❌ Warning: Return value of Transaction::commit() must not be discarded!
```

If you *know* what you're doing and want to discard the value, use the new `(void)` cast to suppress the warning:

```php
// app/Services/Handler.php
(void) $tx->commit(); // ✅ Explicitly discarded, no warning!
```

## The Native URI Extension (RFC 3986)

URLs and URIs are notoriously hard to parse correctly due to security bugs like path traversal. PHP 8.5 bundles an always-enabled `uri` extension that implements spec-compliant parsing according to RFC 3986 and the WHATWG URL standard.

```php
// app/Services/UrlParser.php
$uri = Uri\parse('https://user:pass@example.com:8080/path?query=1#hash');

echo $uri->host;     // example.com
echo $uri->port;     // 8080
echo $uri->userInfo; // user:pass
```

<a id="new-functions"></a>
## New Utility Helpers: `array_first()` and `array_last()`

Instead of resetting array pointers or writing custom functions, PHP 8.5 introduces native, performant helpers:

```php
// app/Services/Collection.php
$list = ['apple', 'banana', 'cherry'];

$first = array_first($list); // 'apple'
$last  = array_last($list);  // 'cherry'
```

Additionally, `FILTER_THROW_ON_FAILURE` can now be passed to validation filters so they throw exceptions instead of returning `false` on failure:

```php
// app/Http/Request.php
$id = filter_input(INPUT_GET, 'id', FILTER_VALIDATE_INT, FILTER_THROW_ON_FAILURE);
```

<a id="backward-incompatible"></a>
## Backward Incompatible Changes (Upgrade Checklist)

Before upgrading to PHP 8.5, verify these critical changes:

1. **Opcache is statically compiled**
   Opcache is now a core part of the PHP binary and cannot be compiled as a shared extension. Adding `zend_extension=opcache.so` in your INI files will emit a warning.
2. **PDO Fetch Constant Numeric Changes**
   If you store PDO fetch mode integers (e.g. `PDO::FETCH_GROUP`) in database tables or dynamic configurations, be careful: their backing integer values have changed in 8.5.
3. **`class_alias()` restriction**
   You can no longer use `"array"` or `"callable"` as alias names.

## 🧠 Self-Check Questions

Let's test your understanding of PHP 8.5:
1. **True or False?** The right-hand side of the pipe operator (`|>`) can accept multiple arguments by default.
2. What is the syntax for explicitly suppressing a warning for a method marked with `#[\NoDiscard]`?
3. How should you load Opcache in your `php.ini` file under PHP 8.5?
4. **True or False?** `array_first()` and `array_last()` work on associative arrays.

<details>
<summary><b>Reveal Answers</b></summary>

1. **False.** The right-hand side must accept exactly one argument. If the target function accepts more parameters, you must wrap it in a closure or arrow function.
2. Prefix the call with a `(void)` cast (e.g. `(void) $obj->method();`).
3. You don't need to load it at all! It is statically compiled into the binary. You only need to enable it via `opcache.enable=1`.
4. **True.** They return the first and last element of any array, regardless of whether keys are numeric or associative.
</details>
