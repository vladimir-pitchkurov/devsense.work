# PHP 7.1: Major Features

What if you could catch three different exception types in a single block without repeating boilerplate catch blocks? Or define class constants that are strictly hidden from external access? PHP 7.1 introduces these capabilities, bringing robust type safety and expressiveness to modern PHP architectures. It enhances type systems and syntax with nullable types, void functions, symmetric array destructuring with keys, class constant visibility, and multi-catch exceptions.

<a id="nullable-types"></a>
## Nullable types

You can prefix any type hint with **`?`** to allow **`null`** as a valid value alongside the primary type:

```php
// src/UserService.php
function findUser(int $id): ?User 
{
    return $id === 0 ? null : new User($id);
}
```

> [!NOTE]
> Did you know? In PHP 7.0, a type hint of `User` was absolute: returning `null` threw a TypeError. Nullable types solve this without forcing developers to drop type hinting entirely.

<a id="void-functions"></a>
## Void functions

Functions that return nothing use **`void`**. Only a bare **`return;`** or omitting `return` altogether is permitted. Returning anything else (including explicit **`return null;`**) is a compile-time failure.

```php
// src/Notifier.php
function notify(string $message): void 
{
    echo $message;
    return; // Bare return is valid, returning any value is a type error
}
```

> [!NOTE]
> Did you know? `void` is a return-only type. You cannot use it to type-hint a function parameter (e.g. `function foo(void $x)` is invalid).

<a id="symmetric-destructuring"></a>
## Symmetric array destructuring

Unpack arrays using short array syntax **`[]`** as an alternative to **`list()`**:

```php
// src/Config.php
[$host, $port] = ['127.0.0.1', 3306];
```

This syntax can also be used in `foreach` loops: `foreach ($data as [$id, $name])`.

<a id="constant-visibility"></a>
## Class constant visibility

Constants can have **`public`**, **`protected`**, or **`private`** visibility:

```php
// src/PaymentGateway.php
class PaymentGateway {
    private const API_KEY = 'secret-key';
    public const DEFAULT_TIMEOUT = 30;
}
```

> [!NOTE]
> Did you know? Constants default to `public` if no visibility modifier is declared, maintaining backward compatibility with older PHP versions.

<a id="iterable-type"></a>
## `iterable` pseudo-type

Matches any value satisfying **`is_array()`** or **`$val instanceof \Traversable`**:

```php
// src/Collection.php
function processItems(iterable $items): void 
{
    foreach ($items as $item) {
        // Works for both arrays and generator/iterator objects
    }
}
```

<a id="multi-catch"></a>
## Catching multiple exception types

Catch different exceptions in a single block using the **`|`** operator:

```php
// src/ApiConnector.php
try {
    // Perform API request
} catch (ConnectionException | ResponseException $e) {
    // Handle either exception type here
}
```

<a id="destructuring-keys"></a>
## Keys in list / short destructuring

You can specify keys when destructuring arrays:

```php
// src/UserProfile.php
['id' => $userId, 'name' => $username] = $user;
```

This works for both `list()` and the new short `[]` syntax.

<a id="negative-offsets"></a>
## Support for negative string offsets

Index strings from the end using negative numbers:

```php
// src/StrHelper.php
$lastChar = 'abcdef'[-1]; // 'f'
$sub = substr('abcdef', -3, -1); // 'de'
```

Negative offsets are also supported in string character access: `$str[-2] = 'z';`.

<a id="common-mistakes"></a>
## Common Mistakes

Here are typical pitfalls in PHP 7.1:

### 1. Returning `null` from a `void` Function
In PHP 7.1, returning `null` explicitly from a function marked `void` triggers a Fatal Error.
```php
// src/BadVoid.php
// Bad: Explicitly returning null is prohibited for void returns
function doNothing(): void {
    return null; // Fatal Error: A void function must not return a value
}
```
```php
// src/GoodVoid.php
// Good: Use bare return or omit it entirely
function doNothingGood(): void {
    return; 
}
```

### 2. Assuming `iterable` only accepts arrays
Checking `is_array()` on an `iterable` parameter might skip generators or iterator classes, causing unexpected runtime errors.
```php
// src/BadIterable.php
// Bad: Throws errors if $items is a Traversable object, not an array
function dumpItems(iterable $items) {
    echo count($items); // Fatal Error if $items is a Generator (not Countable)
}
```
```php
// src/GoodIterable.php
// Good: Convert to array if needed or use foreach (which handles both)
function dumpItemsGood(iterable $items) {
    foreach ($items as $item) {
        echo $item;
    }
}
```

<a id="limitations"></a>
## Limitations

* **Nullable Types**: You cannot combine nullable types with Union Types. Writing `?int|string` is a syntax error (Union types are introduced in PHP 8.0).
* **Constant Visibility**: Enforces access control but doesn't support type-hinting class constants. Typing `public const int TIMEOUT = 10;` remains a syntax error until PHP 8.3.

<a id="backward-incompatible"></a>
## Backward incompatible changes

### Core & types

* **Throwing on too few arguments**: passing too few arguments to a user-defined function now throws an **`ArgumentCountError`** exception (instead of a Warning).
* **String offsets behavior**: empty index `[]` access on strings is **no longer silent** or fallback-coerced.
* **`iterable` is a reserved word**: you cannot name a class, interface, or trait `iterable`.

## Closing thoughts

PHP 7.1 is a fundamental release for **strict type hygiene** and cleaner data structures. Convert old `list()` structures to `[]`, add `?` to optional arguments, and wrap your exception catches to prepare your application for PHP 7.2+.
