# PHP 7.0: Major Features

What if you could double your application's performance overnight simply by upgrading your language engine? PHP 7.0 achieved exactly that. Driven by the new Zend Engine 3, it introduced massive speed improvements while bringing strict scalar types, return type declarations, and modern operators like null coalescing. PHP 7.0 marks a monumental leap in the history of PHP, establishing the foundation of modern type-safe, high-performance web applications.

<a id="scalar-types"></a>
## Scalar type declarations

Scalar parameters can use type hints: **`int`**, **`float`**, **`string`**, and **`bool`**:

```php
// src/Math.php
declare(strict_types=1);

function add(int $a, int $b): int 
{
    return $a + $b;
}
```

> [!NOTE]
> Did you know? Without `declare(strict_types=1);` at the top of the file, PHP remains in **coercive mode**, meaning it will silently convert strings like `"5"` into integers to satisfy parameter checks.

<a id="return-types"></a>
## Return type declarations

Define what type a function is required to return:

```php
// src/Generator.php
function generateId(): string 
{
    return uniqid();
}
```

If a return statement does not match this type, PHP will throw a **`TypeError`** exception.

<a id="null-coalescing"></a>
## Null coalescing operator (`??`)

Syntactic sugar for `isset()` checks:

```php
// src/Config.php
$username = $_GET['user'] ?? 'anonymous';
```

It can be chained: `$value = $a ?? $b ?? $default;`.

<a id="spaceship-operator"></a>
## Spaceship operator (`<=>`)

Three-way comparison returning `-1`, `0`, or `1`:

```php
// src/SortHelper.php
usort($list, function($a, $b) {
    return $a <=> $b;
});
```

Useful for sorting operations where standard comparisons require verbose conditional logic.

<a id="constant-arrays"></a>
## Constant arrays via `define()`

Define array constants at runtime:

```php
// src/Constants.php
define('ALLOWED_ROLES', ['admin', 'editor', 'guest']);
```

Previously, arrays could only be defined as constants inside classes using `const`.

<a id="anonymous-classes"></a>
## Anonymous classes

Instantiate simple throw-away objects:

```php
// src/LoggerProvider.php
$logger = new class {
    public function log(string $msg) {
        echo $msg;
    }
};
```

Useful for mocking interfaces during unit tests.

<a id="unicode-escape"></a>
## Unicode codepoint escape syntax

Embed Unicode symbols directly inside strings:

```php
// src/Emoji.php
echo "\u{1F600}"; // Outputs a smiling emoji 😀
```

<a id="group-use"></a>
## Group use declarations

Import multiple classes from the same namespace cleanly:

```php
// src/Controller.php
use App\Models\{User, Post, Comment};
```

<a id="throwable-exceptions"></a>
## Throwable interface & Engine Exceptions

Fatal and recoverable errors are now thrown as **`Error`** exceptions. Catch them using the **`Throwable`** interface:

```php
// src/ErrorHandler.php
try {
    nonExistentFunction();
} catch (Throwable $t) {
    // Catches both Engine Errors and user Exceptions
    echo "Caught: " . $t->getMessage();
}
```

> [!NOTE]
> Did you know? `Error` does not extend `Exception`. Catching `Exception` will not prevent engine errors like calling an undefined function from crashing your script. Use `Throwable` instead.

<a id="csprng-functions"></a>
## CSPRNG functions

Generate cryptographically secure random values directly from the OS:

```php
// src/TokenGenerator.php
$bytes = random_bytes(32);
$number = random_int(1, 100);
```

These functions replace insecure generators like `rand()` or `mt_rand()` for security contexts.

<a id="common-mistakes"></a>
## Common Mistakes

Here are typical pitfalls when migrating to PHP 7.0:

### 1. Forgetting to Declare Strict Types
Without declaring strict types explicitly per file, PHP runs in coercive mode and silently converts argument values.
```php
// src/BadStrict.php
// Bad: Coercive mode is active, string "10" is converted to int silently
function setAge(int $age) {
    return $age;
}
setAge("10"); // No error thrown
```
```php
// src/GoodStrict.php
// Good: Enable strict types at the very top of the file
declare(strict_types=1);

function setAgeGood(int $age) {
    return $age;
}
// setAgeGood("10"); // Throws TypeError
```

### 2. Catching `Exception` to Handle Engine Failures
Many developers caught `Exception` expecting it to handle errors like division by zero, which fails because engine errors implement `Error`.
```php
// src/BadCatch.php
// Bad: Division by zero throws DivisionByZeroError (extends Error), which bypasses Exception
try {
    $value = 1 / 0;
} catch (Exception $e) {
    echo "This block is not executed!";
}
```
```php
// src/GoodCatch.php
// Good: Catch Throwable or Error to capture engine failures
try {
    $value = 1 / 0;
} catch (Throwable $e) {
    echo "Caught error: " . $e->getMessage();
}
```

<a id="limitations"></a>
## Limitations

* **Scalar Type Declarations**: Cannot be nullable by default. Typing `int $x` and passing `null` throws a TypeError (Nullable types arrive in PHP 7.1).
* **Return Type Declarations**: Cannot be marked as returning `void` (added in PHP 7.1) or multiple types (Union types added in PHP 8.0).

<a id="backward-incompatible"></a>
## Backward incompatible changes

### Core Changes

* **ASP tags (`<% %>`) and script tags (`<script language="php">`)** are completely removed.
* **`$HTTP_RAW_POST_DATA`** is removed; use `php://input` instead.
* **Multiple default blocks in `switch`** throw a ParseError.
* **Global variables and dynamic calls** are parsed strictly from left to right (e.g. `$$foo['bar']` has new evaluation ordering).
