# PHP 5.6: The Bridge to Modern PHP

A simple math expression like `2 ** 3 ** 2` or a strict validation check on user-supplied JSON input can completely alter your program's execution logic when moving to PHP 5.6. As the final release of the 5.x branch, PHP 5.6 is the bridge between the old-school PHP engine and the modern PHP 7 runtime.

Before PHP 5.6, writing functions with a dynamic number of arguments required using clunky functions like `func_get_args()` and forwarding them via slow `call_user_func_array()` calls. Importing functions from namespaces required messy wraps, and constant values could not contain basic mathematical formulas.

> [!IMPORTANT]
> PHP 5.6 introduced variadic signatures, argument unpacking, and strict encryption defaults to prepare codebases for the major leap to PHP 7.

<a id="variadic"></a>
## Variadic Parameters (`...$params`)

Functions can now accept a variable number of arguments natively without relying on `func_get_args()`.

```php
// app/Helpers/Math.php
function sum(int $first, int ...$others): int
{
    $accumulator = $first;
    foreach ($others as $number) {
        $accumulator += $number;
    }
    return $accumulator;
}

echo sum(1, 2, 3, 4); // 10
```

* **Why it matters**: Signature definitions are now self-documenting, and IDEs can properly type-check and autocomplete variadic arguments.

<a id="unpacking"></a>
## Argument Unpacking

Arrays and `Traversable` objects can be unpacked into parameter lists during function calls.

```php
// app/Services/Logger.php
$args = ["User %s logged in from IP %s", "admin", "127.0.0.1"];
echo sprintf(...$args);
```

* **Why it matters**: Replaces slow and hard-to-read `call_user_func_array()` calls with clean, native compiler-level speed.

<a id="pow-op"></a>
## Exponentiation Operator (`**`)

PHP 5.6 introduces the `**` operator for calculating powers, providing a shorthand for the `pow()` function.

```php
// app/Services/Physics.php
$square = 4 ** 2; // 16
$cube = 2 ** 3;   // 8
```

> [!WARNING]
> The `**` operator is right-associative. This means `2 ** 3 ** 2` is evaluated as `2 ** (3 ** 2) = 2 ** 9 = 512`, not `(2 ** 3) ** 2 = 8 ** 2 = 64`.

<a id="use-imports"></a>
## `use function` & `use const`

The `use` namespace block is expanded to support importing functions and constants, not just classes.

```php
// app/Services/StringManager.php
namespace App\Services;

use function SomeLib\stringHelper;
use const SomeLib\API_VERSION;

class StringManager
{
    public function getVersion(): string
    {
        return stringHelper(API_VERSION);
    }
}
```

* **Why it matters**: Keeps global namespaces clean and explicitly declares external library dependencies at the top of the file.

<a id="const-expr"></a>
## Constant Expressions

You can now use scalar expressions (mathematical formulas, string concatenation) when defining class constants, static property defaults, and parameter defaults.

```php
// app/Config/Limits.php
class Limits
{
    public const ONE_MB = 1024 * 1024;
    public const MAX_UPLOAD = self::ONE_MB * 50; // 50MB
    public static $debugMode = (self::MAX_UPLOAD > 10000);
}
```

<a id="hash-equals"></a>
## Timing-Safe String Comparison (`hash_equals`)

Compares two strings in constant time, regardless of whether the characters match or not.

```php
// app/Services/Security.php
$signature = $_GET['signature'];
$expected = hash_hmac('sha256', $data, $key);

if (hash_equals($expected, $signature)) {
    // Verified successfully
}
```

* **Why it matters**: Prevents side-channel timing attacks when validating user tokens, passwords, or HMAC signatures.

<a id="common-mistakes"></a>
## ⚠️ Common Mistakes

### 1. Unary Operators and Exponentiation Precedence
Mixing `-` or other unary operators with `**` without parenthesis can produce unexpected mathematics.

```php
// app/Demo/MathErrors.php
// ❌ Compile Error! Exponentiation has higher precedence
$result = -2 ** 2; 

// ✅ Correct Approach
$result = (-2) ** 2; // 4
```

### 2. Relying on `$HTTP_RAW_POST_DATA`
Prior to PHP 5.6, `$HTTP_RAW_POST_DATA` was populated for non-multipart POST payloads. It is deprecated in 5.6.

```php
// app/Http/Webhook.php
// ❌ Deprecated in PHP 5.6, throws E_DEPRECATED
$data = $HTTP_RAW_POST_DATA;

// ✅ Correct Approach
$data = file_get_contents('php://input');
```

### 3. Loose handling of `json_decode()` failures
`json_decode()` now strictly rejects invalid JSON literals (`true`/`false`/`null` as malformed strings), throwing errors in cases where it was previously silent.

## Practical Recipes

### Upgrading `call_user_func_array`

```php
// app/Demo/UnpackDemo.php
class Invoker
{
    public function execute(callable $callback, array $params)
    {
        // Expectation: Replacing slow call_user_func_array with unpacking
        // Reality:
        // PHP 5.5: call_user_func_array($callback, $params);
        // PHP 5.6:
        return $callback(...$params);
    }
}
```

<a id="backward-incompatible"></a>
## Backward Incompatible Changes

1. **Strict SSL/TLS defaults**: Peer verification is enabled by default. Secure streams connecting to hosts with self-signed certificates will fail unless configured with custom stream contexts.
2. **`**` precedence**: Right-associative precedence can alter calculations ported from older PHP engines.
3. **`json_decode()` strictness**: Non-lowercase JSON literals like `TRUE`, `FALSE`, or `NULL` will trigger syntax errors.
4. **Array keys override**: Static array declarations that contain duplicate keys will override keys in order.
