# Релационни бази данни и операторът SELECT

В основата на съвременното съхранение на данни стои моделът на релационните бази данни, предложен за първи път от Едгар Ф. Код през 1970 г. Вместо да съхранява данни в неструктурирани текстови файлове или твърди йерархични дървета, релационната база данни организира информацията в структурирани таблици, които могат да бъдат съединявани и заявявани динамично с помощта на Structured Query Language (SQL). Независимо дали използвате MySQL или PostgreSQL, разбирането на основните концепции за релационен дизайн и как да извличате данни ефективно е от решаващо значение.

---

## 1. Релационният модел: Таблици, колони и ключове

В релационната база данни данните се представят като съвкупност от релационни таблици. Всяка таблица се състои от:
* **Колони (Атрибути)**: Дефинират типа данни и свойствата на съхраняваната информация (напр. `user_id` като цяло число, `email` като низ).
* **Редове (Записи/Кортежи)**: Представят отделни екземпляри от данни (напр. запис за конкретен потребител).

За да се поддържа целостта, таблиците разчитат на две основни концепции:
1. **Първичен ключ (Primary Key - PK)**: Колона (или набор от колони), която уникално идентифицира всеки ред в таблица. Не може да съдържа стойности `NULL`.
2. **Външен ключ (Foreign Key - FK)**: Колона в една таблица, която препраща към първичния ключ на друга таблица, установявайки връзка между тях.

| Концепция | Описание | Аналогия |
| :--- | :--- | :--- |
| **Таблица** | Структурирана мрежа от колони и редове. | Раздел в електронна таблица (spreadsheet tab). |
| **Ред** | Единичен запис на данни. | Единичен ред в електронна таблица. |
| **Първичен ключ** | Уникален идентификатор за ред. | Номер на паспорт. |
| **Външен ключ** | Връзка към първичния ключ на друга таблица. | Идентификатор на отдел на служител. |

---

## 2. Извличане на данни със `SELECT`

Най-основната операция в SQL е извличането на данни с помощта на оператора `SELECT`. В най-простата си форма една заявка изисква клауза `SELECT` (какви колони да се извлекат) и клауза `FROM` (коя таблица да се запита).

### Избор на всички колони срещу специфични колони
Можете да извлечете всички колони с помощта на символа за заместване звездичка (`*`) или да посочите само колоните, от които се нуждаете.
```sql
-- MySQL & PostgreSQL
-- Retrieve all columns (not recommended for production)
SELECT * FROM users;

-- Retrieve specific columns (recommended)
SELECT id, email, first_name FROM users;
```

> [!TIP]
> **Знаехте ли, че?**
> Използването на `SELECT *` в производствена среда се счита за антимодел (anti-pattern). То принуждава сървъра на базата данни да извършва допълнителни операции за четене от диска (disk I/O) за колони, които не са ви необходими, консумира излишен мрежов трафик и може да счупи приложението ви, ако към таблицата бъде добавена нова колона или премахната стара.

### Псевдоними на колони (`AS`)
Псевдонимите ви позволяват да преименувате колони в резултата от заявката за по-добра четимост или за да съответстват на очакванията на приложението.
```sql
-- MySQL & PostgreSQL
SELECT first_name AS given_name, last_name AS surname FROM users;
```

## 3. Филтриране на резултати с `WHERE`

За да извлечете само определени редове, използвайте клаузата `WHERE`. Клаузата `WHERE` оценява булево условие за всеки ред, като връща само тези, за които то е истина (true).

### Стандартни оператори
SQL поддържа стандартни оператори за сравнение:
* `=` (равно на)
* `<>` или `!=` (различно от)
* `>` (по-голямо от), `<` (по-малко от)
* `>=` (по-голямо или равно на), `<=` (по-малко или равно на)

```sql
-- Retrieve active users registered after a specific ID
SELECT email FROM users WHERE is_active = true AND id > 100;
```

### Разширени оператори за филтриране
* **`BETWEEN`**: Филтрира стойности в рамките на определен диапазон (включително крайните точки).
* **`IN`**: Проверява дали дадена стойност съвпада с някоя стойност в посочен списък.
* **`LIKE`**: Извършва просто съпоставяне по шаблон с помощта на заместващи символи:
  - `%` представя нула или повече знаци.
  - `_` представя точно един знак.

```sql
-- Retrieve users with IDs 1, 3, or 5
SELECT email FROM users WHERE id IN (1, 3, 5);

-- Retrieve users registered in a specific range
SELECT email FROM users WHERE id BETWEEN 10 AND 50;

-- Retrieve users whose email starts with 'admin'
SELECT email FROM users WHERE email LIKE 'admin%';
```

## 4. Ключови разлики: MySQL срещу PostgreSQL

Въпреки че и двете системи следват стандартния SQL, те се различават по синтаксис и поведение по подразбиране.

### Цитати за идентификатори (Quoting Identifiers)
Идентификаторите (имена на таблици, имена на колони) трябва да бъдат оградени в кавички, ако са в конфликт с резервирани ключови думи в SQL или съдържат специални символи/интервали.
* **MySQL**: Използва обратни кавички (`` ` ``).
* **PostgreSQL**: Използва двойни кавички (`"`).

```sql
-- MySQL
SELECT `select`, `group` FROM `my_table`;

-- PostgreSQL
SELECT "select", "group" FROM "my_table";
```

### Чувствителност към регистъра при съпоставяне на шаблони (Case Sensitivity)
* **PostgreSQL** е строго чувствителен към регистъра (главни/малки букви) за `LIKE`. За да извършите търсене, нечувствително към регистъра, трябва да използвате специфичния за PostgreSQL оператор `ILIKE`.
* В **MySQL** операторът `LIKE` по подразбиране не е чувствителен към регистъра при стандартни колации (напр. `utf8mb4_0900_ai_ci`). За да го направите чувствителен към регистъра, трябва да кастнете (конвертирате) низа към двоичен (binary) или да използвате двоична колация.

```sql
-- Case-insensitive search for 'john'
-- PostgreSQL
SELECT email FROM users WHERE email ILIKE 'john%';

-- MySQL
SELECT email FROM users WHERE email LIKE 'john%';
```

### Обединяване на низове (String Concatenation)
* **PostgreSQL** използва стандартния за SQL оператор с две вертикални черти (`||`).
* **MySQL** по подразбиране не поддържа `||` за обединяване на низове (той разглежда `||` като логическия оператор `OR`, освен ако не е активиран режимът `PIPES_AS_CONCAT`). Вместо това MySQL използва функцията `CONCAT()`.

```sql
-- PostgreSQL
SELECT first_name || ' ' || last_name AS full_name FROM users;

-- MySQL
SELECT CONCAT(first_name, ' ', last_name) AS full_name FROM users;
```

### Булеви типове данни (Boolean Data Types)
* **PostgreSQL** има вграден тип `BOOLEAN`, който поддържа литературните стойности `true` и `false`.
* **MySQL** няма истински булев тип; той свързва `BOOLEAN` като псевдоним към `TINYINT(1)`, където `0` е лъжа (false), а `1` е истина (true).

```sql
-- PostgreSQL: Returns true/false
SELECT is_active FROM users;

-- MySQL: Returns 1/0
SELECT is_active FROM users;
```

> [!WARNING]
> **Капан с кавичките!**
> Никога не използвайте двойни кавички (`"`) за низови литерали (текстови стойности) в PostgreSQL. PostgreSQL разглежда двойните кавички като кавички за идентификатори (за имена на колони или таблици), което ще доведе до синтактична грешка `column "value" does not exist`. Винаги използвайте единични кавички (`'`) за низови литерали както в MySQL, така е и в PostgreSQL.

## 5. Резюме и добри практики

1. **Бъдете конкретни**: Изброявайте изрично имената на колоните, вместо да използвате `SELECT *`, за да подобрите производителността и устойчивостта на кода.
2. **Стандартизирайте кавичките**: Използвайте единични кавички (`'`) за низови литерали във всички СУБД.
3. **Познавайте операторите си**: Използвайте `ILIKE` в PostgreSQL за съвпадения без чувствителност към регистъра и помнете, че съединяването с `||` е стандартно в Postgres, но изисква `CONCAT()` в MySQL.
4. **Проверки за булеви стойности**: Помнете, че MySQL съхранява булеви стойности като `1` или `0`, което може да повлияе на начина, по който кодът на вашето приложение анализира резултатите от заявките.
