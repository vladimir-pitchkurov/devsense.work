# Реляційні бази даних та оператор SELECT

В основі сучасного зберігання даних лежить реляційна модель баз даних, вперше запропонована Едгаром Ф. Коддом у 1970 році. Замість зберігання даних у неструктурованих текстових файлах або жорстких ієрархічних деревах, реляційна база даних організовує інформацію у структуровані таблиці, які можна динамічно об'єднувати та запитувати за допомогою мови структурованих запитів (SQL). Незалежно від того, використовуєте ви MySQL чи PostgreSQL, розуміння фундаментальних концепцій реляційного проектування та ефективного вибору даних є вкрай важливим.

---

## 1. Реляційна модель: таблиці, стовпці та ключі

У реляційній базі даних дані представлені у вигляді колекції реляційних таблиць. Кожна таблиця складається з:
* **Стовпців (атрибутів)**: визначають тип даних та властивості інформації, що зберігається (наприклад, `user_id` як ціле число, `email` як рядок).
* **Рядків (записів/кортежів)**: представляють окремі екземпляри даних (наприклад, запис конкретного користувача).

Для підтримки цілісності таблиці спираються на дві основні концепції:
1. **Первинний ключ (PK)**: стовпець (або набір стовпців), який унікально ідентифікує кожен рядок у таблиці. Він не може містити значень `NULL`.
2. **Зовнішній ключ (FK)**: стовпець в одній таблиці, який посилається на первинний ключ іншої таблиці, встановлюючи зв'язок між ними.

| Концепція | Опис | Аналогія |
| :--- | :--- | :--- |
| **Таблиця** | Структурована сітка зі стовпців та рядків. | Вкладка електронної таблиці. |
| **Рядок** | Один запис даних. | Один рядок в електронній таблиці. |
| **Первинний ключ** | Унікальний ідентифікатор рядка. | Номер паспорта. |
| **Зовнішній ключ** | Посилання на первинний ключ іншої таблиці. | ID відділу працівника. |

## 2. Отримання даних за допомогою `SELECT`

Найважливішою операцією в SQL є отримання даних за допомогою оператора `SELECT`. У своїй найпростішій формі запит вимагає пропозиції `SELECT` (які стовпці отримати) та пропозиції `FROM` (з якої таблиці отримати дані).

### Вибір усіх стовпців порівняно з конкретними стовпцями
Ви можете отримати всі стовпці за допомогою символу підстановки зірочки (`*`) або вказати лише ті стовпці, які вам потрібні.
```sql
-- MySQL & PostgreSQL
-- Отримання всіх стовпців (не рекомендується для продакшену)
SELECT * FROM users;

-- Отримання конкретних стовпців (рекомендується)
SELECT id, email, first_name FROM users;
```

> [!TIP]
> **Чи знаєте ви?**
> Використання `SELECT *` у продакшені вважається антипатерном. Це змушує рушій бази даних виконувати додаткові операції введення-виведення на диску для читання стовпців, які вам не потрібні, споживає зайву пропускну здатність мережі та може зламати ваш додаток, якщо до таблиці буде додано новий стовпець або видалено старий.

### Псевдоніми стовпців (`AS`)
Псевдоніми дозволяють перейменовувати стовпці у результуючому наборі запиту для кращої читабельності або відповідно до вимог додатка.
```sql
-- MySQL & PostgreSQL
SELECT first_name AS given_name, last_name AS surname FROM users;
```

## 3. Фільтрація результатів за допомогою `WHERE`

Щоб отримати лише певні рядки, використовуйте пропозицію `WHERE`. Пропозиція `WHERE` оцінює логічну умову для кожного рядка, повертаючи лише ті, для яких умова є істинною (true).

### Стандартні оператори
SQL підтримує стандартні оператори порівняння:
* `=` (дорівнює)
* `<>` або `!=` (не дорівнює)
* `>` (більше), `<` (менше)
* `>=` (більше або дорівнює), `<=` (менше або дорівнює)

```sql
-- Отримання активних користувачів, зареєстрованих після певного ID
SELECT email FROM users WHERE is_active = true AND id > 100;
```

### Розширені оператори фільтрації
* **`BETWEEN`**: фільтрує значення в межах певного діапазону (включаючи граничні значення).
* **`IN`**: перевіряє, чи відповідає значення будь-якому значенню у вказаному списку.
* **`LIKE`**: виконує просте співставлення за шаблоном за допомогою символів підстановки:
  - `%` представляє нуль або більше символів.
  - `_` представляє рівно один символ.

```sql
-- Отримання користувачів з ID 1, 3 або 5
SELECT email FROM users WHERE id IN (1, 3, 5);

-- Отримання користувачів, зареєстрованих у певному діапазоні
SELECT email FROM users WHERE id BETWEEN 10 AND 50;

-- Отримання користувачів, чий email починається на 'admin'
SELECT email FROM users WHERE email LIKE 'admin%';
```

## 4. Ключові відмінності: MySQL проти PostgreSQL

Хоча обидва рушії дотримуються стандартного SQL, вони різняться в синтаксисі та поведінці за замовчуванням.

### Екранування ідентифікаторів
Ідентифікатори (назви таблиць, стовпців) потрібно екранувати, якщо вони конфліктують із зарезервованими ключовими словами SQL або містять спеціальні символи/пробіли.
* **MySQL**: використовує зворотні апострофи (`` ` ``).
* **PostgreSQL**: використовує подвійні лапки (`"`).

```sql
-- MySQL
SELECT `select`, `group` FROM `my_table`;

-- PostgreSQL
SELECT "select", "group" FROM "my_table";
```

### Чутливість до регістру при співставленні за шаблоном
* **PostgreSQL** є строго чутливим до регістру для `LIKE`. Для виконання пошуку без урахування регістру необхідно використовувати специфічний для PostgreSQL оператор `ILIKE`.
* У **MySQL** оператор `LIKE` за замовчуванням нечутливий до регістру при стандартному кодуванні (наприклад, `utf8mb4_0900_ai_ci`). Щоб зробити його чутливим до регістру, необхідно привести рядок до бінарного типу або використовувати бінарне кодування.

```sql
-- Пошук без урахування регістру для 'john'
-- PostgreSQL
SELECT email FROM users WHERE email ILIKE 'john%';

-- MySQL
SELECT email FROM users WHERE email LIKE 'john%';
```

### Конкатенація рядків
* **PostgreSQL** використовує стандартний оператор конкатенації SQL з подвійною вертикальною рискою (`||`).
* **MySQL** за замовчуванням не підтримує `||` для конкатенації (він трактує `||` як логічний оператор `OR`, якщо не увімкнено режим SQL `PIPES_AS_CONCAT`). Замість цього MySQL використовує функцію `CONCAT()`.

```sql
-- PostgreSQL
SELECT first_name || ' ' || last_name AS full_name FROM users;

-- MySQL
SELECT CONCAT(first_name, ' ', last_name) AS full_name FROM users;
```

### Логічні типи даних (Boolean)
* **PostgreSQL** має вбудований тип `BOOLEAN`, що підтримує літеральні значення `true` та `false`.
* **MySQL** не має справжнього логічного типу; він використовує псевдонім `BOOLEAN` для `TINYINT(1)`, де `0` означає false, а `1` — true.

```sql
-- PostgreSQL: Повертає true/false
SELECT is_active FROM users;

-- MySQL: Повертає 1/0
SELECT is_active FROM users;
```

> [!WARNING]
> **Пастка екранування!**
> Ніколи не використовуйте подвійні лапки (`"`) для рядкових літералів (текстових значень) у PostgreSQL. PostgreSQL трактує подвійні лапки як лапки ідентифікаторів (для назв стовпців або таблиць), що призведе до синтаксичної помилки `column "value" does not exist`. Завжди використовуйте одинарні лапки (`'`) для рядкових літералів як у MySQL, так і в PostgreSQL.

## 5. Підсумок та найкращі практики

1. **Будьте конкретними**: явно вказуйте назви стовпців замість використання `SELECT *` для підвищення продуктивності та стійкості коду.
2. **Стандартизуйте лапки**: використовуйте одинарні лапки (`'`) для рядкових літералів у всіх рушіях баз даних.
3. **Знайте свій оператор**: використовуйте `ILIKE` у PostgreSQL для співставлення без урахування регістру та пам'ятайте, що конкатенація `||` є стандартною в Postgres, але вимагає використання `CONCAT()` у MySQL.
4. **Логічні перевірки**: пам'ятайте, що MySQL зберігає логічні значення як `1` або `0`, що може вплинути на те, як код вашого додатка обробляє результати запитів.
