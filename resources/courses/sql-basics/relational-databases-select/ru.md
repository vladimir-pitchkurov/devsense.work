# Реляционные базы данных и оператор SELECT

В основе современного хранения данных лежит реляционная модель баз данных, впервые предложенная Эдгаром Ф. Коддом в 1970 году. Вместо хранения данных в неструктурированных текстовых файлах или жестких иерархических деревьях, реляционная СУБД организует информацию в виде структурированных таблиц, которые можно динамически связывать и опрашивать с помощью структурированного языка запросов (SQL). Независимо от того, используете ли вы MySQL или PostgreSQL, понимание основ реляционного проектирования и эффективного извлечения данных имеет решающее значение.

---

## 1. Реляционная модель: таблицы, колонки и ключи

В реляционной базе данных данные представлены в виде набора таблиц связей. Каждая таблица состоит из:
* **Колонок (Атрибутов)**: определяют тип данных и свойства сохраняемой информации (например, `user_id` как целое число, `email` как строка).
* **Строк (Записей)**: представляют отдельные экземпляры данных (например, запись конкретного пользователя).

Для поддержания целостности данных таблицы опираются на две важные концепции:
1. **Первичный ключ (Primary Key / PK)**: колонка (или набор колонок), которая уникально идентифицирует каждую строку в таблице. Он не может содержать значения `NULL`.
2. **Внешний ключ (Foreign Key / FK)**: колонка в одной таблице, которая ссылается на первичный ключ другой таблицы, устанавливая связь между ними.

| Понятие | Описание | Аналогия |
| :--- | :--- | :--- |
| **Таблица** | Структурированная сетка из колонок и строк. | Вкладка в табличном редакторе. |
| **Строка** | Единичная запись данных. | Одна строка в таблице. |
| **Первичный ключ** | Уникальный идентификатор строки. | Номер паспорта. |
| **Внешний ключ** | Ссылка на первичный ключ другой таблицы. | ID отдела в профиле сотрудника. |

## 2. Извлечение данных с помощью `SELECT`

Самая фундаментальная операция в SQL — получение данных с помощью оператора `SELECT`. В своей простейшей форме запрос требует указания предложения `SELECT` (какие колонки извлечь) и предложения `FROM` (из какой таблицы).

### Выбор всех колонок против выбора конкретных колонок
Вы можете извлечь все колонки, используя групповой символ «звездочка» (`*`), или указать только те колонки, которые вам действительно необходимы.
```sql
-- MySQL и PostgreSQL
-- Извлечь все колонки (не рекомендуется для продакшена)
SELECT * FROM users;

-- Извлечь конкретные колонки (рекомендуемый подход)
SELECT id, email, first_name FROM users;
```

> [!TIP]
> **А знаете ли вы?**
> Использование `SELECT *` в реальных проектах считается антипаттерном. Это заставляет движок базы данных выполнять лишние операции дискового ввода-вывода для чтения ненужных колонок, расходует сетевую пропускную способность и может сломать ваше приложение, если в таблицу будет добавлена новая колонка или удалена старая.

### Псевдонимы колонок (`AS`)
Псевдонимы позволяют переименовывать колонки в результирующем наборе запроса для улучшения читаемости или соответствия ожиданиям приложения.
```sql
-- MySQL и PostgreSQL
SELECT first_name AS given_name, last_name AS surname FROM users;
```

## 3. Фильтрация результатов с помощью `WHERE`

Чтобы отфильтровать только нужные строки, используется предложение `WHERE`. Оно вычисляет логическое условие для каждой строки, возвращая только те из них, для которых условие истинно (`true`).

### Стандартные операторы сравнения
SQL поддерживает стандартные операторы сравнения:
* `=` (равно)
* `<>` или `!=` (не равно)
* `>` (больше), `<` (меньше)
* `>=` (больше или равно), `<=` (меньше или равно)

```sql
-- Получить активных пользователей, зарегистрированных после определенного ID
SELECT email FROM users WHERE is_active = true AND id > 100;
```

### Расширенные операторы фильтрации
* **`BETWEEN`**: фильтрует значения в указанном диапазоне (включая граничные значения).
* **`IN`**: проверяет, соответствует ли значение какому-либо элементу из заданного списка.
* **`LIKE`**: выполняет простой поиск по шаблону с использованием спецсимволов:
  - `%` соответствует строке любой длины (включая пустую).
  - `_` соответствует ровно одному символу.

```sql
-- Получить пользователей с ID 1, 3 или 5
SELECT email FROM users WHERE id IN (1, 3, 5);

-- Получить пользователей, зарегистрированных в определенном диапазоне ID
SELECT email FROM users WHERE id BETWEEN 10 AND 50;

-- Получить пользователей, чей email начинается на 'admin'
SELECT email FROM users WHERE email LIKE 'admin%';
```

## 4. Ключевые различия: MySQL и PostgreSQL

Хотя оба движка следуют стандартам SQL, они имеют существенные отличия в синтаксисе и поведении.

### Экранирование идентификаторов
Имена таблиц и колонок должны экранироваться, если они совпадают с зарезервированными ключевыми словами SQL или содержат специальные символы и пробелы.
* **MySQL**: использует обратные апострофы (`` ` ``).
* **PostgreSQL**: использует двойные кавычки (`"`).

```sql
-- MySQL
SELECT `select`, `group` FROM `my_table`;

-- PostgreSQL
SELECT "select", "group" FROM "my_table";
```

### Чувствительность к регистру при поиске по шаблону
* **PostgreSQL** строго чувствителен к регистру при использовании `LIKE`. Для регистронезависимого поиска необходимо использовать специфичный для Postgres оператор `ILIKE`.
* В **MySQL** оператор `LIKE` по умолчанию нечувствителен к регистру при использовании стандартных кодировок (например, `utf8mb4_0900_ai_ci`). Чтобы сделать поиск чувствительным к регистру, необходимо привести строку к бинарному виду или использовать бинарное сопоставление (collation).

```sql
-- Регистронезависимый поиск по имени 'john'
-- PostgreSQL
SELECT email FROM users WHERE email ILIKE 'john%';

-- MySQL
SELECT email FROM users WHERE email LIKE 'john%';
```

### Конкатенация (объединение) строк
* **PostgreSQL** использует стандартный для SQL оператор с двойной вертикальной чертой (`||`).
* **MySQL** по умолчанию не поддерживает оператор `||` для конкатенации (он интерпретирует его как логическое `OR`, если только не включен специальный режим `PIPES_AS_CONCAT`). Вместо этого в MySQL используется функция `CONCAT()`.

```sql
-- PostgreSQL
SELECT first_name || ' ' || last_name AS full_name FROM users;

-- MySQL
SELECT CONCAT(first_name, ' ', last_name) AS full_name FROM users;
```

### Булев тип данных
* **PostgreSQL** имеет полноценный встроенный тип `BOOLEAN`, поддерживающий литеральные значения `true` и `false`.
* В **MySQL** нет истинного булева типа; ключевое слово `BOOLEAN` является синонимом для `TINYINT(1)`, где `0` означает ложь, а `1` — истину.

```sql
-- PostgreSQL: возвращает true/false
SELECT is_active FROM users;

-- MySQL: возвращает 1/0
SELECT is_active FROM users;
```

> [!WARNING]
> **Ловушка с кавычками!**
> Никогда не используйте двойные кавычки (`"`) для текстовых литералов (строк) в PostgreSQL. PostgreSQL воспринимает двойные кавычки исключительно как экранирование имен колонок или таблиц, что приведет к синтаксической ошибке вида `column "value" does not exist`. Всегда используйте одинарные кавычки (`'`) для строковых литералов как в MySQL, так и в PostgreSQL.

## 5. Резюме и лучшие практики

1. **Конкретизируйте запросы**: явно указывайте имена колонок вместо `SELECT *` для повышения производительности и отказоустойчивости кода.
2. **Стандартизируйте кавычки**: используйте одинарные кавычки (`'`) для текстовых значений во всех СУБД.
3. **Изучите различия**: используйте `ILIKE` в PostgreSQL для регистронезависимого поиска и помните, что конкатенация `||` является стандартной для Postgres, в то время как в MySQL требуется вызов `CONCAT()`.
4. **Булевы проверки**: учитывайте, что MySQL хранит логические значения в виде `1` или `0`, что влияет на обработку результатов на стороне бэкенда.
