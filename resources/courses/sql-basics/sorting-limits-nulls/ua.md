# Сортування, ліміти та значення NULL

Отримання даних у випадковому порядку рідко буває корисним. У реальних додатках вам потрібно представляти записи відсортованими за алфавітом, числово або хронологічно. Крім того, бази даних часто містять величезні набори даних, що робить необхідним обмеження обсягу отриманих рядків (наприклад, для пагінації). Нарешті, ви повинні розуміти, як SQL обробляє відсутні або невідомі дані, представлені значенням `NULL`.

У цьому розділі ми розглянемо, як організовувати, обмежувати та безпечно запитувати дані за допомогою `ORDER BY`, `LIMIT` та порівняння з `NULL`, а також дізнаємося про відмінності в роботі цих функцій у MySQL та PostgreSQL.

---

## 1. Сортування результатів за допомогою `ORDER BY`

За замовчуванням рушії реляційних баз даних повертають рядки у невизначеному порядку (часто залежно від того, як вони фізично збережені на диску). Щоб гарантувати певний порядок, необхідно використовувати пропозицію `ORDER BY`.

### Сортування за зростанням та спаданням
* **`ASC` (Ascending)**: сортує значення від найменшого до найбільшого (поведінка за замовчуванням).
* **`DESC` (Descending)**: сортує значення від найбільшого до найменшого.

```sql
-- MySQL & PostgreSQL
-- Сортування товарів за ціною, спочатку найдорожчі
SELECT name, price FROM products ORDER BY price DESC;
```

### Сортування за кількома стовпцями
Ви можете сортувати за кількома стовпцями. Рушій спочатку сортує дані за першим стовпцем, а за наявності однакових значень — сортує їх за другим стовпцем і так далі.
```sql
-- MySQL & PostgreSQL
-- Сортування за категорією в алфавітному порядку, а потім за ціною у порядку спадання всередині кожної категорії
SELECT category, name, price 
FROM products 
ORDER BY category ASC, price DESC;
```

## 2. Обмеження виводу: `LIMIT` та `OFFSET`

Отримання мільйонів рядків може призвести до збою сервера додатків та блокування ресурсів бази даних. Щоб запобігти цьому, ви можете обмежити результуючий набір.

* **`LIMIT`**: вказує максимальну кількість рядків для повернення.
* **`OFFSET`**: пропускає певну кількість рядків перед поверненням результатів (зазвичай використовується для пагінації).

```sql
-- MySQL & PostgreSQL
-- Отримання другої сторінки товарів (елементи 11-20)
SELECT name, price 
FROM products 
ORDER BY price DESC 
LIMIT 10 OFFSET 10;
```

## 3. Таємниця значень `NULL`

У SQL `NULL` представляє відсутність даних, невідоме значення або відсутній атрибут. Воно **не** є еквівалентом порожнього рядка `''` або числа `0`.

### Пастка тризначної логіки
У стандартних мовах програмування `true` та `false` є єдиними логічними станами. SQL, однак, використовує **тризначну логіку**: `true`, `false` та `unknown` (невідомо, що представляється як `NULL`).

Оскільки `NULL` означає "невідомо", ви не можете порівнювати його за допомогою стандартних операторів на кшталт `=` або `!=`. Наприклад:
* Чи дорівнює невідоме значення 5? **Невідомо (`NULL`)**.
* Чи дорівнює одне невідоме значення іншому невідомому значенню? **Невідомо (`NULL`)**.

```sql
-- ЦЕ НЕ ПРАЦЮВАТИМЕ! Запит поверне нуль рядків.
SELECT * FROM users WHERE middle_name = NULL;
```

### Правильне порівняння з NULL
Щоб перевірити, чи є стовпець порожнім чи заповненим, потрібно використовувати `IS NULL` або `IS NOT NULL`.
```sql
-- MySQL & PostgreSQL
-- Правильний спосіб знайти користувачі без по батькові (middle name)
SELECT email FROM users WHERE middle_name IS NULL;

-- Правильний спосіб знайти користувачі із заповненим по батькові
SELECT email FROM users WHERE middle_name IS NOT NULL;
```

## 4. Ключові відмінності: MySQL проти PostgreSQL

### Сортування Null (`NULLS FIRST` проти `NULLS LAST`)
Коли ви сортуєте стовпець, який містить значення `NULL`, як саме рушій бази даних їх розташовує?
* **MySQL**: трактує `NULL` як найменше можливе значення. При сортуванні за зростанням (`ASC`) значення `NULL` з'являються першими. При сортуванні за спаданням (`DESC`) значення `NULL` з'являються останніми.
* **PostgreSQL**: трактує `NULL` як найбільше можливе значення. При сортуванні за зростанням (`ASC`) значення `NULL` з'являються останніми. При сортуванні за спаданням (`DESC`) значення `NULL` з'являються першими.

Однак PostgreSQL підтримує стандартне перевизначення SQL: `NULLS FIRST` або `NULLS LAST`. MySQL не підтримує це нативно.

| База даних | Сортування | Позиція NULL за замовчуванням | Ручне перевизначення |
| :--- | :--- | :--- | :--- |
| **MySQL** | `ASC` | Спочатку | Немає (Потрібен обхідний шлях) |
| **MySQL** | `DESC` | В кінці | Немає (Потрібен обхідний шлях) |
| **PostgreSQL** | `ASC` | В кінці | `ORDER BY price ASC NULLS FIRST` |
| **PostgreSQL** | `DESC` | Спочатку | `ORDER BY price DESC NULLS LAST` |

#### Обхідний шлях для сортування Null у MySQL
Щоб змусити значення `NULL` переміститися в кінець при сортуванні за зростанням у MySQL, можна скористатися перевіркою логічного виразу:
```sql
-- MySQL: NULL сортуються останніми при сортуванні за зростанням
SELECT name, price FROM products ORDER BY price IS NULL ASC, price ASC;
```

### Нестандартний синтаксис `LIMIT`
* **MySQL** підтримує скорочений синтаксис через кому: `LIMIT offset, row_count`.
* **PostgreSQL** не підтримує цей синтаксис і видасть синтаксичну помилку.

```sql
-- Лише для MySQL (Скорочений синтаксис: ліміт 10 рядків, пропускаючи перші 5)
SELECT name FROM products LIMIT 5, 10;

-- Стандарт PostgreSQL & MySQL (Рекомендовано)
SELECT name FROM products LIMIT 10 OFFSET 5;
```

> [!WARNING]
> **Пастка продуктивності при великих зміщеннях (Offset)!**
> Використання великого значення `OFFSET` (наприклад, `LIMIT 10 OFFSET 500000`) змушує рушій бази даних сканувати та відкидати 500 000 рядків перед поверненням 10 запитаних рядків. Це спричиняє серйозне погіршення продуктивності на великих таблицях. Для глибокої пагінації віддавайте перевагу пагінації на основі курсору (keyset pagination) за допомогою `WHERE id > last_seen_id LIMIT 10`.

> [!TIP]
> **Чи знаєте ви?**
> Стандарт SQL визначає конструкцію `FETCH FIRST n ROWS ONLY` замість `LIMIT`. Хоча і MySQL, і PostgreSQL підтримують `LIMIT`, PostgreSQL також підтримує офіційний стандарт:
> `SELECT name FROM products ORDER BY price DESC FETCH FIRST 10 ROWS ONLY;`

## 5. Підсумок та найкращі практики

1. **Завжди використовуйте `ORDER BY` з `LIMIT`**: без сортування `LIMIT` повертатиме випадковий набір рядків залежно від стану бази даних.
2. **Ніколи не використовуйте `=` з `NULL`**: завжди використовуйте `IS NULL` або `IS NOT NULL`.
3. **Використовуйте стандартний `LIMIT/OFFSET`**: уникайте використання скороченого запису `LIMIT` через кому в MySQL, щоб зберегти переносимість запитів.
4. **Звертайте увагу на сортування Null**: пам'ятайте, що MySQL ставить `NULL` першими при `ASC`, тоді як PostgreSQL ставить їх останніми. Використовуйте модифікатори `NULLS FIRST/LAST` у Postgres або трюки з сортуванням `IS NULL` у MySQL, якщо потрібна точна поведінка.
