# Сортиране, лимити и NULL стойности

Извличането на данни в произволен ред рядко е полезно. В реалните приложения трябва да представяте записите сортирани по азбучен ред, числово или хронологично. Освен това базите данни често съдържат огромни масиви от данни, което налага ограничаване на обема на извлечените редове (напр. за странициране). Накрая, трябва да разберете как SQL обработва липсващи или неизвестни данни, представени с `NULL`.

В тази глава ще изследваме как да организираме, ограничаваме и сигурно да заявяваме данни с помощта на `ORDER BY`, `LIMIT` и сравнения с `NULL`, заедно с различните начини, по които MySQL и PostgreSQL управляват тези функции.

---

## 1. Сортиране на резултати с `ORDER BY`

По подразбиране системите за релационни бази данни връщат редове в неуточнен ред (често въз основа на това как са физически записани върху диска). За да гарантирате конкретен ред, трябва да използвате клаузата `ORDER BY`.

### Възходящ и низходящ ред
* **`ASC` (Ascending)**: Сортира стойностите от най-ниската към най-високата (поведение по подразбиране).
* **`DESC` (Descending)**: Сортира стойностите от най-високата към най-ниската.

```sql
-- MySQL & PostgreSQL
-- Sort products by price, highest first
SELECT name, price FROM products ORDER BY price DESC;
```

### Сортиране по няколко колони
Можете да сортирате по няколко колони. Системата първо сортира по първата колона и ако има повтарящи се стойности, сортира тези дубликати по втората колона и т.н.
```sql
-- MySQL & PostgreSQL
-- Sort by category alphabetically, and then by price descending within each category
SELECT category, name, price 
FROM products 
ORDER BY category ASC, price DESC;
```

---

## 2. Ограничаване на резултатите: `LIMIT` и `OFFSET`

Извличането на милиони редове може да срине сървъра на вашето приложение и да блокира ресурсите на базата данни. За да предотвратите това, можете да ограничите набора от резултати.

* **`LIMIT`**: Указва максималния брой редове, които да бъдат върнати.
* **`OFFSET`**: Пропуска определен брой редове преди връщането на резултатите (обикновено се използва за странициране).

```sql
-- MySQL & PostgreSQL
-- Get the second page of products (items 11-20)
SELECT name, price 
FROM products 
ORDER BY price DESC 
LIMIT 10 OFFSET 10;
```

## 3. Мистерията на `NULL` стойностите

В SQL `NULL` представлява липса на данни, неизвестна стойност или липсващ атрибут. Той **не** е еквивалентен на празен низ `''` или на числото `0`.

### Капанът на тризначната логика (Three-Valued Logic)
В стандартните езици за програмиране `true` (истина) и `false` (лъжа) са единствените булеви състояния. SQL обаче използва **Тризначна логика**: `true`, `false` и `unknown` (неизвестно, представено чрез `NULL`). 

Тъй като `NULL` означава „неизвестно“, не можете да го сравнявате с помощта на стандартни оператори като `=` или `!=`. Например:
* Равна ли е неизвестна стойност на 5? **Неизвестно (`NULL`)**.
* Равна ли е една неизвестна стойност на друга неизвестна стойност? **Неизвестно (`NULL`)**.

```sql
-- THIS WILL NOT WORK! It returns zero rows.
SELECT * FROM users WHERE middle_name = NULL;
```

### Правилно сравняване с NULL
За да проверите дали дадена колона е празна или съдържа стойност, трябва да използвате `IS NULL` или `IS NOT NULL`.
```sql
-- MySQL & PostgreSQL
-- Correct way to find users without a middle name
SELECT email FROM users WHERE middle_name IS NULL;

-- Correct way to find users with a middle name
SELECT email FROM users WHERE middle_name IS NOT NULL;
```

## 4. Ключови разлики: MySQL срещу PostgreSQL

### Подреждане на Null стойности (`NULLS FIRST` срещу `NULLS LAST`)
Когато сортирате колона, която съдържа `NULL` стойности, как ги разполага сървърът?
* **MySQL**: Третира `NULL` като възможно най-ниската стойност. При възходящ ред (`ASC`) `NULL` стойностите се появяват първи. При низходящ ред (`DESC`) `NULL` стойностите се появяват последни.
* **PostgreSQL**: Третира `NULL` като възможно най-високата стойност. При възходящ ред (`ASC`) `NULL` стойностите се появяват последни. При низходящ ред (`DESC`) `NULL` стойностите се появяват първи.

PostgreSQL обаче поддържа стандартната за SQL възможност за промяна: `NULLS FIRST` или `NULLS LAST`. MySQL не поддържа това нативно.

| База данни | Ред | Позиция на NULL по подразбиране | Потребителска промяна (Override) |
| :--- | :--- | :--- | :--- |
| **MySQL** | `ASC` | Първи | Няма (Изисква заобиколен начин) |
| **MySQL** | `DESC` | Последен | Няма (Изисква заобиколен начин) |
| **PostgreSQL** | `ASC` | Последен | `ORDER BY price ASC NULLS FIRST` |
| **PostgreSQL** | `DESC` | Първи | `ORDER BY price DESC NULLS LAST` |

#### Заобиколен начин за подреждане на Null в MySQL
За да принудите `NULL` стойностите да отидат накрая при възходящо сортиране в MySQL, можете да използвате проверка с булев израз:
```sql
-- MySQL: NULLs sorted last in ascending order
SELECT name, price FROM products ORDER BY price IS NULL ASC, price ASC;
```

### Нестандартен синтаксис за `LIMIT`
* **MySQL** поддържа съкратен синтаксис с разделител запетая: `LIMIT offset, row_count`.
* **PostgreSQL** не поддържа този синтаксис и ще хвърли синтактична грешка.

```sql
-- MySQL Only (Shorthand syntax: limit 10 rows, skipping the first 5)
SELECT name FROM products LIMIT 5, 10;

-- PostgreSQL & MySQL Standard (Recommended)
SELECT name FROM products LIMIT 10 OFFSET 5;
```

> [!WARNING]
> **Капан за производителността при Offset!**
> Използването на висок `OFFSET` (напр. `LIMIT 10 OFFSET 500000`) принуждава сървъра на базата данни да сканира и отхвърли 500 000 реда, преди да върне 10-те реда, които сте поискали. Това причинява сериозно влошаване на производителността при големи таблици. За дълбоко странициране предпочитайте странициране, базирано на курсор (keyset pagination), с помощта на `WHERE id > last_seen_id LIMIT 10`.

> [!TIP]
> **Знаехте ли, че?**
> Стандартът SQL дефинира `FETCH FIRST n ROWS ONLY` вместо `LIMIT`. Въпреки че и MySQL, и PostgreSQL поддържат `LIMIT`, PostgreSQL поддържа също и официалния стандарт:
> `SELECT name FROM products ORDER BY price DESC FETCH FIRST 10 ROWS ONLY;`

## 5. Резюме и добри практики

1. **Винаги използвайте `ORDER BY` с `LIMIT`**: Без сортиране `LIMIT` ще върне произволен набор от редове в зависимост от състоянието на базата данни.
2. **Никога не използвайте `=` с `NULL`**: Винаги използвайте `IS NULL` или `IS NOT NULL`.
3. **Използвайте стандартен `LIMIT/OFFSET`**: Избягвайте съкратения синтаксис на MySQL с разделител запетая за `LIMIT`, за да поддържате преносимостта на заявките.
4. **Внимавайте със сортирането на Null**: Имайте предвид, че MySQL поставя `NULL` стойностите първи при `ASC`, докато PostgreSQL ги поставя последни. Използвайте модификаторите `NULLS FIRST/LAST` в Postgres или триковете за сортиране с `IS NULL` в MySQL, когато се изисква точно определено поведение.
