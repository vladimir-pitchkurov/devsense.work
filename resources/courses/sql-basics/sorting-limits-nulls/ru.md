# Сортировка, лимиты и значения NULL

Получение данных в случайном порядке редко бывает полезным. В реальных приложениях записи необходимо отображать отсортированными по алфавиту, числам или датам. Кроме того, базы данных часто содержат огромные объемы информации, что делает необходимым ограничение количества извлекаемых строк (например, для постраничного вывода). Наконец, важно понимать, как SQL обрабатывает отсутствующие или неизвестные данные, представленные значением `NULL`.

В этой главе мы разберем, как упорядочивать, ограничивать и безопасно опрашивать данные с помощью `ORDER BY`, `LIMIT` и сравнений с `NULL`, а также рассмотрим особенности обработки этих конструкций в MySQL и PostgreSQL.

---

## 1. Сортировка результатов с помощью `ORDER BY`

По умолчанию СУБД возвращают строки в неопределенном порядке (часто зависящем от физического расположения данных на диске). Чтобы гарантировать конкретный порядок, необходимо использовать предложение `ORDER BY`.

### Сортировка по возрастанию и убыванию
* **`ASC` (Ascending)**: сортирует значения от меньшего к большему (поведение по умолчанию).
* **`DESC` (Descending)**: сортирует значения от большего к меньшему.

```sql
-- MySQL и PostgreSQL
-- Сортировка товаров по цене, начиная с самых дорогих
SELECT name, price FROM products ORDER BY price DESC;
```

### Сортировка по нескольким колонкам
Вы можете сортировать результаты по нескольким колонкам. Движок сначала сортирует данные по первой указанной колонке, а при совпадении значений — упорядочивает их по второй и так далее.
```sql
-- MySQL и PostgreSQL
-- Сортировка по категории по алфавиту, а внутри категории — по цене по убыванию
SELECT category, name, price 
FROM products 
ORDER BY category ASC, price DESC;
```

## 2. Ограничение вывода: `LIMIT` и `OFFSET`

Загрузка миллионов строк может привести к падению сервера приложений и исчерпанию ресурсов базы данных. Для предотвращения этого результирующий набор строк ограничивают.

* **`LIMIT`**: указывает максимальное количество возвращаемых строк.
* **`OFFSET`**: пропускает указанное количество строк перед началом вывода результатов (часто применяется для пагинации).

```sql
-- MySQL и PostgreSQL
-- Получить вторую страницу товаров (записи с 11 по 20)
SELECT name, price 
FROM products 
ORDER BY price DESC 
LIMIT 10 OFFSET 10;
```

## 3. Загадка значений `NULL`

В SQL `NULL` представляет собой отсутствие данных, неизвестное значение или пропущенный атрибут. Это **не** пустая строка `''` и **не** число `0`.

### Ловушка трехзначной логики
В обычных языках программирования существуют только два булевых состояния: `true` и `false`. Однако SQL использует **трехзначную логику**: `true`, `false` и `unknown` (неизвестно), которое и представляется значением `NULL`.

Поскольку `NULL` означает «неизвестно», его нельзя сравнивать с помощью обычных операторов, таких как `=` или `!=`. Например:
* Равно ли неизвестное значение числу 5? **Неизвестно (`NULL`)**.
* Равно ли одно неизвестное значение другому неизвестному значению? **Неизвестно (`NULL`)**.

```sql
-- ЭТО НЕ БУДЕТ РАБОТАТЬ! Запрос вернет 0 строк.
SELECT * FROM users WHERE middle_name = NULL;
```

### Правильное сравнение с NULL
Для проверки того, пуста ли колонка или заполнена, необходимо использовать специальные конструкции `IS NULL` или `IS NOT NULL`.
```sql
-- MySQL и PostgreSQL
-- Правильный поиск пользователей без отчества
SELECT email FROM users WHERE middle_name IS NULL;

-- Правильный поиск пользователей с указанным отчеством
SELECT email FROM users WHERE middle_name IS NOT NULL;
```

## 4. Ключевые различия: MySQL и PostgreSQL

### Порядок сортировки NULL (`NULLS FIRST` против `NULLS LAST`)
Как СУБД располагает `NULL` значения при сортировке колонки?
* **MySQL**: рассматривает `NULL` как минимально возможное значение. При сортировке по возрастанию (`ASC`) `NULL` идут первыми. При сортировке по убыванию (`DESC`) `NULL` идут последними.
* **PostgreSQL**: рассматривает `NULL` как максимально возможное значение. При сортировке по возрастанию (`ASC`) `NULL` идут последними. При сортировке по убыванию (`DESC`) `NULL` идут первыми.

PostgreSQL поддерживает стандартное переопределение этого поведения с помощью ключевых слов `NULLS FIRST` или `NULLS LAST`. MySQL не поддерживает этот синтаксис нативно.

| СУБД | Направление | Положение NULL по умолчанию | Переопределение |
| :--- | :--- | :--- | :--- |
| **MySQL** | `ASC` | В начале | Нет (требуется обходное решение) |
| **MySQL** | `DESC` | В конце | Нет (требуется обходное решение) |
| **PostgreSQL** | `ASC` | В конце | `ORDER BY price ASC NULLS FIRST` |
| **PostgreSQL** | `DESC` | В начале | `ORDER BY price DESC NULLS LAST` |

#### Обходной путь для сортировки NULL в MySQL
Чтобы принудительно отправить значения `NULL` в конец при сортировке по возрастанию в MySQL, можно использовать сортировку по логическому выражению:
```sql
-- MySQL: значения NULL окажутся в конце при сортировке по возрастанию
SELECT name, price FROM products ORDER BY price IS NULL ASC, price ASC;
```

### Нестандартный синтаксис `LIMIT`
* **MySQL** поддерживает сокращенный синтаксис через запятую: `LIMIT offset, row_count`.
* **PostgreSQL** не поддерживает такой синтаксис и вернет ошибку.

```sql
-- Только в MySQL (вернуть 10 строк, пропустив первые 5)
SELECT name FROM products LIMIT 5, 10;

-- PostgreSQL и MySQL (Рекомендуемый стандартный вариант)
SELECT name FROM products LIMIT 10 OFFSET 5;
```

> [!WARNING]
> **Падение производительности при больших OFFSET!**
> Использование большого смещения (например, `LIMIT 10 OFFSET 500000`) заставляет базу данных просканировать и отбросить 500 000 строк перед возвратом нужных 10. Это приводит к серьезным задержкам на больших таблицах. Для глубокой пагинации используйте курсорную пагинацию (keyset pagination) с условием `WHERE id > last_seen_id LIMIT 10`.

> [!TIP]
> **А знаете ли вы?**
> Стандарт SQL определяет конструкцию `FETCH FIRST n ROWS ONLY` вместо `LIMIT`. Хотя обе СУБД поддерживают `LIMIT`, PostgreSQL также поддерживает и официальный стандарт:
> `SELECT name FROM products ORDER BY price DESC FETCH FIRST 10 ROWS ONLY;`

## 5. Резюме и лучшие практики

1. **Всегда используйте `ORDER BY` вместе с `LIMIT`**: без сортировки `LIMIT` может возвращать случайные наборы строк при каждом запуске.
2. **Никогда не сравнивайте с `NULL` через `=`**: всегда используйте `IS NULL` или `IS NOT NULL`.
3. **Пишите стандартный `LIMIT/OFFSET`**: избегайте синтаксиса MySQL через запятую для сохранения переносимости кода.
4. **Следите за сортировкой NULL**: помните, что MySQL помещает `NULL` в начало при `ASC`, а PostgreSQL — в конец. Используйте модификаторы `NULLS FIRST/LAST` в Postgres или логические трюки сортировки в MySQL при необходимости.
