# Агрегиране и групиране

Досега извличахме само отделни редове. В много сценарии обаче е необходимо да анализирате данните на по-високо ниво: намиране на средната заплата на служител, преброяване на общите поръчки или намиране на най-скъпия продукт в определена категория.

SQL предоставя мощни **агрегатни функции** и клаузата `GROUP BY` за обобщаване на хиляди редове в смислени резюмета. В тази глава ще усвоим групирането на данни, филтрирането на тези групи с помощта на клаузата `HAVING` и ще разгледаме как се различава изпълнението им в MySQL и PostgreSQL.

---

## 1. Агрегатни функции

Агрегатните функции извършват изчисление върху набор от стойности и връщат единична стойност.

* **`COUNT()`**: Връща броя на редовете.
* **`SUM()`**: Връща сумата от числови стойности.
* **`AVG()`**: Връща средната стойност от числови стойности.
* **`MIN()`**: Връща най-малката стойност.
* **`MAX()`**: Връща най-голямата стойност.

```sql
-- MySQL & PostgreSQL
-- Calculate count, average price, and max price for all products
SELECT COUNT(*) AS total_products, AVG(price) AS average_price, MAX(price) AS highest_price 
FROM products;
```

### Агрегатни функции и `NULL` стойности
Разпространено заблуждение е, че агрегатните функции включват `NULL` стойностите в своите изчисления.
* Повечето агрегатни функции (като `SUM`, `AVG`, `MIN`, `MAX`) **напълно игнорират NULL стойностите**.
* `COUNT(column_name)` брои само редовете, в които посочената колона **не е NULL**.
* `COUNT(*)` брои всеки ред, включително редовете с `NULL` стойности.

```sql
-- If we have 5 users, and only 3 have a middle name:
SELECT COUNT(*) FROM users;            -- Returns 5
SELECT COUNT(middle_name) FROM users;  -- Returns 3
```

## 2. Групиране на данни с `GROUP BY`

Клаузата `GROUP BY` разделя редовете на таблицата на групи. След това сървърът на базата данни прилага агрегатните функции за всяка група самостоятелно.

```sql
-- MySQL & PostgreSQL
-- Get average price per product category
SELECT category, AVG(price) AS avg_price 
FROM products 
GROUP BY category;
```

---

## 3. Филтриране на групи с `HAVING`

Какво да направите, ако искате да намерите само категориите, в които средната цена е по-голяма от $100? Може да се опитате да напишете:
```sql
-- THIS WILL FAIL!
SELECT category, AVG(price) FROM products WHERE AVG(price) > 100 GROUP BY category;
```
Това е неуспешно, тъй като клаузата `WHERE` филтрира редовете **преди** те да бъдат групирани и агрегирани. Сървърът на базата данни все още не знае средната цена, когато оценява условието `WHERE`.

За да филтрирате групите, трябва да използвате клаузата `HAVING`, която се изпълнява **след** групирането.

| Клауза | Къде филтрира | Може ли да използва агрегати? |
| :--- | :--- | :--- |
| **`WHERE`** | Индивидуални редове (преди групиране). | Не |
| **`HAVING`** | Групирани резултати (след групиране). | Да |

```sql
-- MySQL & PostgreSQL
-- Correct way to filter aggregated groups
SELECT category, AVG(price) AS avg_price 
FROM products 
WHERE is_available = true -- 1. Filters rows
GROUP BY category         -- 2. Groups remaining rows
HAVING AVG(price) > 100;  -- 3. Filters groups
```

## 4. Ключови разлики: MySQL срещу PostgreSQL

### Правилото за строго групиране (Strict Grouping Rule)
Стандартният SQL изисква, че при използване на `GROUP BY`, всяка колона във вашия `SELECT` списък, която не е обвита в агрегатна функция, **трябва** да бъде декларирана в клаузата `GROUP BY`.
* **PostgreSQL** налага това правило строго. Ако изберете колона, която не е в клаузата `GROUP BY` (и не е функционално зависима от първичните ключове в `GROUP BY`), Postgres хвърля синтактична грешка.
* **MySQL** се държи по подобен начин при своя режим по подразбиране `ONLY_FULL_GROUP_BY`. Въпреки това, ако този режим е деактивиран, MySQL позволява да избирате колони, които не са изброени в `GROUP BY`, като връща стойността на произволен ред за тези колони — чест източник на грешки.

```sql
-- Violating the strict grouping rule
SELECT category, brand, AVG(price) 
FROM products 
GROUP BY category;
```
* **PostgreSQL**: Пропада незабавно с `ERROR: column "products.brand" must appear in the GROUP BY clause...`
* **MySQL**: Пропада само ако е активиран режимът `ONLY_FULL_GROUP_BY`. Ако е деактивиран, той връща категорията, произволна марка (brand) от тази категория и средната цена.

### Агрегация на низове (`GROUP_CONCAT` срещу `string_agg`)
Ако искате да комбинирате текстови стойности от групирани редове в единичен низ, разделен със запетаи:
* **MySQL** използва функцията `GROUP_CONCAT()`.
* **PostgreSQL** използва функцията `string_agg()` и изисква синтаксис с изрична клауза `ORDER BY`, ако е необходима подредба.

```sql
-- MySQL: Combines tags per product
SELECT product_id, GROUP_CONCAT(tag_name ORDER BY tag_name SEPARATOR ', ') AS tags
FROM product_tags
GROUP BY product_id;

-- PostgreSQL: Combines tags per product
SELECT product_id, string_agg(tag_name, ', ' ORDER BY tag_name) AS tags
FROM product_tags
GROUP BY product_id;
```

 > [!WARNING]
> **Null капанът на `AVG()`!**
> Тъй като `AVG()` игнорира `NULL` стойностите, това може да изкриви вашите бизнес показатели. Например, ако изчислявате средния бонус на служителите и 9 от 10 служители имат `NULL` (неизвестен/няма) бонус, `AVG(bonus)` ще изчисли средната стойност въз основа на единия служител с бонус, вместо да раздели общата сума на 10. Използвайте `COALESCE(bonus, 0)` вътре в агрегата, за да третирате `NULL` като `0`.

> [!TIP]
> **Знаехте ли, че?**
> Можете да извършвате условна агрегация чрез комбиниране на `SUM` или `COUNT` с изрази. В съвременния PostgreSQL можете да използвате по-чистата клауза `FILTER`:
> `SELECT count(*) FILTER (WHERE price > 100) AS expensive_count FROM products;`
> В MySQL трябва да използвате оператор `CASE` вътре в агрегата:
> `SELECT SUM(CASE WHEN price > 100 THEN 1 ELSE 0 END) AS expensive_count FROM products;`

## 5. Резюме и добри практики

1. **Поддържайте SELECT чист**: Уверете се, че всяка неагрегирана колона във вашия списък `SELECT` присъства и в клаузата `GROUP BY`, за да поддържате съвместимост между различните СУБД.
2. **`WHERE` срещу `HAVING`**: Използвайте `WHERE` за филтриране на необработени редове преди агрегацията, и `HAVING` за филтриране на агрегирани групи.
3. **Управлявайте NULL в показателите**: Не забравяйте, че агрегатните изчисления (с изключение на `COUNT(*)`) игнорират `NULL`. Обвивайте колоните в `COALESCE`, за да зададете стойност по подразбиране 0, ако е необходимо.
4. **Научете диалектните функции**: Използвайте `GROUP_CONCAT` в MySQL и `string_agg` in PostgreSQL при съединяване на низове в групирани редове.
