# Агрегатные функции и группировка

До сих пор мы работали только с отдельными строками. Однако на практике часто требуется анализировать данные на более высоком уровне: рассчитать среднюю зарплату сотрудника, подсчитать количество заказов или найти самый дорогой товар в определенной категории.

Для этого в SQL используются **агрегатные функции** и предложение `GROUP BY`, которые позволяют объединять тысячи строк в единые сводные отчеты. В этой главе мы научимся группировать данные, фильтровать группы с помощью предложения `HAVING`, а также разберем различия в поведении MySQL и PostgreSQL.

---

## 1. Агрегатные функции

Агрегатные функции выполняют вычисления на наборе значений и возвращают одно итоговое значение.

* **`COUNT()`**: возвращает количество строк.
* **`SUM()`**: возвращает сумму числовых значений.
* **`AVG()`**: возвращает среднее арифметическое числовых значений.
* **`MIN()`**: возвращает минимальное значение.
* **`MAX()`**: возвращает максимальное значение.

```sql
-- MySQL и PostgreSQL
-- Рассчитать общее количество, среднюю цену и максимальную цену для всех товаров
SELECT COUNT(*) AS total_products, AVG(price) AS average_price, MAX(price) AS highest_price 
FROM products;
```

### Агрегатные функции и значения `NULL`
Распространенным заблуждением является то, что агрегатные функции включают значения `NULL` в расчеты.
* Большинство агрегатных функций (такие как `SUM`, `AVG`, `MIN`, `MAX`) **полностью игнорируют значения NULL**.
* Функция `COUNT(имя_колонки)` подсчитывает только те строки, в которых указанная колонка **не равна NULL**.
* Функция `COUNT(*)` подсчитывает абсолютно все строки, включая те, что содержат `NULL`.

```sql
-- Если у нас 5 пользователей, и только у 3 указано отчество:
SELECT COUNT(*) FROM users;            -- Вернет 5
SELECT COUNT(middle_name) FROM users;  -- Вернет 3
```

## 2. Группировка данных с помощью `GROUP BY`

Предложение `GROUP BY` разделяет строки таблицы на группы. СУБД применяет агрегатные функции к каждой группе независимо.

```sql
-- MySQL и PostgreSQL
-- Получить среднюю цену для каждой категории товаров
SELECT category, AVG(price) AS avg_price 
FROM products 
GROUP BY category;
```

## 3. Фильтрация групп с помощью `HAVING`

Что если нужно получить только те категории, средняя цена товаров в которых превышает $100? Попытка написать следующий запрос приведет к ошибке:
```sql
-- ЭТОТ ЗАПРОС НЕ ВЫПОЛНИТСЯ!
SELECT category, AVG(price) FROM products WHERE AVG(price) > 100 GROUP BY category;
```
Этот запрос завершится ошибкой, поскольку предложение `WHERE` фильтрует строки **до** того, как они будут сгруппированы и агрегированы. В момент оценки условия `WHERE` СУБД еще не знает среднюю цену.

Для фильтрации уже сгруппированных и агрегированных данных используется предложение `HAVING`, которое выполняется **после** группировки.

| Предложение | Где фильтрует | Можно ли использовать агрегаты? |
| :--- | :--- | :--- |
| **`WHERE`** | Отдельные строки (до группировки). | Нет |
| **`HAVING`** | Сгруппированные результаты (после группировки). | Да |

```sql
-- MySQL и PostgreSQL
-- Правильный способ фильтрации сгруппированных данных
SELECT category, AVG(price) AS avg_price 
FROM products 
WHERE is_available = true -- 1. Фильтрация исходных строк
GROUP BY category         -- 2. Группировка оставшихся строк
HAVING AVG(price) > 100;  -- 3. Фильтрация полученных групп
```

## 4. Ключевые различия: MySQL и PostgreSQL

### Правило строгой группировки
Стандарт SQL требует, чтобы при использовании `GROUP BY` любая колонка, указанная в `SELECT` и не обернутая в агрегатную функцию, **обязательно** присутствовала в предложении `GROUP BY`.
* **PostgreSQL** строго следует этому правилу. Если вы попытаетесь выбрать колонку, не указанную в `GROUP BY` (и функционально не зависящую от первичных ключей в `GROUP BY`), Postgres выдаст ошибку.
* **MySQL** ведет себя так же при включенном режиме `ONLY_FULL_GROUP_BY` (активен по умолчанию в новых версиях). Однако если этот режим отключен, MySQL разрешает выбирать колонки, не перечисленные в `GROUP BY`, возвращая значение первой попавшейся строки в группе, что является частой причиной багов.

```sql
-- Нарушение правила строгой группировки
SELECT category, brand, AVG(price) 
FROM products 
GROUP BY category;
```
* **PostgreSQL**: сразу вернет ошибку `ERROR: column "products.brand" must appear in the GROUP BY clause...`
* **MySQL**: выдаст ошибку только при включенном `ONLY_FULL_GROUP_BY`. Если режим отключен, запрос выполнится и вернет категорию, случайный бренд из этой категории и среднюю цену.

### Агрегация строк (`GROUP_CONCAT` против `string_agg`)
Если требуется объединить текстовые значения из сгруппированных строк в одну строку через запятую:
* В **MySQL** используется функция `GROUP_CONCAT()`.
* В **PostgreSQL** используется функция `string_agg()`, которая требует обязательного явного указания синтаксиса сортировки, если требуется определенный порядок.

```sql
-- MySQL: объединяет теги для каждого продукта
SELECT product_id, GROUP_CONCAT(tag_name ORDER BY tag_name SEPARATOR ', ') AS tags
FROM product_tags
GROUP BY product_id;

-- PostgreSQL: объединяет теги для каждого продукта
SELECT product_id, string_agg(tag_name, ', ' ORDER BY tag_name) AS tags
FROM product_tags
GROUP BY product_id;
```

> [!WARNING]
> **Ловушка с расчетом среднего (`AVG`)!**
> Поскольку `AVG()` игнорирует значения `NULL`, это может исказить бизнес-метрики. Например, если вы рассчитываете средний бонус сотрудников, и у 9 из 10 сотрудников бонус равен `NULL` (отсутствует), `AVG(bonus)` посчитает среднее значение только на основе одного сотрудника, у которого есть бонус, вместо того чтобы разделить общую сумму на 10. Используйте `COALESCE(bonus, 0)` внутри агрегата, чтобы интерпретировать `NULL` как `0`.

> [!TIP]
> **А знаете ли вы?**
> Вы можете выполнять условную агрегацию, комбинируя `SUM` или `COUNT` с логическими выражениями. В современном PostgreSQL для этого есть удобная конструкция `FILTER`:
> `SELECT count(*) FILTER (WHERE price > 100) AS expensive_count FROM products;`
> В MySQL для этого приходится использовать оператор `CASE` внутри агрегатной функции:
> `SELECT SUM(CASE WHEN price > 100 THEN 1 ELSE 0 END) AS expensive_count FROM products;`

## 5. Резюме и лучшие практики

1. **Пишите совместимый SELECT**: всегда вносите все неагрегированные колонки из `SELECT` в предложение `GROUP BY` для переносимости кода.
2. **Различайте WHERE и HAVING**: используйте `WHERE` для предварительной фильтрации строк и `HAVING` — для фильтрации результатов группировки.
3. **Обрабатывайте NULL в расчетах**: помните, что большинство агрегатов (кроме `COUNT(*)`) пропускают `NULL`. Оборачивайте колонки в `COALESCE` для замены NULL на 0.
4. **Используйте правильные функции**: пишите `GROUP_CONCAT` в MySQL и `string_agg` в PostgreSQL для сборки строк из сгруппированных записей.
