# Агрегатні функції та групування

Досі ми отримували лише окремі рядки. Проте в багатьох сценаріях вам потрібно аналізувати дані на більш високому рівні: обчислювати середню зарплату працівника, підраховувати загальну кількість замовлень або знаходити найдорожчий товар у певній категорії.

SQL надає потужні **агрегатні функції** та пропозицію `GROUP BY` для згортання тисяч рядків у змістовні підсумки. У цьому розділі ми навчимося групувати дані, фільтрувати ці групи за допомогою пропозиції `HAVING`, а також розглянемо відмінності в їх виконанні у MySQL та PostgreSQL.

---

## 1. Агрегатні функції

Агрегатні функції виконують обчислення на наборі значень і повертають одне значення.

* **`COUNT()`**: повертає кількість рядків.
* **`SUM()`**: повертає суму числових значень.
* **`AVG()`**: повертає середнє значення числових значень.
* **`MIN()`**: повертає найменше значення.
* **`MAX()`**: повертає найбільше значення.

```sql
-- MySQL & PostgreSQL
-- Обчислення кількості, середньої ціни та максимальної ціни для всіх товарів
SELECT COUNT(*) AS total_products, AVG(price) AS average_price, MAX(price) AS highest_price 
FROM products;
```

### Агрегатні функції та значення `NULL`
Поширеною помилкою є думка, що агрегатні функції враховують значення `NULL` у своїх обчисленнях.
* Більшість агрегатних функцій (такі як `SUM`, `AVG`, `MIN`, `MAX`) **повністю ігнорують значення NULL**.
* `COUNT(column_name)` підраховує лише ті рядки, де вказаний стовпець **не є NULL**.
* `COUNT(*)` підраховує кожен рядок, включаючи рядки зі значеннями `NULL`.

```sql
-- Якщо у нас є 5 користувачів, і лише 3 мають по батькові:
SELECT COUNT(*) FROM users;            -- Повертає 5
SELECT COUNT(middle_name) FROM users;  -- Повертає 3
```

## 2. Групування даних за допомогою `GROUP BY`

Пропозиція `GROUP BY` розділяє рядки таблиці на групи. Після цього рушій бази даних застосовує агрегатні функції до кожної групи окремо.

```sql
-- MySQL & PostgreSQL
-- Отримання середньої ціни для кожної категорії товарів
SELECT category, AVG(price) AS avg_price 
FROM products 
GROUP BY category;
```

---

## 3. Фільтрація груп за допомогою `HAVING`

Що робити, якщо ви хочете знайти лише ті категорії, де середня ціна перевищує $100? Ви можете спробувати написати:
```sql
-- ЦЕЙ ЗАПИТ ПРИЗВЕДЕ ДО ПОМИЛКИ!
SELECT category, AVG(price) FROM products WHERE AVG(price) > 100 GROUP BY category;
```
Цей запит завершиться помилкою, оскільки пропозиція `WHERE` фільтрує рядки **до** того, як вони будуть згруповані та агреговані. Рушій бази даних ще не знає середньої ціни на момент оцінки умови `WHERE`.

Для фільтрації груп необхідно використовувати пропозицію `HAVING`, яка виконується **після** групування.

| Пропозиція | Що фільтрує | Чи можна використовувати агрегати? |
| :--- | :--- | :--- |
| **`WHERE`** | Окремі рядки (до групування). | Ні |
| **`HAVING`** | Згруповані результати (після групування). | Так |

```sql
-- MySQL & PostgreSQL
-- Правильний спосіб фільтрації агрегованих груп
SELECT category, AVG(price) AS avg_price 
FROM products 
WHERE is_available = true -- 1. Фільтрує рядки
GROUP BY category         -- 2. Групує рядки, що залишилися
HAVING AVG(price) > 100;  -- 3. Фільтрує групи
```

## 4. Ключові відмінності: MySQL проти PostgreSQL

### Правило строгого групування
Стандарт SQL вимагає, що при використанні `GROUP BY` будь-який стовпець у вашому списку `SELECT`, який не обгорнутий в агрегатну функцію, **мусить** бути оголошений у пропозиції `GROUP BY`.
* **PostgreSQL** суворо дотримується цього правила. Якщо ви вибираєте стовпець, якого немає в пропозиції `GROUP BY` (і який функціонально не залежить від первинних ключів у `GROUP BY`), Postgres видасть синтаксичну помилку.
* **MySQL** поводиться аналогічно при увімкненому за замовчуванням режимі SQL `ONLY_FULL_GROUP_BY`. Однак, якщо цей режим вимкнено, MySQL дозволяє вибирати стовпці, не вказані в `GROUP BY`, повертаючи значення випадкового рядка для цих стовпців — що часто є джерелом багів.

```sql
-- Порушення правила строгого групування
SELECT category, brand, AVG(price) 
FROM products 
GROUP BY category;
```
* **PostgreSQL**: одразу повертає помилку `ERROR: column "products.brand" must appear in the GROUP BY clause...`
* **MySQL**: видає помилку лише тоді, коли увімкнено `ONLY_FULL_GROUP_BY`. Якщо його вимкнено, запит поверне категорію, випадковий бренд із цієї категорії та середню ціну.

### Агрегація рядків (`GROUP_CONCAT` проти `string_agg`)
Якщо ви хочете об'єднати текстові значення зі згрупованих рядків в один рядок, розділений комами:
* **MySQL** використовує функцію `GROUP_CONCAT()`.
* **PostgreSQL** використовує функцію `string_agg()` і вимагає явного вказання синтаксису `ORDER BY`, якщо потрібен певний порядок.

```sql
-- MySQL: Об'єднує теги для кожного товару
SELECT product_id, GROUP_CONCAT(tag_name ORDER BY tag_name SEPARATOR ', ') AS tags
FROM product_tags
GROUP BY product_id;

-- PostgreSQL: Об'єднує теги для кожного товару
SELECT product_id, string_agg(tag_name, ', ' ORDER BY tag_name) AS tags
FROM product_tags
GROUP BY product_id;
```

> [!WARNING]
> **Пастка Null в `AVG()`!**
> Оскільки `AVG()` ігнорує значення `NULL`, це може спотворити ваші бізнес-метрики. Наприклад, якщо ви обчислюєте середній бонус працівника, і 9 з 10 працівників мають бонус `NULL` (невідомо/немає), `AVG(bonus)` обчислить середнє значення на основі одного працівника, який отримав бонус, замість того, щоб поділити загальну суму на 10. Використовуйте `COALESCE(bonus, 0)` всередині агрегатної функції, щоб трактувати `NULL` як `0`.

> [!TIP]
> **Чи знаєте ви?**
> Ви можете виконувати умовну агрегацію, поєднуючи `SUM` або `COUNT` із виразами. У сучасному PostgreSQL ви можете використовувати більш чистий синтаксис із пропозицією `FILTER`:
> `SELECT count(*) FILTER (WHERE price > 100) AS expensive_count FROM products;`
> У MySQL вам доведеться використовувати конструкцію `CASE` всередині агрегатної функції:
> `SELECT SUM(CASE WHEN price > 100 THEN 1 ELSE 0 END) AS expensive_count FROM products;`

## 5. Підсумок та найкращі практики

1. **Тримайте SELECT чистим**: переконайтеся, що кожен неагрегований стовпець у списку `SELECT` також вказаний у пропозиції `GROUP BY` для забезпечення сумісності між різними рушіями баз даних.
2. **`WHERE` проти `HAVING`**: використовуйте `WHERE` для фільтрації вихідних рядків перед агрегацією, і `HAVING` — для фільтрації агрегованих груп.
3. **Обробляйте NULL у метриках**: пам'ятайте, що aggregate calculations (крім `COUNT(*)`) ігнорують `NULL`. Обгортайте стовпці в `COALESCE`, щоб замінити їх на 0 за замовчуванням, якщо це необхідно.
4. **Вивчайте специфічні функції діалектів**: використовуйте `GROUP_CONCAT` у MySQL та `string_agg` у PostgreSQL для конкатенації рядків у згрупованих рядках.
