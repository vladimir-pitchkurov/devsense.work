# CRUD та транзакції

Отримання даних — це лише половина справи. Для створення динамічних додатків необхідно вміти записувати, змінювати та видаляти записи (операції, відомі під загальною абревіатурою CRUD: Create, Read, Update, Delete — створення, читання, оновлення, видалення). Крім того, при виконанні кількох пов'язаних модифікацій бази даних (наприклад, переказ грошей між двома рахунками) необхідно гарантувати, що або всі операції завершаться успішно, або жодна з них. Саме тут на допомогу приходять **транзакції**.

У цьому останньому розділі ми навчимося змінювати дані, впроваджувати транзакції, а також розберемо ключові відмінності в тому, як PostgreSQL та MySQL керують станами транзакцій та конфліктами запису.

---

## 1. Модифікація даних: INSERT, UPDATE та DELETE

### Вставка записів
Ви можете вставити один рядок або виконати масову вставку (bulk insert) одним запитом.
```sql
-- MySQL & PostgreSQL
-- Одинична вставка
INSERT INTO users (email, name) VALUES ('bob@devsense.work', 'Bob');

-- Масова вставка (рекомендується для підвищення продуктивності)
INSERT INTO users (email, name) 
VALUES 
    ('alice@devsense.work', 'Alice'),
    ('charlie@devsense.work', 'Charlie');
```

### Оновлення записів
Модифікує існуючі записи. Завжди переконуйтеся, що ви фільтруєте оновлення за допомогою пропозиції `WHERE`.
```sql
-- MySQL & PostgreSQL
UPDATE users SET is_active = true WHERE id = 42;
```

### Видалення записів
Видаляє записи назавжди. Як і `UPDATE`, ця операція вимагає наявності пропозиції `WHERE` для уникнення катастрофічної втрати даних.
```sql
-- MySQL & PostgreSQL
DELETE FROM users WHERE is_active = false;
```

> [!WARNING]
> **Пастка відсутності пропозиції `WHERE`!**
> Якщо ви запустите `UPDATE users SET is_active = true;` або `DELETE FROM users;` без пропозиції `WHERE`, рушій бази даних змінить або видалить **абсолютно всі рядки** в таблиці. Завжди перевіряйте свій запит перед виконанням!

## 2. Транзакції: захист цілісності даних

Транзакція — це послідовність операторів SQL, що виконується як єдина, неподільна одиниця роботи. Транзакції відповідають стандартам **ACID**:
* **Atomicity (Атомарність)**: усі оператори виконуються успішно, або вся транзакція повністю скасовується (все або нічого).
* **Consistency (Узгодженість)**: гарантує, що база даних переходить з одного валідного стану в інший, дотримуючись усіх обмежень.
* **Isolation (Ізольованість)**: транзакції, що виконуються одночасно, не заважають одна одній.
* **Durability (Довговічність)**: після фіксації зміни остаточно записуються на диск і зберігаються навіть у разі збоїв системи.

### Команди транзакцій
* **`BEGIN` / `START TRANSACTION`**: запускає блок транзакції.
* **`COMMIT`**: остаточно зберігає всі зміни, зроблені під час транзакції.
* **`ROLLBACK`**: скасовує всі зміни, зроблені під час транзакції, повертаючи базу даних до стану, що передував транзакції.

```sql
-- MySQL & PostgreSQL
BEGIN; -- Початок транзакції

UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;

-- Якщо все гаразд:
COMMIT;

-- Якщо сталася помилка або ми передумали:
-- ROLLBACK;
```

## 3. Ключові відмінності: MySQL проти PostgreSQL

### Синтаксис Upsert (вставка або оновлення при конфлікті ключів)
Операція "upsert" вставляє рядок, якщо він не існує, або оновлює його, якщо він викликає конфлікт з існуючим унікальним індексом чи первинним ключем.
* **MySQL**: використовує пропозицію `ON DUPLICATE KEY UPDATE`.
* **PostgreSQL**: використовує пропозицію `ON CONFLICT (conflict_column) DO UPDATE`.

```sql
-- MySQL (ON DUPLICATE KEY UPDATE)
INSERT INTO users (id, email, visits) 
VALUES (1, 'user@devsense.work', 1)
ON DUPLICATE KEY UPDATE visits = visits + 1;

-- PostgreSQL (ON CONFLICT DO UPDATE)
INSERT INTO users (id, email, visits) 
VALUES (1, 'user@devsense.work', 1)
ON CONFLICT (id) DO UPDATE SET visits = users.visits + 1;
```

### Транзакційна DDL (мова визначення даних)
Це одна з найважливіших структурних відмінностей між двома базами даних.
* **PostgreSQL** підтримує повністю транзакційну DDL. Ви можете виконувати такі команди, як `CREATE TABLE`, `DROP TABLE` або `ALTER TABLE` всередині транзакції і безпечно скасовувати їх (rollback), якщо щось піде не так.
* **MySQL** НЕ підтримує транзакційну DDL. Якщо ви виконаєте оператор DDL всередині транзакції в MySQL, це викличе **неявну фіксацію (implicit commit)** (також відому як автофіксація). MySQL негайно фіксує транзакцію до цього моменту, виконує DDL, і ви вже не зможете скасувати жоден з попередніх записів.

```sql
-- PostgreSQL (Це працює і буде повністю скасовано!)
BEGIN;
DROP TABLE users;
ROLLBACK; -- Таблиця 'users' безпечно відновлена!

-- MySQL (Це скасувати не вдасться!)
START TRANSACTION;
INSERT INTO logs (message) VALUES ('Deleting users table');
DROP TABLE users; -- Викликає неявну фіксацію!
ROLLBACK; -- Нічого не робить; вставка та DROP вже зафіксовані!
```

### Синтаксис початку транзакції
* **PostgreSQL**: віддає перевагу стандартній команді `BEGIN` (хоча приймає і `START TRANSACTION`).
* **MySQL**: віддає перевагу `START TRANSACTION` (хоча приймає `BEGIN` у більшості контекстів клієнтів; проте всередині збережених процедур `BEGIN` зарезервовано для блокових структур, тому там вимагається саме `START TRANSACTION`).

> [!TIP]
> **Чи знаєте ви?**
> PostgreSQL підтримує пропозицію `RETURNING` для операцій запису. Це дозволяє негайно отримати згенерований первинний ключ або обчислені стовпці без запуску окремого запиту `SELECT`.
> `INSERT INTO users (email) VALUES ('new@devsense.work') RETURNING id, created_at;`
> *MySQL не підтримує `RETURNING` і вимагає від клієнтських бібліотек виклику функцій на кшталт `LAST_INSERT_ID()` для отримання згенерованого ключа.*

## 4. Підсумок та найкращі практики

1. **Тримайте транзакції короткими**: тривалі транзакції утримують блокування на рядках бази даних, блокуючи інших користувачів та збільшуючи ймовірність виникнення взаємних блокувань (deadlocks).
2. **Остерігайтеся неявних фіксацій у MySQL**: не змішуйте зміни схеми (DDL на кшталт `ALTER TABLE`) зі змінами даних (DML на кшталт `UPDATE`) всередині транзакцій, якщо ви плануєте покладатися на можливість скасування (rollback).
3. **Використовуйте upsert обережно**: підбирайте правильний синтаксис для вашої бази даних (`ON CONFLICT` для PostgreSQL та `ON DUPLICATE KEY UPDATE` для MySQL) для коректної обробки порушень обмежень унікальності ключів.
4. **Завжди вказуйте WHERE**: захистіть себе від випадкового очищення таблиць, переконуючись, що запити `UPDATE` та `DELETE` містять строгі умови `WHERE`.
