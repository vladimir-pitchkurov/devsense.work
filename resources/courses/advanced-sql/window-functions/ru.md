# Оконные функции: партиционирование, сортировка и границы фрейма

Представьте, что вы разрабатываете дашборд для отображения списка транзакций клиентов. Вам нужно показать детали каждой транзакции, но дополнительно требуется вывести накопительный итог трат по каждому клиенту, его ранг на основе суммы операции, а также сумму его предыдущей транзакции.

Использование стандартной конструкции `GROUP BY` свернет строки, из-за чего вы потеряете детализацию отдельных транзакций. Решение этой задачи на стороне приложения потребует загрузки всех записей в память и последующего обхода в цикле, что медленно и ресурсозатратно. **Оконные функции** решают эту проблему, выполняя вычисления по набору строк таблицы, связанных с текущей строкой, без сворачивания результирующего набора.

---

## 1. Основные механизмы: группировка против оконных вычислений

В отличие от `GROUP BY`, который агрегирует несколько строк в одну итоговую строку, оконные функции вычисляют агрегатное значение или ранг для каждой строки индивидуально, сохраняя все детализированные поля.

```
GROUP BY:
[Строка 1] \
[Строка 2]  --> [Агрегированная строка]
[Строка 3] /

ОКОННАЯ ФУНКЦИЯ:
[Строка 1] --> [Строка 1] [Вычисленное значение 1]
[Строка 2] --> [Строка 2] [Вычисленное значение 2]
[Строка 3] --> [Строка 3] [Вычисленное значение 3]
```

### Базовый синтаксис
```sql
-- MySQL 8.0+ и PostgreSQL
SELECT 
    employee_id, 
    department_id, 
    salary,
    SUM(salary) OVER(PARTITION BY department_id) AS dept_total_salary
FROM employees;
```
* **`PARTITION BY`**: Разделяет строки на группы (партиции), имеющие одинаковые значения. Если опущено, весь результирующий набор обрабатывается как одна партиция.
* **`ORDER BY`**: Определяет физический порядок сортировки строк внутри каждой партиции. Это критично для последовательного расчета значений.

## 2. Функции ранжирования и смещения

Оконные функции делятся на агрегатные (например, `SUM` или `AVG`), ранжирующие и функции смещения.

### Ранжирование: `ROW_NUMBER()`, `RANK()` и `DENSE_RANK()`
При совпадении значений (связях/ties) эти функции ведут себя по-разному:
* **`ROW_NUMBER()`**: Назначает уникальный последовательный номер, начиная с 1. Дубликаты нумеруются произвольно.
* **`RANK()`**: Присваивает ранг с пропусками. Если две строки делят 1-е место, обе получат ранг 1, а следующая строка получит ранг 3.
* **`DENSE_RANK()`**: Присваивает плотный ранг без пропусков. Если две строки делят 1-е место, обе получат ранг 1, а следующая строка — ранг 2.

| Сотрудник | Зарплата | `ROW_NUMBER()` | `RANK()` | `DENSE_RANK()` |
| :--- | :--- | :--- | :--- | :--- |
| Alice | $10,000 | 1 | 1 | 1 |
| Bob | $10,000 | 2 | 1 | 1 |
| Charlie | $8,000 | 3 | 3 | 2 |
| David | $7,000 | 4 | 4 | 3 |

### Функции смещения: `LAG()`, `LEAD()` и `FIRST_VALUE()`
* **`LAG(col, offset, default)`**: Доступ к значению из строки на указанном смещении *перед* текущей строкой.
* **`LEAD(col, offset, default)`**: Доступ к значению из строки на указанном смещении *после* текущей строки.

```sql
-- Получение суммы текущей и предыдущей транзакции для расчета разницы
SELECT 
    transaction_date,
    amount,
    LAG(amount, 1, 0) OVER(ORDER BY transaction_date) AS prev_amount
FROM transactions;
```

## 3. Границы фрейма: скользящее окно

Фрейм окна определяет динамический подмножество строк внутри партиции относительно текущей строки. Фрейм смещается по мере того, как СУБД обрабатывает каждую строку.

### Типы фреймов: `ROWS` против `RANGE` против `GROUPS`
* **`ROWS`**: Учитывает физические строки относительно текущей (например, 5 строк до текущей).
* **`RANGE`**: Учитывает логический диапазон значений на основе колонки в `ORDER BY`. Сюда включаются все строки-дубликаты по значению сортировки (обрабатываются как единое целое).
* **`GROUPS`**: Учитывает группы одинаковых значений на основе сортировки.

```sql
-- Пример накопительного итога с фреймом
SUM(amount) OVER(
    PARTITION BY user_id 
    ORDER BY transaction_date
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
)
```

> [!WARNING]
> **Ловушка с `LAST_VALUE()`!**
> Если вы напишете `LAST_VALUE(salary) OVER(PARTITION BY dept_id ORDER BY salary)`, вы можете ожидать, что вернется максимальная зарплата в отделе. На деле вернется зарплата текущей строки!
> Это происходит потому, что при указании `ORDER BY` дефолтный фрейм выглядит так:
> `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`
> Чтобы исправить это, явно задайте границы фрейма:
> `LAST_VALUE(salary) OVER(PARTITION BY dept_id ORDER BY salary RANGE BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING)`

## 4. Сравнение MySQL и PostgreSQL: архитектурные различия

Несмотря на то, что обе СУБД соответствуют стандарту ANSI SQL, они различаются по набору функций, синтаксическим расширениям и производительности.

### 1. Предложение `FILTER` (Только в PostgreSQL)
PostgreSQL поддерживает выражение `FILTER` совместно с агрегатными оконными функциями, что позволяет выборочно собирать строки без использования громоздких конструкций `CASE WHEN`.
```sql
-- Только в PostgreSQL
SELECT 
    department_id,
    COUNT(employee_id) FILTER (WHERE salary > 5000) OVER(PARTITION BY department_id) AS highly_paid_count
FROM employees;
```
В MySQL вам придется писать:
```sql
-- Аналог для MySQL
SELECT 
    department_id,
    SUM(CASE WHEN salary > 5000 THEN 1 ELSE 0 END) OVER(PARTITION BY department_id) AS highly_paid_count
FROM employees;
```

### 2. Исключение строк из фрейма (Только в PostgreSQL 11+)
PostgreSQL поддерживает расширенное исключение строк из фрейма, позволяя тонко настраивать расчеты:
* `EXCLUDE CURRENT ROW`: Исключает текущую строку из расчета.
* `EXCLUDE GROUP`: Исключает текущую строку и все строки с аналогичным значением сортировки.
* *MySQL 8.0 не поддерживает конструкции `EXCLUDE` при определении фрейма.*

> [!TIP]
> **Совет по оптимизации:**
> Оконные функции выполняются на завершающем этапе обработки запроса (после `WHERE` и `GROUP BY`). Чтобы ускорить их работу, создайте составной индекс, соответствующий колонкам в `PARTITION BY` и `ORDER BY`. Это позволит оптимизатору избежать дорогостоящей промежуточной сортировки на диске (filesort).

## 5. Резюме и лучшие практики

1. **Сохраняйте идентичность строк**: Используйте оконные функции, когда вам нужны агрегированные данные бок о бок с деталями записей.
2. **Следите за дефолтами**: Помните, что добавление `ORDER BY` меняет дефолтный фрейм на расчет от начала до текущей строки, что влияет на кумулятивные суммы и функции вроде `LAST_VALUE()`.
3. **Используйте индексы**: Всегда проверяйте, чтобы поля для `PARTITION BY` и `ORDER BY` были покрыты индексами во избежание создания временных таблиц на диске.
