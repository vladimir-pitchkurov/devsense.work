# Віконні функції: секціонування, впорядкування та фрейми

Уявіть, що ви створюєте дашборд для відображення списку транзакцій клієнтів. Вам потрібно показати деталі кожної транзакції, але також ви хочете відобразити накопичувальний підсумок витрат для кожного клієнта, його ранг на основі суми транзакції та суму його попередньої транзакції.

Використання стандартного `GROUP BY` згортає ваші рядки, втрачаючи деталі окремих транзакцій. Виконання цього в логіці додатка вимагає отримання всіх записів та проходження по них у циклі, що є повільним і ресурсомістким процесом. **Віконні функції** вирішують цю проблему, виконуючи обчислення на наборі рядків таблиці, які пов'язані з поточним рядком, без згортання результуючого набору.

---

## 1. Основна механіка: групування проти віконного аналізу

На відміну від `GROUP BY`, який агрегує кілька рядків в один підсумковий рядок, віконні функції обчислюють агрегат або ранг для кожного рядка окремо, зберігаючи всі детальні поля.

```
GROUP BY:
[Рядок 1] \
[Рядок 2]  --> [Агрегований рядок]
[Рядок 3] /

ВІКОННА ФУНКЦІЯ:
[Рядок 1] --> [Рядок 1] [Обчислене значення 1]
[Рядок 2] --> [Рядок 2] [Обчислене значення 2]
[Рядок 3] --> [Рядок 3] [Обчислене значення 3]
```

### Базовий синтаксис
```sql
-- MySQL 8.0+ & PostgreSQL
SELECT 
    employee_id, 
    department_id, 
    salary,
    SUM(salary) OVER(PARTITION BY department_id) AS dept_total_salary
FROM employees;
```
* **`PARTITION BY`**: розділяє рядки на групи (секції), які мають однакові значення. Якщо його опустити, весь результуючий набір буде оброблятися як одна секція.
* **`ORDER BY`**: визначає фізичний порядок сортування рядків всередині кожної секції. Це визначає, як значення обробляються послідовно.

## 2. Функції ранжування та отримання значень

Віконні функції поділяються на агрегатні (наприклад, `SUM` або `AVG`), функції ранжування та функції отримання значень.

### Ранжування: `ROW_NUMBER()`, `RANK()` та `DENSE_RANK()`
Коли значення ідентичні (збіги), ці функції поводяться по-різному:
* **`ROW_NUMBER()`**: призначає унікальне послідовне ціле число, починаючи з 1. Збіги вирішуються довільно.
* **`RANK()`**: призначає ранг із пропусками. Якщо два рядки претендують на 1-ше місце, обидва отримають ранг 1, а наступний ранг буде 3.
* **`DENSE_RANK()`**: призначає ранг без пропусків. Якщо два рядки претендують на 1-ше місце, обидва отримають ранг 1, а наступний ранг буде 2.

| Працівник | Зарплата | `ROW_NUMBER()` | `RANK()` | `DENSE_RANK()` |
| :--- | :--- | :--- | :--- | :--- |
| Alice | $10,000 | 1 | 1 | 1 |
| Bob | $10,000 | 2 | 1 | 1 |
| Charlie | $8,000 | 3 | 3 | 2 |
| David | $7,000 | 4 | 4 | 3 |

### Функції отримання значень: `LAG()`, `LEAD()` та `FIRST_VALUE()`
* **`LAG(col, offset, default)`**: звертається до значення з рядка на певному фізичному зміщенні *перед* поточним рядком.
* **`LEAD(col, offset, default)`**: звертається до значення з рядка на певному фізичному зміщенні *після* поточного рядка.

```sql
-- Отримання поточної та попередньої суми транзакції для обчислення різниці
SELECT 
    transaction_date,
    amount,
    LAG(amount, 1, 0) OVER(ORDER BY transaction_date) AS prev_amount
FROM transactions;
```

## 3. Фрейми вікна: ковзне вікно

Фрейм вікна (window frame) визначає динамічну підмножину рядків усередині секції відносно поточного рядка. Фрейм зміщується в міру того, як рушій бази даних обробляє кожен рядок.

### Типи фреймів: `ROWS` проти `RANGE` проти `GROUPS`
* **`ROWS`**: підраховує фізичні рядки відносно поточного рядка (наприклад, 5 рядків перед ним).
* **`RANGE`**: підраховує логічні значення на основі стовпця в пропозиції `ORDER BY`. Він включає всі рядки, які мають такі самі значення, як і поточний рядок (збіги обробляються разом).
* **`GROUPS`**: групи однакових значень на основі стовпця впорядкування.

```sql
-- Приклад фрейму для накопичувального підсумку
SUM(amount) OVER(
    PARTITION BY user_id 
    ORDER BY transaction_date
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
)
```

> [!WARNING]
> **Пастка `LAST_VALUE()`!**
> Якщо ви напишете `LAST_VALUE(salary) OVER(PARTITION BY dept_id ORDER BY salary)`, ви можете очікувати, що запит поверне найвищу зарплату у відділі. Натомість він поверне зарплату поточного рядка!
> Це відбувається тому, що за наявності `ORDER BY` фрейм за замовчуванням є таким:
> `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`
> Щоб виправити це, явно вкажіть фрейм:
> `LAST_VALUE(salary) OVER(PARTITION BY dept_id ORDER BY salary RANGE BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING)`

## 4. MySQL проти PostgreSQL: архітектурні відмінності

Хоча обидва рушії відповідають стандартам ANSI SQL, вони відрізняються своїми можливостями, розширеннями синтаксису та продуктивністю виконання.

### 1. Пропозиція `FILTER` (Лише PostgreSQL)
PostgreSQL підтримує пропозицію `FILTER` з агрегатними віконними функціями, що дозволяє вибірково агрегувати рядки без використання складних конструкцій `CASE WHEN`.
```sql
-- Лише для PostgreSQL
SELECT 
    department_id,
    COUNT(employee_id) FILTER (WHERE salary > 5000) OVER(PARTITION BY department_id) AS highly_paid_count
FROM employees;
```
У MySQL вам доведеться написати:
```sql
-- Еквівалент у MySQL
SELECT 
    department_id,
    SUM(CASE WHEN salary > 5000 THEN 1 ELSE 0 END) OVER(PARTITION BY department_id) AS highly_paid_count
FROM employees;
```

### 2. Виключення з фрейму (Лише PostgreSQL 11+)
PostgreSQL підтримує розширені опції виключення з фрейму (frame exclusion), що дозволяє виключати певні рядки з обчислень фрейму вікна.
* `EXCLUDE CURRENT ROW`: виключає поточний рядок із фрейму.
* `EXCLUDE GROUP`: виключає поточний рядок та всі його однакові за значеннями впорядкування рядки.
* *MySQL 8.0 не підтримує пропозиції `EXCLUDE` у фреймах вікна.*

> [!TIP]
> **Порада щодо продуктивності:**
> Віконні функції виконуються на завершальному етапі обробки запиту (після `WHERE` та `GROUP BY`). Для їхньої оптимізації створіть складений індекс, який відповідає стовпцям у `PARTITION BY` та `ORDER BY`. Це дозволить рушію запитів отримувати вже відсортовані дані напряму, уникаючи дорогих операцій сортування (filesorts).

## 5. Підсумок та найкращі практики

1. **Зберігайте ідентичність рядків**: використовуйте віконні функції, коли вам потрібні агрегатні обчислення разом із полями окремих рядків.
2. **Слідкуйте за значеннями за замовчуванням**: пам'ятайте, що додавання `ORDER BY` автоматично змінює стандартний фрейм вікна, що впливає на накопичувальні суми та такі функції, як `LAST_VALUE()`.
3. **Використовуйте індекси**: завжди перевіряйте, щоб ключі `PARTITION BY` та `ORDER BY` були проіндексовані, щоб запобігти створенню тимчасових таблиць бази даних на диску.
