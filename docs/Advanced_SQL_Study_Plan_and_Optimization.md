# **План обучения: Продвинутый SQL, Архитектурные различия и Оптимизация (MySQL vs PostgreSQL)**

**Цель курса:** Выход на уровень экспертного владения реляционными СУБД, понимание внутренних механизмов выполнения запросов, проектирование высоконагруженных схем данных и миграция между диалектами.

## ---

**Модуль 1: Продвинутый синтаксис и Аналитический SQL**

### **1.1 Common Table Expressions (CTE) — Обобщенные табличные выражения**

* **Базовые и последовательные CTE:** Линеаризация сложной логики, область видимости временных таблиц.  
* **Рекурсивные CTE (WITH RECURSIVE):** Обход графов, построение деревьев категорий, вычисление иерархических структур (менеджер-подчиненный, меню). Защита от бесконечных циклов (лимиты глубины).  
* **Под капотом СУБД:** Механизмы материализации. Различия в оптимизации CTE в PostgreSQL (MATERIALIZED / NOT MATERIALIZED) и MySQL 8.0 (Cost-based inline/materialization).

### **1.2 Оконные функции (Window Functions)**

* **Анатомия окна:** Секции PARTITION BY, ORDER BY, и определение границ фрейма (ROWS/RANGE/GROUPS BETWEEN ... AND ...).  
* **Функции ранжирования:** Разница и бизнес-кейсы применения ROW\_NUMBER(), RANK(), DENSE\_RANK(), NTILE().  
* **Функции смещения:** LAG(), LEAD(), FIRST\_VALUE(), LAST\_VALUE(), NTH\_VALUE().  
* **Агрегаты как оконные функции:** Вычисление скользящего среднего, нарастающего итога (Running Total), кумулятивных сумм.  
* **Оптимизация:** Избежание лишних сортировок (шаги WindowAgg в планах запросов), влияние композитных индексов на производительность оконных функций.

### **1.3 Продвинутые JOIN-ы и операции над множествами**

* **Нестандартные соединения:** CROSS JOIN (декартово произведение), SELF JOIN (соединение таблицы с самой собой), NATURAL JOIN (почему это антипаттерн).  
* **Условные соединения:** Использование нестрогих неравенств в условиях ON (например, поиск пересечений временных интервалов).  
* **Операции над множествами:** UNION vs UNION ALL (влияние на производительность и выделение памяти), INTERSECT, EXCEPT / MINUS.

## ---

**Модуль 2: Программирование внутри СУБД и Объекты базы**

### **2.1 Представления (Views) и Материализованные представления**

* **Обычные представления (Views):** Логическая абстракция, синтаксический сахар, безопасность доступа.  
* **Обновляемые представления:** Условия, при которых через View можно делать INSERT/UPDATE (MySQL WITH CHECK OPTION).  
* **Материализованные представления (Materialized Views):** Кэширование тяжелых аналитических агрегатов. Стратегии и инкрементальное обновление данных.

### **2.2 Хранимые процедуры и Функции (SP & Functions)**

* **Разница между процедурой и функцией:** Возврат значений, контекст вызова, управление транзакциями внутри процедур.  
* **Языки программирования:** PL/pgSQL в Postgres против процедурного диалекта MySQL. Различия в синтаксисе циклов, ветвлений и объявления переменных.  
* **Обработка ошибок:** Использование \`DECLARE CONTINUE/EXIT HANDLER\` в MySQL и блоков \`BEGIN ... EXCEPTION\` в Postgres.

### **2.3 Триггеры (Triggers)**

* **Типы триггеров:** BEFORE, AFTER, INSTEAD OF (для сложных Views). Уровни: FOR EACH ROW (строчные) против FOR EACH STATEMENT (операторные).  
* **Бизнес-кейсы:** Аудит изменений (историрование), поддержание денормализованных счетчиков, кастомная валидация данных перед вставкой.  
* **Опасности:** Падение производительности при массовых вставках (Bulk Updates), скрытая логика, приводящая к взаимным блокировкам (Deadlocks).

**Модуль 3: Архитектурная битва: MySQL vs PostgreSQL**

| Критерий сравнения | MySQL (Engine: InnoDB) | PostgreSQL   |
| :---- | :---- | :---- |
| **Модель конкурентности** | Блокировки строк \+ Undo Log для MVCC. Кластеризованный индекс (данные лежат в PK). | Чистый MVCC. Данные лежат в куче (Heap), индексы ссылаются на cтроки (TID/CTID). |
| **Проблема раздувания (Bloat)** | Старые версии строк очищаются в фоне через Purge-потоки из Undo Log. Таблицы не раздуваются. | Старые версии строк остаются прямо в таблице. Требуется агрессивный VACUUM / AUTOVACUUM. |
| **Работа с JSON** | Тип данных JSON. Поддержка бинарного формата, JSON-индексы через виртуальные колонки. | Типы JSON и JSONB (бинарный, разобранный). Мощные индексы GIN для мгновенного поиска внутри объектов. |
| **Диалекты и синтаксис** | Регистронезависимость по умолчанию (зависит от Collation), кавычки (\`), нестрогий GROUP BY в старых версиях. | Строгая типизация, чувствительность к регистру имен без кавычек ("), обилие кастомных операторов (например, \-\>\>). |
| **Расширяемость** | Ограничена встроенным функционалом и плагинами хранилищ. | Максимальная: поддержка кастомных типов данных, индексов, расширений (PostGIS, TimescaleDB, pg\_stat\_statements). |

### **3.1 Уникальные фичи PostgreSQL, которых нет в MySQL**

* **Типы данных:** Массивы (INT\[\]), диапазоны (DATERANGE), перечисления (CREATE TYPE AS ENUM).  
* **Специфический синтаксис:** INSERT ... ON CONFLICT DO UPDATE (с мощным синтаксисом исключений), оператор DISTINCT ON (column).  
* **Фичи CTE:** Изменение данных внутри CTE (WITH moved\_rows AS (DELETE ...) INSERT INTO ...).

### **3.2 Уникальные фичи MySQL, которых нет в Postgres**

* **Кластеризованные индексы:** Первичный ключ физически упорядочивает данные таблицы, что делает выборки по PK максимально быстрыми.  
* **Специфический синтаксис:** INSERT INTO ... ON DUPLICATE KEY UPDATE, конструкции REPLACE INTO.  
* **Dual Table:** Историческая таблица DUAL для фиктивных запросов (хотя в современных версиях можно писать SELECT 1 без FROM).

**Модуль 4: Глубокая Оптимизация и Тюнинг Производительности**

### **4.1 Анализ планов запросов (Execution Plans)**

* **Сбор метрик:** Использование EXPLAIN, EXPLAIN ANALYZE (в обеих СУБД), форматирование планов в JSON для детального разбора.  
* **Критические операции:** Понимание разницы между Seq Scan / Table Scan (полное сканирование), Index Scan (сканирование по индексу) и Index Only Scan / Covering Index (выборка данных напрямую из дерева индекса).  
* **Алгоритмы соединений:** Разбор стратегий СУБД для JOIN-ов: Nested Loop (вложенные циклы), Hash Join (хэш-соединение), Merge Join (соединение слиянием). Как помочь базе выбрать правильный алгоритм.

### **4.2 Индексы: Мастерский уровень**

* **Типы индексов в Postgres:** B-Tree (стандарт), Hash (только равенство), GiST/SP-GiST (геометрия, интервалы), GIN (массивы, JSONB), BRIN (для гигантских упорядоченных таблиц, логирование).  
* **Продвинутые техники:**  
  * Композитные (составные) индексы: правило левого префикса, правильный порядок колонок (равенство, диапазон, сортировка).  
  * Частичные (партиционированные) индексы: CREATE INDEX ... WHERE active \= true; (экономия места на диске и ускорение поиска).  
  * Индексы по выражениям (функциональные): CREATE INDEX ... ON users (LOWER(email));.  
* **Покрывающие индексы:** Использование секции INCLUDE в Postgres для добавления неключевых колонок в B-Tree индекс.

### **4.3 Архитектурные паттерны оптимизации**

* **Борьба с N+1 на уровне БД:** Оптимизация пакетных апдейтов, генерация JSON на стороне СУБД для отдачи в бэкенд одной строкой.  
* **Партиционирование (Partitioning):** Секционирование гигантских таблиц по диапазонам дат (Range) или хэшу (Hash). Различия декларативного партиционирования в MySQL и Postgres.  
* **Оптимизация пагинации:** Почему OFFSET / LIMIT деградирует на больших сдвигах и как переписать запросы на Keyset Pagination (пагинация на основе курсоров / WHERE id \> LastID).
